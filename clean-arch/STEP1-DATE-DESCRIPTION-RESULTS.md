# Step 1 date-text description diagnostic

## Result and limits

All 48 calls completed: eight previously examined articles, three fresh answers with the saved description and three with the candidate. Each pair used the same source, model settings and that article's original saved thesis context. Three independent readers compared all answers with the source while the condition labels were hidden; the author checked the records and then opened the labels. The [article replay](../poc/data/clean-step1-date-description-2026-11-07/review.html) contains every source, open-thesis context, answer and citation. The cases were selected to investigate known problems, not sampled from the whole feed, and a previous FEV example uses prepared text while the other cases use their saved cleaned sources.

The candidate is not adopted. Its results are mixed: it avoided some previously observed date-field mistakes, but errors remained and other extraction concerns appeared. The existing system prompt already asks for the distinction, and this comparison does not identify the internal cause of any error. An improvement on three draws of a known article is a lead, not evidence of production readiness.

## Source-backed observations

- **Optical networking:** all three control answers put the time of a product introduction or partner-list growth into `statement_date_text`; one of three candidate answers also put the introduction year there. The specific 2028 optical implementation forecast was kept in all three candidate answers and no control answer. One control kept a separate “next couple of years” statement, which is not necessarily equivalent to the 2028 prediction. These are selected-case observations, not proof that the field wording caused coverage changes.
- **SambaNova financing:** all six answers retained the explicitly dated Wednesday financing announcement and JPMorgan statement, even though that day also matched the publication date. One control answer also gave Wednesday to an interview and IPO discussion for which the article does not establish the date. One candidate answer put the literal string `"null"` into the date-text field for two evidence items; it is text, not JSON null. All six financing records omitted the first source sentence supporting the $1 billion amount from their attached passages, although that amount appears in the full source.
- **FEV release:** most answers preserved the release's 9 July date instead of the page's 10 July date. One control answer retained “9 July 2026” as text but left the normalized date empty in two records. One candidate answer left both date fields empty for a company official's quote in the dated release; the source supports the release date but not necessarily the date the official originally spoke offline. These distinctions require source interpretation.
- **SK Hynix:** all six kept “said in June” for the chairman's statement and separated it from the five-year plan. One candidate answer used Friday's listing date as a statement date; one control answer used the market-share “as of June” date as a statement date. Two answers called the person SK Hynix chairman when the source says SK Group chairman; the response condition is not established as the cause.
- **LG racks:** one answer in each arm treated “last month,” which modifies Huang's visit, as the time of the reported discussion. The article does not explicitly date the discussion. Some answers connected rack specifications to the existing Vera CPU performance/adoption question without the source establishing those CPU outcomes; others treated them as broader context or proposed a distinct question. Industry attribution and source tier also varied.
- **NVIDIA and Hugging Face robotics:** one control answer assigned the media byline day to corporate statements whose original dates were not established; the three candidate answers did not. All three candidate answers and one control answer linked the robotics material to the existing Nemotron/NemoClaw adoption question without an explicit source bridge. Two control answers proposed a robotics question. Whether an indirect link is useful is a judgement, but the original source does not establish that these are the same products.
- **NVIDIA's own blog:** some answers assigned its publication date to third-party actions or quotations without an independently stated original date. One candidate answer left the date empty for NVIDIA's own availability statement even though the input metadata dates NVIDIA's analysis; whether date *text* must be populated when the date is supplied only in metadata is ambiguous. Keep this as a potential regression, not an established mistake.
- **Bloomberg valuation:** all six left the original statement-date fields empty for figures and forecasts whose statement dates were not supplied, rather than using the market-share or forecast periods. Several answers still differed in attribution, which source facts were attached, and coverage.

The eight cases do not exhaust older-statement-in-own-release situations or other domains. Correctness of dates, source attribution, source-support and thesis relevance must be judged against the source, not by the number of evidence records.

Two later continuations of the exact saved robotics answers each recognized, when explicitly asked, that the named robotics tools do not establish adoption of the Nemotron/NemoClaw agent stack. Both cited the instructions to match an existing question and consider indirect relevance. One considered a separate robotics question; the other favored no link and expressed uncertainty about opening a topic. These were leading follow-ups, not proof of the original model's reasoning or a new rule that a topic needs proven business impact. [Full requests and responses](../poc/data/clean-step1-robotics-link-accounts-2026-11-07/).

## Literal `"null"` in the date-text field

A reproducible exact-field [census](../poc/data/clean-step1-date-description-2026-11-07/null-string-census.json) examined seven saved diagnostic cohorts: twelve evidence items across four answers contained the literal string `"null"` in `statement_date_text`, among 904 evidence records. The subsequent preregistered eight-source cohort contained none among 158 records. Claude identified the sixth cohort after the initial five-cohort census; its six additional instances occur in one answer. The cohorts repeat articles and settings; this is not a population rate. The original 49-article clean replay contains none among its 160 evidence records. The twelve literal strings occurred across three source articles, including two SambaNova articles. Their full `statement_date` values were actual JSON null.

The schema accepts either a string or JSON null; the string `"null"` is structurally a string, so the local schema check and clean validator retain it. The exploratory output retains the text. The new comparison replay now displays JSON date-text values explicitly, so `null` and `"null"` are visually distinct without rewriting the original answer. The clean Step 1 to existing production-writer conversion is not implemented and tested, so there is no evidence this reached the production database or that any downstream decision used it. No semantic rejection or automatic rewriting has been added. The right handling must preserve the distinction between actual unknown and a source's literal words, retain useful evidence, and be tested at the real handoff before any production claim.

## Resource use

Each arm had 24 calls. Control used 129,138 prompt and 33,027 completion tokens, including 7,016 reasoning tokens; candidate used 130,842 prompt and 37,457 completion tokens, including 6,925 reasoning tokens. The 76 control versus 88 candidate evidence records reflect different grouping and selection, not a quality score. The candidate description grew from 70 characters / 15 tokens to 406 / 85; it was tested in isolation, not accepted as production prompt growth.
