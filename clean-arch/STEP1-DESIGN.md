# Step 1 implementation design

## Exploratory continuation for unmatched passages

Alex asked that mechanical quotation checks not stop the forward review. On an unmatched nonempty passage the isolated runner retains the exact model text and article, records a null verified passage in the same position, and continues with the model's proposed thesis state. Every later state is provisional because it may depend on an unverified evidence item. Exact or safely normalized source matches keep their existing verified spans; the legacy prefix recovery remains rejected when it loses words. An unmatched passage is never labeled verified or sent to the production ledger. Empty passages, schema and identity errors, transport errors and incomplete responses retain their previous behavior. The replay shows the model's passage and an explicit unverified label. The original stopped runs remain unchanged.

The source, original model output, current article state and subsequent requests remain visible to the reviewer. The new rule only changes the clean exploratory writer and replay reader; it does not change production, the original model output, source database or historical ruler. No new quote-matching algorithm or second model call is introduced.

## Exploratory continuation for an unresolved thesis link

Article 21 returned two evidence items linking to `nt1` as a new thesis, but its `new_theses` list was empty. The intended thesis cannot be recovered from an ID alone. The exploratory runner therefore retains each proposed evidence and its exact model link, marks unresolved references in the result, and does not invent or add a thesis for them. An actual new thesis without any resolved evidence link is retained in the trace but is not added to the open state. Resolved pairs in the same answer may advance; the next article sees only defined, supported new theses. All affected and later states remain provisional. The replay explicitly marks missing new or existing references. Invalid model response shape and transport failures remain separate errors; no production behavior changes.

Continuation after a stopped run starts a new trace from the last completed state with the remaining frozen articles in order, beginning with the failed article. The failed response is preserved in the first trace; the new segment is an explicitly recorded fresh send, not an overwrite of history. The replay presents the completed prefix and the new segment together, with the original failed attempt retained in its original trace.

Status: independently reviewed design. The earlier single-passage path completed one selected live run; the revised multi-passage schema was exercised in the 49-article exploratory run and is not formally accepted. Scope: isolated, sequential Step 1 only; no Step 2–4 or production writes. `PRD.md` sections 4, 12, 17 and 18 govern this path. The prompt and schema are read from the PRD to keep one source of truth. The production extractor and its frozen configuration remain unchanged.

## State and events

One run owns one new SQLite output file, a fixed ordered list of item IDs, entity and configuration. There is one writer and no automatic resume or retry. A record of the full request is committed before the external call; a response and its resulting state are committed together. Existing files are refused. The source is opened read-only. No cross-entity behavior is implemented. Initial IDs are preserved, and new IDs are chosen without colliding with initial or earlier generated IDs. Caller supplies item count, budget and speed target before any paid run; the runner must not imply targets are achieved.

| State | Event | Transition and writes | Time and visibility |
|---|---|---|---|
| Not started | Valid configuration, source, unique ordered IDs and new output path | Create run, initial theses and a complete ordered manifest of selected source records. Initial IDs are unique; every thesis includes question, outcome and known period and belongs to the chosen entity. | Use dates supplied in the source; list order is caller-owned. |
| Not started | Invalid input or existing output | Refuse without a model call. | No state change. |
| Ready for item | Build request | Commit full source item, prior thesis state and exact request as in-flight. | Read all open theses for the run entity; no evidence history. |
| In flight | Valid response with valid links and source passages | In one transaction save raw response, interpreted links and new theses; mark complete. | Next item reads the committed preceding state. New IDs are assigned by the library. |
| In flight | Unmatched passage or unresolved thesis link | Retain the original output and mark it provisional; advance only defined new theses with resolved evidence. | Later exploratory states remain provisional; no production write. |
| In flight | Malformed, refused or invalid schema | Save raw response and reason; mark failed, stop. No thesis advances. | Earlier committed state stays visible; no automatic retry. |
| In flight | Transport error | Save available error, mark failed, stop. | Same as invalid response. |
| In flight | Crash before/after send or commit | Committed in-flight trace stays visible; if transaction completed it is complete. | Do not resume automatically; inspect output. A new explicit run is required. |
| Failed or complete | Later invocation, modified config, changed input or second writer | Refuse an existing output file rather than continuing. | The original trace remains intact; a new run requires a new file. |

No timestamps determine ordering. Concurrent execution is outside this first runner; SQLite transaction and output-file ownership protect its single process, not a distributed service. All selected source rows and their order are frozen in the run manifest before the first send, so later source edits cannot alter an item waiting its turn. The selection names a bounded date window and is checked against the chosen entity tags and explicit item IDs. The initial eligible subset has feed=1 and excludes identified copies and corrections; it does not claim to reproduce the complete production dispatch. Caller records separate item, monetary and elapsed-time budgets before a paid run. Budget enforcement and measurements must be implemented before a paid run; merely recording them is not a claim they were met.

## Source passage review

The existing `extraction.normalise` and `repair_quote` accept punctuation and glyph changes, omitted runs, limited near edits and exact-prefix truncation; they may return an exact source span different from the model quote. `tests/test_quote_check.py` documents stored examples including cleaned spacing in the CNBC 2026-07-21 record, altered date, omitted text, changed parties and crossing sentence boundaries. Exact matching alone would refuse some source-faithful model quotes that the existing path accepts. The initial runner does not supply entity aliases to the repair function, so it is narrower than production for name-for-pronoun substitutions; it must not claim parity. The first runner must retain both raw model passage and any recovered exact source passage, use the existing repair only when the recovered span is verified against the stored source, and visibly label repair; otherwise retain the original passage as unverified for exploratory review. On the stored CNBC record, the original quote differed in punctuation spacing; `repair_quote` returned a span present verbatim in the source. Review on the new path must also cover refusal cases before accepting the repair.

## Live transport design (pending review)

The exploratory run uses one OpenAI Chat Completions request per selected item, sequentially. It is a separate entry point; the recorded-response mode remains available. The implementation reuses `model.call`, `model.Archive`, `model.openai_transport`, `model.build_request` and the existing price accounting. | Event | State/write and limit behavior |
|---|---|
| Before opening the isolated run | Require fixed ordered manifest, explicit item limit, request output cap, whole-run monetary ceiling and elapsed-time ceiling. Reject unsupported model/provider or missing/invalid limits. |
| Before each send | Rebuild and save the exact request for the current state; compute a conservative estimated maximum charge from its serialized byte size and capped output, with configured conservative prices. Reserve that maximum against the whole-run budget. Check the monotonic deadline before starting. |
| HTTP response | Make one request, no transport retry. Save full provider response and usage. Validate content and references before committing new thesis state. The full clean trace and conservative reservation remain available for those attempts. The provider bill is authoritative. |
| Refusal, malformed response, HTTP error or timeout | Record the response or exception that is available, mark failed and stop; keep the before state. Do not retry. A timeout can still have been billed. |
| Budget exhausted or deadline reached | Refuse the next send and mark the run stopped; no state advances for that item. The socket timeout uses remaining time; it is not a guarantee of an absolute wall-clock deadline. |
| Crash | Keep committed request/in-flight trace. Never silently resend; new run requires a new output file. |

Before any paid send: complete request review, freeze the three selected source IDs and run limits, verify a fake response through the actual runner, and run the applicable no-cost preflight. The preflight checks the historical production path, not this new path. User's requested first run is exploratory and not an acceptance measurement. The proposed conservative budget uses externally specified rates and explicit model identity; it is a guard against starting another call, not a contractual bill cap. Test both permitted and refused paths with fake network responses; verify the negative test against a mutant before use.

Review clarification: the wire body is constructed from the same serialized request saved in the trace. `finish_reason` must be `stop` and an explicit refusal fails even if a content field is present. HTTP status and response body, and malformed provider bytes decoded with replacement, are retained when available. A failed or timed-out request retains its whole reservation as an uncertain possible charge; it is not recorded as free. Test these paths without credentials or network.

## Same-article evidence with several source passages

Alex's direction is that one evidence summary can combine related material from separate parts of the same source article; cross-article integration is outside Step 1. Each model evidence item now has a nonempty array of contiguous source spans. Each span is located separately in the frozen current item and returned with both raw and verified text and its repair flag. No element may be dropped. Empty elements fail; unmatched elements are retained as unverified and the exploratory thesis state is provisional. For a repaired span, require the normalized model quotation to occur contiguously in the normalized recovered source; this tolerates spacing, glyph and case differences and a final source punctuation mark without accepting omitted words or changed comparison symbols. A read-only replay of three historical draws found that the legacy helper accepted 25 quotes which did not appear contiguously under this normalization: the earlier guard refused all 25, including seven prefix recoveries. The current exploratory runner retains them as unverified instead of stopping. The other 18 contain additions or substitutions and may include useful recoveries; quantify and inspect losses before claiming readiness. This checks source location only, not whether the summary logically follows from it. The old production helper and archived data remain unchanged.

| Changed value | Readers and compatibility |
|---|---|
| `source_passages` list | Luna produces one or more contiguous spans per evidence, the schema enforces a nonempty list, and clean validation verifies every element. The prompt requires all passages needed for the summary. |
| `verified_source_passages` and `source_passages_repaired` lists | Trace and reviewer read them in the same order as the original list. No segment is silently removed. |
| Existing production `quote` string | The old writer and downstream readers still expect a single string. The mapping of multiple spans to the production ledger remains Step 3 work; this change does not assert compatibility. |
| Historical single-passage trace | Existing run files retain their historical format and are not rewritten; the new runner uses the new schema for new runs. |

The local check must replay the recorded H200 failure on a copy: a model-style answer with the original joined string as one element must remain unverified, and the same answer with its two real source spans as separate elements must be verified without losing either span. A recorded newline-only repair must remain accepted; a changed fact or missing segment must not be labeled verified. These checks do not call a model and do not establish semantic accuracy or production acceptance.

## Exploratory same-article citation-completion proposal

The check-placement comparison did not produce a clean source-fidelity fix: on the known examples some outputs improved Firmus citation support but other arrangements lost a named customer or the full FEV connectivity condition. The output schema already supports multiple passages; code cannot infer the right semantic support from keywords or numbers. Alex explicitly allows evidence to cite several distinct portions of one article. Cross-article integration remains outside Step 1.

A possible exploratory follow-up uses one separate model call on a **completed saved article answer**, not a new thesis-routing or importance decision. The call receives the exact selected article, available source metadata and source-role selections as explicitly fallible context, plus each model-produced evidence ID, its full summary, its original party, reporter, tier and time fields, link explanation and passages already attached. Original content and roles are preserved; metadata alone cannot establish a company statement or invented numeric amount. It asks the model to check each source-attributed fact and condition against that item's passages and appropriate source metadata. Where support is present elsewhere in the same supplied article, it may propose additional *verbatim contiguous* source passages for that evidence ID; where a summary or a source-attributed fact in a link explanation contradicts or exceeds the source, it may identify the unresolved claim. This does not judge investment importance or rewrite the link. Inferences and cautious statements that the article does not establish a later outcome must not be misrepresented as directly sourced facts. The original summary, thesis links and original passages remain unchanged. An additional passage is a model proposal, not proof that the summary is accurate. Code can locate a proposed span in the selected source and original captured page; it cannot judge the claim's significance or semantic entailment. A proposed passage that cannot be located stays visible as unverified and is not silently rewritten or discarded.

This is an isolated feasibility test, not an adopted production stage or a user-facing hard gate.
