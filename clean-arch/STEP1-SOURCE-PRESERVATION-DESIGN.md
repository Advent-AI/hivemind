# Step 1: test-source preservation candidate

**Status: isolated candidate built and checked, not an adopted cleaner or production source.** Alex authorized correcting the test-source cleaner and test data when their defects interfere with testing. The [source-backed findings](STEP1-FULL-PAGE-RESULTS.md) establish that the current cleanup both loses article text and mixes some unrelated text into article inputs. They also show wrong captures and model interpretation errors that preserving a page cannot resolve.

## Question and proposed comparison

Can an isolated source version preserve the page text that the collector actually saved, retain the target item's identifying metadata and upstream eligibility, and allow Step 1 to inspect records that the cleaner excluded? This is a source-preservation experiment. A captured page may contain a different article, a paywall, later material, generated summaries or navigation; an available page is not proof of a complete target article. The alternative of restoring the upstream eligibility flag while retaining cleaned text leaves 271 excluded records empty and retains the known deleted and mixed passages.

The proposed new, separately named test database is built from copies of the existing raw and cleaned snapshots. For originally eligible article records, it exposes the exact saved page text as the candidate input. Preserve, separately and without rewriting, the original clean text, captured page text, input ID, URL, title, publisher, publication and retrieval timestamps, upstream and cleaned feed flags, coverage values and copy/supersedes identity. Record which representation was selected and that article identity and completeness are unassessed. The candidate must not overwrite either original database or the archived HTML. The captured page is extracted text, not raw HTML.

For a concrete experiment mapping, a row whose raw snapshot has `document_format='article'` and `feed=1` receives candidate `feed=1` and candidate `text` equal to its saved `text_page`; all other rows retain the cleaned snapshot's `feed` and `text`. Candidate `coverage` stays at the cleaned snapshot value for every row, with raw and cleaned coverage stored separately: neither value is a completeness assertion. If a selected page is absent, the candidate text is empty and the current runner refuses a manifest containing it; the absence remains visible for an explicit, separate handling decision. The source representation and snapshot identities are audit metadata in the candidate, not additional model instructions. Do not set the existing `source_preparation` marker merely to trigger its extra page check: candidate text already equals the page for the selected cohort; page-location observations should be recorded separately and compared with the original path. Preserve the semantics of any existing content hash; record a separately named candidate-input hash rather than silently reinterpreting an old one.

For each changed text, write `text_chars = len(candidate text)` and preserve the old cleaned count separately; the old `cleaning` field describes historical cleaning, not the candidate page. Restored rows deliberately pair candidate `feed=1` with the historical cleaned `coverage='none'`. This combination is for the isolated clean runner only: other corpus utilities assume different feed and coverage semantics and must not consume the candidate without an explicit contract. The replay renderer explicitly supports this audit metadata; other viewers must not be assumed to display it.

The representation is a candidate to test, not a claim that all originally eligible records are valid articles. The existing source payload sends a title, publisher, URI, publication date and selected text, but does not send the capture timestamp, coverage or a new provenance field. Any change to what the model sees is a separate request-contract change and must be explicit. In particular, a metadata column stored only for a reviewer is not model context.

## State and event

| Situation | Candidate behavior and record | Date and source |
|---|---|---|
| Before building | Read original snapshots and page fields without modifying them; identify the target record by input ID. | Preserve stored publication and retrieval values; do not infer original publication content from retrieval time. |
| Available saved page | Copy the exact captured page text into the candidate input and retain the old cleaned value and both flags for comparison. | Retain both original dates and source URI. |
| Empty or absent page | Retain the record and record missing source; do not manufacture article text or call it irrelevant. | Record existing source metadata and the missing condition. |
| Copy or superseded item | Retain identity and flags in the candidate; the current runner's existing selection rules still apply. | Keep original IDs and dates. |
| Wrong page, paywall, mixed stories or later material | Preserve what was captured and mark source identity or completeness unassessed. Review source roles; do not call an empty model answer proof that the actual article is irrelevant. | Keep capture and publication dates distinct; do not assign a date absent from the source. |
| Run starts or an item fails | Current runner prevalidates the complete manifest and stops on invalid or empty input; a runtime failure stops the run with its trace. A missing-page outcome cannot be represented by simply including an empty input. Any different continuation or replay behavior requires a separate design and test. | Use manifest order and stored dates; do not use wall-clock time as stream order. |
| Inputs change, build fails or concurrent version exists | Fail the candidate build without modifying either source; use a new destination and retain the compared versions. | Record the actual source snapshot identities and build inputs. |

## Values and readers

| Value | Reader and current behavior | Candidate obligation |
|---|---|---|
| `items.text` | `testdb.item_of`, `runner.selected_items`, request payload and quote validation | Declare the chosen representation; prove request text equals the intended saved page. |
| `items.text_page` | Clean runner quote checks when source preparation is set; diagnostic reviewers | Preserve captured page bytes; a found quote does not prove correct article, attribution or meaning. |
| `feed`, `coverage` | Runner selection checks feed; corpus and test DB utilities interpret these fields | Preserve old and upstream values separately. Any candidate feed or coverage value has an explicit test-only meaning and is not evidence of completeness. |
| IDs, copy and supersedes | Runner's selection and source links | Preserve values and existing selection behavior; do not count copies as independently selectable. |
| Source metadata and extra provenance | Runner selects specific fields for the model; trace stores item data | Record both what is stored and what the model actually receives. Preserve the original item and capture dates, and never imply a stored extra field is sent. |
| Evidence quotations | Runner and later evidence writer/readers | Record exact sent text and captured-page location separately; a successful location check is not semantic verification. Existing multi-passage writer integration remains unproved. |

Before implementation, search the field readers again and review this table against them. The full-page representation may change every formerly fed article's input; preserve and report the actual cohort rather than presenting it as a fix affecting only the 615 excluded records.

## Offline proof before any model send

1. Compare all 34,084 item identities and all fields copied from both snapshots; enumerate the 6,463 upstream-fed article records, original/clean flags and every candidate change. Confirm the 615 cleaner exclusions, 271 empty cleaned texts, nonempty saved pages and two copy markers in that class. Verify page and clean-text hashes and all metadata, including that the actual selected text equals its declared source.
2. Check the known single-line CNBC article and the CFO outlook sentence as positive preservation examples. Check the weather shell, paywall, challenge code, wrong-page capture, unrelated Firmus story and labelled generated summaries as controls. They must remain recognizable in the audit; preserving these pages does not mean they are safe evidence.
3. Exercise the actual clean Step 1 entry point with a fake transport and a temporary database: verify exact source text and metadata in the request, quote checks, selection, state after valid output, existing unresolved-link behavior and a missing-input failure. Describe any case that the current entry point cannot handle instead of claiming it was processed.
4. Compare full request sizes and existing limits on the actual candidate inputs. Keep the result, version and comparison separate from the original test corpus. No paid model run, prompt change, source DB replacement or production-readiness claim follows from this offline proof.

## What a later model test must answer

On a fixed and independently source-reviewed sample, compare the candidate and prior input with the same thesis state and request, and inspect every answer against the sources. Examine recovered information, unrelated material, attribution, source meaning, links, omissions, model refusals and recorded citations. Use previously examined cases to diagnose and separately selected sources to test generalization. A correct quote is not a guarantee of a correct summary; a correct source is not a guarantee that the model uses it. Any sample size or pass criterion needs evidence and a stated purpose, not a threshold chosen to make a case pass.

## First isolated build

[The builder](step1/preserve_page_source.py) created [a candidate database](../poc/data/clean-step1-full-page-diagnostic-2026-11-07/page-source-candidate-v4.sqlite), leaving both source snapshots unchanged. Its audit includes hashes of the ordered item records as read in each snapshot, the old cleaned text and both feed/coverage values. The [full-row comparison](../poc/data/clean-step1-full-page-diagnostic-2026-11-07/check-page-source-candidate.py) checked all 34,084 records: 6,463 candidate article inputs are their captured page text and 615 prior feed exclusions are visible, including 271 with empty old clean text. This comparison verifies preservation and mapping, not whether the captured page is the target article.

An [actual-runner check](../poc/data/clean-step1-full-page-diagnostic-2026-11-07/check-page-source-runner.py) used a recorded fake answer and confirmed that the previously excluded CNBC item reaches the runner with the exact saved page, including the $105 billion passage. This is not a Luna extraction test. The replay renderer now displays the candidate's saved input representation, the earlier cleaned text, capture and publication dates, feed flags, and unassessed source identity and completeness. These audit fields are not sent to the model. Existing runner failure behavior is unchanged. A real comparison of source quality, the other offline controls above, and page identity remain outstanding.

Two further saved-answer replays check whether candidate preservation changes existing observations. The [102-answer replay](../poc/data/clean-step1-full-page-diagnostic-2026-11-07/replay-candidate-answers.py) reconstructs the saved `source_item` fields, uses each saved request and schema, and reproduces all 102 recorded validation outcomes and their 597 passage observations. The [49-answer forward replay](../poc/data/clean-step1-full-page-diagnostic-2026-11-07/replay-forward-answers.py) compares the original sent text and candidate-preserved clean text with the current validator: all 49 completed answers and their 250 passages agree, with 248 passages located. One previously failed answer is excluded and counted separately. These are historical-output and validation checks; they neither send a new model request nor validate source meaning or writer delivery.

The candidate's build manifest explicitly describes its test-only scope and the historical meanings of `content_sha256` and `coverage`; the candidate text has a separate hash. The builder's tests exercise a missing page, copy identity, preservation of a non-article item and refusal when source identity metadata differs. A fake-answer run through the real runner and replay renderer checks that source representation, earlier cleaned text and uncertainty are visible to a reviewer; those audit fields are still not sent to Luna. Two scratch mutations that substituted the old clean text or bypassed the identity comparison failed their corresponding tests.
