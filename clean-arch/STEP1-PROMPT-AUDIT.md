## Post-run source-passage change

Alex chose to let one Step 1 evidence item combine related information from multiple locations in the same article. Cross-article integration belongs to later work. In the selected three-article run, one of eight evidence items combined two distant source passages in one string; the old prefix repair then removed the second, while the summary kept its number. In three older 243-call draws, the same prefix branch was triggered on seven of 2,109 evidence outputs; four were saved with summary details absent from their saved quotes. These are observed counts on those runs, not a general error rate.

| Failure class | Request and code | Standard or decision | Verdict |
|---|---|---|---|
| Two source passages returned as one stitched quote; repaired to prefix | Old draft asked for one verbatim `source_passage`; the model joined two passages with an ellipsis. `repair_quote` intentionally accepts a complete prefix, and the clean adapter accepted that returned span without checking the discarded suffix. | Signed standard §5.4 requires the statement's source meaning and conditions; Alex explicitly chose multiple passages in one article to support one evidence. D266 intentionally retains an exact source prefix for the existing production path. | Shape cannot represent two separate passages; model also did not follow the old verbatim instruction; the new adapter failed to preserve all quoted content. Code and contract must change together. The frozen production helper and historical results do not change. |

The new clean contract uses a nonempty `source_passages` array: each element is a contiguous verbatim span from the current article, and multiple spans may jointly support one evidence summary. The clean validator checks each independently. Legacy quote repair may be used only when the normalized model quotation occurs contiguously in the normalized recovered source; an unverifiable or truncated element was initially set to fail the item; Alex later chose to retain it as unverified and continue the isolated exploratory state. This is a text-location check, not proof of semantic entailment. On the three historical draws, the guard refuses all 25 previously accepted noncontiguous repairs, including seven prefix recoveries; the other 18 contain additions or substitutions and may include useful recoveries that require review; this is a documented tradeoff for the isolated clean path, not a claim that production changed. The provider accepted the revised schema in the exploratory run; two passages were recorded as unverified, and source-location compliance is not a measure of semantic quality.

### Independent complete-request review

A separate reader checked the assembled request against the signed standard and clean decisions. The final section says “Check for” errors but does not explicitly direct the model to correct each class and return the corrected result. This may make the final check less operational; the traces do not establish that it caused the observed errors. The schema's requirement that a returned evidence item have a link does not by itself force a wrong link: the answer can propose a new thesis or return no evidence. Sharing an entity or broad ecosystem is not by itself a connection to the specific research question; the request already asks for matching subject, outcome and scope, but its examples do not explicitly contrast a shared ecosystem with an unsupported link.

The signed standard also excludes interpretation of an already recorded event that adds no new fact or calculation. The saved prompt mentions commonplace or unargued views and specific new analysis with a fact or calculation, but does not state that boundary as explicitly. Article 37's commentary is a possible example; its reported revenue figure remains separately useful. This is an audit lead, not a proven causal explanation.

Article 1 shows a possible state consequence: its new performance thesis `T1` is linked only to the company-reported benchmark E1. If E1 is excluded under the signed standard, this answer has no remaining evidence for T1. The separate adoption thesis `T2` has other evidence and must not be removed on that basis. This is one observed trace, not proof that a blanket thesis filter is appropriate.

The full archived source-role instruction, numbered page, and structured-output schema were read together. ## Prepared-source citation failures and check placement

The seven-item prepared-source run used the clean extraction prompt recorded in each local packet. Two independent readers inspected every returned item: 21 evidence records and 33 exact source passages. Two summaries contained concrete claims absent from their own citations despite support elsewhere in the article: Firmus evidence-1 included the US$2bn raising, and FEV ev-2 included limited/no-internet operation. Several other passages used a pronoun or company reference whose referent appears in adjacent source text. The source-location code did not remove these passages; the raw model answer did not return the missing passages. Original page and selected text were available in both cases. Whether article metadata may establish the reporting outlet is assessed separately from a claim that a passage itself establishes a financial amount or condition.

The assembled request says to return source passages supporting each standalone summary, to copy each passage separately and contiguously, and to include every passage needed for the summary. The final check asks for unsupported claims and missing conditions, but it is in the system message before the article JSON. The recorded schema allows a nonempty array of multiple `source_passages`. The signed extraction standard's source-fidelity rules and Alex's decision to preserve complete citations support the requirement; no new evidence category is proposed. The whole original system text, user JSON and schema are preserved. A source-locating check does not decide semantic entailment, so code must not infer an extra passage based on a number or an entity name.

The model's leading self-review found the Firmus paragraph but did not notice the FEV connectivity condition, even though that paragraph is in its input. This is a retrospective signal that a generic second look may still miss details, not proof of the original mechanism. An independently reviewed placement comparison in `STEP1-DESIGN.md` holds final-check words and the exact JSON fixed while testing message ordering; the current and historical production prompts are not changed by the test.

A blind request-only reader independently audited the actual FEV request against the signed standard and Alex's broader topic rule, without reading the model answer. They identified the missing explicit exclusion of purely descriptive executive praise as a separate potential noise gap, and a possible ambiguity between splitting distinct matters and preserving a mixed single matter. Neither finding establishes the cause of the citation omissions. They initially called the FEV day a date conflict; after checking the timezone conversion, they withdrew that claim: the host page's July 10 Vietnam timestamp is July 9 in New York, and the listing timestamp and FEV release day are separate provenance values.

A fourth isolated comparison arm tests a clarification of the existing final-check row: `- Missing or mislinked evidence; source-attributed facts or conditions not supported jointly by the cited passages and source metadata.` It does not require every passage to contain every name, or treat inference as a source fact. A separate standard reader checked that the clarification adds no new keep/reject rule. The candidate is not inserted into the PRD prompt or production.

### Final-check placement comparison result

All 84 selected-case calls completed and were reviewed blind before the arm key was opened. On Firmus, the $2bn raising was cited adequately in 2/3 System, 2/3 Before, 3/3 After and 3/3 After + citation answers. On FEV, source-supported connectivity wording appeared in 2/3, 2/3, 3/3 and 1/3 respectively, with further ambiguous or omitted conditions; explicit no-internet language appeared in 2/3, 2/3, 1/3 and 1/3. ## Proposed per-idea NONE clarification (2026-11-06)

The implementation council proposed one isolated change to the clean request, recorded in [the implementation plan](STEP1-IMPLEMENTATION-COUNCIL.md); it has not changed the active PRD prompt. Stored article 4 and article 27 answers link evidence to a thesis while the explanation states that the evidence does not inform it. Of 199 returned links in that selected 49-item run, three explicitly deny their own relationship; these are visible examples, not a census of every wrong link. The raw response contains the links. The model later acknowledged examples when asked leading questions; that retrospective account does not establish why the original response made them.

| Request and observed class | Governing boundary | Verdict |
| --- | --- | --- |
| Existing `NONE` describes an empty result for the whole item; other instructions already require evidence to inform its thesis and allow existing, new or no pairs. The observed outputs violate that implied relationship. | Clean PRD: an evidence item may support, challenge or add context; multiple informed links are allowed; a meaningful topic may open with evidence. The signed standard distinguishes relevant evidence and source fidelity; its historical opening rule is not identical to Alex's later clean topic rule. | Candidate is a clarification and controlled hypothesis. No prompt contradiction or causal mechanism has been demonstrated. |

The proposed replacement clarifies `NONE` per idea and places the existing link requirement outside that conditional. A blind request reader checked the full system prompt and schema in both directions and found no material new contradiction; the earlier version incorrectly made the prohibition read as conditional and was revised. Risks include overly narrow treatment of indirect context, omitted worthwhile new topics, failure to link multiple evidence items to one new thesis, and mishandling related periods. These controls must be reviewed against raw articles and answers. The full saved system prompt grows from 2,697 to 2,727 `o200k_base` tokens; the 30-token growth makes the per-idea option and unconditional instruction explicit. This is a reason for an exploratory candidate, not evidence of improved quality. The six saved control answers pass existing structural checks; the candidate has not been sent.

### Comparison result

Independent blind readers found the candidate still returned a self-denying Shield TV link (1/3, original 2/3), while no candidate DeepSeek answer linked the custom-chip report to the inference-partnership thesis (original 2/3). In that same article both arms omitted the Kyber delay and company denial in every draw, and each retained the separate revenue/margin guidance once. Three-draw selected-case observations do not establish why the model made those choices or a general improvement; the candidate is not adopted.
