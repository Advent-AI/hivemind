# 让向量只找候选，让字段和判官定身份

观点库只该让 embedding 做一件事：高召回地捞出"可能相关的已有观点"。"是不是同一个观点、该 skip（只加证据）、merge 还是新建"，要由代码比较结构化字段（标的、驱动、方向、财期或事件日期），再加一次"从几个排好序的候选里选一个"的 LLM 判定来决定。同一件事被多家报道，要先聚成事件簇，每簇只记一次证据。证据很一致。单向量模型在否定对比检索上最好只有 39%（随机为 25%）；在只差一个数字的金融句子上平均 54%（随机为 50%），四位数（也就是年份）处于随机水平。所以项目内部测到的"同一句话、不同季度 cosine 0.988"是预料之中的系统性行为，不是偶然。在实体匹配上，让 LLM 一次看完约 4 个候选再"选择"，比逐对判"是否相同"的 F1 高约 17 点，成本还更低。agent 记忆系统的演化指向同一方向：Mem0 在 2026 年 4 月放弃了让 LLM 在相似邻域上 UPDATE/DELETE；Graphiti 从不删除，只由代码按日期置失效；独立测评显示，这类系统的主要失败是漏更新（遗漏率 52–98%），而不是错更新。嵌入本身很便宜，每天 3,000 份文件全部分块嵌入，估计每月 4–45 美元；2 万条观点全部重嵌不到 1 美元。钱和风险都在判官调用和验证集上。没有任何公开基准测过"投资观点是否与已有观点相同"，所以下文推荐方案里的阈值、top-k 和事件时间窗，都只能在项目自己存储的数据上标定。

## 记忆系统两年内从"改写与删除"退到"只追加、打失效标记"

### Mem0 先让 LLM 增删改，再亲手拆掉

Mem0 论文（2025 年 4 月）描述的是被模仿最多的两段式流水线。第一次 LLM 调用从对话里抽出事实。第二次对每条事实用向量取 top s=10 条最相似的记忆，让 GPT-4o-mini 通过 function calling 直接选操作：没有语义等价记忆时 ADD，有补充信息时 UPDATE，被新信息反驳时 DELETE，否则 NOOP。中间没有单独的分类器 ([Mem0 paper](https://arxiv.org/html/2504.19413))。开源代码 v1.0.11 实际每条事实只取 `limit=5`，调用前把 UUID 映射成 "0""1"……"for handling UUID hallucinations"。UPDATE 在同一 id 下覆盖文本和向量。DELETE 直接从向量库硬删，旧值只留在一张检索从不读取的 SQLite 历史表里 ([mem0 v1.0.11 main.py](https://github.com/mem0ai/mem0/blob/v1.0.11/mem0/memory/main.py#L555-L592); [L1340-L1364](https://github.com/mem0ai/mem0/blob/v1.0.11/mem0/memory/main.py#L1340-L1364))。提示词用例子划边界："Likes cheese pizza" 与 "Loves cheese pizza" 不更新；"cheese pizza" 加 "chicken pizza" 被合并改写成一句；"Loves" 遇上 "Dislikes" 就 DELETE ([mem0 prompts.py](https://github.com/mem0ai/mem0/blob/0724291bd864cf807e88ee8981c8226644e8fb42/mem0/configs/prompts.py#L176-L325))。图变体 Mem0g 后来把删关系改成了软删除（`r.valid = false, r.invalidated_at`），理由是要支持对历史状态做时间推理 ([graph_memory.py](https://github.com/mem0ai/mem0/blob/v1.0.11/mem0/memory/graph_memory.py#L420-L432))。

**2026-04-14，Mem0 把整套流水线换掉了。** 新算法只追加（"nothing is overwritten or deleted"），检索改成语义 + BM25 + 实体加权的混合打分。官方给的理由是旧算法的 UPDATE/DELETE 会丢历史、处理"信息变了"很差：用户从纽约搬到旧金山，两条事实都应该带着时间保留下来 ([Mem0 migration v2→v3](https://github.com/mem0ai/mem0/blob/0724291bd864cf807e88ee8981c8226644e8fb42/docs/migration/platform-v2-to-v3.mdx))。现在的开源写入路径是：整批新消息嵌入后只取 top_k=10 条已有记忆，一次 LLM 调用抽取新记忆，机械去重只有 MD5 精确文本比对 ([main.py L918-L1220](https://github.com/mem0ai/mem0/blob/0724291bd864cf807e88ee8981c8226644e8fb42/mem0/memory/main.py#L918-L1220))。语义去重完全交给提示词里的两句话："语义等价且没有新上下文就跳过"，"拿不准就抽，下游去重系统会处理真重复" ([prompts.py L468-L946](https://github.com/mem0ai/mem0/blob/0724291bd864cf807e88ee8981c8226644e8fb42/mem0/configs/prompts.py#L468-L946))。研究笔记读代码时还发现，模型返回的 `linked_memory_ids`（包括标"矛盾"的链接）在 Python 开源路径里根本没有写入存储 ([main.py L1007-L1200](https://github.com/mem0ai/mem0/blob/0724291bd864cf807e88ee8981c8226644e8fb42/mem0/memory/main.py#L1007-L1200))。真正的冲突处理搬进了闭源平台的 "Dream" 层。Supersede 把被反驳的旧事实标成过时，并链接到新事实。Merge 把重复折叠进一条规范记忆，被合并的记录默认对读取隐藏，但保留不删，原话是 "Nothing Dream does is destructive" ([dream.mdx](https://github.com/mem0ai/mem0/blob/0724291bd864cf807e88ee8981c8226644e8fb42/docs/platform/features/dream.mdx))。Dream 的提示词、候选数和阈值都没有公开，也没有精度或召回数字。

Mem0 的效果数字全部是厂商自报，而且有争议。论文表格里 LoCoMo 的 LLM-judge 分数是 Mem0 66.88、Mem0g 68.44、Zep 65.99、LangMem 58.10、A-Mem 48.38，但**全上下文的 72.90 高于所有记忆系统** ([Mem0 paper](https://arxiv.org/html/2504.19413))。Zep 指出 Mem0 有三处配置错误，比如把两个说话人都设成 user；纠正后 Zep 自报 75.14 ([Zep blog](https://www.getzep.com/blog/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/))。Letta 用一个只带 grep、打开文件这类工具的普通 agent 跑出 74.0% ([Letta blog](https://www.letta.com/blog/benchmarking-ai-agent-memory))。v3 自报 LoCoMo 91.6、LongMemEval 93.4，没有找到独立复现 ([Mem0 changelog](https://github.com/mem0ai/mem0/blob/0724291bd864cf807e88ee8981c8226644e8fb42/docs/changelog/highlights.mdx))。对观点库来说，这些问答分数用处不大，因为它们测的是回答问题，不是"这一条是否重复"的判断。

### Graphiti 用结构定候选，一次调用出两张下标表，日期交给代码

Graphiti 是 Zep 的开源核心，也是"不删、只失效"做得最完整的公开参考，候选生成和判定拆得最干净。去重候选按结构定：只在**同一对实体之间**的边里找，先用 BM25 + cosine 混合检索（RRF 融合，默认取 10 条，cosine 下限 0.6），再按端点精确过滤。矛盾候选是在整个 group 里不加端点过滤再搜一次，并扣掉已经是去重候选的那些 ([edge_operations.py L399-L646](https://github.com/getzep/graphiti/blob/d50741d1bf463cbe3859eb73914cbff1b66839e6/graphiti_core/utils/maintenance/edge_operations.py#L399-L646); [search_config.py](https://github.com/getzep/graphiti/blob/d50741d1bf463cbe3859eb73914cbff1b66839e6/graphiti_core/search/search_config.py))。如果新事实的文本和端点与已有边逐字相同，就直接复用旧边，把新 episode 的 uuid 追加进 `episodes` 来源列表，不调用 LLM ([edge_operations.py L864-L1087](https://github.com/getzep/graphiti/blob/d50741d1bf463cbe3859eb73914cbff1b66839e6/graphiti_core/utils/maintenance/edge_operations.py#L864-L1087))。这是"重复报道只加来源"最便宜的实现。其余情况交给一次 small 模型调用，同时返回 `duplicate_facts` 和 `contradicted_facts` 两个下标列表，代码丢弃越界的下标。提示词明令："数值、日期或关键限定词有差异，就不算重复"；"不能仅凭时间更近、日期不同，或同一批实体出现了新事件，就推断矛盾" ([dedupe_edges.py](https://github.com/getzep/graphiti/blob/d50741d1bf463cbe3859eb73914cbff1b66839e6/graphiti_core/prompts/dedupe_edges.py))。

谁失效，由确定性代码按两条时间线决定。`valid_at`/`invalid_at` 是事实在世界上成立的区间，`created_at`/`expired_at` 是系统何时得知、何时让它退役。被反驳的旧边得到 `invalid_at = 新边.valid_at`。如果矛盾候选的 `valid_at` 反而比新边晚，说明新到的这条才是旧消息（乱序到达），这时把新边的 `invalid_at` 设成候选的 `valid_at`。区间不重叠的一概不动，什么都不删 ([edge_operations.py L715-L783](https://github.com/getzep/graphiti/blob/d50741d1bf463cbe3859eb73914cbff1b66839e6/graphiti_core/utils/maintenance/edge_operations.py#L715-L783))。还有一个可以直接搬来用的细节是未来时守卫：含 "plans to / expects to / scheduled to" 的事实，`valid_at` 夹到陈述日；"by / before" 这样的截止日期不当作失效日 ([temporal_edge_utils.py](https://github.com/getzep/graphiti/blob/d50741d1bf463cbe3859eb73914cbff1b66839e6/graphiti_core/utils/maintenance/temporal_edge_utils.py))。实体解析同样确定性优先：精确名和 MinHash（Jaccard ≥ 0.9）先判，只有低熵名称和多重匹配才交给 LLM；cosine 候选 15 条、下限 0.6，不重排 ([node_operations.py](https://github.com/getzep/graphiti/blob/d50741d1bf463cbe3859eb73914cbff1b66839e6/graphiti_core/utils/maintenance/node_operations.py); [dedup_helpers.py](https://github.com/getzep/graphiti/blob/d50741d1bf463cbe3859eb73914cbff1b66839e6/graphiti_core/utils/maintenance/dedup_helpers.py))。它的弱点也很具体。批量导入 `add_episode_bulk` 跳过了失效处理，所以矛盾检测依赖逐条按顺序摄入 ([bulk_utils.py](https://github.com/getzep/graphiti/blob/d50741d1bf463cbe3859eb73914cbff1b66839e6/graphiti_core/utils/bulk_utils.py))。在 MemoryAgentBench 的事实合并单跳任务上，Zep 只有 **7.0** 分，远低于纯 BM25 的 48.0 ([MemoryAgentBench](https://arxiv.org/html/2507.05257))：只认显式矛盾的保守规则，漏掉了隐式替代。

### 其余系统：要么自由改写、要么按名字哈希，少数把冲突当成记录

其余系统大致分三类。第一类让 agent 自由改写记忆文本，但不一定留历史。Letta 已把 MemGPT 式的记忆工具换成 git 仓库里的 markdown 文件，"every change to memory is automatically versioned"，另有"defragmentation"技能合并重复，但没有给出任何测量 ([Letta blog](https://www.letta.com/blog/context-repositories))。LangMem 默认允许插入和更新、关闭删除，更新就是同一 key 下 `store.put` 覆盖，没有版本 ([langmem extraction.py](https://github.com/langchain-ai/langmem/blob/48e3c11f5bb527282c7d5339c6a87a0b35abccfc/src/langmem/knowledge/extraction.py))。A-MEM 每加一条取 k=5 个近邻，让 LLM 改写邻居的标签和上下文；研究笔记读代码发现，它把检索结果里的排名位置当成了存储下标，库里超过 k 条之后就会改错笔记 ([A-mem memory_system.py](https://github.com/agiresearch/A-mem/blob/ceffb860f0712bbae97b184d440df62bc910ca8d/agentic_memory/memory_system.py))。第二类按确定性身份去重。Cognee 的节点 id 是规范化名称的 uuid5 ([generate_node_id.py](https://github.com/topoteretes/cognee/blob/37f788bd287750e10d7610173e5332b3843f6ebd/cognee/infrastructure/engine/utils/generate_node_id.py))，便宜，但同名的不同事物会被并成一个，相当于"值相等即同一身份"。第三类少数系统把冲突当成一等记录，最贴近观点库。Cognee 的 `review_conflicts` 由代码按"同关系名 + 共享一个端点"构造候选组，LLM 把每个冲突标成 `time_varying`（后来的来源可以合法地给出不同值）或 `fixed`（只可能有一个真值，不同就说明有一方错了），只记录争议、不改事实，"值只是计划或提议时不算冲突"，并写明"Omitting a conflict is the safe outcome" ([review_conflicts.txt](https://github.com/topoteretes/cognee/blob/37f788bd287750e10d7610173e5332b3843f6ebd/cognee/infrastructure/llm/prompts/review_conflicts.txt))。Hindsight 的观点网络给每条观点一个置信度，新事实按 reinforce / weaken / contradict 加减 α 或 2α ([Hindsight](https://arxiv.org/html/2512.12818v1))。MemoryOS 则按容量淘汰：长期知识是 `deque(maxlen=100)`，最老的被静默丢掉 ([MemoryOS long_term.py](https://github.com/BAI-LAB/MemoryOS/blob/587ed7755c7aed179965792830ff1b5ad9a6fa92/memoryos-pypi/long_term.py))。

| 系统 | 候选怎么找 | 谁判、判什么 | 历史怎么留 |
|---|---|---|---|
| Mem0 论文 / v1.0.11 | 每条事实向量 top 5–10 | LLM 直接选 ADD/UPDATE/DELETE/NOOP | UPDATE 覆盖、DELETE 硬删；只有检索不读的 SQLite 历史表 |
| Mem0 v3（2026-04） | 整批向量 top 10；检索时语义 + BM25 + 实体 | 单次 LLM 只追加；MD5 精确去重 | 不覆盖、不删；平台 Dream 打 supersede/merge 标记 |
| Graphiti / Zep | 同实体对 + BM25/cosine RRF top 10 | small LLM 返回重复与矛盾下标；代码定失效日期 | 不删，`invalid_at` / `expired_at` 双时间线 |
| Letta（2026） | agent 自己用工具检索 | agent 改写 markdown 文件 | git 版本 |
| LangMem | LLM 生成查询，取 5 条 | LLM 插入/更新（删除默认关闭） | 同 key 覆盖，无版本 |
| A-MEM | ChromaDB k=5 | LLM 改写邻居的标签与上下文 | 覆盖；历史字段从不写入 |
| Cognee | 节点 uuid5（规范化名称） | 代码组候选，LLM 标 time_varying / fixed | 记录争议，不改事实 |
| Hindsight | 实体重叠或相似度超过 θ | reinforce / weaken / contradict 调置信度 | 事实保留，置信度有轨迹 |
| MemoryOS | 语义 + 关键词 Jaccard ≥ 0.6 | 无冲突操作 | LFU 淘汰，长期区上限 100 |

### 专测"更新"这一步的基准：主要失败是漏，不是错

有三个基准单独测了更新这一步，结论一致：商用记忆系统主要败在遗漏，也就是旧事实没被替换、新事实没被记下，错更新反而很少。HaluMem 把更新的结果拆成正确率、幻觉率和遗漏率。在 Medium 集上，**Mem0 的遗漏率是 74.02%，幻觉率只有 0.45%**；到 Long 集，遗漏率升到 98.51%。Zep 两个集上的遗漏率是 52.31% 和 62.14% ([HaluMem](https://arxiv.org/html/2511.03506v3))。不过 HaluMem 出自 MemOS 的开发方 MemTensor，表里排第一的 MemOS 那一行不算独立数字。MemoryAgentBench 的事实合并任务，明确告诉 agent"序号大的事实更新"。单跳题上，GPT-4o 长上下文 60.0、BM25 48.0、Mem0 18.0、Cognee 28.0、Zep 7.0；多跳题上，所有系统都不超过约 7% ([MemoryAgentBench](https://arxiv.org/html/2507.05257))。

确定性规则在有键、有顺序的地方赢过 LLM。一篇 2026 年的论文让 LLM 只负责识别证据，再由代码选序号最新的那条，单跳题达到 82%（gpt-4o-mini）和 93%（gpt-4o）。作者的结论是，增益主要来自"把证据识别与最终策略执行分开" ([2606.01435](https://www.alphaxiv.org/abs/2606.01435))。TEPA 给每个条目设 Hypothesis / Active / Revoked 三种状态，在 FC-SH-6k 上，**只追加不设状态得 0.583，最后写入胜出得 0.890**。在隐藏的全量反转下，只追加只有 0.210，比完全不用记忆的 0.309 还差 ([TEPA](https://arxiv.org/html/2608.07429v2))。反过来，也有误判矛盾的典型案例：用户在不同会话里说自己领养了两只狗，普通记忆管理器把这当成矛盾，执行了 DELETE + ADD ([Memory-R1](https://arxiv.org/html/2508.19828v4))。

对观点库的推论（推断）如下。记忆系统的 UPDATE 指"把更多细节并进同一 id 并改写文本"，这会违反"观点原文不改写"的规则。所以 skip 只能是挂一条证据或改状态。合并是写一个 `merged_into` 指针。改写过的论点是一条新观点加一个 `superseded_by` 指针。检索默认只看活跃状态，历史按需查询。TEPA 的结果说明，光保留历史行而没有状态字段，比不保留更糟。HaluMem 说明，首要指标应该是"该挂上某观点的证据没挂上"的召回率，挂错的精度排在其次。

## 口语输入让声明检索从 0.9 跌到 0.35，"选一个"比"逐对判"高 17 点

事实核查领域的"已核查声明检索"是观点匹配最近的学术近亲，它最重要的教训是：输入长什么样，比用哪个向量模型更要紧。Shaar 等人 2020 年定义这个任务时就发现，PolitiFact 的辩论句里有 48% 的真匹配无法靠近似字符串找到，句向量单独用（MRR 0.395）还不如 BM25 匹配核查正文（0.565）([Shaar et al. 2020](https://arxiv.org/abs/2005.06058))。CheckThat! 2021 上，推文对 Snopes 的冠军 MAP@5 是 0.883；同年政治辩论与演讲那一轨，**没有任何队伍打败 BM25 基线（0.346）**。2022 年两轨的最好成绩分别是 0.956 和 0.459 ([CheckThat! 2021](https://arxiv.org/abs/2109.12987); [CheckThat! 2022](https://ceur-ws.org/Vol-3180/paper-29.pdf))。SemEval-2025 Task 7 用 20.6 万条已核查声明、27 种语言，单语 success@10 的冠军达到 0.9601，跨语言低 10 个点以上。有效做法都一样：对比学习微调加难负例，召回 top-50，再重排 ([SemEval-2025 Task 7](https://arxiv.org/abs/2505.10740))。财报电话会、卖方研报和新闻里的观点句，口语、指代多、常省略主语和时间，更像辩论那一轨。所以入库前先把声明规范化（补全主体、财期、方向、指标），是这条证据最直接的推论。

LLM 判官的措辞决定它往哪边错。ClaimMatch 的 1,000 对平衡测试集上，text-embedding-3-small 的余弦只有 77.2 F1；好模板下零样本 LLM 能到 96–97，但 few-shot 时 GPT-3.5 掉到 59.5。错误分析显示，模型会因为非实质性的细节（同一次执法行动，限速写 70 还是 72 mph）拒绝匹配，问"含义是否相同"的模板还会因为一方多出一个子声明而拒绝 ([Pisarevskaya & Zubiaga 2025](https://arxiv.org/abs/2501.10860))。反过来，问"是否相关"时，**约 65% 的假阳性只是因为话题相同** ([Vykopal et al. 2025](https://arxiv.org/abs/2503.02737))。项目内部测过逐对判官，精度 0.99、召回只有 0.32（内部测量，非公开来源），正是"问得太严"那一侧的表现。

判定架构上，"在一个上下文里看完全部候选再选一个"稳定胜过独立的逐对判断。ComEM 在 8 个实体匹配数据集上，GPT-3.5 逐对匹配平均 F1 64.02、成本 4.52 美元，**选择式 81.60、成本 1.71 美元**，组合方案 85.61、成本 0.92 美元。它先用小模型排序，只留 top-4 交给选择，因为真匹配在列表里越靠后，准确率越低 ([ComEM](https://arxiv.org/abs/2405.16884))。LLM-CER 让模型对约 9 条记录的集合做聚类，API 调用比逐对少 12–108 倍，成本低 3–22 倍 ([LLM-CER](https://arxiv.org/abs/2506.02509))。GPT-4 零样本做实体匹配已能比肩微调模型；手写匹配规则反而让 GPT-4 降 1–3 点，只对弱模型有帮助 ([Peeters et al.](https://arxiv.org/abs/2310.11244))。OpenSanctions Pairs 上，GPT-4o 逐对达到 98.95% F1，作者据此认为逐对判定已接近天花板，剩下的误差在 blocking 和聚类 ([OpenSanctions Pairs](https://arxiv.org/html/2603.11051))。项目内部的选择式判官测到精度 0.975、召回 0.76，text-embedding-3-large 的 top-4 召回了 99% 的已知重述（内部测量），和 ComEM 的方向与量级都吻合。

"同一件事被报道多次只算一次"属于跨文档事件共指和新闻聚类问题，这里的证据都指向时间和论元。ECB+ 上，微调模型的 CoNLL F1 在 85–89，零样本逐对 LLM 只有 76.6–79.2。到了全是枪击事件、同类高度密集的 GVC 语料，**零样本 GPT-3.5 的 B³ 精度跌到 35.4%**，大面积过度合并。作者的诊断是模型只盯触发词，忽略了时间、地点和参与者 ([ACCI](https://arxiv.org/abs/2506.01488))。每季度"Apple 业绩超预期"正是这种同类密集的分布。Ahmed 等人 2023 年指出，任何数据集里只有 5–10% 的提及对真正共指。他们先用廉价规则（触发词词元、句子重叠，阈值按召回调）把 n² 对压成线性，再把判别预算花在难对上；错误分析点名了"弱时间推理"：不同日期发布的文章里，"周六"可能指同一天 ([Ahmed et al. 2023](https://arxiv.org/abs/2305.05672))。Miranda 等人做流式新闻聚类，加入时间戳特征是最大的单项增益，排序准确率从 86.5% 提到 96.9%，高斯时间窗在开发集上调出 σ = 72 小时 ([Miranda et al. 2018](https://aclanthology.org/D18-1483/))。

金融领域有相邻的研究，但缺最关键的那个基准。区分"前瞻性声明"和"已发生的数值事实"已经做得很好：研报上零样本约 0.92 F1，电话会上零样本掉到 0.76，微调后在 0.96 左右 ([Shah et al. 2024](https://aclanthology.org/2024.fever-1.21/))。这正好对应"观点候选 vs 证据候选"。"From Text to Alpha"用嵌入衡量同一指标在相邻披露期之间的语义变化，并从中得到 alpha ([From Text to Alpha](https://arxiv.org/abs/2510.03195))。这提醒我们：管理层跨季度重复同一说法本身就是信号，不能被去重吞掉。但**没有找到任何公开基准或带精度/召回的生产报告，评测"投资论点是否与已有论点相同"**。RavenPack 的新颖度分数基于 24 小时窗口，算法和准确率都未公开 ([Finextra](https://www.finextra.com/pressarticle/56610/ravenpack-upgrades-rpna))。

## 方向、数字、季度和主体，向量几乎都分不清

把 embedding 当"是否相同"的裁判，会在观点库最在意的四个维度上同时失灵，而且 2025–2026 年的新模型没有修好其中任何一个。方向上，NevIR 的两组查询与文档只差一个否定，随机水平 25%。2025 年重测，最好的单向量模型 GritLM-7B 只有 **39.0%**，text-embedding-3-large 22.6%，比随机还低；cross-encoder 在 43–65%，listwise LLM 重排在 64–77%（o3-mini 77.3%）([Reproducing NevIR](https://arxiv.org/html/2502.13506))。对观点库更要紧的是"词汇否定"：refuse、block 这类隐含否定的动词，以及 tighten / ease 这类反义对。否定分类研究把它们单列为一类，结论同样是 cross-encoder 和 LLM 最好，而针对性微调会损害通用检索 ([Petcu et al. 2025](https://arxiv.org/html/2507.22337v3))。SentenceSmith 用受控编辑构造难负例，发现 E5-Mistral-7B 和 GTE-Qwen-7B 在极性翻转上错一半以上，主客互换（"A 收购 B"变成"B 收购 A"）平均最难，而这个排名和 MTEB 排名的相关只有 0.54 ([SentenceSmith](https://aclanthology.org/2025.emnlp-main.1343.pdf))。一篇 2026 年的预印本审计了线上 agent 的 cosine 闸门："withhold the study drug"改成"administer"，cosine 仍有 0.9608；90 个配置 × 阈值 × 任务的组合里，平衡准确率的中位数只有 0.525。作者的说法是，cosine 衡量的是"措辞改了多少" ([Frias 2026](https://arxiv.org/abs/2608.10216))。ICML 2025 的 SparseCL 给出了理论原因：cosine 有传递性，两句互为改写的话可以都和第三句矛盾、彼此却不矛盾，所以"矛盾"不可能是一个 cosine 邻域 ([SparseCL](https://arxiv.org/html/2406.10746v1))。

数字和时间同样不在向量里。EmbedNum-1K 用只差一个数字的金融句子做测试，13 个模型平均 **0.54，随机是 0.5**：Qwen3-Embedding-8B 53.7%，text-embedding-3-small 52.7%，排 FinMTEB 第一的 Fin-E5 51.7%。四位数整数（年份的形状）处于随机水平，8% 与 0.08 被当成不同的东西 ([Numeracy gap](https://arxiv.org/pdf/2509.05691))。TEMPS 指出，稠密检索器继承自 BERT 一类的编码器，"not trained to make temporal distinctions" ([TEMPS](https://arxiv.org/html/2609.28048v1))。为时间专门微调虽能把 TimeQA 的 R@20 从 64.07 提到 71.12，却让 Natural Questions 从 53.13 崩到 22.69 ([TSM](https://arxiv.org/html/2507.06782))。主体上，2021 年 DPR 在实体类问题上平均 49.7%，BM25 有 72.0% ([EntityQuestions](https://arxiv.org/abs/2109.08535))。2025 年的 LIMIT 在属性组合查询上，Gemini Embeddings 和 Qwen3 Embeddings 的 Recall@100 只有 10.0 和 4.5，BM25 有 93.6 ([LIMIT](https://arxiv.org/html/2508.21038v1))。FinMTEB 更直接：在金融语义相似度任务上，**词袋基线（0.4845）胜过所有稠密模型** ([FinMTEB](https://arxiv.org/abs/2502.10990))。

| 维度 | 实测（单向量模型） | 对照 | 对观点库的含义 |
|---|---|---|---|
| 否定 / 方向 | NevIR 最好 39.0%，3-large 22.6% | 随机 25%；LLM 重排 64–77% | 方向必须是枚举字段，由代码比较 |
| 数字 | 13 个模型平均 54%，Fin-E5 51.7% | 随机 50% | 阈值、百分比解析成带单位的字段 |
| 时间 / 财期 | "未为时间区分而训练"；时间微调使 NQ 53→23 | 内部：同句不同季度 cosine 0.988 | 财期或事件日是身份键的一部分 |
| 主体 / 角色 | LIMIT Recall@100 4.5–18.9；角色互换最难 | BM25 93.6 | 按实体 id 预过滤；BM25 补精确 token |

([Reproducing NevIR](https://arxiv.org/html/2502.13506); [Numeracy gap](https://arxiv.org/pdf/2509.05691); [TSM](https://arxiv.org/html/2507.06782); [LIMIT](https://arxiv.org/html/2508.21038v1))

这些弱点在候选生成阶段反而有用（推断）。既然向量不区分方向，一篇主张"出口管制将放松"的文件，自然会捞出库里"出口管制将收紧"的观点，而这正是要把它当作反向证据送过去所需要的。所以向量应该用来找"同一驱动"的候选，不管方向，但永远不要用它判方向。项目内部"cosine ≥ 0.95 的对里只有 34% 是真重复"（内部测量）也符合这套文献：高 cosine 只说明措辞重叠，重叠的对里真重复、方向反转和不同期的同一句话混在一起。

## 阈值只配当召回下限：混合检索、预过滤、重排与"嵌入什么"

证据最充分的模式是级联：先用便宜、高召回的候选阶段（词法 + 稠密，按排名融合），再交给精确的判官。Anthropic 的 Contextual Retrieval（厂商测量）里，top-20 检索失败率是：只用嵌入 5.7%；给每块加上 LLM 写的上下文前缀，降到 3.7%；再加 BM25，2.9%；再加重排，1.9%，**合计减少 67%**。BM25 的功劳主要在错误码这类精确字符串上 ([Anthropic](https://www.anthropic.com/news/contextual-retrieval))。RRF 按 Σ 1/(k + rank) 融合（原文 k = 60），不需要校准分数 ([Cormack et al. 2009](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf))。观点库的数据里，ticker、产品名（H20）、规则编号（ECCN 3A090）和财期 token，正是 BM25 能补上召回的精确 token。重排器在训练时没见过的查询上普遍掉 5–15%，listwise 掉得最少 ([How Good are LLM-based Rerankers?](https://arxiv.org/pdf/2508.16757))。为否定或时间做对比微调，每一次都在目标能力上有提升，也每一次都测到了附带损伤：HedgeMPNet 的 NevIR 从 8.1 升到 40.6，MTEB 从 58.79 降到 57.14 ([HedgeMPNet](https://arxiv.org/html/2507.12782v1))。所以微调自己的向量模型去识别方向，是最弱的一注。

固定 cosine 阈值不能当"相同"的判决，因为分数的刻度随模型、提示词和文本长度一起漂移。ada-002 的相似度挤在 0.75–0.88；text-embedding-3-small 大多落在 0.2–0.4 ([Pamela Fox](https://blog.pamelafox.org/2025/05/a-visual-exploration-of-vector.html))。MeanCache 在验证集上扫出的最优阈值，MPNet 是 0.83、Albert 是 0.78；GPTCache 用固定的 0.7，在 700 条唯一查询上误命中 233 次，调过阈值的系统只有 89 次 ([MeanCache](https://arxiv.org/html/2403.02694v4))。长文本的向量会彼此聚拢、互相的 cosine 偏高（length collapse）([arXiv 2410.24200](https://arxiv.org/html/2410.24200v2))；默认提示词会系统性地高估或低估效果 ([arXiv 2605.22544](https://arxiv.org/abs/2605.22544))。Frias 还发现，评测集如果不在"词汇重叠 × 含义"上做 2×2 平衡，18 个单元里有 13 个的 AUROC 恰好是 0.000，也就是会校准出一个方向完全反了的阈值 ([Frias 2026](https://arxiv.org/abs/2608.10216))。实际可行的做法是把阈值只当召回下限，取固定的 top-k（几十条）；在自己的标注对上按模型标定；模型、维度、前缀或嵌入文本的形态一变就重测；负例里必须有措辞几乎相同的方向反转和异期副本。

"每来一份文件找相关观点"是长文档对短观点的不对称匹配。整篇嵌入是证据最差的选项：一份 10-K 里有几十个互不相关的主张，长文本的向量还会塌缩到一起。证据支持更小、能独立成立的单位。按命题检索比按段落检索，Recall@20 在无监督检索器上高 10.1，在有监督的上高 2.2 ([Dense X Retrieval](https://arxiv.org/abs/2312.06648))；带上下文前缀的分块能减少 35% 的失败 ([Anthropic](https://www.anthropic.com/news/contextual-retrieval))。前缀要按模型的训练方式加。E5 作者写明不加 "query: / passage: " 会退化；Voyage 要求设置 `input_type`，"Do not omit" ([E5 model card](https://huggingface.co/intfloat/e5-large-v2); [Anthropic embeddings](https://platform.claude.com/docs/en/build-with-claude/embeddings))。把"驱动 | 方向 | 期限 | 对象"这样的规范形式拼起来再嵌入，没有找到任何公开实验，仍是待测的假设。过滤的实现也有一个陷阱：pgvector 用近似索引时是先扫索引、再做过滤，过滤后可能返回不足 k 条，0.8.0 起要打开 iterative index scans 才能修正；精确检索没有这个问题 ([pgvector](https://github.com/pgvector/pgvector))。

## 嵌入一年花几百美元，钱和风险都在判官与验证集上

模型选择上，唯一独立的金融嵌入基准 FinMTEB（EMNLP 2025）的英文总平均是：Fin-E5 0.6767、voyage-3-large 0.6765、text-embedding-3-large 0.6613；检索子项 voyage-3-large 以 0.746 领先。它还发现通用 MTEB 排名和金融表现的相关不显著 ([FinMTEB](https://arxiv.org/html/2502.10990); [FinMTEB leaderboard](https://financemteb-finmteb.hf.space))。Anthropic 不做嵌入模型，文档指向 Voyage AI（现属 MongoDB）([Anthropic embeddings](https://platform.claude.com/docs/en/build-with-claude/embeddings))。Voyage 4 系列在 2026-01-15 发布，large、标准版、lite 和开放权重的 nano **共享同一个向量空间**：可以用 voyage-4-large 嵌入库存，用 lite 嵌入查询，升级查询端的模型也不必重嵌文档 ([Voyage 4 blog](https://blog.voyageai.com/2026/01/15/voyage-4/))。voyage-finance-2 已在同一天转为 Legacy，官方推荐的替代就是 voyage-4 ([MongoDB lifecycle](https://www.mongodb.com/docs/voyageai/models/lifecycle/))；Voyage 自己的数据也显示 voyage-3-large 胜过它的金融专用模型 ([voyage-3-large blog](https://blog.voyageai.com/2025/01/07/voyage-3-large/))。要提醒的是，Voyage 4、Qwen3-Embedding、Gemini Embedding 2、Cohere Embed 5 都没有独立的金融评测，它们在金融上的优势全是厂商自报。需要自托管时，Qwen3-Embedding（Apache 2.0）和 BGE-M3（MIT，一个模型同时输出稠密、稀疏和多向量）是可商用的选项；NV-Embed-v2 是 CC-BY-NC，不能商用 ([Qwen3-Embedding](https://huggingface.co/Qwen/Qwen3-Embedding-8B); [BGE-M3](https://huggingface.co/BAAI/bge-m3); [NV-Embed-v2](https://huggingface.co/nvidia/NV-Embed-v2))。英文文件对中文观点的跨语言金融检索没有任何基准，所以较稳的做法（推断）是：每条观点存一份英文规范文本用于嵌入，中文只用于展示。

这个规模不需要独立的向量服务（推断，依据是文档里的功能说明加上算术）。2 万条观点、1024 维 float32 约 82 MB，精确暴力检索每次查询只要毫秒级。pgvector 支持精确检索、HNSW，并能和 Postgres 全文检索在 SQL 里做 RRF，但 HNSW 索引上限是 2,000 维，超过要用 halfvec（≤ 4,000）或截断 ([pgvector](https://github.com/pgvector/pgvector))。sqlite-vec 可以和 FTS5 在 SQL 里做 RRF 混合 ([Simon Willison](https://simonwillison.net/2024/Oct/4/hybrid-full-text-search-and-vector-search-with-sqlite/))，但它仍是 pre-v1、"expect breaking changes"，必须钉版本 ([sqlite-vec](https://github.com/asg017/sqlite-vec))。LanceDB 在进程内运行，默认先过滤再检索、默认用 RRF ([LanceDB](https://docs.lancedb.com/search/hybrid-search))。Elasticsearch 的原生 RRF 据第三方文章需要付费档位（未在 Elastic 官方页面确认）([dev.to](https://dev.to/u11d/reciprocal-rank-fusion-on-free-elasticsearch-licensing-workarounds-and-the-opensearch-alternative-56jk))。

换模型的规则很简单：不同模型（或同一厂商不兼容的两代）的向量互相不可比，必须重嵌。Gemini 明说从 001 升级到 2 "requires re-embedding all existing data" ([Gemini embeddings](https://ai.google.dev/gemini-api/docs/embeddings))。共享空间只在同一代之内成立，没有任何承诺说下一代 Voyage 会和 Voyage 4 兼容。Qdrant 推荐的迁移方式是在同一条记录上加第二个命名向量：双写、回填、用标注查询验证 Recall@10 和 nDCG，然后切换，最后删旧向量 ([Qdrant migration](https://qdrant.tech/documentation/tutorials-operations/embedding-model-migration/))。Drift-Adapter 学一个从新空间到旧空间的映射，能恢复 95–99% 的召回 ([Drift-Adapter](https://arxiv.org/abs/2509.23471))，但在这个规模下全量重嵌只要几美元，映射带来的风险换不回相应的节省（推断）。每条向量至少要记：模型 id、空间族、维度、dtype、`input_type` 和模板、实际发送文本的哈希。代码要拒绝比较空间、维度或 dtype 不同的向量。改了嵌入模板（拼接哪些字段）也等于换了模型。原文永远保留，绝不只存向量。

成本按 2026-10-17 的标价估算。文件构成是假设的：每天 2,400 条短讯、450 份中等长度文件、120 份电话会记录、30 份 10-K/10-Q，合计约 720 万 token/天。电话会长度取 S&P 500 记录的中位数 53,734 字符 ([HF transcripts](https://huggingface.co/datasets/kurry/sp500_earnings_transcripts/blob/f3ded372da8d18dc6ad98955c4558e34b5fe6d45/README.md))；10-K 取 2013 年的平均 4.2 万词，数据可能已经过时 ([NYSSCPA](https://nysscpa.org/news/1046127-10-ks-reaching-novel-length-2015-06-02))。单价来自各家定价页 ([Voyage pricing](https://docs.voyageai.com/docs/pricing); [OpenAI pricing](https://developers.openai.com/api/docs/pricing); [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing))。

|---|---|---|---|---|

| voyage-4（$0.06） | 约 $13 | 约 $3.5 | $0.30 | 约 $158 |

以上全部是估算。只嵌主张的口径假设每份文件约 8 条主张、每条 80 token；观点按每条 250 token 计；Voyage 4 系列另有 2 亿 token 的免费额度，batch 打 67 折。真实的大头是判官调用：每份文件（或每条主张）都要读原文片段和若干候选观点，做一次 LLM 判定。本轮没有取到 Claude 的价格，这部分费用没有估算。用 `count_tokens` 数一下存储的一天文件，就能零成本地把上面假设的文件构成换成实测值。

## 推荐方案：字段阻断、混合召回、选择式判官、事件簇计数

推荐的流水线把每个判断交给证据显示最可靠的那一层：能由代码判的身份字段，交给代码；向量和 BM25 只负责不漏候选；LLM 只在少数排好序的候选里做选择，并给出支持还是削弱。

```
一份新文件
├─ 1 抽取：按观点库同一 schema 抽出主张与证据
│     标的/实体 id、驱动、方向枚举、指标、财期或事件日、期限、数值+单位、原文片段、发言人、来源
├─ 2 证据去重：事件键 = 实体 id + 事件类型/指标 + 事件日或财期
│     向量 + BM25 只在同键附近找候选事件簇 → 同簇只记一次，新来源挂到簇上
├─ 3 观点候选
│     a 代码阻断：同标的的活跃观点 ∪ 宏观/行业驱动的观点 ∪ 期限覆盖文件日期的观点
│     b 混合召回：BM25 + 向量，RRF 融合，固定 top-k（几十条），只设很低的下限
├─ 4 代码比较字段：方向相反 → 反向证据；财期不同 → 同一观点的新一期证据；数值按单位比较
├─ 5 选择式判官：一次看按分数排好的少量候选
│     输出 {同一观点 → skip 挂证据 / 并入观点 X / 新观点} × {支持 / 削弱}
│     候选 id 映射成小整数，返回值按封闭集合校验
└─ 6 写入：观点原文不改；merge = merged_into；改写 = 新观点 + superseded_by；状态与日期由代码写
离线：定期按标的对活跃观点做集合级聚类（约 9 条一组），回收在线阶段漏掉的重复
```

用一个例子走一遍（推断）。库里有一条活跃观点："美国对 AI 芯片的出口管制将收紧，压制 NVIDIA 数据中心收入"。新来一篇报道："据报道，美国商务部考虑放宽 H20 的出口许可"。第 1 步抽出：驱动是美国 AI 芯片出口管制，方向是放松，对象是 NVDA 和 AMD，事件日是报道日。第 2 步：当天另有 20 家媒体转载同一消息，它们共享事件键（商务部 + 出口许可 + 同一日期），聚成一个簇，只记一条证据。第 3 步：因为驱动是宏观的，不能只按 NVDA 硬过滤，要并入宏观驱动的路径；向量不区分方向，"收紧"那条观点会被捞出来。第 4 步：代码看到方向相反，把它路由成那条观点的削弱证据，而不是另开一条"管制将放松"的新观点。第 5 步：判官只确认它是不是同一个驱动、同一批对象。下一季度电话会上管理层又说了一遍同样的话，那是第二期证据（财期不同），不算重复，也不算新观点。

| 环节 | 推荐 | 依据 | 关键来源 |
|---|---|---|---|
| 匹配单位 | 先抽成与观点同 schema 的主张，再做对称匹配；分块索引只作兜底，每块加实体/文件类型/财期前缀 | 部分证据 + 推断（两者的组合没人测过） | [Dense X](https://arxiv.org/abs/2312.06648)；[Contextual Retrieval](https://www.anthropic.com/news/contextual-retrieval)；[CheckThat! 2021](https://arxiv.org/abs/2109.12987) |
| 身份字段 | 方向、财期/事件日、实体 id、数值由代码比较，不交给向量 | 有证据（向量分不清）；具体的路由规则是推断 | [NevIR](https://arxiv.org/html/2502.13506)；[Numeracy gap](https://arxiv.org/pdf/2509.05691)；[SentenceSmith](https://aclanthology.org/2025.emnlp-main.1343.pdf) |
| 候选生成 | 代码阻断 + BM25 + 向量 + RRF；宏观/行业驱动走另一条路径，不硬过滤 | 有证据（检索与实体解析领域）；宏观路径是推断 | [Graphiti](https://github.com/getzep/graphiti/blob/d50741d1bf463cbe3859eb73914cbff1b66839e6/graphiti_core/utils/maintenance/edge_operations.py#L399-L646)；[LIMIT](https://arxiv.org/html/2508.21038v1)；[FinMTEB](https://arxiv.org/abs/2502.10990) |
| 阈值与 k | 固定 top-k，阈值只作召回下限；在存储的标注对上按模型标定，负例按 2×2 设计 | 有证据 | [Frias 2026](https://arxiv.org/abs/2608.10216)；[MeanCache](https://arxiv.org/html/2403.02694v4) |
| 判官形态 | 选择式（listwise），约 4 个排好序的候选；问"能否被同一论点/证据覆盖"；不写长篇规则 | 有证据（实体匹配、声明匹配）+ 内部测量 | [ComEM](https://arxiv.org/abs/2405.16884)；[Pisarevskaya 2025](https://arxiv.org/abs/2501.10860)；[Vykopal 2025](https://arxiv.org/abs/2503.02737)；[Peeters](https://arxiv.org/abs/2310.11244) |
| 输出约束 | id 映射成小整数，越界即拒绝；输出用枚举 | 有证据（工程实践） | [Mem0 v1.0.11](https://github.com/mem0ai/mem0/blob/v1.0.11/mem0/memory/main.py#L555-L592)；[Graphiti](https://github.com/getzep/graphiti/blob/d50741d1bf463cbe3859eb73914cbff1b66839e6/graphiti_core/utils/maintenance/edge_operations.py#L864-L1087) |
| 历史 | 不删、不改写；状态 + `merged_into` / `superseded_by`；检索默认过滤状态 | 有证据 | [Mem0 v3](https://github.com/mem0ai/mem0/blob/0724291bd864cf807e88ee8981c8226644e8fb42/docs/migration/platform-v2-to-v3.mdx)；[TEPA](https://arxiv.org/html/2608.07429v2) |
| 日期与过期 | 代码写日期；预测从陈述日起生效，目标日不是过期日；按截止日由代码改成过期，而不是衰减 | Graphiti 的实现有证据；映射到观点是推断 | [temporal_edge_utils.py](https://github.com/getzep/graphiti/blob/d50741d1bf463cbe3859eb73914cbff1b66839e6/graphiti_core/utils/maintenance/temporal_edge_utils.py) |
| 证据去重 | 事件簇：键里含日期或财期；时间窗按事件类型在开发集上调；跨期重复记为新一期证据 | 部分证据 + 推断（没有金融基准） | [Miranda 2018](https://aclanthology.org/D18-1483/)；[ACCI](https://arxiv.org/abs/2506.01488)；[From Text to Alpha](https://arxiv.org/abs/2510.03195) |
| 离线合并 | 按标的做集合级 LLM 聚类，加误聚类护栏；在线阶段偏精度 | ER 有证据；"误合并比漏重复代价高"是推断 | [LLM-CER](https://arxiv.org/abs/2506.02509) |
| 度量 | 首要指标是证据挂载召回；金标从存储文件里自建，测试集只评一次 | 有证据（遗漏是主要失败） | [HaluMem](https://arxiv.org/html/2511.03506v3) |
| 模型 | Voyage 4 系列（库存用 large 或标准版，查询可用 lite），设好 `input_type`；嵌入英文规范文本 | 前代在 FinMTEB 最强；Voyage 4 的优势是厂商自报；跨语言做法是推断 | [FinMTEB](https://arxiv.org/html/2502.10990)；[Voyage 4](https://blog.voyageai.com/2026/01/15/voyage-4/) |
| 存储与迁移 | pgvector 或 sqlite-vec + FTS5，观点精确检索；每条向量带模型元数据，跨空间比较由代码拒绝；换模型时双写、验证、重标定阈值 | 不兼容有证据；选型是推断 | [pgvector](https://github.com/pgvector/pgvector)；[Qdrant migration](https://qdrant.tech/documentation/tutorials-operations/embedding-model-migration/) |

误差的代价不对称，这决定了两阶段该偏向哪一边（推断）。在观点层面，误合并会把两个不同论点的证据和状态搅在一起，很难撤销；漏掉一个重复只是多出一条重复观点，离线合并可以修复。所以在线判官应该偏精度。证据层面正好相反：漏掉一个重复，20 家转载就会被算成 20 条独立证据，置信度虚高；而误合并会把两个季度的同类事件当成一次。事件键里的日期或财期字段，就是这两种错误的分界线。

## 结论

这项研究改变的不是"用哪个向量模型"，而是"向量在系统里站在哪一层"。文献里每一个让向量（或者在相似邻域里自由发挥的 LLM）直接决定身份的设计，都在观点库最在意的维度上失败过：方向反转得分高于真改写；同类事件被过度合并；DELETE 误删了仍然成立的事实；只追加不设状态时，比不用记忆还差。而每一个站得住的设计，都把身份放进可由代码比较的键里（Graphiti 的实体对和日期，TEPA 的 key 和状态，事件共指里的时间与论元），把模型限制在封闭候选集上的选择题。这正好和项目已有的规则"Build where code decides""Code over prose"重合。外部证据给这些规则提供了量化理由，不是要推翻它们。

最大的未知在观点层面，不在检索层面。召回容易做到接近 100%（内部 top-4 已到 99%），难的是"同一驱动、同一方向、相近期限"在论点级别上该怎么定义，而这个问题没有任何公开基准可借。所以下一步最便宜、信息量最大的动作，不是选模型，也不是建索引，而是从已存的文件里建一份观点级的金标：包含方向反转和异期副本这两类措辞几乎相同的难负例，以及 skip / merge / 新建 / 反向证据四类标签。然后在这份金标上，把"只嵌入驱动和对象文本"这类假设先测一遍，再决定建什么。
