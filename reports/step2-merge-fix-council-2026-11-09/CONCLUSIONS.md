# Step 2 wrong-merge council: candidate direction, not a proven fix

2026-11-09. Alex requested a council to think through a general fix. Codex and Claude independently read the saved requests, source-backed records, decisions, current contracts and prior trials, challenged each other's proposals, and converged after further challenges. This is a read-only investigation; no model experiment, production/configuration change, new ruler, or change to the concurrent end-to-end run was made. Streams and handoffs are preserved in this directory.

## What was found

In one fresh draw and three dev draws, 363 accepted-as-repeat outcomes received recorded reviews: 316 accepted, 43 overlap and 4 wrong. These are instance counts, not an independent population error rate: the three dev draws reuse the same articles and one source pair appears twice. The three different source-pair cases are: production/forecast versus commercial deliveries; revenue-level forecasts versus growth figures whose relation is not established by the records; and a cloud-provider revenue-share description versus an article describing a developer future-sales share. Same source or topic does not prove their specific statements identical. Source accuracy is separate from what a news report actually says. Reader/model disagreement remains and no historical label is changed. Raw source and count: `stored-census.md` and run-specific `merge-third-answer.json`, `library.json`, `decisions.json`.

The observed mechanism is that Jev selects repeat and the writer groups accordingly. The model does not produce a verbal account; the reason for these decisions is unproven. Some records bundle multiple related facts. The issue is not uniquely a low score: the cloud/developer case was selected at 0.84 in one draw. On the 363 fixed saved decisions a 0.5 floor would block one reader-marked wrong merge, four reader-accepted merges and one overlap; this is not a forward-run estimate. In an earlier 102-merge diagnostic an overly strict 'nothing new' rule reduced merges to 22, including valid retellings. Numbers are diagnostic, not an efficacy claim.

## One candidate to investigate

Before grouping a pair that Jev says is a repeat, obtain an independent comparison, with the same source-backed input and without Jev's selection or probabilities: does the incoming statement actually report the old record's main statement? The checker must allow extra details and paraphrases and distinguish different facts, changed claims and cases whose relation cannot be established. This is a proposal for an experiment, not an established root fix, change to D381, a new automatic veto, or proof that another model's errors are independent. We do not choose a model or a disagreement rule in this council.

Use original speaker, the subject, values, period, original date, hedges and actual source when relevant; do not infer the same original claim solely from similar topic, a matching number or common announcement. Different reporting outlets can repeat the same claim while retaining each source. Do not silently adopt D248 boundary 7's dormant exception or a new threshold. Current Jev comparison text excludes an explicit evidence-period field; adding it would be a separate changed input, not silently mixed into this comparison.

The reviewer must not treat a genuine extra detail as automatically disqualifying; X47 is an accepted example. Conversely a broad shared topic or a shared minor fact need not make a whole new record a repeat; X22 and AWS/three-cloud overlap are controls, with source-backed classifications and disagreement. The acceptance reference and Step 2 use different meanings/units for revision in X22; that concern stays separate and the frozen reference remains unchanged. The source itself does not show that the old production statement and the delivery claim were separate statements by the same original speaker, so the revision label is not settled by this case.

## Evidence that would decide whether to proceed

1. Start with a small, predeclared diagnostic of the three reader-marked wrong source pairs and counterexamples: accepted repeats with added details (including X44 and X47), true updates/denials, different speakers/periods, and known missed repeats. Use the identical Jev comparison payload for the independent comparator. It sees no prior result. A source-blind reader who did not write the proposal reviews the source and differences; same-day fresh Jev controls and request fidelity are required for model comparisons. A small pilot is a lead, not a performance claim.
2. If the pilot provides an actual signal without obvious counterexample regressions, prospectively freeze an expanded evaluation of all 363 historical merged instances and known missed repeats and revisions, marking the model-written judgments and 43 contested overlaps; do not relabel frozen gold or infer that 363 are independent. Assess wrong groupings, correct repeats split, unmerged repeats, update errors and source fidelity; give every case and disagreement. Fixed-history comparison cannot establish new forward-history behavior, latency or downstream judgment impact.
3. Only if those comparisons merit it, plan a separate isolated forward-path evaluation with a fresh same-day baseline, held-out articles and eventual reader/judgment effects, including cost and speed. Do not use the 50 fresh-test articles as previously unseen again. No new scorer substitutes for source-backed trace review.

A useful test must show the independent comparison catches cases Jev misses without unnecessarily breaking true repeats or losing/relabeling updates. If errors are correlated, correct repeats are split, or the model's additional cost exceeds the observed value, do not adopt it. The pilot may be inconclusive, especially with few confirmed wrong pairs. It cannot prove absence of a problem.

Whether a reviewer disagreement creates a new group, a pending case or some other outcome changes product behavior; it is not decided by the council and must be shown to Alex with evidence. Likewise source-matter revision vs statement revision and risk trade-offs need an explicit decision if the existing rules do not resolve them. The final delivered investment judgment has not been shown to suffer from X22; the currently running July end-to-end comparison does not contain this September case and cannot isolate this merge.
