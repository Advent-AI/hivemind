**结论：Alex 的 linked list 思路能保住“前后关系”，但不能单独保证依赖继续正确工作。还需要明确“跟哪一条、何时换过去、换过去后读什么”。**

我推荐保留单层观点，增加两样东西：

- **接续关系**：记录新观点接着哪条旧观点，属于血缘。
- **依赖的选取规则与实际读取记录**：前者决定这次该读谁，后者保存这次确实读了谁。

不恢复“长期观点＋多期考卷”。已读完重建记录、上一轮调研及相关决定；以下都是设计建议，没有修改文件。例子中的数值和政策变化均为示意。

## 1. 对 linked list 假设的结论

### 1.1 链表解决“从哪里来”，不自动解决“现在读谁”

链表就是每条记录连着前一条或后一条：

```text
美联储 2026 年末利率观点
        │ 接续
        ▼
美联储 2027 年末利率观点
        │ 接续
        ▼
美联储 2028 年末利率观点
```

它能告诉我们这些观点的前后关系。但如果 JPM 的箭头仍指向 2026 年观点，新增这条链**不会自动改变箭头的含义**。

严格说，旧箭头没有成为“悬空指针”：旧观点仍在。断掉的是对未来变化的跟踪。

而且，第 2 条已经使问题发生变化：

```text
2026 年 10 月，可以同时存在：
├─ 美联储 2026 年末利率观点
└─ 美联储 2027 年末利率观点
```

这时，“最后建立的”“链尾”“尚未关闭的”都不能唯一说明 JPM 应该读谁。

JPM 的“2027 全年净利息收入”可能需要：

```text
JPM 2027 全年净利息收入
├─ 2026 年末利率：2027 年的起点
└─ 2027 年末利率：对年内利率路径的一个判断依据
```

两条依赖可以同时有用。2026 年观点出答案后，第一条依赖变成已知历史条件；第二条继续提供预测。**把两条都自动改指 2027 年，反而丢了含义。**

### 1.2 推荐把三种关系分开

```text
关系一：接续
2026 年观点 ──接续──→ 2027 年观点
意思：研究往后接着做。

关系二：并入
重复观点 X ──并入──→ 观点 Y
意思：X、Y 原来就在问同一个问题。

关系三：依赖
JPM 观点 ──依赖──→ 美联储观点
意思：判断 JPM 时，需要读取这里的输入。
```

**接续不等于相同，并入不等于接续，依赖不等于继承。**

这也解释了为什么不能直接照搬 Wikidata 重定向。Wikidata 合并要求两个条目描述同一对象；被合并的旧 ID 重定向到保留条目。2026 年利率与 2027 年利率是两个不同答案，不符合这种“同一个”的条件。[Wikidata 合并说明](https://www.wikidata.org/wiki/Help:Merge)

### 1.3 链表还缺哪些规则

| 情况 | 只有链表会怎样 | 推荐补法 |
|---|---|---|
| 单一路径，前一期结束后才有后一期 | 可以找到后继 | 仍须规定依赖是否允许跟随 |
| 今年、明年同时开放 | 不知道读哪一个 | 数字依赖明确写目标年份 |
| 一个问题拆成两个 | `next` 只能指一个，或含义不明 | 记录拆分关系；逐条重新判断依赖 |
| 两个问题合成一个新问题 | 单个 `previous` 不够 | 允许多个来源关系；不自动继承原判断 |
| 后继梯子方向相反 | 同一个格号可能意思相反 | 核对指标、口径和方向；不按格号继承 |
| 新旧都在“中性” | 误以为输入没变 | 更换被读取的观点，本身触发一次重判 |
| 接错后继 | 修改指针会抹掉错误历史 | 追加撤销关系，再追加正确关系 |
| 新观点出现、旧观点已关闭 | 旧观点的订阅者可能收不到 | 新建／接续动作主动寻找等待它的依赖 |
| 没有新观点 | 沿链找不到任何未来判断 | 明确显示缺少来源；链表不能生成观点 |

所以，存储上我更推荐**单独的关系记录**，而不是在不可变观点里只放一个永远改不了的 `next`。正常接续仍是一条链；遇到拆分、合并时，才自然成为有分叉的图。

Git 正好说明了这个区别：提交记录保存父提交，合并提交可以有多个父提交；“当前使用哪个提交”则由另一种可移动的引用决定。父关系本身不负责选择当前版本。[Git：提交、父关系与分支指针](https://git-scm.com/book/en/v2/Git-Branching-Branches-in-a-Nutshell)

### 1.4 四种做法的比较

| 做法 | 优点 | 主要问题 | 我的建议 |
|---|---|---|---|
| 每次把所有箭头硬改到后继 | 直接，容易理解 | 容易把固定年份依赖也改掉；覆盖历史后难审计 | 不覆盖；用追加的变更记录表达 |
| 链表＋沿链寻找 | 保留接续历史，不需要长期父观点 | 仍须解决年份、分叉、方向和通知 | 保留，但只负责血缘 |
| 指向长期身份键 | 方便集中管理订阅者 | 单个“当前观点”装不下两个年份；容易恢复被否决的父层 | 可以是纯技术索引，不能拥有梯子、证据或判断 |
| 按规则解析的“通用代码” | 能明确表达年份、阶段、跟随方式 | 规则不清就会悄悄换问题 | 推荐其思想，先用少量明确字段，不造一门复杂规则语言 |

最终的依赖应当能用一句话读出来：

> JPM 这条观点，需要“美联储目标利率上限、2027 年最后一次议息后”的判断；本次实际读到观点 A27 的第 8 次判断。

这比“JPM 依赖 FED 最新版”清楚得多。

## 2. 五个问题分别怎么解

### 2.1 第 1 题：上游到期以后，依赖怎么继续

**推荐规则：固定年份的依赖固定年份；明确需要延续的依赖才跟随后继。**

#### 数字观点：先按年份选，不沿链追到最新

```text
JPM 2027 全年净利息收入
│
├─ 依赖美联储 2026 年末利率
│    └─ 2026 年观点关闭后，继续读取它的最终答案
│       用途：已知的年初条件
│
└─ 依赖美联储 2027 年末利率
     ├─ 已有 2027 年观点 → 读取它
     └─ 尚未建立 → 记录“缺少对应年份的观点”
        不能把 2026 年预测当成 2027 年预测
```

**第 2 条实际上消除了一部分“每年两百条箭头都要搬家”的问题。** 对固定年份答案的依赖，本来就不该搬家。新一年的对象观点建立时，再建立对应年份的依赖。

#### 事件观点：允许跟随同一件事的后继

```text
NVDA FY27 中国区收入
    │
    └─ 依赖 H20 对华出口许可的执行状态
          │
          ├─ 原观点仍开放 → 读取原观点
          ├─ 原观点关闭，存在合格后继 → 改用后继，留下记录
          └─ 没有合格后继 → 保留旧答案，但标明仅为历史情况
```

这里的“合格后继”至少满足：

- 仍是同一件事、同一范围、同一执行阶段；
- 没有把 H20 扩大成所有先进芯片；
- 梯子的方向仍能解释原箭头；
- 只有一个符合选取规则的候选。

数字接续则允许目标年份按规则变化，但指标、范围、单位等仍须核对。**后继的五格可以重定阈值，不能直接继承旧格号。**

例如，旧观点“中性”是利率 4%—4.5%，新观点“中性”是 3%—3.5%；它们名字相同，内容不同。

#### 换源必须通知，即使没有“换格”

建议把现有通知规则补成：

> 同一观点的普通更新，仍只在事实格或预测格变化时通知；更换被依赖的观点、增删依赖、来源变为不可用，另触发一次重判。

这是对现有规则的**明确补充**，不是链表自然带来的行为。

关闭时若还有需要持续跟踪的依赖、却没有后继，应当检查能否利用此次信息走原有的新建观点流程。建不出来就显示缺口，不能靠延用旧答案假装仍在跟踪。

#### 现实里的对照：期货通用代码

期货里要区分两件事：

1. **选择具体合约**；
2. **把不同合约的数据拼成连续序列**。

JPM 的公开产品文件把 Bloomberg `CL1` 写为第一近月 WTI 合约，`CL2` 写为第二近月，并明确规定产品在近月最后交易日改用第二近月。可见，**代码之外仍要有选择规则**；不能从“通用代码”四个字推出所有产品使用同一种换月日。[JPM 产品文件](https://www.sec.gov/Archives/edgar/data/19617/000121390026038814/ea0284751-01_424b2.htm)

`FF1` 这类联邦基金期货通用序列也要区分月份与指标。尤其不能把它的隐含利率直接当成“最后一次议息后的政策目标利率”：CME 说明，联邦基金期货反映的是**合约月份平均有效联邦基金利率**；转成议息结果还需要假设和计算。[CME FedWatch 方法](https://www.cmegroup.com/articles/2023/understanding-the-cme-group-fedwatch-tool-methodology.html)

公开文档中，Databento 把规则写得非常明确：按到期顺序、前一日持仓量或前一日成交量排序，再选第几个合约；同时保存按日期生效的实际合约映射。[Databento 合约解析规则](https://databento.com/docs/standards-and-conventions/symbology)

拼接又是另一层。TradingView 的向后调整会按换月价差修改此前的价格，以消除接缝。这种处理适合某些图表，**不能用于抹平观点历史**：不能为了让新旧梯子看起来连续，就改写旧判断或旧答案。[TradingView 连续期货调整](https://www.tradingview.com/support/solutions/43000685266-how-can-i-enable-backadjustment-for-continuous-futures/)

我没有验证 Bloomberg Terminal 当前各品种的 GFUT 默认配置，因此不把某个统一换月日当成 Bloomberg 的通则。

**与第 2 条相容：**相容，而且必须利用年份选择。需要避免的是“最新一条”“第一条开放观点”这类不带年份含义的快捷规则。

### 2.2 第 3 题：累计数和时点数，怎样放在同一结构里

**推荐不拆成两种观点结构，只把数字的时间口径写清楚。**

XBRL 已有成熟区分：

- **期间数**：覆盖一段时间，例如收入、利润。
- **时点数**：对应一个时点，例如资产、负债。

这不是数据来源区别，而是这个数自身的含义。[XBRL：时点与期间](https://www.xbrl.org/dates-in-xbrl/)

| 问题 | 预测位置 | 到期前的事实位置 |
|---|---|---|
| NVDA FY27 全年中国区收入 | 可以有 | 全年答案未公布，留空 |
| JPM 2027 全年净利息收入 | 可以有 | 全年答案未公布，留空 |
| 2027 年最后一次议息后的目标利率上限 | 可以有 | 可把最新已知上限放到这把梯子上，作为当前参照 |
| 年末某 ETF 的持仓量 | 可以有 | 只能使用最近披露时点的持仓，不能称实时持仓 |
| 到期时 H20 许可执行状态 | 可以有 | 有充分事实证据时，可以有当前状态 |

这里有三个容易混淆的地方。

**第一，季度数不能冒充全年数。**

```text
NVDA FY27 全年收入观点
├─ Q1 收入 → 证据
├─ 上半年收入 → 证据
├─ 全年指引 → 证据
└─ FY27 全年实际收入 → 答案
```

即使累计收入已经很高，仍然不等于全年结果。也不需要因此另开季度观点。

**第二，“时点数”不等于“随时可知”。**

价格可能更新频繁，持仓可能数周或数月才披露。必须同时保留：

```text
事实值
├─ 对应哪个时点
├─ 什么时候公布
└─ 系统什么时候收到
```

因此界面最好表达为“最新已知事实”，而不是无条件称“现在”。

**第三，当前参照不是未来答案。**

今天的政策利率即使落在 2027 年观点的第三格，也只表示“当前值按这把梯子落在第三格”，不表示 2027 年结果已经确定。

如果梯子衡量的是“相对某个起点降了多少”，计算当前格与最终格都必须使用**建观点时固定的同一个起点**。

**与第 2 条相容：**相容。年份决定问哪个数；期间／时点决定这个数何时形成。公司还应保存真实财年起止日期，不能仅凭 `FY27` 字符串推断自然年。

### 2.3 第 4 题：到期答不出来，怎样结束

**推荐把“没有答案”和“答案在中性格”彻底分开；同时把“暂时没拿到”与“最终无法判定”分开。**

```text
到了判定时点
│
├─ 有符合原口径的答案
│    └─ 记答案、出处、关闭
│
├─ 只是公告延期、来源暂时不可访问
│    └─ 停止预测，等待答案
│       原问题、梯子和到期日都不改
│
├─ 确认无法取得原口径答案
│    └─ 无答案关闭，记原因，不计预测对错
│
├─ 对象退出研究名单
│    └─ 停止跟踪，保留原判断
│       不能据此声称世界上没有答案
│
└─ 确认是重复观点
     └─ 并入关闭，记保留对象，不计为一次独立预测
```

几个具体例子：

| 情况 | 推荐处理 |
|---|---|
| NVDA 不再单独披露原口径收入 | 若原判定规则没有允许替代口径，不能事后拿地区总收入代替 |
| 公司被收购，但仍披露完整目标年度数字 | 仍可能正常判定 |
| 公司被收购，只剩收购日前的短期间报表 | 短期间数不是原全年数；不能强行年化作为答案 |
| 从名单移除 | 记停止跟踪；与“不能判定”分开 |
| 下载失败或解析失败 | 是处理故障，不是无答案关闭理由 |
| H20 到期仍有许可限制 | 若事实符合某一格，就正常判定；不需要宣布问题失效 |

Metaculus 区分停止预测与最终判定，也允许无法清楚判定的问题不评分。GJ Open 明确示例：问六月失业率，可以在六月结束时停止预测，等待七月报告；默认按首次公布值判定。[Metaculus 判定规则](https://www.metaculus.com/faq/)、[GJ Open 判定与数据规则](https://www.gjopen.com/faq)

你们可以借鉴这种区分，但**不必借用平台允许事后改题的做法**。原问题仍保持不可变。

#### 无答案关闭也会影响依赖

```text
上游无答案关闭
├─ 下游原来需要这个事实答案 → 明确标记缺少输入
├─ 下游原来读取最后预测 → 可保留为历史判断，注明没有验证
└─ 有合格后继 → 按既定跟随规则处理
```

不能把“没有答案”转成零、没有发生或中性。

#### 与“两条年度观点”的边界

这里有一个必须写进决定的边界：

```text
2027 年初：
├─ 2026 年观点：停止预测，等待年报
├─ 2027 年观点：开放
└─ 2028 年观点：可能准备开放
```

若“最多两条”指**所有尚未最终关闭的记录**，就必须等 2026 年判完才能开 2028 年。

我的推荐解释是：**最多开放今年、明年两条；旧年等待答案的记录不再开放预测，但继续保留。** 这不是增加第三个预测年份。

这一解释需要 Alex 明确接受，不能由实现悄悄放宽。到期仍无法判定时，也不能为了腾位置假装已有答案。

### 2.4 第 5 题：后建主题，怎样补上旧观点的依赖

**推荐把“主题建立”视为一次依赖关系检查的触发，不只等它以后换格。**

```text
新建“中国限制采购 H20”主题观点
        ↓
检查已有开放观点
├─ NVDA FY27 中国区收入
├─ AMD 对应收入观点
├─ 其他可能受影响的主题观点
└─ 无关观点
        ↓
逐个决定：直接依赖／无须新增／信息不足
        ↓
提交新增箭头
        ↓
受影响的旧观点重判一次
```

这里必须包括**既有主题观点**，不能只搜公司。否则新主题与旧主题之间的链也会缺失。

不过，不能仅凭检索相似就连线：

```text
“中国限制采购 H20”
├─ NVDA 中国区收入：可能有直接作用
├─ 全球半导体景气：需要论证，不能凭“芯片”二字连
└─ JPM 净利息收入：通常没有这条直接依赖
```

每条新增依赖应写一句具体机制，以及方向。已有路径已经表达同一机制时，也不应为了“更相关”再加一条重复路径。

#### 检索怎么用

推荐先遍历全部开放观点的简短描述，再按明确范围和检索结果组织需要模型判断的候选。**不把 Top-K 检索当成完整性证明。**

原因很直接：这道题修的是“漏连”。如果只取最相似的十条，排第十一的就会永久漏掉。

处理记录至少应能回答：

- 此次检查覆盖了哪些开放观点；
- 哪些被范围规则排除；
- 哪些被判定需要连；
- 哪些没有连、为什么。

这不意味着一定要把全库正文一次塞进模型，更不需要重读所有证据。

Bazel 的依赖计算有一个很贴切的教训：计算读取了某个输入，却没有把它登记成依赖，后续增量更新就会错误。依赖关系必须真实反映判断读取的输入。[Bazel Skyframe](https://bazel.build/reference/skyframe)

#### 会出错的地方

- 只检查公司，漏掉既有主题；
- 把相关性当成因果关系；
- 新增箭头但没有让旧观点第一次读取新主题；
- 新增箭头后形成环；
- 新主题实际上是旧主题的后继，却又给所有对象加一条平行依赖。

最后一种应先走第 1 题的接续处理，不能把“接续”和“新增独立因素”混在一起。

**与第 2 条相容：**相容。NVDA 今年、明年的收入可能都依赖这个事件，应分别判断；补箭头不会合并两个年度观点。

### 2.5 第 6 题：怎样避免沿依赖链重复重判

**推荐按“一条输入引起的一轮变化”处理，先等上游完成，再让下游判断。**

这种错误在响应式系统里叫 **glitch，毛刺**：下游短暂读到了新旧混杂的输入。

以下图中箭头表示“变化传给谁”，与“B 依赖 A”的画法相反：

```text
             美联储
             /    \
            ▼      \
        十年期利率   \
            \       ▼
             ────→ JPM
```

错误顺序：

```text
美联储更新
→ JPM 读取：新美联储＋旧十年期
→ 十年期更新
→ JPM 再读取一次
```

推荐顺序：

```text
第 N 条输入进入
    ↓
先完成本条输入的挂证据、建观点、接续和补箭头
    ↓
固定本轮依赖图
    ↓
美联储完成判断
    ↓
十年期完成判断，或者确认本轮不需要判断
    ↓
JPM 读取本轮已经稳定的两个输入，只提交一次判断
```

**拓扑顺序**就是“每个节点都排在它依赖的节点后面”。Excel 按依赖关系组织重算次序；Jane Street 的 Incremental 则把一轮更新推进到稳定状态。[Excel 重算机制](https://learn.microsoft.com/en-us/office/client-developer/excel/excel-recalculation)、[Jane Street：增量计算与稳定过程](https://www.janestreet.com/tech-talks/seven-implementations-of-incremental/)

#### 不能只加一个“去重通知 ID”

如果 JPM 收到第一次通知就计算，随后把第二次通知当重复丢掉，它反而会永久停在“新美联储＋旧十年期”的结果。

正确顺序是：

> 先合并本轮触发原因，等相关上游完成，再判断；不是先判断，再丢通知。

#### 也不能无条件重算全部下游

```text
美联储换格
    ↓
十年期重判
├─ 十年期也换格 → 通知只依赖十年期的下游
└─ 十年期没换格 → 这条传播路径到此停止
```

JPM 如果还直接依赖美联储，仍会重判，但要等十年期本轮处理结束。Bazel 的“结果未变则停止向下传播”与此相似。[Bazel 的变化剪枝](https://bazel.build/reference/skyframe#incrementality)

#### 本轮几个关键情况

| 情况 | 推荐行为 |
|---|---|
| 两条路径都触达 JPM | 合并触发原因，稳定后提交一次 |
| 上游已检查，格没有变化 | 标记本轮完成；按原规则停止该路径 |
| 上游判断失败 | 依赖它的下游等待；不能拿旧值冒充本轮新结果 |
| 无关分支失败 | 不必阻挡没有依赖它的分支 |
| 下一条输入又到来 | 第一版按分发序号逐轮处理，不混入本轮 |
| 中途崩溃或重试 | 恢复本轮记录，已提交判断不重复提交 |
| 本轮出现新依赖 | 在判断前纳入图并检查环；不在下游判断途中悄悄加边 |

“只判一次”应准确写成：**每轮每观点最多提交一个成功判断。** 模型调用可能因外部失败而重试，不能承诺物理上绝不调用第二次。

另外，**一次重判不等于消除了重复经济解释**。美联储和十年期都被 JPM 读取时，仍须说明两者分别提供什么信息，不能把同一个降息消息当两份独立支持。

**与第 2 条相容：**相容。图上的节点是明确的年度观点；同一轮可以分别更新两个年份，它们不是重复节点。

├─ 观点 ID
├─ 对象／主题

│   ├─ 指标或事件
│   ├─ 范围、口径、单位／事件阶段
│   ├─ 数字：期间数或时点数
│   └─ 数字：目标年份、实际期间或目标时点

├─ 判定来源、数据版本规则

关系记录：只追加

├─ 接续：旧观点 → 新观点

### 现实做法分别支持哪一部分

| 现实做法 | 借鉴什么 | 不能据此推出什么 |
|---|---|---|
| **FIGI**：金融工具的持久标识 | 更名不必换身份；退市后旧标识仍保留 | 被收购公司的观点自动变成收购方观点 |
| **CUSIP**：证券标识及公司行动记录 | 不同标识体系有不同变更规则，要保存具体行动 | 所有代码变化都只是别名变化 |
| **PermID**：组织、工具等实体的持久标识 | 实体 ID 与可变交易代码分开 | 同一公司不同年份的财务数字是同一个数 |
| **Wikidata 合并** | 真重复可以重定向，旧 ID 不复用 | 后继年度等于旧年度 |
| **Zenodo 概念 DOI／版本 DOI** | 动态查找入口与精确历史引用分开 | 所有读者都该自动读取最新版本 |
| **Git 父关系** | 保留接续、分叉和多来源历史 | 父关系决定当前使用哪个节点 |
| **SCD Type 2**：属性变化时新增历史版本 | 业务身份与具体历史记录分开 | 不同年度预测只是同一条记录的属性修改 |
| **事件溯源**：用追加事件还原状态 | 撤销也留记录，历史不覆盖 | 任意跨观点关系都能靠一条事件流自动解释 |

来源：[FIGI 分配规则](https://www.openfigi.com/about/allocation-rules)、[CUSIP 公司行动规则](https://www.cusip.com/apply/index.html)、[LSEG PermID 与历史代码](https://developers.lseg.com/en/article-catalog/article/workspace-corporate-actions-content-set-guide)。

FIGI 特别值得注意：更名、并购并不让旧金融工具的 FIGI 自动转移给另一工具；旧标识继续描述原工具。CUSIP 则可能因公司行动分配新代码。因此应该借鉴的是**身份＋行动关系**，而不是照搬某种代码的变更习惯。

Zenodo 的概念 DOI 可以指向最新版本，但它同时建议，可复现的引用使用具体版本 DOI。这正对应“依赖可以动态选取，但判断记录必须固定实际读取版本”。[Zenodo 版本机制](https://zenodo.org/help/versioning)

SCD Type 2 通常会更新旧行的有效状态；你们不必照搬这一写法。可以保留其历史版本思想，用追加事件表示某记录已结束。[Microsoft：SCD Type 2](https://learn.microsoft.com/en-us/fabric/iq/plan/powertable-concept-slowly-changing-dimensions)

接错关系时，也应用追加的撤销事件，而不是删除旧记录。过去基于错接关系产生的判断仍保留；纠正后生成新判断。[Microsoft：事件溯源与补偿事件](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)

### 预测平台给出的额外校验

Metaculus 曾按月或季度发布同一组宏观指标问题。这支持“系列相连、每个期间各自判定”，但不能证明它们自动继承旧题依赖；我没有找到这方面的一手实现资料。[Metaculus 宏观预测系列](https://metaculus.medium.com/can-metaculus-create-a-trading-signal-8131b7da6cac)

它的条件问题则明确问“若 A 为是／否，B 会怎样”，条件未发生的分支不评分。你们当前的箭头只是**让 B 读取 A 的判断背景**，并不是这种条件问题：

```text
当前设计：
H20 放松 → 重新判断 NVDA 收入，收入仍可能很差。

条件问题：
假设 H20 放松，NVDA 收入会怎样？
```

两者不应混用；A 的答案不能替 B 判卷。[Metaculus 条件问题](https://www.metaculus.com/faq/#conditional-pairs)

## 4. 我最不确定的三点

### 第一：JPM 到底需要“年末利率”，还是“全年利率路径”

血缘再完整，也不能补救输入问错了。

```text
两种路径，年末都为 3%：
├─ 一月已降到 3%，全年维持
└─ 十二月才降到 3%
```

对全年净利息收入，两者可能很不同。此外，资产重定价、存款成本和收益率曲线也会影响方向。

所以我不确信“一个年末政策利率观点＋一个方向”足以支撑 JPM 这个例子。下一步应拿真实分析师论证检查：现有年度观点组合是否够用。这属于投研问题定义，不能由链表选取规则代替决定。

### 第二：哪些改变仍可自动接续

“同一指标换一年”通常清楚；“H20 许可”变成“所有对华 AI 芯片销售限制”，就未必。

我倾向于：

- 年份变化、阈值重定：可以按明确规则接续；
- 指标、范围、执行阶段变化：保留血缘，但重新判断依赖；
- 分拆、组合：不自动继承所有箭头。

真正困难的是中间地带，需要真实成对案例确定边界。相似度、稳定 ID、链表都不能替代这项业务判断。

### 第三：等待答案与停止跟踪，如何进入历史成绩

最容易明确的是：没有可验证答案，就不判预测对错。

较难的是：因为退出名单而停止跟踪，但以后其实出了答案，要不要补判？若永不补判，退出名单可能使差的预测从成绩里消失；若一律继续追答案，又扩大了已冻结名单之外的工作。

我的倾向是把**继续研究**与**原预测的结果记账**分开：停止研究可以，但不能抹掉原预测；是否继续取得最终答案，应有一条统一决定。这个决定应先定，再设计相应处理流程。
