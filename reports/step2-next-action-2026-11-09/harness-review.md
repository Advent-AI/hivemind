## What is prepared

`probe.py` is an isolated experimental draft. `--prepare CANDIDATE_TEXT NEW_PLAN_DIRECTORY` is an **offline-only** entry point; it deliberately exposes **no send CLI or registration gate yet**. The candidate is loaded from one reviewed UTF-8 file (without a trailing newline) and is pinned by SHA-256. The tool rebuilds original bodies from the archive, checks archive identity, historic typed answers, full state and every original candidate question, and the candidate's only changed input is the `supersedes` criterion repeated across all candidate questions. No criteria, state, group identity or source text is edited elsewhere. It preserves all candidate IDs, historic group ordering, and `compare.outcome` for deterministic replay of all typed answers.

The program's callable `execute` function is intended for a *future reviewed launch wrapper*: it makes an exclusive new output directory; refuses changed input/code/candidate hashes; dispatches at most 42 attempts with fixed-seed order and an eight-thread pool; reserves the entire batch against a fixed $0.10 hard **reservation** limit; records an fsynced `may_have_been_sent` event before every dispatched batch; uses the previous separately reviewed `diagnostic.py:send_one` implementation (no retries, no cache lookups, bounded response, no redirects, strict complete-question Jev validation, response allowlisting and credential scanning); writes sanitized outcomes and all candidate choices; and prevents later batches after any failure. A deadline produces unknown status and terminates the process to prevent unrecorded late sends. There is no resume, no automatic retry, no product DB write and no production code edit. A crash still requires treating already journaled attempts as potentially charged. The reservation is not a provider billing cap. `old.run_state` catches known repository paid-process patterns, but cannot prove no unrelated paid process exists.

**No user credential was read and no Jev network request was sent.** The fake sender tests use a fake secret and run within temporary directories. ## Implementation revision awaiting independent review

Following reviewer feedback, a gated real CLI was added: `probe.py --send PLAN_JSON REGISTRATION_JSON REGISTRATION_SHA256 NEW_OUTPUT_DIR`. It refuses before credential access unless the registration hash, plan and candidate hashes, code/tests/dependencies, audit and review hashes, source inputs, output path, exact v108 preflight and process state all match. The independent audit and review must start with `READY TO SEND` and include exact `plan-sha256: ...` and `candidate-sha256: ...` lines. The registration itself is SHA-pinned on the command line; no secret belongs in it or any command argument. The application holds a persistent-file `flock` until completion; the lock file is never removed, avoiding two-inode races. The key is obtained in memory only after all gates and preflight pass.

Events record UTC observation times and monotonic elapsed durations as diagnostics; ordering remains owned by the dispatch sequence. The pinned dependencies now include model.py, jev_matching.py, two blind-source reader files, source packet, and reference mapping. The dispatch loop (including task submission) is under a hard-exit handler after its durable may-have-been-sent entries. A journal error or interrupt while threads may be sending cannot leave live network workers behind; unknown charged attempts remain represented by those entries, and no output is marked complete. The actual destination is exclusively created and is never resumed.
