Scope: actual archived D392 d1 `92:e2` request `reports/step2-loop-retrospective-2026-11-09/current-request-example.json`, its ten stored candidates and saved Jev answers, `clean-arch/step2/compare.py`, `src/hivemind/jev.py`, PRD §5 and explicitly draft §13, D168, D202, D204, D381, `reports/step2-revision-census-2026-11-09/RESULTS.md` and the two source-reader challenges. ## Entire request and implementation, not just the edited sentence

The saved request contains only model, one incoming `state`, and ten typed-choice questions. Each question repeats the same three criteria and instructions, with one distinct stored candidate. The exact state is the company spokesperson's statement disputing the *Kyber NVL144 delay*. The data in each piece is its summary, all stored quote passages, source tier, reporter, original party and stated time as available; there is no full article, separate `evidence_period`, or structured financial figure. Only supplied text is permitted. There is no separate generated-text rationale, hidden system message or output schema description in this stored Jev request; the response type is Jev `choice`, three labels and probabilities, validated by `jev.validate`, not a JSON-schema writing prompt.

Each of q0–q9 has the same criteria. In the actual saved answer q0 (the earlier report of the Kyber delay) is `supersedes` .99, q1 (the earlier company denial) is `same_statement` .98; q3 (NVL576), q7 (the CPO-NVSwitch/Feynman statement), q9 (the cancelled backup rack) are `supersedes` .71/.94/.79. Two independent source readers judge the last three different in this source context, although q3's NVL576 broader interpretation deserves individual examination. These are one request and one draw, not three independent incidents or a global metric. The q0 article already contains the denial so q0 is a target-recognition control, not a clean chronology control. q1 is a known repeat in this request. The actual search results, candidate order, other candidate answers, link and repeat selection must be retained in an experiment; `compare.outcome` selects highest `same_statement` probability with original group order for ties and records **all** other `supersedes` answers. It has no evidence-comparison probability cutoff or uncertain label; the `.5` threshold in `later_link_judge` is a different task and cannot be imported.

## Failure classes and practical meaning

- Wrong revision to a related but distinct main statement: 14 of 56 selected `supersedes` answers were independently labeled different before reader challenge (13 reports around one event, one cloud program). All 56 are chosen by the model and collapse to 30 actual group relations; they are not a random precision estimate. Current supersedes criterion already says same main statement and same-topic exclusion, so the sentence does not contradict PRD. The unresolved question is whether explicit target identification helps Jev apply it. `abstract/misread, cause unproven`; no model-authored account exists in typed Jev.
- Source-supported repeats called revisions: 6 of 56 independently before challenge, 7 after; retain unchanged `same_statement` rule and complete candidate sets. A real repeat may add details, and an official confirmation of a reported claim is still a permitted revision under D168; distinguish whether the official is making a separate confirming assertion or re-reporting the same official statement. Candidate examples C029, C028; `misread or input ambiguity`, not shown to be a missing rule.
- Repeat not found in grouping H01: old $12.9bn vs rounded $13bn, candidate was found and criterion permits different precision. Source reference is diagnostic, not signed gold; Jev's failure and hypothetical procedural change are separate. `misread, cause unproven`, revision-only candidate is not claimed to fix it.
- True change / confirmation/denial: C035 targets NVL576 timeline but does not resolve low volumes; C073 is a later source-reported conditional H200 policy easing, not official proof or completed purchasing; two source-only AI readers support each. C021 / q0 is direct denial of stored main claim but older full source already contains the denial; it tests target recognition rather than true temporal order. These controls prevent a one-sided removal of links.
- C051 and C049 ambiguous denials, C059 disputed stockout/discontinuation and C047's conflicting source dates: preserve source ambiguity and time limits, do not hard-set them as gold or force the candidate to pick 'different'.

## One narrow candidate for blind independent challenge, not approved wording or a send

An intervention that preserves all current criteria byte-for-byte except the targeted supersedes procedural preface can be expressed as follows:

```
first identify the statement the incoming piece addresses; a later version of the stored piece's main statement, changed: the same speaker revises that guidance, forecast or event-progress statement, an official confirms or denies that reported claim, or the original source revises it; another statement on the same topic is not this
```

This is deliberately an instruction about evaluating identity, not a new semantic rule or extra Jev output. It does not demand a literal, separately named target, alter legal `confirms`, strengthen date evidence or assert missing facts. Even so, the phrase `addresses` can be understood too broadly or too narrowly, a single piece may refer to several statements, and Jev does not expose the requested intermediate determination; whether the instruction helps, harms valid repeat/revision cases, or is ignored is unknown. It is an abstractness hypothesis sourced to PRD §5's same-statement requirement and its §13 working-draft phrase `what each statement refers to`, not a proven missing signed rule. No case-specific wording or source event examples are introduced. It must receive the prompt-audit skill's independent blind read and council challenge before any send. If no actionable procedural distinction is accepted, do not sell this as a fix; discuss a different experiment with the council rather than expanding the census.

The original criterion is 275 characters, the proposed prefix is 59 characters, total 334. No equivalent text is removed, so this draft **does not satisfy the AGENTS §6 cut-at-least-as-much requirement as written**. Before sending, an independent reader must identify safe equivalent cuts or establish an applicable, documented growth exception; do not claim this audit alone clears the prompt. Jev-specific prompt tokens before/after were not measured; local `tiktoken` is unavailable, and another tokenizer is not authoritative. Budget and provider usage must be measured by the approved cost/preflight mechanism, not estimated from characters as billable tokens.
