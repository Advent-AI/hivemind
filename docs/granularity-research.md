## 一句话

裸用 GPT 每次给你一篇新写的作文。Hivemind 给的不是数据，是这家公司上已经开着的那 2–4 个争论：各自现在站在梯子哪一格、是哪几条带日期的证据推到这里的、什么时候见分晓，以及我们过去在这类问题上判对了多少。这三样（事先写死的问题、带日期的状态、到期定格的记分）一个没有记忆的对话做不出来，市面上也没有人卖给散户。

## 1. 先认账：裸用 GPT 已经能做什么

- 一篇像样的初稿。给它「我想买 NVDA，因为推理需求在加速」，它能讲清业务、找来申报、分开训练和推理、列出对手、写出反方、给出催化剂和出局条件。Codex 的判断：这一点 Hivemind 应该直接承认。
- 数据接入已经不是产品。2026-09-10 OpenAI 发布 ChatGPT for Financial Services，Bloomberg、FactSet、Daloopa、PitchBook、LSEG 加约 50 个 MCP 连接器都打包进去，「每个数字都带引用」；Anthropic 的 Claude for Financial Services 同样接了 FactSet、S&P、Morningstar、Daloopa（[Fortune](https://fortune.com/2026/09/10/openai-courts-wall-street-with-chatgpt-for-financial-services-developed-with-morgan-stanley)）。Alex 自己 2026-09 也说过（旧仓库 `context/discussion/USER_REQUESTS.md` 第 6 条）：「我们早就有这些金融和各种情绪面数据了……不是壁垒」。
- 所以同事说对了一半：「数据商」确实不是一个能站住的位置。图上第一层叫 Data Vendor，交付叫 Versioned Thesis State API；要紧的是后半句「state」，不是前半句「data」。

## 2. 裸用 GPT 在哪里断掉（都有测过的数）

| 断在哪 | 证据 | 接数据能不能修 |
|---|---|---|
| 数字错、财期错 | FinanceBench（2023）：GPT-4-Turbo 配共享向量库，150 题里 29 对、20 错、101 拒答；整份申报放进上下文也还错 26 题（[表 2](https://arxiv.org/abs/2311.11944)）。Daloopa 2026 基准：三家前沿模型接上结构化数据库后约 90% 对，Claude 的 46 个错里 63% 是财期弄混；3 月财年的公司只有 65% 对（[Daloopa](https://daloopa.com/benchmark/benchmarking-ai-agents-on-financial-retrieval)）。Vals Finance Agent 基准 2026-06：最好的模型 64%（转述） | 能修大半，厂商都在修。不是我们的增量 |
| 顺着用户说 | 《The Price of Agreement》（ICLR 2026 FinAI workshop）：用户只是反驳，掉得不多（Claude Sonnet 4.5 掉 17%）；用户先亮出自己的偏好，掉得很狠：GPT-5-Nano 0.83 → 0.47，Gemini-3-Pro 0.83 → 0.24；加过滤只能部分救回（0.49 → 0.67，基线 0.87）（[论文](https://arxiv.org/abs/2604.24668)）。「我这个想法怎么样」正是「先亮偏好」这一种 | 修不了。状态得在用户开口之前就已经判好，用户拿到的是一次查询，不是一次回答 |
| 不知道「当时知道什么」 | 模型答出的「预测」有一部分是训练数据里的事后信息：Gao–Jiang–Yan 的 lookahead propensity 在训练截止后归零（转述）；Kim、Muhn、Nikolaev 要把公司名和年份全抹掉才敢测（转述） | 要一套带日期的证据集：「这一天、凭这几份文件，状态是 X」 |
| 每次答得不一样 | 同一个问题连问三天，推荐方向反转（Lee 2026，转述）；IMF 工作论文：重跑一致率 88%（转述）。AGENTS §6：模型调用是一次采样 | 要存下来的状态，只在证据变了的时候变，变了有记录 |
| 没有记分 | FactSet 的产品负责人：客户要的是「一条长的预测记录，好让他们自己下注」（转述）。Alpha Theory 对 300 多家基金的统计：经理默认 75% 的成功率，实测 batting average 55%（[Alpha Theory](https://www.alphatheory.com/blog/probability-inflation-the-risk-of-ignoring-batting-average-2)） | 要到期定格 + 记分。没有一个对话产品有 |
| 不知道市场预期在哪一格 | 没有任何基准测「这件事是不是已经在价里」；裸用 GPT 答不了 | 要把「市场当时预期哪一格」摆在状态旁边比。见第 8 节的选择 1 |

散户那一侧的数也对得上：用 ChatGPT 做「预测」的散户，表现和这个用法负相关（β = −0.511，n = 121，小样本，转述）；用它做数据整理和风险框架的正相关。没接地的 ChatGPT 比 DeepSeek 多 12.5% 的乐观偏差，接上本地新闻后偏差消失（HBS 2026，转述）。

## 3. 对冲基金的做法到底是什么

单位。一个和价格隐含预期不同的看法，落在一个关键因素上，有一个触发事件和一个日期。Steinhardt 的 variant perception 要讲四件事：想法、市场共识、我们哪里不同、什么事件让市场看到。Sonkin & Johnson 的 PM 四问：上行多少、下行多少、为什么市场错了、什么时候由什么把差距合上。

数量。「每家公司找出 2–4 个 critical factors」；「十条信息里至少八九条动不了股价」（Valentine，[原话](https://tearsheet.co/?p=1603)）。卖方的 key debates 也是这个数：Morgan Stanley 的 Joseph Moore 2026-05 对 NVDA 点名三个（ASIC 份额、毛利率走势、Vera Rubin 进度，[Yahoo](https://finance.yahoo.com/markets/stocks/articles/morgan-stanley-resets-nvidia-stock-154922400.html)），2024-12 也是三个（Hopper 放缓、Blackwell 各版本的出货时间、ASIC），集合换了，数量没变；Goldman 对 AMZN 三个；Bernstein 对 AAPL 两个。

结算单。每个争论有一张结算单和一个 bogey：「12 月季度指引隐含 7,000 万部 iPhone 或更少，会被看成令人担心」（Bernstein 2016）；「这是会动股价的那一个数：EBITDA 6,300 万对预期 7,000 万」（前 Citadel 分析师）。事前写下出局条件（kill criteria）：指标 + 门槛 + 期限。

厂商怎么切（作对照）。Visible Alpha 每家公司平均 156 条共识线；Daloopa 每家最多 1,100 个数据点。Distilla 的 company_drivers 每家 7–10 条（本次查到：NVDA 10、MSFT 10、AMZN 8、META 8、AAPL 8、TSLA 7），每条是「一个话题 + 因果关系 + 支撑事实」，不是问题，也没有到期日。NVDA 这 10 条里真正在争的大约 4 条（定制芯片分份额、HBM 涨价压毛利、对华出口、给客户融资的信用风险）；「AI 算力需求」是共识事实，「投资人仓位」不是业务上的事。争论在估计分歧最大的地方：Blackwell 的季度收入 11 家预估从 25 亿到 244 亿美元。

旧仓库的两次失败。先是「每个角度开一条」：META 一轮长出 27 条，其中约 5 条青少年诉讼、约 5 条 Muse，分析师只会算 2 条（`docs/DOSSIER_MODEL.md:244`）。改成「每条 value line 一个 debate」以后又反过来：23 把梯子里 14 把是一条财务线的区间；18 条观点里 13 条用同一个「下季总收入」做第一道检验；三条估值观点只有股价当出局条件（lesson 47；`FACTOR_PRD.md:154`）。Alex 当时的话：「财务指标真的只是一个维度而已……我们重点要搞 thesis 抽取和 hedge fund analyst 一样」。旧仓库自己最后的修正：一条观点是一个原因（cause），财务线和 KPI 是分辨原因处在哪种状态的证据；它的参照集是 3 家公司 9 条（6 条公司的、3 条共用的），也就是每家 3–5 条加 1–2 条它依赖的主题。

## 4. 一条观点该多大（提议）

一条观点 = 能让人换仓的一个争论：业务上或世界上的一个原因，懂行的人现在就它有分歧，由一个数或一件事在一个日期结算，落到梯子两头会让 PM 改仓位。

```
候选观点要过的五道检验（提示词里让模型逐条写）
├─ 在争吗 → 现在有人看多有人看空；估计分歧大。共识事实不开（「AI 需求强」是背景，不是观点）
├─ 一张结算单 → 一个数或一件事、一个日期就定格。要两张结算单的，是两条观点，用依赖连（D46 第 2 条已定）
├─ 会换仓吗 → 落到最远那一格，PM 会改仓位。不会的，是别的观点下的证据
├─ 不是财务线的复述 → 「收入会涨吗」不是观点；观点是让这条线动的那个原因，线是梯子的单位。两个原因打在同一个数上，是一条观点，理由里写两面；一个原因要看两个数，是两条观点
└─ 不是一个角度 → 一个产品、一桩官司、一家供应商、一个地区，是证据，不是观点，除非它一件事就能动股价几个百分点
```

数量。每家公司同时开着的对象观点一般 2–4 条，最多 5；它依赖的主题观点另算。写成提示词里的预算，不写成代码里的配额（D44：代码不查名额）。集合会轮换：NVDA 从「Hopper/Blackwell 的交接」换到「中国」再换到「ASIC 份额、毛利、Rubin」，数量一直是三。

和已冻结设计的关系。观点的身份是「对象 + 看的是什么 + 哪一期」（D46），按结算的那个数认；对冲基金按原因认。两者合起来就是上面第四道检验：问题写原因，「看的是什么」写结算的数；两个原因打在一个数上，就是一条观点。这一条不改冻结的规矩，只是说清提示词该怎么写。

太粗的样子：「AI 会赢吗」——放不到一张结算单上；「收入会涨吗」——一条线的复述，三个月后状态变成上一次财报落在哪个区间。太细的样子：第 156 条共识线；Muse 的五个角度各开一条；每个季度的数各开一条（季报是证据，D46）。

### 例子：NVDA，2026-10-22

Distilla 列的 10 条 driver，过五道检验以后：

```
NVDA 开着的观点（示意；财年 FY27 到 2027-01，FY28 是明年）
├─ 对象观点 1 → 对华出口许可下，NVDA FY28 中国区数据中心收入，比 FY27 会怎样？｜五格：涨 50% 及以上 … 降 80% 及以上｜到期 FY28 年报日
│   └─ 依赖 → 主题观点 A「H200 这一档对华出口许可，到 2027-06-30 处在哪一格」（放松那头看多）
├─ 对象观点 2 → 云厂商自研芯片分走份额以后，NVDA FY28 数据中心收入同比落在哪一格？｜≥50% / 25–50% / 10–25% / 0–10% / 负增长｜到期 FY28 年报日
│   └─ 依赖 → 主题观点 B「四大云厂商 2027 年资本开支，比 2026 年」（涨那头看多）
├─ 对象观点 3 → HBM 和代工涨价下，NVDA FY28 全年 GAAP 毛利率落在哪一格？｜≥75% / 73–75 / 70–73 / 65–70 / <65%｜到期 FY28 年报日
├─ 对象观点 4 → NVDA 给客户的融资和担保（约 990 亿美元股权投资、最多 1,050 亿美元信用支持），到 FY28 年报日有没有计提损失？｜两格：有 / 没有｜到期 FY28 年报日
└─ 不开 → 「AI 算力需求」（共识事实，是观点 2 的证据）；「主权 AI」（观点 2 的一个角度）；「投资人仓位、Burry 做空」（第三方看法和传闻那两层的证据，不是业务上的原因）；「Vera Rubin 进度」要开也是短期事件观点（到 2027-03-31 机柜有没有按时出货，两格），不占长期的名额
```

同一张图换成银行：JPM 开两条，「2027 全年净利息收入比 2026」（依赖「美联储 2027 年末利率」）和「2026 全年信用卡净核销率」（<3% / 3–4 / 4–5 / 5–6 / ≥6%）；资本回报只在这笔交易押它的时候才开。换成加密货币：ETH 开两条，「到 2027-04-22 前 90 天的年化净供应增速」（费用销毁对发行）和「2027 上半年现货 ETF 净流入」；两条分开，因为链上活跃和代币稀缺可以一个升一个降。

## 5. 对同事的回答：角度

用户对 GPT 说「我觉得 NVDA 要涨，因为中国市场要放开」。裸用 GPT 会顺着这句话写一篇牛市作文（第 2 节第二行）。接上 Hivemind 的 GPT 答的是下面这样（示意：证据编号和最后那句记分都是编的，事实部分来自 Distilla 2026-10-15 的 driver 表）：

> 你说的是对象观点 1。它现在在「看空」那一格：2 月发了 H200 许可，但到 5 月中没有一单成交，中国市场份额 H1 2026 掉到 34%，10 月参议院又推进了新的限制法案（证据 e12、e15、e19，三条都是「发生的事」那一层）。它依赖的主题观点 A 现在在第 3 格「要许可，发了，但附条件」。见分晓的日子是 FY28 年报日。你的想法要成立，先得主题观点 A 走到第 4、5 格。另外，你没提的那两条观点（毛利率、融资风险）现在都在往看空那头推，这两条和中国无关。我们过去 11 条到期的对华许可类观点，到期前 90 天的状态有 8 条落在最后那一格。

这段话里没有一句是 GPT 现场写的判断。它读的是状态、证据编号、依赖和记分。这就是 Gap 1 的「intelligence」：不是更好的作文，是一个事先写死的问题、一个带日期的状态、一份到期定格的记录。三样东西，一个无状态的对话做不出来：

1. **问题是在证据来之前写下的。** GPT 的问题是看完今天的新闻以后才写的，天然事后诸葛。事前写死的出局条件是对冲基金防 thesis creep 的做法；散户那边有对照实验：事前设好的自动卖出显著降低处置效应，而「提醒」没有效果（Fischbacher、Hoffmann、Schudy，RFS 2017）。
2. **状态带着「当时知道什么」。** 每次重判写明依据哪几条证据、哪一层、哪天说的；要知道某天怎么判，翻那天的记录，不重新问模型（观点库 PRD 已定）。这正是那几篇 lookahead 论文要求的控制，对话里没有。
3. **到期定格是唯一能建立信任的东西。** 评级能带动资金流（Morningstar 五星基金半年内多 53% 的流入，转述），但脱离结果以后就衰退成人气投票（Value Line、WSJ 分析师排名，转述）。引用脚注单独看反而有害：加了随机引用信任也上升，真去核对信任才下降，而且多数用户根本不点（Ding 等 2025，转述）。有结算记录的记分是证据最强的一种：Estimize 的众包估计、Metaculus 的 Brier、Kalshi 对 CPI 和联储决议的定价都在这条线上。

Codex 的反方值得记下来：「GPT 加一本日记，可能就拿到大部分好处了」；「业务判断对了，价格付高了也是一笔坏交易」。回应：日记要用户自己记、自己更新，Alpha Theory 的数据是连职业经理都不刷新过期的目标价；日记里的问题仍是看完新闻以后写的；一本日记攒不出跨对象、跨用户的记分，而记分才是让人信的东西。第二句是对的，它就是第 8 节的选择 1。

## 6. 怎么证明（Gap 1 的 benchmark）

图上写的是「同题同时间对比 baseline；grounding、calibration、out-of-sample alpha」。按 AGENTS §5、§7 排成三层，先便宜的：

1. **$0，存下的数据，Pull 模式能跑第一天就能算。** 每条到期的观点，到期前 90 天、30 天的状态落在定格那一格的比例，和 Brier 分数。对照：全填「中性」；再加一个「卖方当时的数落在哪一格」（只要第三方那一层的证据里有数就能算）。先量尺子：五格的随机命中率、中性格的基率、两个对照互相比；一个对照自己都过不了的线判不了东西。
2. **拆题质量，$0。** 我们对一家公司开着的观点，对照同一天卖方 note 点名的 key debates 和一位盲评分析师写的 3–6 个争论，算查准查全。旧仓库做过这件事（参照集 9 条，建库当天找到 3 条），仪器现成。这是颗粒度规则本身的验收。
3. **用户层，六个月，贵，是第二、三层的事。** Codex 的设计：用户随机分成「接 Hivemind」和「强对照（GPT + 网搜 + 反方提示 + 一本日记）」，每个决定连同信息截止日冻结，盲评员按当时能拿到的材料数「错的根据」（错财期、过期指引、没证据的断言、漏掉的反证）。目标是错的根据少 25% 以上，研究时间相同。六个月的纸面收益只是辅助，证明不了 alpha。

「同题同时间问裸 GPT」做对照时要锁信息集：给它和我们一样的证据集，不然比的是数据接入，不是状态。

## 7. Gap 1 交付的是什么

就是观点库本身，不另做一个 API：对一个对象，开着的观点（问题、梯子、到期日、状态和理由、依据的证据编号和层和日期、结论变不变的历史）、依赖和方向、关掉的观点和定格、以后再加记分。记分来自到期定格，到期定格是 Pull 模式做的（D54），所以记分是 Pull 模式设计里的一项。第二层（图上的 Path A：GPT/Claude + research harness）做的事是：把用户的想法搜到对应的观点、把他的格和状态比、列出变了什么、什么时候由什么结算、记分多少。这一层不在冻结范围里，也不在这份稿子里设计。

## 8. 给 Alex 的选择

1. **市场预期放不放在状态旁边（最大的一个）。** 先把词分开。状态是模型按证据判的格，就是我们的共识，Alex 的话：「D51 存的当前就是 consensus 或是模型判断」；一条观点只有这一个位置，这条不动。这里说的是另一样东西：市场预期，卖方一致预期或价格里隐含的那一格。Steinhardt 的四件事里的「市场共识」、Codex 说的「判对了业务、付错了价格」、第 6 节第 1 层的那个对照，要的都是它：状态和它不一样才是 edge，一样就不是。四个选项：
   - A：第一层不存。第二层读第三方那一层的证据（卖方的数本来就带日期存着），告诉用户「街上的数落在第 X 格」。不改任何冻结的东西；限制是只看得到信息流碰巧带进来的卖方数。
   - B：Pull 模式每天给每条数字的观点存一个厂商一致预期的快照（Visible Alpha 或 Distilla 那种线），写在观点旁边，不进状态的判断。要一条新决定（动 Pull 模式的设计），信息流一点不动（D12、D13 不碰）。
   - C：不存，记用户自己的格当他的 prior，到期和定格比。答不了「是不是已在价里」。
   - D：第一层什么都不加。第二层的 agent 自己去数据厂商（Daloopa、Distilla）拿一致预期，按梯子的阈值对成一格，再和状态比。第一层只要保证数字观点的梯子阈值是能对数的数，今天已经是。厂商也有历史的一致预期，第 6 节的对照照样能做。
   - 倾向：D。市场预期是数据厂商的产品，不是状态；放进第一层是又一个数字仓库（D24、D28）。B 留给以后：第二层证明每天都要用、而厂商的历史线不够用时再谈。
2. **五道检验怎么落地。** 写进抽取提示词第 1、5 块（等颗粒度定了再写，05-extraction 已经留了位置）；比对标注里多一个标签：人标每条新开的观点是「争论 / 财务线 / 角度 / 捆绑」，攒给小模型。不加代码配额。倾向：就这样。
3. **每家 2–4 条写成预算。** 提示词里的一句话，不是上限；人手动打开的不受它管（D57）。倾向：写。
4. **记分归 Pull 模式。** 到期定格和记分一起放进 Pull 模式的设计（选择 1 要是选了 B，B 也归它）。倾向：是。

## 9. 这份稿子的限度

- 「有结算记录能让散户的交易更好」没有对照实验直接证明；证据是间接的（事前承诺有效、反馈让人校准、记分产品确实携带信息）。得在我们自己的数据上量（第 6 节）。
- 记分类产品（CAPS、Estimize）作为散户生意都没活下来，故事类和评级类反而做大了。记分要出现在用户已经在用的那个对话里、在他做决定的那一刻，不然对了也没人用。
- 散户仍会仓位过大、交易过多、追热点；产品改善的是被它问到的那些决定，不是「要不要问它」这个决定。社交和跟单功能让事情更糟（有对照实验，转述）。
- Distilla 的 driver 样本是六家美国大盘股；银行和加密货币的例子是按同样规则推的，没有厂商样本。
