## 规矩

- 依据的顺序：Alex 的话 > docs/DECISIONS.md > PRD 和设计页。PRD 和 DECISIONS 不一致时，以 DECISIONS 为准，并改 PRD。
- **有任何改动，都要全部刷一遍：由 Claude 推理，不靠脚本。** 按这个顺序逐个模块过：研究对象名单 → 分类 → Config → 分发 → 抽取 → 观点库 → 最终判定 → Pull 模式 → 人工复核池 → 系统总览。每个模块对照 DECISIONS 问四件事：
  1. 这次改动影响它吗？
  2. 设计页和 PRD 说的是不是同一件事？
  3. 例子还成立吗？
  4. 验收标准和“还没定的”要不要改？

  发现不一致就改，最后列出改了哪里、为什么。DECISIONS 和 CURRENT_STATE 也在同一次改动里更新。
- **最后一步才跑 `python3 docs/check.py`**，只做机械检查：PRD 里标着 `generated` 的段落和设计页的数据是否逐字一致（不一致只报告，由 Claude 改）、重新打包 PRD（直接双击打开设计页时读的是打包副本）、分类仿真、设计页能否正常打开。它通过不代表刷完了，推理那一遍才是刷新。
