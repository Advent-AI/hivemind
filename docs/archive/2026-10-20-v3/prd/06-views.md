## 一句话

系统的核心。一条观点是一个问题、一把梯子和一个到期日，写下不改；证据把我们的判断往两头推，到期拿答案对一下，就知道判得准不准。抽取交来两样东西，在这里各走一条线、走法一样：候选观点和这个对象开着的观点比，挂上去、接续、开新的，或者不开；证据和它那条观点下已有的证据比，是重复、替代还是新证据；只是重复的，不重判。

## 为什么这样设计

- Alex 给这个模块定的要求：“store the theses, the evidence, and the ladder in a very, very clear data structure manner that has linkages to whatever is passing through the data pipeline.” 观点、证据、梯子各有清楚的结构，每条证据都连回管道里的一条信息。
- 观点是一个问题加一个状态，不是一句断言（Alex：“这个 hypo 更像是一个 thesis with a state”）。反方向的说法不用另建一条观点，只是把状态往另一头推；哪条信息先到，也不决定观点长什么样。
- 梯子事先写死，每一格是看得见的结果：什么事实会证明我们错了，建观点时就写在上面，事后挪不了球门。现实里的对照：卖方的牛、基准、熊三种情景，买方事先写下的止损条件，超级预测者要求每个问题有明确的判定标准。
- 事实和判断分开放：现在在哪一格只有发生的事能动；状态是判断，每次从这条观点下没被替代的全部证据重新判，不在上一次的基础上加减；替代按这句话是哪天说的排先后，晚到和修正过的信息不会因为处理先后不同而读到不同的证据。回放靠存下来的重判记录，不靠重新调用模型。
- 对象观点和主题观点分开（Alex：“有些事情不一定对所有人都是 bull / bear，有可能完全相反”）。主题观点只说世界会变成什么样，好坏由依赖它的对象观点自己说。
- 一条观点只有一层（Alex：“一条观点一定是有一个明确的 ladder 和到期日，这样才构成一个观点”）；到期日定在争论见分晓的那天，一般 6–12 个月，中间的季报是证据。
- 对上像分析师：看到一条 NVDA 的新闻，先打开 NVDA 那两三个争论，看它属于哪一个（Alex：“已经存在的观点就 merge，日期遵照之前已经存在的期限”）。相似度只用来拉清单，当不了裁判。
- 证据和观点走一样的路（Alex 问过：“It's not clear to me how this logic is similar to thesis”）：先打开文件夹，再和里面已有的比。候选观点打开的是这个对象的文件夹，证据打开的是它那条观点。不比的话，一条观点下的证据只增不减：2 月的“资本开支涨 12%”和 4 月的“改成 25%”并排放着，重判每次都得自己从一堆里分出哪条过时了，分完也不留下。
- 重复、替代在进库时判一次、记下来，就是让模型自己给证据做加和删（Alex：“这个难道 LLM 不能自己 append delete evidence 吗”）；被替代的只是不再算数，留在历史里，不删。只是重复的不重判，转载不用再调一次模型才知道什么都没变。
- 只有是或否的问题用两格，不硬分五格（Alex：“如果只有是否就不用硬分，可以 binary”）。
- 依赖只连输入（Alex：“我觉得这个应该是 thesis 的定义问题”）：B 的答案要用到 A 的答案才连；对方对已经发生的事做出的反应，是证据。看起来互相依赖的两个问题，是问题没起好，要改写。
- 先用通用大模型做对上，让系统跑起来；每次都记下来，人标一部分，以后训练一个更快的小模型接手（Alex：“let's do a general LLM at this point because we need to make it work first … a logging system … human label … train a small model classifier that's faster”）。Alex 说的 RLHF，这里落成人工标注加监督训练，用不到强化学习。

## 结构

<!-- generated: structure -->
```
观点库
├─ 对象 → 名单里的公司、加密货币、商品、主题
│   └─ 观点 → 一个问题 + 一把梯子 + 一个到期日（写下不改；梯子五格，只有是或否的问题两格；对象观点的身份是“对象 + 看的是什么”，主题观点的身份只看“看的是什么”）
│       ├─ 两个位置 → 现在在哪一格、状态（前者是事实，后者是我们的判断）
│       ├─ 连线 → 证据（证据只存一次，带出处和层；往哪边推记在连线上；被替代的证据留在历史里，不再算数）
│       ├─ 依赖 → 别的观点（它的答案要用到对方的答案；箭头带一个方向：对方的哪一头对它是看多）
│       └─ 接续 → 上一期的观点（同一样东西一期接一期，连成一条链）
└─ 只追加的记录 → 对上记录、重判记录、关掉记录、标注（每一步都新加一条，不改不删；想知道某天当时怎么判，就翻那天以前的记录）
```

## 两种观点

<!-- generated: kinds -->
| 种类 | 挂在哪 | 梯子的格 | 例子 |
|---|---|---|---|
| 对象观点 | 能交易的对象：公司、加密货币、商品 | 五格：强烈看多、看多、中性、看空、强烈看空；只有是或否的问题两格：看多、看空。说的是对业务好还是坏，建的时候定，以后不变 | NVDA FY27 全年中国区收入，比 FY26 会怎样？ |
| 主题观点 | 主题：宏观、政策、行业 | 一条轴上的几种结果（五格；只有是或否的问题两格），用结果命名，不说好坏；好坏由依赖它的对象观点各自的箭头说 | 美联储 2026 年最后一次议息后的目标利率上限，比现在会怎样？（大幅降息……大幅加息） |

同一件世界上的事，对不同的对象可能好坏相反：降息对以太坊是看多，对 JPM 的净利息收入是看空。所以主题观点不说好坏。对股价的看法，是我们的状态和共识（市场押在哪一格）差多少；共识怎么记还没定。

## 梯子

<!-- generated: ladder -->
```
两种梯子（区间示意）
├─ 数字的梯子 → NVDA FY27 全年中国区收入，比 FY26｜代码拿公布的数比区间（一段时间的数；到期 = FY27 年报的财报日；判卷看年报里按地区分的收入（NVDA 只公布中国区含香港的总数））
│   ├─ 强烈看多 → 涨 50% 及以上
│   ├─ 看多 → 涨 10% 及以上，不到 50%
│   ├─ 中性 → 涨不到 10%，或降不到 10%
│   ├─ 看空 → 降 10% 及以上，不到 80%
│   └─ 强烈看空 → 降 80% 及以上（基本归零）
└─ 事件的梯子 → 2025-04 那条规定管的这一档芯片（H20、MI308 等）对华出口许可，到 2026-04-15 处在哪一格｜模型只看“发生的事”判，写明依据（以那天已经生效的规定为准）
    ├─ 第 1 格 → 全面禁止，不再受理许可
    ├─ 第 2 格 → 要许可，实际不发（2025-04 现在在这一格）
    ├─ 第 3 格 → 要许可，发的时候附条件（2025-08 现在在这一格（据报道发许可，上缴 15% 的中国收入））
    ├─ 第 4 格 → 要许可，发的时候不附条件
    └─ 第 5 格 → 不再要许可
```

1. 每把梯子五格：对象观点是强烈看多到强烈看空，主题观点是一条轴上的五种结果，用结果命名。只有是或否的问题用两格，不硬分五格：对象观点的两格是看多、看空；主题观点的两格用结果命名，比如“到期前签署了”“没签署”。
2. 每一格是一个看得见的、是或否的条件；各格不重叠，盖住所有可能，到期时正好一格成立。没有“部分”：部分做到的单独写成一格。分得出程度的事按程度分五格，比如“12 月 FOMC 会怎样”：降 50 个基点以上、降 25 个基点、不动、加 25 个基点、加 50 个基点以上。
3. 一把梯子只放一种东西。数字的梯子是同一个数在写明那一年的几段区间，由代码判；事件的梯子是同一件事到期那天可能处在的几种状态，写清是哪个阶段（宣布、签署、生效、执行），由模型只看“发生的事”判，写明依据。
4. 一个观点只看一件东西。既要数字又要事件的，拆成两条，用依赖连起来（NVDA 中国区收入依赖出口许可）；两部分可能往相反方向走的（H20 这一档和 Blackwell 这一档），拆成两条，有真实的依赖才连箭头。
5. 梯子由模型在建观点时定，定了到期以前不改；后来合并进来的候选观点带的梯子一律不要。中性跟什么比，写在那一格的条件里，比如“比去年同期变动在 10% 以内”。
6. 数字的观点写明三件事：哪一年（公司按财年，其他按自然年）；是一段时间的数（收入）还是时点的数（政策利率）；判卷来源（公司写财报里的哪一项，宏观写哪个官方数据序列）。到期日就是这个数公布的那天。“今年”“明年”按已经处理过的信息里最晚的发布日算（只往前走，不看电脑时钟）；期末已过的年份不再新开观点。
7. 到期日定在这个争论见分晓的那天，一般 6–12 个月；中间的季报是证据，不另开观点。

## 一把梯子上的两个位置

<!-- generated: positions -->
| 位置 | 是什么 | 谁能动它 | 例子 |
|---|---|---|---|
| 现在在哪一格 | 事实：现在落在哪一格；到期那天就是答案 | 只有“发生的事”能动它。事件的观点由模型判；时点的数由代码按最近公布的值定，记下是哪天的值；一段时间的数在答案公布前没有这个位置 | 2025-08：要许可，发的时候附条件 |
| 状态 | 判断：我们认为到期会落在哪一格 | 四层证据都能推它。每次由模型从这条观点下没被替代的全部证据（每条带上它替掉的那条，看得到变化）、加上它依赖的观点的现状重新判，不在上一次的基础上加减；写明依据哪几条证据，代码核对它们确实连在这条观点上。这一轮只多了重复的证据、依赖也没变，就不重判。回放靠存下来的重判记录，不靠重新调用模型 | 看到 8-K 以后：强烈看空 |
<!-- /generated: positions -->

## 证据分四层

<!-- generated: tiers -->
| 哪一层 | 例子 | 能做什么 |
|---|---|---|
| 发生的事 | 官方动作、公布的数、已经完成的交易 | 能动“现在在哪一格”，也能推状态 |
| 当事人说的 | 公司指引、管理层表态、官员讲话 | 只能推状态 |
| 第三方看法 | 卖方、媒体分析、专家 | 只能推状态 |
| 传闻 | “知情人士称”、没有出处的消息 | 只能推状态 |

- 推多远由模型判，写明依据；层不给固定分数。
- 独立来源按原始来源数：二十家媒体转述同一条独家，是同一条证据的二十个出处，算一份。
- 层看是谁确认的：“知情人士称商务部开始发许可证”是传闻；商务部或公司确认以后，确认的那条是发生的事，替代那条传闻；传闻还是传闻，留在历史里。
- 证据只存一次，本身不带方向；往哪边推记在证据和每条观点之间的连线上，由每次重判写。同一句话可以连几条观点，各推各的。
<!-- /generated: tiers -->

## 依赖：箭头怎么读

<!-- generated: dependencies -->
```
B 依赖 A｜A 是哪一种观点？（箭头带一个方向：A 的哪一头对 B 是看多；两条主题观点之间是同向或反向）
├─ 数字的观点 → 钉住年份（例：JPM 2027 全年净利息收入 → 美联储 2027 年末利率）
│   ├─ A 开着 → 读 A 的现状
│   ├─ A 出了答案 → 读 A 的答案（答案本来就是 B 要的输入，不算断）
│   ├─ A 答不出 → 标“缺这个输入”（不能把没有答案当成中性）
│   └─ A 还没建 → 箭头先等着（A 建出来时自动连上，B 重判一次）
└─ 事件的观点 → 顺着接续往下走（例：NVDA FY27 全年中国区收入 → 这一档芯片对华出口许可）
    ├─ A 开着 → 读 A 的现状
    ├─ A 关了，有接续的 → 读接续的那条（记一笔，B 重判一次）
    └─ A 关了，没有接续 → 读 A 的答案，标“只是历史”（A 答不出的，标“缺这个输入”）
```

- 依赖只连输入：B 的答案要用到 A 的答案，才连 B → A。对方对已经发生的事做出的反应，是证据，不是依赖：OPEC+ 看着已经发生的油价定产量，每天的油价是“OPEC+ 配额”这条观点的证据；“原油年均价”这条观点要用到 OPEC+ 配额的答案，才依赖它。
- 主题观点不说好坏，好坏由每个依赖它的对象观点自己的箭头说：降息那头对以太坊是看多，对 JPM 是看空。
- 箭头只有一个方向。看起来要“先好后坏”，说明中间还有一条观点没写出来，要拆出来：钢铁关税抬高国内钢价是一条路，拖垮下游用钢需求是另一条路。
- 只传通知，不搬证据：A 的证据不复制到 B，B 重判时把 A 的现状当背景读。B 重判时，代码把同时连在 A 上的证据标出来：“这条已经算进 A 了”。
- 什么时候通知 B：A 的“现在在哪一格”或状态换了格；B 读的那条换了（顺着接续换到下一条、等着的箭头连上了）；A 答不出。没换格就不通知。B 每次读的是哪一条、哪一版，记在 B 的重判记录里。
- 不能绕成环。两个问题互为输入（同一时期一起决定），说明问题没起好：合成一个问题，或者只留对投资判断有用的那个方向，另一个方向的影响走证据。代码不收会绕成环的箭头，退回给模型改写，留记录；加箭头、顺着接续换下一条时都查。
- 建一条新观点时，模型挑它依赖哪几条：开着的主题观点（用检索找几条来挑），或别的对象的观点（比如供应链）；数字的依赖也可以指向还没建的那一年，写明哪个对象、看的是什么、哪一年，箭头先等着。每条写方向和一句怎么影响；代码核对被依赖的观点确实存在，或者写明了要等的那一年。接续的新一期，照上一期的依赖挪一年，由模型确认。
- 真正新的一条主题观点（不接续谁）建出来时，把全部开着的观点分批过一遍，由模型挑出该依赖它的，补上箭头，这些观点各重判一次。新主题很少，全过一遍花得起；只取检索的前几名会漏掉排在后面的。
<!-- /generated: dependencies -->

## 接续：同一样东西一期接一期

<!-- generated: chain -->
- 同一样东西的下一条观点接着上一条，连成一条链：美联储 2026 年末利率 → 2027 年末利率 → 2028 年末利率。链存的是血缘，箭头怎么读见上面。
- 一条最多被接续一次，不能分叉。一条写坏了要拆成两条时不算接续；依赖它的箭头收到通知，重判时重新挑。
- 接续的那条，梯子的方向和上一条一样（第一格永远是同一头），门槛可以重定。所以箭头只按“哪一头”读，不按“第几格”。
- 接错了，追加一条“撤销接续”，不改原来的记录。
- 接续、并入、依赖是三种关系，分开记：接续是下一期，并入是重复，依赖是箭头。
<!-- /generated: chain -->

## 进库：候选观点和证据各走一条线，走法一样

<!-- generated: shape -->
|  | 候选观点 | 证据 |
|---|---|---|
| 去哪比 | 这个对象开着的观点（主题观点用检索找几条） | 它那条观点下已有的证据 |
| 判什么 | 挂到已有的、接续、新观点、不开、拿不准 | 重复、替代、新证据 |
| 链 | 接续：美联储 2026 年末利率 → 2027 → 2028 | 替代：AMZN 资本开支指引涨 12% → 25% |
| 什么算现在 | 链上开着的那条 | 没被替代的那些 |
| 搜全库吗 | 公司不搜；主题只在主题观点里检索 | 不搜 |
<!-- /generated: shape -->

## 一条信息进来，怎么写进库

一条信息走一轮，按顺序号一条一条来。模型只做第 4、7、8 步，其余是代码。

<!-- generated: intake -->
```
抽取交来的证据和候选观点（一条信息一轮）
  ↓ 1 核对出处（代码）：出处在处理记录里查不到的不要，记下原因
  ↓ 2 收证据（代码）：重试不重复存；上游修正版只换它自己那一处出处：它只是转载的，不动原来那条证据；它本身是原始来源的，新版的句子照常对上，改了的就替代原句
  ↓ 3 拉清单（代码）：候选观点讲的每个对象开着的观点，加上每条链最近关掉的那条；讲的是主题时，再从全部开着的主题观点里检索补 5 条；超出今年、明年的数字候选观点先筛掉；清单是空的，也照样交给第 4 步，只判新观点还是不开
  ↓ 4 对上（模型）：一次调用，不读原文：每个候选观点挂到哪一条、接续哪一条、新观点、不开，还是拿不准，写理由；每条证据和它那条观点下没被替代的证据比，是重复、替代还是新证据
  ↓ 5 核对（代码）：编号必须在清单里，或者是那条观点下的证据；接续合规矩
  ↓ 6 写进库（代码）：各对象自己的队列写，先写主题，再写对象；重复只多一个出处；替代按说的时间排（这句话是哪天说的），后说的算数，先说的标“被替代”，晚到的旧说法直接进历史；被替代的证据还连着别的观点，新的那条也连过去；原始来源自己的修正版里找不到、也没被新句替代的原句，算删了，标“被替代”；对上那一刻看到的变了，这部分重新对上
  ↓ 7 连依赖（模型）：新观点挑它依赖哪几条；新的主题观点反过来补箭头；代码查环
  ↓ 8 重判一轮（模型）：这一轮有新证据或替代、或者依赖变了的观点，按依赖先后各判一次；只多了重复的不判；换了格的再往下通知
```

## 第 4 步对上：候选观点的去向

<!-- generated: outcomes -->
| 去向 | 什么时候 | 写什么 |
|---|---|---|
| 挂到已有的 | 候选观点看的就是那条观点看的东西，或者是它的一部分：“H20 在中国的收入”是“中国区收入”的一部分 | 只挂证据，证据再和那条观点下的证据比；候选观点的问题、梯子、到期日都不要，用已有的 |
| 接续 | 同一样东西的下一年（数字）；或者那条已经关了，要接着看（事件） | 建新观点，记接续；依赖照上一期挪一年 |
| 新观点 | 另一样东西，会和已有的各走各的：Blackwell 这一档对华许可，不是 H20 这一档 | 建新观点，梯子和到期日从此定死 |
| 不开 | 候选观点太宽，捆了几样东西，比如“美国对华芯片管制” | 不建；只挂在它上面的证据不存 |
| 拿不准 | 说不清 | 还没定：先建新的、由查重来并，还是先并进最像的那条 |

- 对上问的是“挂到哪”，不只是“是不是同一条”：只要属于已有的争论，就挂过去；只有确实是另一样东西，才开新观点。分析师不会为“H20 在中国的收入”单开一个争论，它是“中国区收入”这个争论的证据。
- 拉清单靠对象：公司观点把这家公司开着的观点全拿出来就行，不用搜，也不会漏。主题观点的身份只看“看的是什么”，主题只是放它的地方，所以要跨全部主题比；主题标得模糊、条数多，这里和定期查重才用检索。相似度只用来拉清单，当不了裁判：“H20 对华许可”和“Blackwell 对华许可”很像，却是两条；看多和看空的两种说法，是同一条。
- 主题观点的范围按管它的那条规定或那个决定来写：写成“2025-04 那条规定管的这一档芯片（H20、MI308 等）”，AMD 的 MI308 就会挂上去，不会另开一条。
- 抽取只交挂在观点上的证据；候选观点不开、证据又没挂在别的观点上的，不存，只在处理记录里留一笔。
<!-- /generated: outcomes -->

## 第 4 步对上：证据的去向

<!-- generated: evidence-outcomes -->
| 去向 | 什么时候 | 写什么 |
|---|---|---|
| 重复 | 说的就是那条观点下已有的一条：转载；正文和表格里的同一个数；同一个人把同样的话再说一遍 | 那一条多记一个出处；证据不多一条，不重判 |
| 替代 | 和已有的一条是同一件事的前后两个说法：同一个人后来改了说法或数（指引、预测、状态）；官方证实或否认了一条传闻；原始来源自己出了修正版，改了原句 | 按说的时间排（这句话是哪天说的），后说的算数，先说的标“被替代”，留在历史里；晚到的旧说法直接进历史；重判 |
| 新证据 | 别的都是：新的事、另一期的数、另一个人的说法（说法相反的也是）；拿不准也算新证据 | 加进来，和别的一起算数；重判 |

- 证据只和它那条观点下的证据比，不拿证据去搜全库：观点先定好（抽取时挂上的，或者候选观点对上的那条），再看这条观点自己已经有什么。和观点一个形状：候选观点比的是这个对象开着的观点，证据比的是这条观点下的证据。
- 一条证据挂几条观点，也只存一条：和这几条观点下的证据一起比一次。
- 被替代的证据还连着别的观点，新的那条也连过去，那些观点也重判；不然那条观点手里只剩一个过时的说法。
- 证据是一句话或一个数，替掉的只是那一句：卖方新报告改了收入预测，替掉的是它上一份里的那个预测，别的论据照样算数。
- 对上不读原文，比的是证据里“一句话说清”的那句；拿不准算新证据，最坏也就是两条都算数，由重判自己看。

## 合并有三种，发生在不同的时候

<!-- generated: merges -->
| 合并 | 什么时候 | 做什么 |
|---|---|---|
| 挂到已有的 | 每条信息对上时 | 只加证据和连线 |
| 接续 | 对上时，同一样东西的下一期 | 建新观点，记接续 |
| 并入 | 定期查重：Pull 模式每天发起一次；同一对象开着的观点两两比，主题观点跨全部主题用检索找相像的 | 后建的那条关掉，记“并入 X”；它的连线加到 X 上；指向它的箭头顺着“并入”读到 X，方向按 X 的梯子重新核对，代码查环；X 重判一次 |

## 对上标注：先用大模型跑起来，攒下标注，以后交给小模型

第 4 步的裁判，第一版是通用大模型。它的每一次判断都留下来，挑一部分由人标出正确的去向（候选观点去哪、证据是重复、替代还是新证据）；人标的结果先用来量准不准，攒够了再训练一个小的匹配模型。小模型只在它有把握、而且考试成绩过了线的地方接手，其余照旧交给大模型。

### 标注的规矩

<!-- generated: labels -->
- 标注不挡流程：系统照常跑，标注是事后做的。
- 人标的选项和模型的一样：候选观点是挂到哪一条、接续哪一条、新观点、不开；证据是重复、替代、新证据；都另加“说不清”；写一句理由。
- 标准由 Alex 定：先标一批，大家对齐“同一样东西”“一部分”和“替代”的边界，再往下标。
- 用来考试的那一份，标的人看不到模型的答案；考试集固定，只在换裁判（换模型、换提示词、换上小模型）时评一次；平时调提示词只用另一份。
- 标注不直接改库：人标出来的重复观点，交给查重并入；证据的标注和其余的先记着。
- 这里用的是人工标注加监督训练：训练一个分“是不是同一样东西”的小模型，用不到强化学习。
- 同样的请求和返回也给连依赖、重判和查重记着（重判记录里本来就有）；第一版只标对上。

## 一条观点怎么结束

<!-- generated: lifecycle -->
```
一条观点｜到哪一步了？
├─ 开着 → 没被替代的证据变了、或者依赖变了，就重判一次（名额：事件同一件事一条；数字同一个数今年、明年两条）
├─ 期末已过，答案没出 → 等答案（数字的观点；不占今年、明年的名额）
└─ 关掉 → 三种方式｜为什么关？
    ├─ 出答案 → 记答案和出处（按梯子写明的判卷来源，用第一次公布的值；拿答案对的，是带来答案的那条信息进来之前最后的状态）
    ├─ 答不出 → 记原因，不算准不准（不再披露这个数、事情本身没了；对象退出名单也先这样关，算不算成绩还没定；下载或解析失败是故障，要重试，不算答不出）
    └─ 并入 → 记“并入 X”（查重发现重复）
```

- 到期由 Pull 模式发起，等发布日不晚于到期日的信息都处理完再定答案。事件观点的答案由谁来定、要不要先经最终判定，等最终判定按新设计重做时定。
- 答案出来以后，后来的修订记下来，但不改这条观点的答案。要接着看，就开一条新观点接续它。

## 一条证据记什么

<!-- generated: evidence -->
| 部分 | 写什么 |
|---|---|
| 原文 | 信息里的那一句，或表里的那一格 |
| 一句话说清 | 离开原文也看得懂的一句：谁、做了什么、多少、哪一期；对上和重判读这一句 |
| 出处 | 上游编号和版本、类别、发布日、在信息里的位置；重复的（转载、同一条信息的正文和表格、同一个人再说一遍）记成这条证据的又一个出处 |
| 谁说的 | 说这句话的人或机构 |
| 原始来源 | 转述的，指向最初说这句话的人和那一次（哪天）；按它数独立来源，替代也按这一天排先后 |
| 哪一层 | 发生的事、当事人说的、第三方看法、传闻 |
| 事情发生的时间 | 事情什么时候发生或生效；数字写它属于哪一期 |
| 被替代 | 指向替代它的那一条：同一个人后来改了说法或数、官方证实或否认了这条传闻；或者原始来源自己出了修正版，把这句改了、删了（删了的没有后继）；被替代的不再算数，留在历史里 |
<!-- /generated: evidence -->

## 先后、同步和血缘

<!-- generated: order -->
- 只有信息能产生证据；观点之间只传通知，不传证据，所以观点不会自己证明自己。
- 每条观点只有一个写入者：主题观点由主题的队列写，对象观点由对象的队列写；同一条信息先写主题，再写对象。
- 先后按顺序号排，不用电脑时钟。一条信息只读顺序号比它小的信息留下的状态，加上这一轮里它自己已经写下的（比如上游这一轮刚判完的状态）；并行时读到的东西在提交前变了，就重新做一次。
- 一条信息引起的变化算一轮：先做完挂证据、建观点、接续和补箭头，再按依赖先后重判，上游这一轮判完，下游才判，每条观点每轮只提交一次；上游没换格，这条路就停。
- 只追加：观点的问题、梯子和到期日写下就不动；对上、重判、接续、关掉、并入、标注都是新加的记录，带顺序号。
- 晚到的信息：收到时重判，不倒回去改过去的状态；证据记它真实的发布日；晚到的旧说法（和现在算数的某一条是同一件事的前后两个说法，又说得早）直接进历史。
- 同一条信息的修正版只换它自己那一处出处：它只是转载的，不动原来那条证据；它本身是原始来源的，改了的原句由新句替代，删了的标“被替代”。连着变了的证据的观点各重判一次；过去的重判记录不改。
- 失败：每条信息记下做到哪一步，从失败的那一步重试，重试只替换自己上次的结果；多次失败的放进人工复核池。
- 对象被移出名单：它开着的观点关掉，记“答不出（不再跟踪）”；算不算成绩还没定。
- 两头都能查：从一条观点查到推过它的全部信息；从一条信息查到它建过的观点，和它作为出处的全部证据（重复的也查得到）。

存在哪：一个关系数据库就够，记录都是只追加的表；全文检索和向量检索建在同一个库里，是随时能重建的索引，不是原始记录；依赖的箭头用表和递归查询，不需要单独的向量库或图数据库。具体用哪个产品，建的时候定。规模（估算）：约 1,400 条开着的观点，一年约 180 万条证据。
<!-- /generated: order -->

| 抽取 | 拿：证据（挂在已有观点或候选观点上）和候选观点，都带出处。给：提示词第 5 块的已有观点，也就是相关对象开着的观点，加上它们依赖的观点；只给问题和看的是什么，不给状态和证据 |
| Config | 拿：对上、连依赖、重判、查重各一套模型设置；每次调用都记下用的是哪个版本 |
| Pull 模式 | 拿：到期（等发布日不晚于到期日的信息都处理完）和每天的查重 |
| 最终判定 | 给：到期的观点。事件观点的答案由谁定，最终判定按新设计重做时定 |
| 人工复核池 | 给：候选观点讲的是世界上的事、名单里却没有这个主题时，建议新增的主题；多次处理失败的信息。名单外的公司（比如三星）不进，只在处理记录里留一笔 |
| 对上标注 | 给：每次对上的记录（候选观点和证据）。拿：人标的结果，以后还有小模型 |

## 验收标准

- 每条观点都有问题、梯子和到期日，建好以后这三样不再变；梯子五格（只有是或否的问题两格），各是一个是或否的条件，数字的区间首尾相接、不重叠（代码查）。
- 数字的观点写明哪一年、一段时间的数还是时点的数、判卷来源；同一个对象的同一个数，开着的不超过今年、明年两条；事件的同一件事，开着的只有一条。
- 每次对上都留一条对上记录：给模型看了什么、按什么顺序、原始返回、Config 版本、谁定的；模型给的编号不在清单里、也不是那条观点下的证据的，代码不收，记下原因。
- 每条证据的对上写明是重复、替代还是新证据；重复只多一个出处，不重判；替代的旧证据标“被替代”，不删。
- 一条证据挂几条观点也只存一条；被替代的证据还连着别的观点的，新的那条也连过去。
- 只有这一轮有新证据或替代、或者依赖变了的观点才重判；每次重判写明依据哪几条证据，代码核对这些证据确实连在这条观点上、没被替代；只有“发生的事”能动现在在哪一格。
- 依赖不绕成环；B 每次读的是 A 的哪一条、哪一版，写在 B 的重判记录里；数字的箭头钉住年份，事件的箭头顺着接续走。
- 一条信息引起的一轮里，每条观点最多提交一次重判，上游判完才判下游。
- 记录只追加：任何一条观点、证据、连线、对上记录都查得到来历；从一条信息查得到它建过的观点，和它作为出处的全部证据。
- 晚到的信息不改过去的状态；修正版只换它自己那一处出处：转载的修正版不动原来那条证据，原始来源自己的修正版，改了的原句由新句替代，删了的标“被替代”。
- 标注不挡流程；考试集的标注，标的人看不到模型的答案。
