## 一句话

抽取只做一件事：每条信息整份交给模型，用资深对冲基金分析师的视角、按这一类的提示词读完，交出两样东西：证据，挂到这些对象已有的观点上（或这次的候选观点上）；候选观点（thesis），已有观点管不到、又要紧的事。每条带出处，交给观点库。

## 为什么这样设计

- 系统做的事是建立、更新和关掉观点库里的观点（D26），抽取就是把每条信息读成证据和候选观点。怎么和库里已有的比、写进库，是观点库的事，不在这里。
- 推进来的每条信息都整份交给模型读：文件连同里面的表格一起读，表格数据一次发布整批读，不按文字、表格分开处理。
- 不同类别该读的东西不同：新闻读发生了什么、消息从哪来；研报读作者的看法和评级；政府决定读决定本身和生效时间。所以每个类别一份提示词，都用同一个提示词模板拼出来。
- 观点库里的观点是模型（分析师）的判断：一个问题、一把梯子和一个到期日（D38）；谁在哪条信息里说了什么，是客观的证据。多数信息只带来已有观点的证据，少数才提出一条新的候选观点。
- 证据要挂在观点上才算证据：一句话算不算证据，只能对着一个问题来判断（Alex：“evidence 怎么在抽取的时候不挂钩 thesis？这怎么可能。”）。所以提示词第 5 块给模型这些对象已有的观点，读的时候就把证据挂上去。已有的观点里也放上它们依赖的观点，因为一条公司的信息常常带着主题上的事：NVDA 的声明说美国保证会批许可证，这句话该挂到“出口许可”那条主题观点上。
- 已有观点管不到的要紧事（正文点名的另一家公司、这个对象一个新的关键问题、世界上一件要紧的事），写成候选观点，带上提出它的证据；是已有的哪一条还是新观点，由观点库对上时定。
- 每条观点和证据都带出处，以后能快速回到原文去查、去推理。

## 一条信息，一步一步

模型只做第 2 步，其余是代码。

<!-- generated: steps -->
```
一条信息进来（带类别和顺序号）
  ↓ 1 拼提示词（代码）：按这条信息的类别，用同一个提示词模板拼出这一类的提示词；第 5 块由观点库给：相关对象开着的观点，加上它们依赖的观点
  ↓ 2 读（模型）：整份读完，交出两样：证据，挂到第 5 块里的观点上，或挂到这次的候选观点上；候选观点，第 5 块里没有一条观点管、又要紧的事，带上提出它的证据。每条带出处
  ↓ 3 核对出处（代码）：原文那一句在不在这条信息里、数字在不在那一句或那一格里；证据挂的必须是第 5 块里的观点或这次的候选观点；对不上的不要，记下原因
  ↓ 4 交给观点库（代码）：带着顺序号，交给观点库去对上、写进去
```
<!-- /generated: steps -->

## 读出两样东西：证据和候选观点

一遍读完，交出两样东西，各走各的路：证据几乎每条信息都有，挂到已有观点上；候选观点很少，只给已有观点管不到的要紧事。到了观点库，候选观点和搜出来的几条已有观点比，证据和它那条观点下已有的证据比，见 06-views.md。

<!-- generated: two -->
|  | 证据 | 候选观点（thesis） |
|---|---|---|
| 是什么 | 信息里的一句话或一个数：谁说了什么、发生了什么 | 一件要盯的事（thesis） |
| 多不多 | 几乎每条信息都有 | 少：第 5 块里没有一条观点管、又要紧的事 |
| 挂在哪 | 第 5 块里的观点（可以挂几条），或者这次的候选观点 | 带着提出它的证据 |
| 到了观点库 | 和它那条观点下已有的证据比：重复、替代还是新证据 | 和搜出来的几条已有观点比：是哪一条、接续，还是新观点 |
| 例子 | 8-K 里的“H20 出口中国要许可证” | 这一档芯片（H20、MI308 等）的对华出口许可 |

```
读到一句话或一个数｜它和哪条观点有关？
├─ 第 5 块里的观点 → 证据：挂到那条观点上
├─ 第 5 块里没有，但要紧 → 候选观点：这句话是它的证据（是已有的哪一条，还是新观点，由观点库对上时定）
└─ 都没关系 → 不抽（背景、套话）
```

## 提示词模板

所有类别用同一个提示词模板，由这五块拼成这一类的提示词；这一类的读法取自分类规则，不另写。

<!-- generated: template -->
| 部分 | 写什么 | 从哪来 |
|---|---|---|
| 角色 | 你是一位资深对冲基金分析师。读这条信息，是为了检验和形成观点：把支持或削弱已有观点的话和数挑出来，作为证据挂到那条观点上；已有观点管不到、又要紧的事，写成候选观点，带上提出它的证据。观点照观点库的写法：一个观点只看一件东西；数字写明哪一年。 | 所有类别一样 |
| 这一类是什么、怎么读 | 这一类的定义和读法，比如“看法和估计算作者说的，不当成已经发生的事”。 | 取自分类规则，这里不另写 |
| 讲的是谁 | 这条信息的相关对象。 | 这条信息的标签 |
| 这一类要读出什么 | 见下面的表，每类一行。 | 抽取模块 |
| 这些对象已有的观点 | 这条信息相关对象开着的观点，加上它们依赖的观点；只给问题和看的是什么，不给状态和证据：让模型把证据挂到这些观点上，又不被已有的判断带着走。 | 观点库 |

## 每一类有自己的提示词

下面是拼好的一份，以 T7 新闻为例。

<!-- generated: prompt -->
```
T7 新闻的提示词（同一个提示词模板，第 2、4 块换成新闻这一类的）
├─ 1 角色 → 资深对冲基金分析师（读这条信息，是为了检验和形成观点：证据挂到已有观点上；已有观点管不到的要紧事，写成候选观点）
├─ 2 这一类怎么读 → 媒体的报道（取自分类规则：媒体发的内容，除了评论和分析（那归 T8）；媒体登记过的发布系列按系列归类）
├─ 3 讲的是谁 → 这篇报道的相关对象（由代码填，比如 NVDA、AMD）
├─ 4 要读出什么 → 发生了什么事、什么时候、涉及谁；消息从哪来，原始来源是谁（官方确认的算发生的事；“知情人士称”算传闻）
└─ 5 已有的观点 → 这篇报道相关对象开着的观点，加上它们依赖的观点（由代码填，只给问题和看的是什么；比如“NVDA FY27 全年中国区收入，比 FY26 会怎样？”，和它依赖的“这一档芯片对华出口许可”）
```

- 每一类都有自己的提示词：同一个提示词模板，第 2 块（这一类怎么读）和第 4 块（要读出什么）换成这一类的；第 1 块所有类别一样；第 3、5 块由代码按这条信息填进去。
- 研究对象会看的 15 类（T1–T15）各一份；T16 研究对象默认不看，用到时再写。
- 输出的格式（证据、候选观点、出处各有哪些格子）由代码规定和检查，不写进提示词。
- 每一类提示词的具体写法，建的时候在存下的信息上试过再定；每一版记在 Config 里，改一次就是一个新版本。

## 16 个类别：每一类读出什么（提示词第 4 块）

<!-- generated: categories -->
| 类别 | 这一类要读出什么 | 证据一般在哪一层 |
|---|---|---|
| T1 业绩发布 | 实际数、指引、管理层的解释；判卷要用的数 | 实际数是发生的事；指引和解释是当事人说的 |
| T2 定期报告 | 实际数、分部数；风险因素和业务描述里讲到的风险和变化 | 数是发生的事；风险和变化是当事人说的 |
| T3 法律与资本市场文件 | 交易条款（价格、对价、交割条件、时间表）；各方的说法和诉求 | 条款是发生的事；说法是当事人说的 |
| T4 电话会文字稿 | 管理层对关键问题的回答、口径的变化；分析师追问的焦点 | 回答是当事人说的；追问是第三方看法 |
| T5 演示材料 | 管理层给的中长期目标、资本配置的框架、新业务的规模 | 当事人说的 |
| T6 公司其他发布 | 发生了什么事（高管变动、并购、新产品、回购）；公布的经营数字（比如交付量） | 发生的事 |
| T7 新闻 | 发生了什么事、什么时候、涉及谁；消息从哪来，原始来源是谁 | 官方确认的算发生的事；“知情人士称”算传闻 |
| T8 观点与分析 | 作者的看法、论据、预测、评级和目标价，以及它们的变化（用来算共识） | 第三方看法 |
| T9 访谈记录 | 说话人讲的经营情况（订单、价格、份额、库存）；他凭什么知道 | 第三方看法 |
| T10 官方行动与记录 | 决定或行动本身、什么时候生效、影响谁；后面的程序（上诉、截止日），可以用作到期日 | 发生的事 |
| T11 宏观政策与统计 | 公布的数字和政策决定，和上一次比差多少；官方措辞的变化 | 数和决定是发生的事；措辞是当事人说的 |
| T12 市场价格与成交 | 价格和成交的变化 | 发生的事 |
| T13 持仓与资金流 | 谁在买、谁在卖、规模多大 | 发生的事 |
| T14 日历 | 排定的日期，用作到期日或催化剂 | 发生的事 |
| T15 第三方测量 | 测到的经营数据，作为量化证据 | 发生的事（注明是第三方测的） |
| T16 参照数据 | 研究对象默认不看 | — |

每份文件都整份交给模型，里面的表格一起读；表格数据一次发布算一条，也整批交给模型。申报里的 XBRL 数字不另外推，文件本身已经有这些数；判卷要准确的数时，由 Pull 模式去查。

## 例子：两条信息读出什么

<!-- generated: example -->
```
两条信息读出什么（示意；候选观点写到多全还没定，这里只写看的是什么）
├─ 2025-04-15 NVDA 的 8-K → 库是空的，第 5 块里没有观点｜读出两条候选观点（T6 公司其他发布：H20 出口中国要许可证，预计最多约 55 亿美元的费用）
│   ├─ 候选观点（主题观点） → 这一档芯片（H20、MI308 等）的对华出口许可（事件；证据：原文“…requires a license for export to China … of the Company’s H20 integrated circuits…”（发生的事，NVDA 披露：H20 出口中国要许可证）；到了观点库，开成 #1）
│   └─ 候选观点（对象观点 NVDA） → NVDA FY26 全年中国区收入（数字；证据：原文“…charges of up to approximately $5.5 billion…”（当事人说的：公司预计最多约 55 亿美元的费用）；到了观点库，开成 #2，依赖 #1）
└─ 2025-07-14 NVDA 的声明 → 第 5 块：#2 和它依赖的 #1｜读出一条证据，没有候选观点
    └─ 证据 → 挂到 #1（当事人说的；一句话说清：NVDA 称美国政府已保证会批准 H20 对华出口的许可（2025-07-14））
```

出处：每条证据都记上游编号和版本、所在段落和原文那一句（英文原句，中文只是说明）；代码核对“$5.5 billion”确实在那一句里。第一条信息进来时库是空的，第 5 块里没有观点，读到的要紧事只能写成候选观点；第二条信息进来时，第 5 块里已经有出口许可那条，NVDA 的声明就直接挂上去。到了观点库，候选观点去和搜出来的已有观点比，证据去和它那条观点下已有的证据比，见观点库。例子用 NVDA，美股、期货、加密货币都走同一套。

## 出处记什么

<!-- generated: sources -->
```
一条出处
├─ 哪条信息 → 上游编号和版本（凭它去团队的库里取原文）
├─ 哪一类、哪天 → 类别、发布日
├─ 哪一处 → 第几节第几段、表里哪一格（表格数据写数据集和记录编号）
└─ 哪一句 → 原文那一句（代码核对它真的在这条信息里，数字真的印在那一句或那一格里）
```

- 每条观点、每条证据、每一次变化都带出处；状态的每次变化写明依据哪几条证据。
- 抽取核对：原文那一句不在这条信息里、数字不在那一句或那一格里的，证据挂的不是第 5 块里的观点或这次候选观点的，不交出去；观点库核对：出处在处理记录里查不到的，不写进库。都记下原因。
- 两头都能查：从一条观点查到它的全部来源信息，从一条信息查到它产生和改动过的全部观点和证据。
- 原文不存，凭上游编号去团队的库里取。
- 同一条信息里说同一件事的几处（正文和表格里的同一个数），交成一条证据，带几个出处。
<!-- /generated: sources -->

## 验收标准

- 每条交进来的信息都整份交给模型，用这一类的提示词；用的是哪版设置，记在处理记录里。
- 每条证据都挂在给它看的已有观点或这次的候选观点上；挂在别处的、哪都没挂的，不交给观点库，记下原因。
- 同一条信息里说同一件事的几处（正文和表格里的同一个数），交成一条证据，带几个出处。
- 每条证据带原文、一句话说清、谁说的、原始来源、哪一层、事情发生的时间；每个候选观点带讲的是谁、对象观点还是主题观点、看的是什么，和至少一条证据；还写不写问题、梯子和到期日，见还没定的。
- 每条观点和证据都有出处。原文那一句不在这条信息里、数字不在那一句或那一格里的，不交给观点库，记下原因。
- 抽取不改观点库：它只交出证据和候选观点。
- 失败从失败的那一步重试；重试只替换自己上次的结果。

## 还没定的

<!-- generated: open -->
- 每一类提示词的具体写法，建的时候在存下的信息上试过再定；每一版记在 Config 里。
- 候选观点在抽取时写到多全：只写讲的是谁、看的是什么和提出它的证据（第 30 步的写法），还是把问题、梯子、到期日也一起写好（D41 的写法）。挂到已有观点上时，这些都用不上；开成新观点时，梯子和到期日总要有人写。
- 已有观点里放了依赖的主题观点以后，几家公司对宏观的看法会一起挂到主题观点上，可人多不等于信息多：主题观点要不要只收新的观察（发生的事、公司自己看到的订单和价格）。
- 抽取挂错、漏抽的证据，对上标注看不到：要不要另外按信息抽样，对着当时给的已有观点读原文核查。
