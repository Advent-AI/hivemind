## 一句话

系统的核心。一条观点是一个问题、一把梯子和一个到期日，写下不改；证据把我们的判断往两头推，到期拿答案对一下，就知道判得准不准。抽取交来两样东西，在这里各走一条线、走法一样：候选观点和搜出来的几条已有观点比，由模型判是哪一条、接续，还是开新的；证据和它那条观点下已有的证据比，是重复、替代还是新证据；只是重复的，不重判。

## 为什么这样设计

- Alex 给这个模块定的要求：“store the theses, the evidence, and the ladder in a very, very clear data structure manner that has linkages to whatever is passing through the data pipeline.” 观点、证据、梯子各有清楚的结构，每条证据都连回管道里的一条信息。
- 观点是一个问题加一个状态，不是一句断言（Alex：“这个 hypo 更像是一个 thesis with a state”）。反方向的说法不用另建一条观点，只是把状态往另一头推。
- 梯子事先写死，每一格是看得见的结果：什么事实会证明我们错了，建观点时就写在上面，事后挪不了球门。现实里的对照：卖方的牛、基准、熊三种情景，买方事先写下的止损条件，超级预测者要求每个问题有明确的判定标准。
- 状态是判断，由模型判，要尽量确定、只按事实（Alex：“这个基本要 deterministic 一点，模型的设置 temperature 要让他基本不会幻觉，只是基于事实来评价”）：每次从这条观点下没被替代的全部证据重新判，不在上一次的基础上加减；替代按这句话是哪天说的排先后，晚到和修正过的信息不会因为处理先后不同而读到不同的证据。
- 对象观点和主题观点分开（Alex：“有些事情不一定对所有人都是 bull / bear，有可能完全相反”）。主题观点只说世界会变成什么样，好坏由依赖它的对象观点自己说。
- 一条观点只有一层（Alex：“一条观点一定是有一个明确的 ladder 和到期日，这样才构成一个观点”）；到期日定在争论见分晓的那天，一般 6–12 个月，中间的季报是证据。
- 对上像人查东西：先搜出几条可能的，再判是不是同一条（Alex：“If I have a view, I go search it up. If something matches, then it's just the same view. If nothing matches, then essentially it's a new view, or it matches weekly, then it should be a new view”）。判的是模型，代码不替它判（Alex：“I just want LLM to do the matching”）。是同一条就并进去，日期用已有的（Alex：“已经存在的观点就 merge，日期遵照之前已经存在的期限”）。
- 证据和观点走一样的路（Alex 问过：“It's not clear to me how this logic is similar to thesis”）：先找到要比的，再和它比。候选观点比的是搜出来的几条已有观点，证据比的是它那条观点下已有的证据。不比的话，一条观点下的证据只增不减：2 月的“资本开支涨 12%”和 4 月的“改成 25%”并排放着，重判每次都得自己从一堆里分出哪条过时了，分完也不留下。
- 重复、替代在进库时判一次、记下来，就是让模型自己给证据做加和删（Alex：“这个难道 LLM 不能自己 append delete evidence 吗”）；被替代的只是不再算数，留在历史里，不删。只是重复的不重判，转载不用再调一次模型才知道什么都没变。
- 只有是或否的问题用两格，不硬分五格（Alex：“如果只有是否就不用硬分，可以 binary”）。
- 看起来互相依赖的两个问题，是观点没起好，要改问题，不加机制（Alex：“我觉得这个应该是 thesis 的定义问题”）。依赖到底怎么定义，Claude 提了一种，见后面“Claude 提的、Alex 还没定的”。
- 先用通用大模型做对上，让系统跑起来；每次都记下来，人标一部分，以后训练一个更快的小模型接手（Alex：“let's do a general LLM at this point because we need to make it work first … a logging system … human label … train a small model classifier that's faster”）。

## 结构

<!-- generated: structure -->
```
观点库
├─ 对象 → 名单里的公司、加密货币、商品、主题
│   └─ 观点 → 一个问题 + 一把梯子 + 一个到期日（写下不改；梯子五格，只有是或否的问题两格；同一个对象、看同一样东西，同一时间只开一条）
│       ├─ 状态 → 我们认为到期会落在哪一格（模型读这条观点下的证据判）
│       ├─ 连线 → 证据（证据只存一次，带出处和层；往哪边推记在连线上；被替代的证据留在历史里，不再算数）
│       ├─ 依赖 → 别的观点（箭头带一个方向：对方的哪一头对它是看多）
│       └─ 接续 → 上一期的观点（同一样东西一期接一期，连成一条链）
└─ 只追加的记录 → 对上记录、重判记录、关掉记录、标注（每一步都新加一条，不改不删；想知道某天当时怎么判，就翻那天以前的记录）
```

## 两种观点

<!-- generated: kinds -->
| 种类 | 挂在哪 | 梯子的格 | 例子 |
|---|---|---|---|
| 对象观点 | 能交易的对象：公司、加密货币、商品 | 五格：强烈看多、看多、中性、看空、强烈看空；只有是或否的问题两格：看多、看空。说的是对业务好还是坏，建的时候定，以后不变 | NVDA FY27 全年中国区收入，比 FY26 会怎样？ |
| 主题观点 | 主题：宏观、政策、行业 | 一条轴上的几种结果（五格；只有是或否的问题两格），用结果命名，不说好坏；好坏由依赖它的对象观点各自的箭头说 | 美联储 2026 年最后一次议息后的目标利率上限，比现在会怎样？（大幅降息……大幅加息） |

同一件世界上的事，对不同的对象可能好坏相反：降息对以太坊是看多，对 JPM 的净利息收入是看空。所以主题观点不说好坏。对股价的看法，是我们的状态和共识（市场押在哪一格）差多少；共识怎么记还没定。
<!-- /generated: kinds -->

## 梯子

<!-- generated: ladder -->
```
两种梯子（区间示意）
├─ 对象观点（数字） → NVDA FY27 全年中国区收入，比 FY26｜五格：对 NVDA 的业务是好是坏（到期 = FY27 年报的财报日）
│   ├─ 强烈看多 → 涨 50% 及以上
│   ├─ 看多 → 涨 10% 及以上，不到 50%
│   ├─ 中性 → 涨不到 10%，或降不到 10%
│   ├─ 看空 → 降 10% 及以上，不到 80%
│   └─ 强烈看空 → 降 80% 及以上（基本归零）
└─ 主题观点（事件） → 2025-04 那条规定管的这一档芯片（H20、MI308 等）对华出口许可，到 2026-04-15 处在哪一格｜五格：一条轴上的结果，不说好坏（以那天已经生效的规定为准）
    ├─ 第 1 格 → 全面禁止，不再受理许可
    ├─ 第 2 格 → 要许可，实际不发
    ├─ 第 3 格 → 要许可，发的时候附条件
    ├─ 第 4 格 → 要许可，发的时候不附条件
    └─ 第 5 格 → 不再要许可
```

1. 每把梯子五格：对象观点是强烈看多到强烈看空，说的是对业务好还是坏；主题观点是一条轴上的五种结果，用结果命名，不说好坏。只有是或否的问题用两格，不硬分五格：对象观点的两格是看多、看空；主题观点的两格用结果命名，比如“到期前签署了”“没签署”。
2. 每一格写成一个看得见的条件：可以是一个数落在哪段区间，也可以是一件事到了哪一步。分得出程度的事按程度分五格，比如“12 月 FOMC 会怎样”：降 50 个基点以上、降 25 个基点、不动、加 25 个基点、加 50 个基点以上。
3. 一个观点只看一件东西：两部分可能往相反方向走的（H20 这一档和 Blackwell 这一档），是两条观点。
4. 梯子由模型在建观点时定，定了到期以前不改；后来并进来的候选观点，梯子和到期日都用已有的。
5. 数字的观点写明哪一年（按财年）；同一个数，今年、明年最多各开一条；到期日就是这个数公布的那天。
6. 到期日定在这个争论见分晓的那天，一般 6–12 个月；中间的季报是证据，不另开观点。
<!-- /generated: ladder -->

## 状态

<!-- generated: positions -->
|  | 是什么 | 谁来判 | 例子 |
|---|---|---|---|
| 状态 | 判断：我们认为到期会落在哪一格 | 模型判，温度调低，只按事实。每次从这条观点下没被替代的全部证据（每条带上它替掉的那条，看得到变化）、加上它依赖的观点的现状重新判，不在上一次的基础上加减；写明依据哪几条证据。这一轮只多了重复的证据、依赖也没变，就不重判 | 看到 8-K 以后：强烈看空 |
<!-- /generated: positions -->

## 证据分四层

<!-- generated: tiers -->
| 哪一层 | 例子 | 能做什么 |
|---|---|---|
| 发生的事 | 官方动作、公布的数、已经完成的交易 | 能定哪一格成立，也能推状态 |
| 当事人说的 | 公司指引、管理层表态、官员讲话 | 只能推状态 |
| 第三方看法 | 卖方、媒体分析、专家 | 只能推状态 |
| 传闻 | “知情人士称”、没有出处的消息 | 只能推状态 |

- 推多远由模型判，写明依据；层不给固定分数。
- 独立来源按原始来源数：二十家媒体转述同一条独家，是同一条证据的二十个出处，算一份。
- 层看是谁确认的：“知情人士称商务部开始发许可证”是传闻；商务部或公司确认以后，确认的那条是发生的事，替代那条传闻；传闻还是传闻，留在历史里。
- 证据只存一次，本身不带方向；往哪边推记在证据和每条观点之间的连线上，由每次重判写。同一句话可以连几条观点，各推各的。
<!-- /generated: tiers -->

## 依赖：箭头怎么读

<!-- generated: dependencies -->
```
B 依赖 A｜A 是哪一种观点？（箭头带一个方向：A 的哪一头对 B 是看多；两条主题观点之间是同向或反向）
├─ 数字的观点 → 钉住年份（例：JPM 2027 全年净利息收入 → 美联储 2027 年末利率）
│   ├─ A 开着 → 读 A 的现状
│   ├─ A 出了答案 → 读 A 的答案（答案本来就是 B 要的输入，不算断）
│   └─ A 还没建 → 箭头先等着（A 建出来时连上，B 重判一次）
└─ 事件的观点 → 顺着接续往下走（例：NVDA FY27 全年中国区收入 → 这一档芯片对华出口许可）
    ├─ A 开着 → 读 A 的现状
    ├─ A 关了，有接续的 → 读接续的那条（记一笔）
    └─ A 关了，没有接续 → 读 A 的答案，标“只是历史”
```

- 主题观点不说好坏，好坏由每个依赖它的对象观点自己的箭头说：降息那头对以太坊是看多，对 JPM 是看空。
- 箭头只有一个方向。看起来要“先好后坏”，说明中间还有一条观点没写出来，要拆出来：钢铁关税抬高国内钢价是一条路，拖垮下游用钢需求是另一条路。
- 只传通知，不搬证据：A 的证据不复制到 B，B 重判时把 A 的现状当背景读。
- 什么时候通知 B：A 的状态换了格。没换格就不通知。
- 看起来互相依赖的两个问题，是观点没起好，要改问题，不加机制。
- 新观点依赖哪几条，由模型挑，写明方向。
<!-- /generated: dependencies -->

## 接续：同一样东西一期接一期

<!-- generated: chain -->
- 同一样东西的下一条观点接着上一条，连成一条链：美联储 2026 年末利率 → 2027 年末利率 → 2028 年末利率。链存的是血缘，箭头怎么读见上面。
<!-- /generated: chain -->

## 进库：候选观点和证据各走一条线，走法一样

<!-- generated: shape -->
|  | 候选观点 | 证据 |
|---|---|---|
| 去哪比 | 搜出来的几条已有观点 | 它那条观点下已有的证据 |
| 判什么 | 是哪一条、接续，还是新观点 | 重复、替代、新证据 |
| 链 | 接续：美联储 2026 年末利率 → 2027 → 2028 | 替代：AMZN 资本开支指引涨 12% → 25% |
| 什么算现在 | 链上开着的那条 | 没被替代的那些 |
| 搜什么 | 只搜观点，找前几条 | 不搜：只看它那条观点下的 |
<!-- /generated: shape -->

## 一条信息进来，怎么写进库

一条信息走一轮，按顺序号一条一条来。模型只做第 4、7、8 步，其余是代码。

<!-- generated: intake -->
```
抽取交来的证据和候选观点（一条信息一轮）
  ↓ 1 核对出处（代码）：出处在处理记录里查不到的不要，记下原因
  ↓ 2 收证据（代码）：重试不重复存；上游修正版只换它自己那一处出处：它只是转载的，不动原来那条证据；它本身是原始来源的，新版的句子照常对上，改了的就替代原句
  ↓ 3 拉清单（代码）：搜出可能是同一条的几条已有观点；怎么搜、搜几条还没定；清单是空的，也照样交给第 4 步
  ↓ 4 对上（模型）：一次调用，不读原文：每个候选观点是清单里的哪一条、接续哪一条，还是新观点（对不上，或者只是有点像，就开新的），写理由；每条证据和它那条观点下没被替代的证据比，是重复、替代还是新证据
  ↓ 5 核对（代码）：编号必须在清单里，或者是那条观点下的证据
  ↓ 6 写进库（代码）：各对象自己的队列写，先写主题，再写对象；重复只多一个出处；替代按说的时间排（这句话是哪天说的），后说的算数，先说的标“被替代”，晚到的旧说法直接进历史；被替代的证据还连着别的观点，新的那条也连过去；原始来源自己的修正版里找不到、也没被新句替代的原句，算删了，标“被替代”；对上那一刻看到的变了，这部分重新对上
  ↓ 7 连依赖（模型）：新观点挑它依赖哪几条，写明方向
  ↓ 8 重判一轮（模型）：这一轮有新证据或替代、或者依赖换了格的观点，重判；只多了重复的不判；换了格的再往下通知
```
<!-- /generated: intake -->

## 第 4 步对上：候选观点的去向

<!-- generated: outcomes -->
| 去向 | 什么时候 | 写什么 |
|---|---|---|
| 挂到已有的 | 候选观点看的就是那条观点看的东西 | 只挂证据，证据再和那条观点下的证据比；梯子和到期日用已有的 |
| 接续 | 同一样东西的下一期：数字的下一年；事件的那条已经关了，要接着看 | 建新观点，记接续 |
| 新观点 | 对不上，或者只是有点像：Blackwell 这一档对华许可，不是 H20 这一档 | 建新观点，梯子和到期日从此定死 |

- 搜只用来找出几条可能的，是不是同一条由模型判：“H20 对华许可”和“Blackwell 对华许可”很像，却是两条；看多和看空的两种说法，是同一条。
<!-- /generated: outcomes -->

## 第 4 步对上：证据的去向

<!-- generated: evidence-outcomes -->
| 去向 | 什么时候 | 写什么 |
|---|---|---|
| 重复 | 说的就是那条观点下已有的一条：转载；正文和表格里的同一个数；同一个人把同样的话再说一遍 | 那一条多记一个出处；证据不多一条，不重判 |
| 替代 | 和已有的一条是同一件事的前后两个说法：同一个人后来改了说法或数（指引、预测、状态）；官方证实或否认了一条传闻；原始来源自己出了修正版，改了原句 | 按说的时间排（这句话是哪天说的），后说的算数，先说的标“被替代”，留在历史里；晚到的旧说法直接进历史；重判 |
| 新证据 | 别的都是：新的事、另一期的数、另一个人的说法（说法相反的也是）；拿不准也算新证据 | 加进来，和别的一起算数；重判 |

- 证据只和它那条观点下的证据比，不拿证据去搜全库：观点先定好（抽取时挂上的，或者候选观点对上的那条），再看这条观点自己已经有什么。和观点一个形状：候选观点比的是搜出来的几条已有观点，证据比的是这条观点下的证据。
- 一条证据挂几条观点，也只存一条：和这几条观点下的证据一起比一次。
- 被替代的证据还连着别的观点，新的那条也连过去，那些观点也重判；不然那条观点手里只剩一个过时的说法。
- 证据是一句话或一个数，替掉的只是那一句：卖方新报告改了收入预测，替掉的是它上一份里的那个预测，别的论据照样算数。
- 对上不读原文，比的是证据里“一句话说清”的那句；拿不准算新证据，最坏也就是两条都算数，由重判自己看。
<!-- /generated: evidence-outcomes -->

## 例子：三条信息怎么写进库

<!-- generated: intake-example -->
```
三条信息，库从空的开始（示意）
├─ 2025-04-15 NVDA 的 8-K → 库是空的，交来两个候选观点｜对上：清单是空的，都开新观点
│   ├─ #1 主题观点 → 这一档芯片对华出口许可（事件）（证据：H20 出口中国要许可证（发生的事））
│   └─ #2 对象观点（NVDA） → FY26 全年中国区收入（数字）（证据：预计最多约 55 亿美元的费用（当事人说的）；依赖 #1，放松那头看多）
├─ 2025-04-16 AMD 的 8-K → 标到 AMD，AMD 还没有观点，交来两个候选观点｜对上
│   ├─ 候选观点“MI308 对华许可” → 挂到 #1（搜到 #1，模型判是同一件事（同一条规定管的同一档芯片）；它的证据再和 #1 下的证据比：AMD 说的是 MI308，是新证据；#1 重判，没换格，不通知 #2）
```

## 先后、同步和血缘

<!-- generated: order -->
- 只有信息能产生证据；观点之间只传通知，不传证据，所以观点不会自己证明自己。
- 每条观点只有一个写入者：主题观点由主题的队列写，对象观点由对象的队列写；同一条信息先写主题，再写对象。
- 先后按顺序号排，不用电脑时钟。一条信息只读顺序号比它小、发布日不晚于它的信息留下的状态（同一天按顺序号）；结果要和一条一条按顺序处理完全一样；并行时读到的东西在提交前变了，就重新做一次（D31）。
- 只追加：观点的问题、梯子和到期日写下就不动；对上、重判、接续、关掉、标注都是新加的记录，带顺序号。
- 晚到的信息读它发布日的状态，按真实日期写进去（D31）；晚到的旧说法（和现在算数的某一条是同一件事的前后两个说法，又说得早）直接进历史。
- 同一条信息的修正版只换它自己那一处出处：它只是转载的，不动原来那条证据；它本身是原始来源的，改了的原句由新句替代，删了的标“被替代”。连着变了的证据的观点各重判一次；过去的重判记录不改。
- 失败：每条信息记下做到哪一步，从失败的那一步重试，重试只替换自己上次的结果；多次失败的放进人工复核池。
- 两头都能查：从一条观点查到推过它的全部信息；从一条信息查到它建过的观点，和它作为出处的全部证据（重复的也查得到）。

存在哪、用什么数据库，建的时候定。

## 验收标准

- 每条观点都有问题、梯子和到期日，建好以后这三样不再变；梯子五格（只有是或否的问题两格），每格一个看得见的条件。
- 数字的观点写明哪一年；同一个对象的同一个数，开着的不超过今年、明年两条；事件的同一件事，开着的只有一条。
- 每次对上都留一条对上记录：给模型看了什么、原始返回、Config 版本、谁定的；模型给的编号不在清单里、也不是那条观点下的证据的，代码不收，记下原因。
- 每条证据的对上写明是重复、替代还是新证据；重复只多一个出处，不重判；替代的旧证据标“被替代”，不删。
- 一条证据挂几条观点也只存一条；被替代的证据还连着别的观点的，新的那条也连过去。
- 只有这一轮有新证据或替代、或者依赖换了格的观点才重判；每次重判写明依据哪几条证据；只有“发生的事”能定哪一格成立。
- 数字的箭头钉住年份，事件的箭头顺着接续走。
- 记录只追加：任何一条观点、证据、连线、对上记录都查得到来历；从一条信息查得到它建过的观点，和它作为出处的全部证据。
- 晚到的信息读它发布日的状态，按真实日期写进去（D31）；修正版只换它自己那一处出处：转载的修正版不动原来那条证据，原始来源自己的修正版，改了的原句由新句替代，删了的标“被替代”。
- 每次对上都记下来；人标一部分。

## 还没定的

<!-- generated: open -->
- 共识：市场押在哪一格；对股价的看法就是我们的状态和共识的差距。共识怎么记还没定（D30 原来定的是由代码按每个独立第三方来源最新的立场算）。

## Claude 提的、Alex 还没定的

这些是讨论里 Claude 提的，Alex 没有说过同意。定了才算数，才去做。

<!-- generated: proposed -->
1. 两个位置：梯子上除了状态，再记“现在在哪一格”（事实：现在已经落在哪一格，到期那天就是答案）；只有“发生的事”能动它；时点的数（政策利率）由代码按最近公布的值定，一段时间的数（全年收入）在答案公布前没有这个位置。
2. 梯子的写法：每一格是一个是或否的条件，各格不重叠、盖住所有可能，到期时正好一格成立；没有“部分”，部分做到的单独写成一格；一把梯子只放一种东西，既要数字又要事件的拆成两条，用依赖连起来；中性跟什么比，写在那一格的条件里。
3. 谁判格：数字的格由代码拿公布的数比区间，事件的格由模型只看“发生的事”判。为此数字的观点要写判卷来源（财报里的哪一项、哪个官方数据序列），只问公布出来的数，并分清一段时间的数和时点的数。
4. 哪一年怎么算：公司的数按财年，公司以外的数（宏观）按自然年；“今年”“明年”按已经处理过的信息里最晚的发布日算，只往前走；期末已过的年份不再新开观点；超出今年、明年的数字候选观点，由代码在对上前筛掉。
5. 拉清单：公司不搜，把这家公司开着的观点全拿出来，加上每条链最近关掉的那条；主题从全部开着的主题观点里检索补 5 条。主题观点的身份只看“看的是什么”，范围按管它的那条规定或那个决定来写（“2025-04 那条规定管的这一档芯片”）。
6. 对上多两种去向：候选观点是已有观点的一部分，也挂上去（“H20 在中国的收入”挂到“中国区收入”）；候选观点太宽、捆了几样东西的，不开。
7. 依赖只连输入：B 的答案要用到 A 的答案才连；对方对已经发生的事做出的反应，是证据；两个问题互为输入，就合成一个，或者只留对投资判断有用的那个方向；代码不收会绕成环的箭头，退回给模型改写。
8. 接续和依赖的细则：一条最多被接续一次；接续的梯子方向不变，门槛可以重定；接错了追加一条“撤销接续”；新的一期照上一期的依赖挪一年；B 读的那条换了、A 答不出，也通知 B；B 每次读的是哪一条、哪一版，记在 B 的重判记录里；真正新的主题观点建出来时，把全部开着的观点过一遍，补上该连的箭头。
9. 一轮里的先后：一条信息引起的变化，先做完挂证据、建观点、接续和补箭头，再按依赖先后重判，上游判完才判下游，每条观点每轮只判一次；一条信息除了顺序号更小的信息留下的状态，也读这一轮里它自己已经写下的。
10. 结束的另外两种：答不出（不再披露这个数、事情本身没了，不算准不准；依赖它的观点标“缺这个输入”）；等答案（数字的观点期末已过、答案还没公布，不占今年、明年的名额）。
11. 每天查重：Pull 模式每天发起，同一对象开着的观点两两比，主题跨全部主题检索；后建的并入先建的，连线和箭头搬过去，查环，重判；Config 里多一套“查重”的设置。
12. 重判时，代码把同时连在上游观点上的证据标出来：“这条已经算进 A 了”。
13. 重判的核对：代码核对重判引用的证据确实连在这条观点上、没被替代；查某天当时怎么判时，只读存下来的重判记录，不重新调用模型。
14. 到期怎么定答案：按判卷来源，用第一次公布的值，后来的修订不改；拿来打分的，是带来答案的那条信息进来之前的最后状态；等发布日不晚于到期日的信息都处理完再定。
15. 晚到的信息：收到时用现在的证据重判，不读它发布日的状态（D31 定的是读发布日的状态；D39 改成这样，没经 Alex 同意）。
16. 对上标注的细则：后来被并掉的、被代码拒绝的都抽，Pull 模式每周再随机抽一些；拿人标的量对上准不准（新观点判得准不准、挂错多少、换个顺序答案变不变）；考试集标的人看不到模型的答案，固定下来，只在换裁判时评一次；标注不直接改库；训练时大模型的判断和人标的一起用，是监督训练，用不到强化学习；连依赖、重判的请求和返回也记。
17. 存在哪：一个关系数据库，记录都是只追加的表；全文检索和向量检索建在同一个库里，是随时能重建的索引；依赖用表和递归查询，不要单独的向量库或图数据库。规模（估算）：约 1,400 条开着的观点，一年约 180 万条证据。
