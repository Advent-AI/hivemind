## 一句话

系统做的事，就是维护一个观点库：建观点、更新观点、到期关掉观点。上游不断把带着分类结果的信息推进来。抽取用资深对冲基金分析师的视角，对着这些对象已有的观点，把每条信息整份读完，交出两样东西：连到已有观点上的证据，和已有观点管不到的候选观点。观点库再把它们和已有的比：候选观点是归入已有的、接续、开新的，还是不开；证据是重复、替代还是新证据。一条观点是一个问题、一把梯子和一个到期日，证据把它的状态往两头推，到期那天状态定格。

## 为什么重建

旧系统是按日期主动去拉数据、一批一批处理的。同一件事的规则散在很多地方：信息的类别在 9 个模块里各有一套定义，配置分五层、后一层改掉前一层，时间有好几套时钟。结果是问“某类信息进来会怎样”，要读好几处代码才说得清。新系统从头设计，每件事只在一个地方决定。

## 系统的边界

- **上游（不归本系统）**：取得材料、按分类规则贴好标签（分类结果、相关对象、发布时间等），推送进来。以后再谈。
- **本系统**：从“分发”开始，到观点库、最终判定和 Pull 模式。
- **测试**：用一段测试代码，把测试库里的旧数据按发布顺序推进来，走和正式运行完全相同的路；Pull 模式用回放的时间。

信息走的路：

```
上游（取得材料 + 分类）→ 分发（编顺序号）→ 抽取（只读）→ 观点库（搜索、比对、写进去、重判）⇄ 比对标注
                                                              ▲ 每天结束时、或按定时任务：整体过一遍、更新，
                                                              │ 到期的观点状态定格、关掉
                                                          Pull 模式
最终判定：旧稿；还要不要单独一步，以后和 Pull 模式一起定
```

旁边的几条线：

| 从 | 到 | 是什么 |
|---|---|---|
| 研究对象名单 | 上游 | 推哪些对象的哪几类信息 |
| Config | 抽取、观点库、最终判定 | 用哪版模型设置；观点库还有搜索取前几条 |
| 观点库 | 抽取 | 已有观点的问题、看的是什么和到期日：相关对象开着的观点，加上它们依赖的观点，写明谁依赖谁（提示词第 5 块） |
| 观点库 | 比对标注 | 每次比对的记录；人标好的结果，以后用来训练接手比对的小模型 |
| 分发、抽取、观点库 | 人工复核池 | 查不到的、建议新增的主题、多次失败的 |

## 两种工作方式

| | 信息流 | Pull 模式 |
|---|---|---|
| 谁触发 | 有信息推进来 | 每天结束时，或按定时任务的间隔 |
| 谁主动 | 上游推，系统接着处理 | 系统主动去做 |
| 做什么 | 把信息读成证据和候选观点，各自和观点库里已有的比对；开着的观点读的东西变了就重判（自己的证据变了，或者它依赖的观点结论变了） | 主动把观点整体过一遍、更新；到期的观点状态定格、关掉（以后设计） |
| 看不看日历 | 从不看 | 系统里唯一按时间做事的地方；“现在”从外面传进来 |

## 基本原则

1. **从观点出发。** 系统的核心是观点库；读什么、存什么，由观点需要什么决定，不先把财报读成一大堆数。
2. **观点是判断，证据是客观的。** 观点是模型（分析师）写的；谁在哪条信息里说了什么，是证据。只有信息能产生证据，观点之间不互相证明。
3. **每条都带出处。** 每条观点、证据和每一次由信息引起的变化都写明来自哪条信息的哪一处，能回到原文去查。
4. **信息流由信息推动，不由日历推动。** 没有新信息进来，信息流这一边就什么都不做；按时间做事只在 Pull 模式。
5. **先后由顺序号定。** 每条信息进来时编一个顺序号；一条信息只读顺序号比它小的信息写下的内容，加上这一轮里它自己已经写下的，结果和一条一条按顺序处理完全一样。时间线只往后加，不回头改：晚到的旧说法，同一件事已经有更新的就不算；讲新事的照常算，记真实日期。
6. **只有研究对象名单决定处理什么。** 名单写明研究哪些对象、每样看哪几类信息；上游只推这个范围，推进来的都处理。
7. **同一样东西只开一条观点。** 比对开观点时，同一个对象、看同一样东西，同一时间只开一条观点（数字按年，今年、明年各一条；人手动重新打开的不算在内）；是不是同一样东西，由模型在搜索引擎搜出的前 N 条里判；搜索只用来找出前几条，当不了裁判。证据也一样：先定它去哪条观点，再和那条观点下已有的比，是重复、替代还是新证据，不拿证据去搜全库。
8. **问题和梯子事先写死，到期那天状态定格。** 每一格写成能核对的结果，建观点时定，到期以前不改；记录只加不改，关掉的观点、被替代的证据也留在库里。
9. **查不到、规则判断不了的不猜。** 放进人工复核池等人看。
10. **不存原材料。** 原材料留在团队自己的库里，凭编号去取。

| 开着、关了 | 一条观点只有这一个开关：开着的才更新（重判）；到期那天由 Pull 模式定格、关掉，人也可以手动关掉或重新打开（比如资产退市）；关了的留在库里，搜得到 | 不再跟踪；active、inactive |
| 重复、替代、新证据、被替代 | 比对证据的三种结果：重复是说的就是已有的一条（别人转述、正文和表格里的同一个数、同一个人再说一遍），只多记一个出处；替代是同一件事的前后两个说法（同一个人后来改了说法或数、官方证实或否认传闻、原始来源自己的修正版改了原句），按这句话是哪天说的，后说的算数，先说的标“被替代”，留在历史里；新证据加进来，和别的一起算数（这是证据比对的结果；同一份信息又来了，叫“重复的信息”，并到原来那条） | — |
| 依赖 | 一条观点判断时要看另一条观点的结论，就是依赖它，画成一个箭头：它的结果要靠对方的结果；对象观点写明对方的哪一头对它是看多，主题观点写明两把梯子同向还是反向；不能绕成圈 | 前提 |
| 接续、链 | 同一样东西的下一条观点接着上一条，连成一条链；证据的替代也连成一条链（12% → 25%） | — |
| 比对、比对记录 | 和库里已有的比，定去向：候选观点和搜出来的已有观点比（归入已有的、接续、新观点、不开）；证据和它那条观点下搜出来的证据比（重复、替代、新证据）。每次比对留一条比对记录 | 对上 |
| 归入 | 候选观点就是还开着的那条已有观点，或者是它的一部分：归入那一条，它的证据连过去，梯子和到期日用已有的 | 并进 |
| 出处 | 一条证据从哪来：上游编号、类别、发布日、在信息里的位置，和原文那一句或表里那个单元格 | — |
| 原始来源 | 转述的话最初是谁、哪天说的；按它数独立来源，替代也按这一天排先后 | — |
| 一句话说清 | 证据离开原文也读得懂的那一句；比对和重判读的是这一句 | — |
| 查重 | 定期把其实重复的开着的观点找出来，后建的合并到先建的（Claude 提的，Alex 还没定） | — |
| 重判、一轮 | 重判是模型读一条观点下没被替代的证据，和它依赖的观点的结论，重新判状态；只重判开着的观点（关了的不判），只在读的东西变了时重判：自己来了新证据或有证据被替代，或者它依赖的观点结论变了，或者新连上了一条库里已有的证据；连着的证据只多了出处，不算；一条信息引起的全部变化算一轮，先判被依赖的观点，再判依赖它的 | — |
| 比对标注、标注、小模型 | 人给比对记录标出正确的去向；用人标的结果训练、以后接手比对的更快的模型，叫小模型 | — |
| 代码 | 写出来、按规则做事的那部分，和“模型”相对；还没写的、要改的也叫代码；股票代码、申报代码这类名字照写 | 程序 |
| 大类、组 | 信息分成 5 个大类；主题库分成 12 组 | 用“大类”指主题库的分组 |
| 已冻结 | 一个模块的第一版定下来了；要改，先记一条新决定 | 定稿 |

## 和旧系统的区别

| | 旧系统 | 新系统 |
|---|---|---|
| 数据怎么进来 | 按日期主动去拉 | 上游推进来，来了就处理 |
| 怎么处理 | 一批一批跑，按天推进 | 一条一条处理，由信息推动，按顺序号排先后 |
| 信息类别 | 9 个模块各自定义 | 16 个类别，一份规则 |
| 处理什么 | 配置、命令参数、多套预设层层覆盖 | 只有研究对象名单决定 |
| 时间 | 好几套时钟 | 信息流只看发布日；Pull 模式的“现在”从外面传进来 |
| 原材料 | 自己存一份 | 不存，凭编号去团队的库里取 |
| 财报 | 每次刷新把每家公司的财报全部拉下来，拆成一条条数存着，再列给模型去形成结论 | 和别的文件一样整份交给模型，读成观点和证据，不存数字仓库 |
| 观点 | 越长越多、改写后分不清是不是同一条、从来不退出 | 一个问题、一把梯子、一个到期日，写下不改；比对开观点时，同一样东西只开一条：是还开着的那条或它的一部分就归入，对不上或只是有点像就开新的；到期那天状态定格 |

## 还没设计的

人工复核池的处理流程；上游怎样取得材料和分类，以及退回的信息怎样通知上游；每一类提示词的具体写法（建的时候试过再定）；观点库还没定的几项（见 06-views.md），其中观点的颗粒度要先调研：从对冲基金的角度看，一条观点长什么样；最终判定和 Pull 模式以后一起重做（到期那天状态定格已经定了）。
