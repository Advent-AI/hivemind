# 观点库重建：讨论记录

从 2026-10-18 起。Alex 定的做法：之前观点库的草稿（`docs/prd/06-views.md` 和设计页上的观点库）先不看，两个人从头一起推。这份记录跟着讨论一步一步写，最后合成设计，再写进设计页、PRD 和 DECISIONS。

## 起点：这个模块要做什么

Alex：“store the theses, the evidence, and the ladder in a very, very clear data structure manner that has linkages to whatever is passing through the data pipeline.”

也就是：观点库只管它自己。观点、证据、检验条件（ladder）这三样东西，要用清楚的数据结构存下来，而且要和流过管道的每条信息连得上。

## 第 1 步：观点、证据、检验条件各是什么（对齐中）

Claude 照之前的描述给出的定义，等 Alex 确认或改。

```
一条观点（thesis）：模型以分析师身份下的判断，可能判错
│  例：一年内 NVDA 中国数据中心收入基本归零（利空），到 2026-04-15
│
├─ 证据（evidence）：某条信息里有人说了什么、发生了什么，是客观记录，不是判断
│    例：NVDA 8-K · 2025-04-15：“H20 出口中国要许可证，预计计提约 55 亿美元”
│        → 发生的事，支持这条观点
│    └─ 出处 → 指向管道里的那条信息（上游编号和版本、哪一段、原文那一句）
│
└─ 检验条件（ladder）：事先写好的考题，看到什么事实算对、什么事实算错，各带期限
     例：证实：2026-04-15 前，NVDA 公布的中国区收入同比降 50% 以上
         证伪：美国批准 H20 对华出口
```

三者的关系：观点是判断；证据说明为什么信或不信；检验条件是观点自带的考题，只有证据回答了考题，观点才能判对或判错。

之前的描述里说不清的两处：

1. **检验条件（ladder）**：之前压成了平平的两张清单，一张证实条件、一张证伪条件。“ladder”这个词像是一级一级的台阶，比如先出现早期信号，再得到确认，最后有一件事一锤定音。Alex 说的 ladder 是哪一种，还没对齐。
2. **证据到底是什么**：是“原文那一句”，还是“原文那一句加上它对某条观点说明了什么”？同一句话可以支持一条观点、同时削弱另一条。之前的描述把两样混在一起记成一条证据。要想结构清楚，可能得拆成两样：一样是信息里的那句话（只记一次），一样是这句话和某条观点之间的连线（支持还是削弱）。

## 第 2 步：检验条件（ladder）和证据有什么区别（讨论中）

Alex：“我觉得 ladder 这个设计很有问题，和 evidence 之间的区别是什么。”

区别只有一条：检验条件是考题，事先写好，属于观点；证据是答卷，后来才到，属于信息。考题事先写，是为了防止看到结果以后再改口说“我本来就是这个意思”。

```
观点：一年内 NVDA 中国数据中心收入基本归零（到 2026-04-15）

检验条件（事先写，属于观点）            证据（后来到，连着信息）
├─ 证实：中国区收入同比降 50% 以上   ←── NVDA 财报：中国区收入同比降 63%（示意）
└─ 证伪：美国批准 H20 对华出口       ←── 报道：商务部开始发 H20 许可证
```

Claude 的看法：问题出在两道考题都是别处已经写过的东西，又抄了一遍。

- 证实条件就是把主张换成数字再说一遍。而且两遍已经对不上了：“基本归零”和“降 50% 以上”不是一回事。
- 证伪条件说的其实是前提错了。“美国批准 H20 对华出口”就是主题观点“管制会收紧”被证伪，而前提那条连线已经表达了这一点。

同一件事存三遍（主张、检验条件、前提），时间一长就会各说各的。

Claude 的提议（等 Alex 定）：不单独存检验条件。

- “怎么算对”写进主张：主张必须写成能判的样子，写清看什么、看到什么时候、多少算对。例：“到 2026-04-15，NVDA 公布的中国区数据中心收入同比降 80% 以上”。
- “为什么会错”交给前提：连到别的观点上，前提被证伪，这条就要再判一次。
- 证据直接回答主张：“发生的事”这一层的证据（比如财报里的数）能直接判对错。

这样做会丢掉的东西：事先写好的中途路标，也就是到期之前、能早点看出方向的信号。在这个提议里，它们和别的证据一样，进来时挂成支持或削弱。

## 第 3 步：前提到底是什么（讨论中）

Alex：“到底什么是前提，是 hypothesis 吗？就是你自己不觉得这个很绕不清晰吗。”

Claude 承认绕，绕在一处：之前用了三个词说“因为”，理由、前提、证伪条件，各存一处。

说直白点：观点就是 hypothesis，一句到期能判对错的话。前提不是另一种东西，只是两条观点之间的一个箭头，意思是“B 要成立，得先有 A 成立”。

```
观点 A（对象：主题“美联储政策利率”）：年内美联储会降息
观点 B（对象：以太坊）：未来三个月美国现货 ETF 持续净流入
B ──依赖──→ A
```

只有一个真实的情况需要这个箭头：宏观信息只标在主题上，不会标到每个对象上。比如一份 FOMC 声明，相关对象是主题“美联储政策利率”，里面不会提以太坊。没有箭头的话，B 永远听不到“美联储不降息了”。

顺带一点：主题本来就是名单里的对象（D11），所以挂在主题上的观点也就是一条观点，“主题层、对象层”不用当成两种东西。

等 Alex 定：要不要这个箭头。

## 第 4 步：观点是一个问题加一个状态，ladder 是看空到看多的刻度（讨论中）

Alex：“我在想一个 hypothesis 是不是之前讲的所谓的 ladder，意思是它可以是 bullish 到 bearish 来分布；所有 attached evidence 都可以是 contribute to bearish or bullish，所以这个 hypo 更像是一个 thesis with a state。”

Claude 的复述：观点不是一句“会怎样”的断言，而是一个问题加一个状态。问题写下不改；状态是它现在在梯子上的哪一格，从看空到看多。每条证据进来，都把状态往一边推。ladder 就是这把梯子。正式的说法叫贝叶斯更新：一个假设，一个当前的把握，每条证据挪它一下。

```
观点：到 2026-04-15，NVDA 中国区数据中心收入会怎样？
│
├─ 梯子（ladder）：强烈看空 ─ 看空 ─ 中性 ─ 看多 ─ 强烈看多
│
├─ 状态随证据走
│   2025-04-15 8-K：H20 出口要许可证，计提约 55 亿（发生的事）  → 看空
│   2025-07 NVDA 声明：政府保证会批许可证（当事人说的）        → 往中性回一点
│   2025-08 报道：商务部开始发许可证（发生的事）               → 中性
│   之后 报道：中国要求企业不要采购 H20（示意）                → 看空
│
└─ 答案：到期时 NVDA 公布的中国区收入（发生的事）
          答案出来前最后的状态和答案一比，就知道判得准不准
```

它解掉的问题：

- 检验条件和证据不再重复（第 2 步）：梯子是刻度，证据是推力。
- 谁先到不再决定观点：传闻先到也只推一小格，后面的事实照样推得回来。
- 反方向的说法有了自然的位置：往另一头推，不用另建一条观点。
- 之前在对象和观点之间的“驱动”，其实就是这个问题本身，可以少一层。
- 结束变干净了：不再是证实或证伪，而是答案出来了，拿状态去对答案。
- 依赖箭头（第 3 步）也变清楚了：A 的状态挪了，通知 B。

要想清楚的两处：

1. 状态不能变成数条数。二十家媒体转述同一条独家，不能推二十格；财报里的实际数，要比十篇卖方看法推得远。照贝叶斯的说法，一条证据推多远，看它在两头各有多大可能出现：转述的传闻两头都会有，几乎不推；公布的实际数只会在一头出现，推得很远。
2. 主题上的观点没有看多看空。“美国对华 AI 芯片出口管制”收紧，对 NVDA 是看空，对中国本土芯片厂可能是看多。所以梯子的两头由问题自己定：对象上的观点用看空到看多，主题上的观点用结果的方向，比如收紧到放松。

等 Alex 定：状态谁来挪。A，代码算：每条证据带方向和分量，代码加总。B，模型判：有新证据进来，模型读完这条观点的全部证据，重新定在哪一格，代码只管规矩。Claude 倾向 B：分析师挪立场靠判断，不靠加减法；A 的分量怎么定，本身就得有人去拍。代价是每次有新证据进来，都多一次模型调用。

## 第 5 步：状态由模型挪，要尽量确定；对照真实分析师的写法（讨论中）

Alex 定：选 B，状态由模型挪。“但是这个基本要 deterministic 一点，模型的设置 temperature 要让他基本不会幻觉，只是基于事实来评价。”

Claude 的补充：temperature 调低只能少一些随机，既保证不了每次一样，也挡不住幻觉。让模型只按事实判，靠的是三件事：只给它这条观点下挂着的证据和出处；它要写明是哪几条证据把状态挪了，代码核对这几条确实存在；梯子的每一格写成能看到的结果（见下），模型判的是“这件事落在哪一格”，不是凭感觉。temperature 记在 Config 里。

Alex 又问：这样一来，观点是什么、抽取读出什么样的观点，会不会变？并要求查资深股票分析师和对冲基金分析师实际怎么写观点，对齐他的想法和现实。

查到的做法（来源见对话）：

- Steinhardt 的 variant perception：讲一个想法要讲四样：想法本身、市场的共识、我们哪里和共识不同、什么事件会让市场看到。
- 股票推荐的标准写法：只讲 2–3 个市场定价错了的关键因素，每个都要量化到对股价的影响；催化剂是未来 6–12 个月里的具体事件，确定会发生的最好；风险就是把催化剂反过来，也就是什么会让我们错。
- 卖方首次覆盖报告：评级和目标价，几个关键争论，催化剂，风险和反证，牛、基准、熊三种情景。Morgan Stanley 的 Risk-Reward 只盯少数几个关键的不确定性，配几种和投资人争论相关的情景。
- 证伪标准（kill criteria）：结果出来之前就写下的、看得见的事，比如“毛利率连续两个季度低于 30%”；目的是防止事后挪球门（thesis creep）。
- Mauboussin：先从股价倒推出市场预期了什么，再拿自己的预期去比。
- 超级预测者：问题要有明确的判定标准；同一个问题上做很多次小幅更新；最后用 Brier 分数算准不准。

对齐：

| Alex 的想法 | 现实里的做法 | 对上了没有 |
|---|---|---|
| 观点是一个问题 | 关键争论、关键的不确定性；每只股票只有 2–3 个 | 对上了，而且现实只要少数几个 |
| 状态在看空到看多的梯子上 | 牛、基准、熊三种情景，每种都是具体数字，有的还带概率 | 对上了，但现实的每一格是具体结果，不是形容词 |
| 证据把状态往两边推 | 同一个问题上多次小幅更新；卖方随新信息调评级和预测 | 对上了 |
| 到期用答案对状态 | 问题要有判定标准；用 Brier 分数算准不准 | 对上了 |
| 没有 | 每个观点都要和共识（市场已经定价的）比 | 缺这一块 |
| 没有（第 2 步去掉了检验条件） | 事先写下什么会让我们错 | 梯子每一格用具体结果来定，就补上了：什么事实会把状态推到另一头，事先就写在梯子上 |
| 没有 | 催化剂：什么时候能知道 | 部分有（到期日）；中间的日期还没有 |

对第 2 个问题的回答：会变。

- 观点变了：以前是一句带方向的断言（“一年内归零”），现在是一个问题加一个状态。
- 抽取读出的东西会变：以前每条信息都读出“候选观点”；现在大多数信息只读出证据：这句话、对哪个问题、往哪边推。只有信息提出了库里还没有的关键问题，才读出一个新问题，而且每个对象只该有少数几个。
- 抽取已经冻结（D37）。它交出的东西要变，得在观点库定下来以后记一条新决定，现在不动抽取。

等 Alex 定：梯子的每一格要不要用具体结果来写。例：

```
问题：到 2026-04-15，NVDA 中国区数据中心收入同比会怎样？
├─ 强烈看空：降 80% 以上（基本归零）
├─ 看空：降 30% 到 80%
├─ 中性：变动在 30% 以内
└─ 看多：涨 30% 以上
```

## 第 6 步：梯子每一格的条件，可以是数字，也可以是事件（讨论中）

Alex：“每个 state 的条件是可以量化，或是非量化（例如事件的发生：yes / no / partial?）。这个你帮我思考演绎下。”

Claude 的推演：

1. **每一格都是一个“是或否”的条件，数字和事件都一样。** 数字的一格是“这个数落在这个区间吗”，事件的一格是“这件事发生了吗”。
2. **不要“部分”这个答案。** “部分”是判断最容易藏进去的地方：H20 开始发许可证，但要上缴 15% 的中国收入，算放松还是不算？把“部分”单独写成梯子上的一格，这一格本身还是是或否：“开始发许可证，但附条件”。
3. **一把梯子只放一种东西，各格从一头排到另一头，不重叠，到期时正好有一格成立。** 数字的梯子是同一个数的几个区间；事件的梯子是同一件事从一头走到另一头的几个阶段。
4. **一个问题既要数字又要事件，就拆成两个问题，用依赖连起来。** 例：NVDA 中国区收入（数字）依赖出口管制（事件）。之前 H20 那个例子说不清（主题观点被证伪，NVDA 观点却留下），原因就是两个问题挤在了一条观点里。
5. **谁来判。** 数字的格由代码判：拿“发生的事”里公布的数去比区间，每次结果都一样。事件的格由模型判是或否，只能根据“发生的事”这一层的证据，而且要写明是哪几条。当事人说的、第三方看法和传闻，判不了任何一格。
6. **推出来的一点：同一把梯子上其实有两个位置。** 一个是“现在在哪一格”，是事实，由“发生的事”定；一个是“我们认为到期会在哪一格”，是判断，也就是状态，每一层的证据都能推它。到期那天，“现在在哪一格”就是答案。

```
问题 A（主题“芯片出口管制”）：到 2026-04-15，美国对华 AI 芯片出口管制会怎样？（事件）
├─ 更紧：管制扩大到 H20 以外的更多芯片，或全面禁止
├─ 紧：H20 一类芯片要许可证，基本不发          ← 2025-04 现在在这一格（NVDA 8-K）
├─ 部分放松：开始发许可证，但附条件             ← 2025-08 现在在这一格（据报道发证，上缴 15%）
└─ 放松：取消许可证要求

问题 B（NVDA）：到 2026-04-15，NVDA 中国区数据中心收入同比会怎样？（数字，依赖问题 A）
├─ 降 80% 以上
├─ 降 30% 到 80%
├─ 变动在 30% 以内
└─ 涨 30% 以上
现在在哪一格：最近一次公布的中国区收入，代码算
我们认为到期会在哪一格：模型判，写明依据哪几条证据
```

确定性从高到低：数字的格，代码判，完全确定；事件的格，模型判一件具体的事有没有发生，要引用证据，接近确定；我们的判断，是模型的判断，本来就不可能完全确定，所以每次挪动都要写明依据。

Alex：“ok”，同意一把梯子上放这两个位置。

## 第 7 步：梯子固定五格，各带看多看空；展开层和依赖（讨论中）

Alex 定：“ladder 的不同 level 应该自带不同的 bull bear 属性，我觉得这个分布要清晰，我们用 5 个 state 吧：very bullish, bullish, neutral, bearish, very bearish。”

每把梯子都是五格：强烈看多、看多、中性、看空、强烈看空。每一格仍然写成一个看得见的条件。

```
问题 B（NVDA）：到 2026-04-15，NVDA 中国区数据中心收入同比会怎样？（数字，区间示意）
├─ 强烈看多：涨 50% 以上
├─ 看多：涨 10% 到 50%
├─ 中性：变动在 10% 以内
├─ 看空：降 10% 到 80%
└─ 强烈看空：降 80% 以上（基本归零）
```

只有两种结果的事，按程度分成五格。例：“12 月 FOMC 会怎样”：降 50 个基点以上、降 25 个基点、不动、加 25 个基点、加 50 个基点以上。

Claude 指出的一处：主题上的问题，五格的看多看空对谁说？出口管制收紧，对 NVDA 是看空，对中国本土芯片厂可能是看多。提议：主题的梯子也是五格，但每格用结果来命名（大幅收紧……大幅放松）；看多看空写在依赖箭头上，由箭头的方向换算到每个对象。

### 层：证据分四层，层只管“能不能动事实”

```
一条证据进来｜它是哪一层？（抽取读的时候就按这一类的读法标好）
├─ 发生的事：官方动作、公布的数、已经完成的交易
│   ├─ 能动“现在在哪一格”
│   └─ 能推状态
├─ 当事人说的：公司指引、管理层表态、官员讲话 → 只能推状态
├─ 第三方看法：卖方、媒体分析、专家 → 只能推状态
└─ 传闻：“知情人士称”、没有出处的消息 → 只能推状态
```

- 数独立来源：按原始来源数。二十家媒体转述同一条独家，只算一条。
- 推多远由模型判，写明依据；层不给固定分数（第 5 步选了 B，不用代码加权）。
- 同一件事，层看谁确认：“知情人士称商务部开始发许可证”是传闻，只能推状态；商务部或公司确认以后，确认的那条是发生的事，才能动“现在在哪一格”。原来那条传闻还是传闻。

### 依赖：一条观点指向另一条观点

```
依赖：B ──→ A（B 的答案要看 A）；箭头上记两样
├─ 方向：同向还是反向（A 往梯子哪头走，B 被推向哪头）
│   例：NVDA 中国区收入 ──反向──→ 出口管制（管制越紧，NVDA 越看空）
└─ 看过 A 的第几版：A 每动一次多一版；B 看过的版本落后了，就该重判

A 的“现在在哪一格”或状态动了 → 通知 B → 模型带着 A 的现状重判 B 的状态
```

- 只传通知，不搬证据：A 的证据不复制到 B，B 重判时把 A 的现状当背景读。否则同一份 8-K 在 A 上算一次、在 B 上又算一次。
- A 不替 B 定答案：B 的答案只看 B 自己的梯子。例：2025-08 出口管制到了“部分放松”，但据报道中国要求企业不要采购 H20，NVDA 中国区收入仍在“强烈看空”。
- 一个主题被很多对象依赖，它的证据只挂在主题上一次；看一只股票的全貌，就是它自己的观点，加上这些观点依赖的观点。
- 依赖也可以指向别的对象的观点，比如供应链。
- 不能绕成环：A 依赖 B、B 又依赖 A，通知会转个不停，代码拒绝。
- 建一条观点时，模型写出它依赖哪几条已有观点、各是什么方向；代码核对被依赖的观点确实存在。

等 Alex 定：主题上的问题，五格用结果命名，看多看空由依赖箭头的方向换算到每个对象，行不行。

4. **状态每次都从全部证据重新判，不从上一个状态往前挪。** 晚到的文件、修正版，如果在上一个状态上加减，结果就看处理的先后，同样的证据可能得出不同的状态。提议：状态只由“这条观点下的全部证据，加上它依赖的观点的现状”决定；证据一样，状态就一样。这也是让它确定、能回放的办法。顺带解掉第 1 步的问题：证据本身不用事先带方向。那句话只存一次；它和每条观点之间有一条连线，“往哪边推”记在连线上，由重新判状态的那次调用写。
5. **依赖只在换格时通知。** 美联储那个主题被两百个对象依赖，每个官员讲话都会让模型重判一次；如果每次都通知，一句话就是两百次调用。提议：A 的“现在在哪一格”或状态换了一格，才算动了，才通知；重判以后还在原来那一格，就不通知。
6. **箭头上的方向表达不了先好后坏。** 钢铁关税对美国钢厂：适度的关税推高国内钢价，是好事；关税高到把下游拖进衰退，需求下滑，就是坏事。“A 的哪一头对 B 是看多”写不出这种关系。提议：箭头上写一张五格对照：A 的每一格，对 B 是看多、中性还是看空。一头好一头坏只是其中一种写法。
7. **刻度谁来定、中性是跟什么比。** 五格的门槛是第一个提出问题的模型写的。H20 被管以后，NVDA 中国区收入实际可能的结果全在看空那一半，看多那两格基本用不上，而真正要分清的“降 80%”和“降 95%”却挤在一格里。提议：中性写明是跟什么比（比如跟问题建立时的情况比）；门槛怎么定，留到讲“谁提新问题”时一起定。

考虑过但不建议的：把状态从“一格”改成五格上的概率分布（现实里 Morgan Stanley 给三种情景配概率）。概率分布信息更多，但模型给的概率最难做到确定，和“基本 deterministic”冲突。

### 3 和 6：一个观点只看一件东西

Alex 说得对，这两处毛病不在数据结构，是 Claude 把问题起坏了，而且是同一个错：一个问题里塞了两样会往相反方向走的东西。

- 出口管制：H20 这一档和更先进的芯片（Blackwell 这一档）是两条观点。分不分的标准：两部分可能往相反方向走，就拆开；总是一起动的就是一件，比如 2025-04 同一条规定同时管 H20 和 AMD 的 MI308，2025-08 又同时附条件放行。
- 钢铁关税：“先好后坏”是两条路挤进了一个箭头。关税抬高国内钢价，是好事；关税拖垮下游需求，是坏事。把中间那件事写成一条观点，每个箭头就只有一个方向：

```
美国钢厂（对象观点，示意）
├─ 依赖 美国钢铁关税（主题观点）：税率高那头 = 看多（国内钢价上去）
└─ 依赖 美国用钢需求（主题观点）：需求降那头 = 看空
      └─ 依赖 美国钢铁关税：反向（税越高，需求越弱）
```

推出来的：

- 箭头只带一个方向。看起来要“先好后坏”，说明中间还有一条观点没写出来。第 9 步提的“箭头上写五格对照”不要了。
- 事件的观点问的是“到期那天它处在哪一格”，不是期间发生过什么。只看一件东西，五格又把它所有可能的状态都盖住，答案总是正好一格。第 9 步提的“梯子不适用”不要了。每一格写清是哪个阶段（宣布、签署、生效、执行）这条留着。

- 4：证据只存一次，本身不带方向；“往哪边推”记在证据和观点之间的连线上，由重判那次调用写。第 1 步第 2 点就此定了。

- 7：五格由模型在建观点时定，定了到期以前不改；合并进来的候选带的刻度一律不要。“降 80%”和“降 95%”挤在一格，这条观点就认了，下一条观点由模型重新定刻度。中性跟什么比，写进那一格的条件本身（比如“比去年同期变动在 10% 以内”），不另记。

### 1：去重和合并

照 Alex 的规矩：观点的身份是“对象 + 看的是什么”（一个数，或一件事的状态），不含日期；同一个身份只有一条观点。

```
候选观点进来（对象、看的是什么、日期、五格、证据）
  ↓ 代码：拿出这个对象还开着的观点（一个对象一般两三条）
  ↓ 模型：候选看的东西，是不是其中某一条看的？只比看的是什么，不比日期、措辞和刻度；写明理由
  ├─ 是 → 合并：只把证据挂上去；候选的日期和五格都不要，用已有的
  └─ 不是 → 新观点，日期和五格从此定死
```

- 例：AMD 的 8-K 第二天进来，候选“到 2026-06，这一档芯片对华出口许可会怎样”，和已有的那条看的是同一件事 → 合并，到期日还是已有的。候选“Blackwell 这一档对华出口许可” → 不是同一件 → 新观点。
- 对上和合并在观点库做（D33 不变）。抽取提示词第 5 块从“这些对象已有的驱动”改成“这些对象已有的观点”，只给看的是什么，不给状态，让模型尽量把证据对到已有观点上。
- 去重只管住“同一个问题问两遍”，管不住“问太多不同的小问题”（META 的 27 条）。后者还是“什么算关键问题”，放着。

### 推出来要补的一处：观点和期分两层（等 Alex 定）

Alex 的规矩让观点的身份变成长期的，日期只属于其中一期。仿真换期：NVDA 中国区收入 FY27Q1 那期答案出来、关掉以后，下一期如果是一条全新的观点，就从零开始，看不到“H20 要许可证”那份 8-K；出口管制那条的下一期也一样，连“现在在哪一格”都定不出来。

Claude 的提议：分两层。

```
观点：NVDA · 中国区数据中心收入（对象 + 看的是什么；写一次，长期不变）
├─ 证据：都挂在观点上，不管是哪一期进来的
├─ 依赖：→ H20 这一档芯片对华出口许可（也挂在观点上）
├─ 第 1 期：FY27Q1，到期 = 财报公布日｜五格（定死）｜现在在哪一格、状态｜答案：强烈看空，关了
└─ 第 2 期：FY27Q2，到期 = 财报公布日｜五格（模型新定）｜现在在哪一格、状态｜还开着
```

- 同一条观点同时只开一期。去重比的是观点；合并就是把证据挂到观点上。
- 重判当前这一期，看的是这条观点的全部证据，所以换期不用搬任何东西。
- 观点没有开着的期，下一条候选对上它时，用候选的日期和五格开新一期。
- 依赖指向观点，不指向某一期；同一条观点每期五格的方向不变（第一格永远是同一头），箭头上的“哪一头看多”才一直有效。
- 准不准按期算：每期答案出来前最后的状态，对那期的答案。

不分两层的做法：每期是一条单独的观点，换期时把证据和依赖复制到新观点上，再把别人指向旧观点的箭头改过去。规矩多三条，还容易漏。

Alex：“你或许是做对了，但是你的叙述很复杂，explain like I'm 16。”

简单的说法：观点是一个笔记本，期是本子里的一张考卷。

```
笔记本：NVDA 中国区收入              ← 观点：封面只写看什么，永远不换
├─ 笔记：8-K、财报、新闻……          ← 证据：记在本子上
├─ 第 1 张考卷：Q1，5 月财报日交卷    ← 一期：五个选项、我们押哪个、正确答案
│    我们押强烈看空，答案也是 → 考完了
└─ 第 2 张考卷：Q2，8 月财报日交卷    ← 新的一期，正在考
```

1. 一个题目只有一个本子。新信息进来，先问这个题目有没有本子：有，把笔记记进去；没有，才开新本子。这就是去重。
2. 一个本子同时只考一张卷。哪天交卷、五个选项是什么，出卷时定，考完以前不改。
3. 笔记记在本子上，不记在卷子上，所以换新卷子时以前的笔记都还在。

Alex：“我觉得还是没理解为什么分两层。”

换个说法，其实只有一个问题：同一个问题会被回答很多次。“NVDA 中国区收入怎样”每个季度财报都给一次答案，每次有自己的日期和五格。一条观点如果只能回答一次，Q1 答完它就结束了；Q2 得开一条新观点，从空的开始，2025-04 那份 8-K 还挂在旧观点上。所谓“两层”，就是让一条观点能被回答很多次，每次的日期、五格、答案按次记下来，证据一直留在观点上。

等 Alex 定：一条观点出了答案以后，是接着回答下一次（Claude 建议），还是就此结束、下一次开新观点再把证据搬过去。

Alex：“是啊，一条观点一定是有一个明确的 ladder 和到期日，这样才构成一个观点呀。have some common sense, think like a hedge fund analyst trying to build this AI system.”

### 撤回两层：一条观点就是一个问题、一把梯子、一个到期日

Alex 说得对，Claude 想复杂了。到期出了答案，这条观点就关掉；要接着看，就开一条新观点，新梯子、新到期日。只有一层。

Claude 原来担心新观点从空的开始。可分析师写下一个观点时，从来不翻旧笔记，而是从“现在是什么情况”开始；这些东西本来就会进来：

- 回答旧观点的那份财报，本身就是新观点的第一批证据：最新的实际数、管理层的指引。
- 政策这类背景在新观点依赖的主题观点上，靠依赖看到它的现状。
- 旧证据留在旧观点上，查历史用。

去重也跟着变简单：只和这个对象还开着的观点比。看的是同一样东西就合并，日期和五格用已有的；已经出了答案、关掉的，不再合并，开新观点。

```
观点：NVDA FY27 全年中国区数据中心收入同比会怎样？
├─ 到期：FY27 年报的财报日（示意 2027-02）
├─ Q1、Q2、Q3 财报：发生的事，是证据，推状态
└─ 年报公布：答案，关掉
```

每季开一条新观点，观点就会一直换，正好是去重要防的事。

### 查到的（带出处）

- 别人都把身份钉在一个键上，相似度只管召回，不管裁判。RavenPack 用“同一实体 + 同一事件类别”判相似事件；Graphiti（Zep）给关系去重时，只在同一对实体之间的关系里找候选（[Zep 论文](https://arxiv.org/html/2501.13956v1)）。放到我们这里，键就是对象：同一个对象的开着的观点才拿来比。
- 让模型从几条候选里“选一个”，比一对一对问“是不是同一个”准：F1 约 81.6 对 64.0，也更便宜；候选一多就有位置偏差（[Match, Compare, or Select?](https://arxiv.org/html/2405.16884v3)）。
- 集合小的时候，整份给模型比先检索稳。事实合并的测试里，整份上下文 60.0，BM25 48.0，Mem0 18.0，Zep 7.0（[MemoryAgentBench](https://arxiv.org/html/2507.05257)）。Mem0 的做法是检索最像的几条旧记忆，再让模型决定 ADD／UPDATE／DELETE／NOOP。
- embedding 分不清只差一个否定、一个数字、一个期间的两句话；“H20 对华出口许可”和“Blackwell 对华出口许可”会非常像。所以 embedding 只能找候选，不能判同一（见 D27 的两份报告）。
- 模型偏向从给定的选项里挑一个：正确答案换成“以上都不是”，28 个模型的准确率降 30–50%（[Tam et al. 2025](https://arxiv.org/abs/2503.01550)）。“新的”必须是正式选项，而且要单独量。
- 误合并比重复更糟：挂错的证据会悄悄推歪一条观点；多出来的重复看得见，能合并。新闻聚类的做法是拿不准就先新建，再定期整体查重（见 D27 的报告）。
- 血缘用两样老办法：每次变化都记一条、只追加不改（[Event Sourcing](https://martinfowler.com/eaaDev/EventSourcing.html)）；分开记“事情什么时候发生”和“系统什么时候知道”（[Bitemporal History](https://martinfowler.com/articles/bitemporal-history.html)）。
- 预测平台的判卷规则：GJ Open 默认按数据第一次公布的值判，后来的修订不改结果；问“宣布”的题，宣布了就算，问“生效”的题，要真生效才算（[GJ Open FAQ](https://gjopen.com/faq)）。

### 对 Alex 两个假设的结论

- embedding：对一半。它能跨措辞、跨中英文找到“可能相关”的观点，但判不了“是不是同一个”。
- 搜索引擎召回：对，但在我们这里召回大部分已经由对象完成了。一条信息标了 NVDA，就把 NVDA 开着的两三条观点全拿出来，不用搜，也不会漏。搜索只在四处用得上：清单超过上限时排序；主题的标注比较模糊，给主题候选补一网；定期查重时跨全库找相像的；人查历史。搜到第一名也不能直接合并。

### 推荐的做法

**1. 怎么比去重**

```
一条信息抽完（候选观点 + 证据，都带出处）
 ↓ 代码：取这条信息标到的每个对象的全部开着的观点
 │       （同一对象的信息一条一条处理，D31 的单写入者）
 ↓ 模型：一次“对上”调用，不读原文，只读候选、证据和观点清单
 │   ├─ 每个候选：是清单里的哪一条（写编号）／新的／拿不准，写理由
 │   └─ 每条证据：推的是清单里的哪几条（可以零条、一条或几条）
 ↓ 代码：编号必须在清单里，不在的拒绝
     ├─ 同一条 → 只挂证据，到期日和五格用已有的
     ├─ 新的 → 建观点，五格和到期日从此定死
     └─ 拿不准 → 先建，标“待查重”
定期查重：同一对象开着的观点再两两比一遍（主题跨全库，用检索找相像的）
     确认重复 → 后建的那条关掉，记“并入 X”，它的连线挪到 X，X 重判
```

例：AMD 的 8-K 进来，标到 AMD 和主题“芯片出口管制”。清单里有主题观点“H20 这一档芯片对华出口许可”和 AMD 自己的两条。候选“这一档芯片对华出口许可会怎样”选中已有那条；“预计计提约 8 亿美元”这条证据推的是 AMD 的中国区收入。

**2. 怎么纳入证据**

- 证据只存一次。同一份文件被重复抽取，用同一条证据；二十家转述同一条独家，各自留出处，记同一个原始来源，重判时按原始来源算一个。
- 连线由“对上”调用写（推哪几条），方向由之后的重判写（往哪边推）。
- 证据不复制给依赖它的观点，依赖只传通知（第 7 步）。
- 每条信息、每条被碰到的观点只重判一次：读这条观点的全部证据（转述折成一组）和依赖的观点的现状，写新状态、每条连线的方向和引用；代码核对引用的证据确实连在这条观点上。

**3. 怎么存、怎么保留血缘**

```
信息：不存原文，只记上游编号和版本、公布时间、分发序号
└─ 证据：一句话或一个数｜出处｜层｜原始来源｜事情发生的时间｜被哪一版修正替代（如有）
     └─ 连线 → 观点（哪次对上建的；往哪边推，每次重判各记一次）
观点：对象｜看的是什么｜问题｜五格｜到期日｜判卷看哪个来源｜从哪条信息建的｜接着哪条旧观点（可选）
├─ 依赖 → 另一条观点（方向；什么时候建的）
├─ 重判记录（只追加）：第几版｜读了哪些证据、依赖的哪一版｜状态、现在在哪一格、引用｜换没换格｜Config 版本｜原始请求和返回
└─ 关闭记录：答案和出处｜关闭前最后的状态｜或“并入 X”
对上记录（只追加）：这条信息的每个候选 → 哪条／新的／拿不准；每条证据 → 连哪几条；理由；Config 版本
```

- 只追加，不改不删。观点的问题、五格、到期日写下就不动；变的只有新加的记录。
- 两个时间：事情什么时候发生、公布，和系统什么时候收到（分发序号）。“某天我们当时怎么判”，就是取那天以前的记录。
- 晚到的信息：收到时重判，不倒回去改过去的状态。修正版：新版本的证据替代旧的，用于以后的重判；旧的留着，标“被替代”；过去的重判记录不改。
- 判卷：按梯子写明的来源，用第一次公布的值；后来的修订记下来，但不改这条观点的答案。
- 换模型、换提示词：每条重判记录都带 Config 版本。新版本可以拿已经关掉、有答案的观点做试算，看判得准不准；试算单独存，不覆盖历史。关掉的观点越多，这个考题库越大，系统就是这样越改越好、又不丢血缘。
- 存在哪：一个关系数据库就够，记录都是只追加的表；全文检索和向量检索建在同一个库里，是随时能重建的索引，不是原始记录。规模（约 1,400 条开着的观点、一年约 180 万条证据，Codex 估算）不需要单独的向量库或图数据库，依赖箭头用表和递归查询就行。

### 1. 有区别吗

结构一样（问题、五格、到期日、两个位置、证据、连线、依赖），流程也一样（对上、挂证据、重判、换格通知）。不一样的有四处，后两处会改第 11 步的做法：

2. **量和扇出。** 主题观点证据多（美联储天天有人讲话），被依赖得多（两百家）；对象观点证据少，几乎没人依赖它。重判的花费和换格通知的压力都在主题上。
3. **对上用的“键”不一样。** 对象是股票代码，信息标得准，拿这个对象开着的观点就够了。主题标得模糊：一条“中国限制镓出口”的新闻，可能标“芯片出口管制”，也可能标“中美贸易”；同一件事可能被挂到两个主题下。所以主题观点的身份实际上只看“看的是什么”，主题只是个文件夹；对上时要和全部主题观点比。主题观点有一百多条，整份给模型太长，这里才真的要先用检索（BM25 + embedding）挑出几条，再让模型选。
4. **箭头总是指向主题。** 对象观点依赖主题观点（主题也可以依赖主题），反过来没有。建一条对象观点时，要从一百多条主题观点里找它依赖哪几条，也要检索。

### 链表：存血缘对，但它不决定箭头读哪一条

Alex 的链表是对的：同一样东西一期接一期，用“接续”连起来，就是血缘。

```
美联储 2026 年末利率 ──接续──→ 美联储 2027 年末利率 ──接续──→ 美联储 2028 年末利率
```

现实里一样的做法：git 每个提交记父提交；Zenodo 每个版本有自己的 DOI，另有一个总指最新版本的“概念 DOI”；Wikidata 合并重复条目后，旧条目变成重定向，指向它的链接照样能用。

两边一起发现的缺口：链表只回答“从哪来”，不回答“JPM 现在该读哪一条”。第 12 步第 2 条定了今年、明年可以同时开着，链上同时有两条开着的，“读最新的”“读第一条开着的”都说不清。而且 JPM“2027 全年净利息收入”真正要的，本来就是美联储 2027 那条，不是“美联储最新的那条”。

所以箭头按观点的种类读，像期货代码一样分两种：

```
箭头怎么读
├─ 数字的观点：钉住年份（像具体合约 CLZ26）
│   JPM 2027 净利息收入 ──→ 美联储 2027 年末利率
│   ├─ 那条关了 → 读它的答案，答案本来就是要的输入，不算断
│   └─ 那条还没建 → 箭头记“等着”；它建出来时自动连上，JPM 重判一次
└─ 事件的观点：顺着链走（像通用代码 CL1，到期换到下一个）
    NVDA FY27 中国区收入 ──→ H20 这一档对华出口许可
    ├─ 原来那条开着 → 读它
    ├─ 关了，有接续的 → 读接续的那条，记一笔
    └─ 关了，没有接续 → 读它的答案，标“只是历史”
```

第 12 步第 1 条（箭头会断）就这样解了：数字的箭头不会断，因为本来就该读那一年；事件的箭头顺着链走，链不会断，因为记录只追加，旧观点永远在。

链表要补的几条规矩：

1. **三种关系分开记**，都是只追加的记录：接续（下一期）、并入（查重发现是重复）、依赖（箭头）。接续不等于同一条，并入不等于接续。
2. **不能分叉**：一条观点最多被接续一次，代码查。一条写坏了要拆成两条时，不算接续；依赖它的箭头收到通知，重判时重新挑。
3. **接续的那条五格方向不变**（第一格永远是同一头），门槛可以重定。所以不能按“第几格”继承，只按“哪一头”。数字的梯子代码能查方向。
4. **接错了**，追加一条“撤销接续”，不改原记录。
5. **换了读哪一条，也要重判**：原规矩是“换格才通知”；顺着链换到下一条、补上一条等着的箭头、上游答不出，这三种情况即使没换格也通知重判。
6. **每次重判记下实际读的是哪一条、哪一版**（第 11 步的重判记录里已有，这里写明）。
7. **新的一期建出来时，依赖照上一期的挪一年**，由模型确认：JPM 2028 照着 JPM 2027 的依赖，提议连美联储 2028。这是链表的另一个用处。

### 其余四个问题

**第 3 条：时点的数和一段时间的数。** 财报的 XBRL 早就这么分：收入、利润是一段时间的数（duration），资产、负债是时点的数（instant）。数字的梯子写明是哪种：一段时间的数，答案公布前没有“现在在哪一格”，季度数是证据；时点的数，代码拿最近公布的值定“现在在哪一格”，同时记这个值是哪天的、哪天公布的。这只是当前参照，不是答案；梯子比的起点在建观点时定死。

**第 4 条：答不出。** 关掉一条观点只有三种方式：出答案；答不出（写明原因：不再披露、对象退出名单、事情本身没了）；并入。答不出不算准不准；依赖它的观点收到通知，标明缺了这个输入，不能把“没有答案”当成中性。下载或解析失败是处理故障，照 D31 重试，不能当成答不出。

另外一条边界：期末已过、答案还没公布（比如财年结束到年报发布之间），这条观点在“等答案”，不占“今年、明年两条”的名额。

**第 5 条：后建的主题没人连。** 两种情况分开：

- 等着的箭头：数字的箭头钉住了一个还没建的年份，那一年一建出来就自动连上（见上）。
- 真正新的一条主题观点（没有接续谁）：建出来时，把全部开着的观点（对象的和主题的都要）分批过一遍，由模型挑出该依赖它的，每条写一句是怎么影响的和方向，追加箭头，这些观点重判一次。新主题很少，全过一遍花得起；只取检索的前几名会漏掉排在后面的。新主题如果其实是旧主题的接续，先走接续，不另加平行的箭头。

**第 6 条：重复重判。** 一条信息引起的所有变化算一轮。先把这一轮的挂证据、建观点、接续和补箭头都做完，再按依赖先后重判：上游这一轮判完，下游才判，每条观点这一轮只提交一次。上游没换格，那条路就停。电子表格重算、响应式系统避免“毛刺”（下游读到新旧混杂的输入）都是这么做的。注意不能“先判、再把第二个通知当重复丢掉”，那样 JPM 会停在“新美联储加旧十年期”上。环的检查也按每轮实际读的那张图做：加箭头、顺着链换下一条时都查。

### 合并以后还剩的

- **事件的“同一件事”边界。** 换一年、重定门槛，明确可以接续；H20 这一档变成“所有对华 AI 芯片”，就不是接续，是新的。中间地带要拿真实案例定。
- **问题本身问得对不对。** JPM 的净利息收入其实看全年利率路径，不只看年末那一个数（Codex 提的）。这是起问题的事，链表和箭头补救不了；建主题观点时要问清依赖它的人要的是哪个数。
- **退出名单的观点算不算成绩。** 不算的话，差的预测可能因为退出名单而从成绩里消失。先记下原因，以后再定。

### 整条流程（一条信息一轮，按分发序号）

```
抽取交来：这条信息的候选观点 + 证据（都带出处）+ 标到的对象

 ↓ 2 收证据（代码）

 │    同一对象同一时间的名额（事件一条，数字今年、明年两条）
 ↓ 6 写进库（各对象自己的队列，先主题后对象）

 ↓ 7 新题要连依赖（模型）：从开着的主题观点里挑（检索补候选），写方向和一句怎么影响；
```

### 改一处：对上问的是“挂到哪”，不只是“是不是同一条”

仿真：库里有“NVDA FY27 中国区数据中心收入”。一篇报道写 H20 在中国卖不动，抽取提了候选“NVDA FY27 H20 在中国的收入”。它和已有的那条不是同一样东西，按“是不是同一条”会判成新题；可分析师不会为它单开一个争论，它就是中国区收入那个争论的证据。只问“是不是同一条”，这类候选会一条条长成新题，又回到观点越长越多的老路。

所以对上时，候选分五种结果：

| 结果 | 什么时候 | 写什么 |
|---|---|---|
| 挂到 #k | 候选看的就是 #k 那样东西，或者是它的一部分（H20 在中国的收入是中国区收入的一部分） | 只挂证据；候选的问题、五格、日期都不要 |
| 接续 #k | 同一样东西的下一年（数字）；或那条已经关了，接着看（事件） | 建新观点，记接续 |
| 新题 | 另一样东西，会和已有的各走各的（Blackwell 对华许可 vs H20 这一档） | 建新观点，五格、日期定死 |
| 不开 | 候选太宽，捆了几样东西（“美国对华芯片管制”） | 不建；它的证据照逐条的连线挂到各自的观点上 |
| 拿不准 | 说不清 | 还没定（第 11 步的问题） |

这和 Alex 的“已经存在的观点就 merge”是一个方向：只要属于已有的争论，就挂过去。新题的门槛提高到“另一样东西”。

### 合并有三种，各在不同的时候

| 合并 | 什么时候发生 | 做什么 |
|---|---|---|
| 挂到已有的 | 每条信息对上时 | 只加证据和连线 |
| 接续 | 对上时，同一样东西的下一期 | 新观点，记接续；依赖照上一期挪一年 |
| 并入 | 定期查重（每天一次）：同一对象开着的观点两两比，主题观点跨全部主题用检索找相像的 | 后建的那条关掉，记“并入 X”；它的连线加到 X 上；指向它的箭头顺着“并入”读到 X；X 重判 |

### 仿真找到的问题和解法

1. **同一句话在上游、下游算两次。** 8-K 里“H20 要许可证”挂在出口许可那条主题观点上；对上时它也可能被连到 NVDA 中国区收入上。NVDA 重判时既读到这句话，又读到出口许可那条的状态，等于算了两次。解法：重判 B 时，代码把同时连在 B 所依赖的观点上的证据标出来：“这条已经算进 A 了”。
2. **主题观点的范围要按管它的那条规定来定。** AMD 的 8-K 说 MI308 要许可证。如果已有那条写的是“H20 对华许可”，模型可能判成新题；写成“2025-04 那条规定管的这一档芯片（H20、MI308 等）”，就会挂上去。这是写问题的规矩，放进抽取提示词；漏掉的由查重来并。
3. **两条信息同时提同一道新题。** NVDA 和 AMD 的 8-K 在各自的队列里同时对上，清单都是空的，都判新题。主题观点只由主题自己的队列写，第二条写的时候发现清单变了，重新对上（D31 已有这条规矩）。
4. **超出年份的数字候选。** FOMC 声明里有 2027 年的点阵图，候选“2027 年末利率”超出今年、明年。代码在对上前就筛掉；相关的证据如果连到了 2026 那条就留着，没连到任何观点就不存。
5. **没标到的对象收不到证据。** 台积电法说会说“最大客户在中国的出货下降”，没点名 NVDA，这条信息只标了 TSM，NVDA 的观点收不到。这是标对象这一步的边界（D11），第一版不做跨对象的逐条检索，先记下来，建之前量一下有多少。
6. **主题不在名单里。** 候选“中国限制采购 H20 这类芯片”找不到对应的主题对象。观点只能挂在名单里的对象上，这条不建、记原因；名单怎么加主题是研究对象名单模块的事（已冻结）。

## 第 15 步：像搜索引擎一样“先搜再判”；裁判除了模型还有什么（讨论中）

### Alex 的思路对在哪里

“先搜出几个候选，再由裁判定”是各行的标准做法：实体解析叫 blocking + matching，搜索叫召回 + 重排。人的做法也一样：Stack Overflow 在你提问时先列出“相似的问题”让你自己看；事后社区再把重复的问题关掉，留一个指向原问题的路标（[Stack Overflow 处理重复问题](https://stackoverflow.blog/2009/04/29/handling-duplicate-questions/)）。这正对应我们的对上（进来时先比）和定期查重（事后并入，留“并入 X”）。

### 要改三处

1. **公司的“搜”就是打开文件夹。** 分析师看到一条 NVDA 的新闻，会打开 NVDA 那两三个争论，而不是搜整个库。公司观点按对象全拿出来就行，不用搜，也不会漏；真要搜的是主题观点（标得模糊、一百多条）和定期查重。
2. **“像不像”当不了裁判。** 相似度分数高不等于同一道题：“H20 对华许可”和“Blackwell 对华许可”分数很高，却是两道题；“H20 在中国的收入”和“中国区收入”分数没那么高，却该挂上去；看多和看空的两个说法是同一道题。
3. **“匹配得弱就开新题”最容易错。** 同一件事换了说法，分数就会偏低：管理层说“中国的压力在缓解”，卖方写“出口许可放宽”。各领域的研究都说“判为新”是更难的一半（第 11 步）。所以弱匹配应该交给裁判，不能直接开新题。

### 不用模型的话，市场上有什么裁判

| 裁判 | 怎么判 | 好处 | 问题 |
|---|---|---|---|
| 钥匙对比（代码） | 两条看的是同一个“键”就是同一条：RavenPack 用“同一实体 + 同一事件类别” | 完全确定，零成本 | 只有能写成键的才行 |
| 相似度门槛 | 分数高于某条线就合并；Meedan 分三档：高于 0.95 自动归组，中间交人确认，其余算新（[Kazemi 2021](https://arxiv.org/pdf/2106.00853)） | 便宜，确定 | 门槛随话题、语言变（0.78–0.96）；上面三种难例都会判错 |
| 训练出来的匹配模型 | 把两段文字放在一起读，打“是不是同一个”的分（cross-encoder；Ditto 在两个几十万条的公司库上 F1 96.5%，[Ditto](https://arxiv.org/pdf/2004.00584)） | 准，快，确定 | 要按我们自己的“同一个”标几百上千对；现成的 Quora 重复问题模型不懂“一部分也挂上去” |
| 大模型 | 在前几名里选一个，写理由（[ComEM](https://arxiv.org/html/2405.16884v3)） | 不用训练，能照我们的规矩判，能解释 | 慢、贵、不完全确定；候选多了有位置偏差；不爱说“都不是” |

市场上的通行路线是两段：先用大模型当标注员，把它的判断攒下来，再训练一个小的匹配模型接手。用大模型标的训练数据，训出来的小模型和用人工标注的差不多，推理快 34–459 倍（[Steiner & Bizer 2026](https://arxiv.org/abs/2606.28823)）。

## 第 17 步：抽取时 thesis 和证据要同时出，还是只出 thesis（讨论中）

先分清一件事：信息里别人的“thesis”（卖方的论点、管理层的判断）在我们这里是证据（第三方看法、当事人说的），不是我们的观点。我们的观点是我们自己要盯的问题。

不能只抽 thesis 的原因：
- 状态只靠证据推。只抽 thesis，观点建出来以后就再也不动了。

- 贵的是读那份文件。同一遍顺手写出证据，多花的很少；分两遍读，文件就要读两次。

- 抽取一遍读完，主要交出证据，每条写明推的是第 5 块里的哪条已有观点；只有信息提出了库里没有的关键问题，才另外提一个新问题，只写对象、看的是什么（数字写哪一年和判卷来源）、一句问题。

## 第 18 步：证据怎么抽取，整条逻辑（讨论中）

已经定了的只有零散几条：证据是一句话或一个数，只存一次，带出处、层、原始来源、事情发生的时间；代码核对原文和数；对上决定连哪几条；方向在重判时写在连线上；没连到任何观点的不存。没讨论过的是从“读一份文件”到“交出一条证据”中间怎么走。

Claude 推的整条线：

```
一条信息（整份）
 ↓ 1 挑（模型，和抽候选观点是同一次读）
 │    对着给它看的观点清单找：哪些句子、哪些数，会让某条观点更可能落在某一格
 │    重复的背景、每年照抄的风险提示不挑；措辞变了的挑
 ↓ 2 写成一条证据（模型）
 │    原文一句（或表里一格）｜一句话说清（离开原文也看得懂：谁、做了什么、多少、哪一期）
 │    谁说的｜原始来源｜哪一层｜事情发生的时间｜推的是清单里哪条
 ↓ 3 核对（代码）：原文在不在这条信息里；数在不在那一句；层和原始来源对不对得上
 ↓ 4 交给观点库：对上定连哪几条；重判时写往哪边推，也可以写“不推”
```

例子（示意）：2025-08 一篇报道：“知情人士称，商务部开始发 H20 许可证，条件是上缴 15% 的中国收入。”
- 挑：会让“这一档芯片对华出口许可”更可能落在第 3 格，是证据。
- 一句话说清：美国商务部开始给 H20 对华出口发许可，条件是上缴 15% 的中国收入（2025-08）。
- 原始来源：未具名的知情人士 → 层是传闻：能推状态，不能动“现在在哪一格”。
- 几天后商务部或 NVDA 确认：那条确认是新的证据，层是发生的事，“现在在哪一格”才移到第 3 格。

推的时候发现的三处缺口：

1. 挑的时候看的清单，和对上时的清单不一样。抽取第 5 块只给标到的对象开着的观点；对上时还会检索补上主题观点。一句只和某条主题观点有关的话，抽取看不到那条观点，就不会挑出来，后面再也补不回来。提议：第 5 块给的清单，和对上用的清单一样（标到的对象开着的观点，加上检索补的主题观点），还要带上每条的五格（不给状态），让模型知道什么数、什么事会动它。
2. 只存原文一句，重判时看不懂。原文常有“this”“上述”“该季度”，离开上下文就不知道说的是谁、哪一期；重判又不读原文。提议：每条证据同时存两样：原文一句（给代码核对）和一句话说清（给对上和重判读）。业界做法：Claimify（ACL 2025）抽取能单独看懂的说法，只在有把握读对时才抽；Choi 等人（2021）把句子改写成离开上下文也能读懂、意思不变。
3. “发生的事”这一层门槛最高（只有它能动“现在在哪一格”），却只靠模型自己标。提议：代码加两条核对：原始来源没写明是谁（“知情人士”）的，只能是传闻；“发生的事”必须写明原始来源是官方、公司或数据发布方。

## 第 19 步：读一份信息时，什么是 thesis、什么是证据；一个提示词还是分开（讨论中）

Claude 承认第 18 步简化了：把 thesis 和证据当成文件里两种可以“抽出来”的东西，再问每句话属于哪种。这个问题本身问错了。

### 先把两样东西分清

- 文件里的一切，都是证据：谁说了什么、发生了什么、公布了什么数。卖方研报里的论点（“我们认为 NVDA 中国区收入会归零”），在我们这里也是证据，层是第三方看法。判断标准：能指着原文说“就是这一句”。
- 我们的观点（thesis）不在文件里。它是我们要盯的一个问题，是读了证据以后由我们提出来的。判断标准：它是一个问题，不是一句话；它得有五格和到期日，能在到期日用一个看得见的事实判卷。

所以读一份文件，不是给每句话分类，而是按顺序回答三个问题：

```
一条信息 + 这一类的提示词 + 观点清单（相关的观点，带五格，不带状态）
 ├─ 问 1：这份信息里，哪些话、哪些数，会让清单上某条观点更可能落在某一格？
 │        → 证据，写明推的是哪条
 ├─ 问 2：还有什么重要的事，清单上没有一条观点管？
 │        → 也是证据，标“清单外”
 └─ 问 3：问 2 里的事，值得新开一个问题吗？要过四道关：
          ① 会实质影响这个对象（主题：是世界上一件要紧的事）
          ② 结果还不确定
          ③ 一般 6–12 个月内有一个看得见的事实能判卷
          ④ 不是清单上某条观点，也不是它的一部分
          → 过关：候选观点，引用问 2 里提出它的证据
          → 不过关：问 2 的那几条证据不要（观点优先）
```

- 电话会里分析师反复追问的焦点，正是市场在争的问题，所以 T4 是新问题最常见的来源之一。

## 第 20 步：抽完以后，证据和新问题各自怎么进库（讨论中）

材料：Claude 补查了 GDELT、RavenPack、买方 thesis 跟踪的做法；Codex 独立研究了同一个问题，全文在 `reports/观点库重建 抽取后的证据和观点怎么进库（Codex 调研）.md`。

查到的：
- GDELT 把“事件”和“提到”分两张表：一件事存一次，每篇报道提到它另记一笔，分开记事情发生的时间和被提到的时间（[GDELT](https://blog.gdeltproject.org/complex-queries-combining-events-eventmentions-and-gkg/)）。
- 新闻里一半以上是跟进报道：一项研究按 RavenPack 的打法聚类，55% 的文章是已有故事的跟进（[arXiv 2608.14014](https://arxiv.org/pdf/2608.14014)）。
- 买方的 thesis 跟踪，每个新数据点只问“加强、削弱还是不影响哪一条支柱”；和哪条支柱都无关的数据点怎么办，公开做法里没写（[thesis-tracker](https://github.com/anthropics/financial-services/blob/main/plugins/vertical-plugins/equity-research/skills/thesis-tracker/SKILL.md)）。

Claude 原来的说法有一处错：“证据找不到已有观点，才考虑开新观点”。Codex 指出，这两件事是独立的。例：H20 的出口规定变了，这条证据推得到已有的“NVDA 中国区收入”；同时它也暴露出一个还没人盯的政策问题，前一件挂上了，不该挡住后一件。所以每条信息问两个各自独立的问题：

```
一条信息 → 读一遍 → 两样东西：一堆证据（几乎都有）＋ 零个或几个新问题（少）

证据，每条问：它推哪些已有观点？
  ├─ 推得到 → 挂上去（可以挂几条）
  │    └─ 只是转载已经有的消息 → 只多记一个出处，不算新的支持
  └─ 哪条都不推 → 不进观点库（处理记录留一笔，原文本来就在上游库里）

新问题，单独问：是我们还没盯、又值得盯的吗？（对上的五种去向照旧）
  ├─ 库里已经有 → 挂过去
  ├─ 值得、库里没有 → 开新观点，带着提出它的证据
  │    └─ 新：回头翻上游库里最近的相关信息，把有用的旧证据补进来（记原来的发布日，不改过去的判断）
  └─ 不值得 → 不开

最后：被碰到的观点各重判一次
```

两边一致的：
- 观点一定从证据来（至少一条证据提出它）；证据可以没有观点，新闻里的纯事实大多就是这样。
- 证据是每天进库的单位；新问题是“开题”，另外判断。
- 纯事实不进观点库：Alex 以前否定过“读什么都存”，原文本来就在上游库里。缺口是后来新开的观点会缺以前的相关证据，补法是开新观点时回头翻上游库（新观点很少，回翻花得起）。不另建一个临时的事实池：留三十天，第三十一天的照样漏；留得越久越像事实仓库。
- 去重分三样：说的是什么、凭什么说（具体哪一次披露、哪一次采访）、推哪条观点。二十家转载同一条独家：一组，算一份；不同来源独立确认：分别算；同一来源的修正版：替代旧的；同一份文件正文和表格说同一个数：一份，两个位置。原始来源要具体到哪一次披露，不能只写机构名；数一样不等于是同一个数。

等 Alex 定：纯事实不进观点库；开新观点时回头翻上游库补旧证据（回看多久另定）。

Alex：“if you just have an evidence, how can you reverse search the database to find similar evidences and then just append to the right thesis? That doesn't even make sense … don't back off just because I'm challenging you. You gotta know for sure.”

## 第 21 步：证据只找观点，不找证据；第 20 步的“回翻”第一版不做（讨论中）

Alex 说得对：“拿一条证据去库里搜相似的证据，再挂到观点上”说不通。整个设计里也没有这一步，是第 20 步写得让人这么理解。把三处讲清楚：

1. 证据怎么找到观点：证据只和观点比，从不和别的证据比。比的是一张很短的观点清单：这家公司开着的两三条；标到主题时再检索补几条，检索的是主题观点的问题，不是证据。
2. 转载怎么不重复算：不用去搜旧证据。每条证据自己写着原始来源（具体到哪一次披露，比如“NVDA 8-K，2025-04-15”）；重判时模型看到二十条写着同一个原始来源，就只算一份。
3. 第 20 步提的“开新观点时回翻上游库”：搜的是“新问题”找旧信息，不是拿证据找证据，所以本身说得通。但想清楚以后，第一版不做：
   - 触发新观点的那条信息，通常自己就把来龙去脉讲了一遍。例：2025-09 中国市场监管总局说 NVDA 违反反垄断法，报道里会写“2024 年 12 月立案调查”，这一句就是证据。
   - 回翻要检索、再读几十份文件，准不准没测过（Codex 自己也把它列为最不确定的一点）。
   - 和第 10 步定的一致：新观点从触发它的那条信息和依赖的现状开始，不搬旧证据。
   - 以后在存下的数据上量“新观点漏掉了多少要紧的旧事”，漏得多再加。

第一版的整条线：

## 第 28 步：互相依赖（环）怎么处理（讨论中）

### 先把问题说准

依赖在设计里干两件事：一是 B 重判时读 A 的现状（参考）；二是 A 变了，同一轮里马上让 B 重判（触发），而且“先判上游、再判下游”。出事的只有第二件：A、B 互相触发时，A 等 B 先判、B 等 A 先判，谁也先不了（这就是死锁）；硬让一个先判，又会 A 改 → B 改 → A 改……停不下来。读别人的现状本身不会出事。

### 现实里别人怎么处理

- Excel 的循环引用：默认报错；打开“迭代计算”以后，最多算 100 次，或者每次变化都小于 0.001 就停（[Microsoft](https://support.microsoft.com/office/remove-or-allow-a-circular-reference-8540bd0f-6e97-4483-bcf7-1b49cd50d123)）。
- 动态贝叶斯网络、带滞后的经济模型：同一时刻不许有环，反馈画成跨时间的箭头（今天的价格影响明天的需求），展开以后还是无环的（[DBN](https://arxiv.org/pdf/1603.06125)）。数字电路也一样：反馈必须经过一个时钟。

我们的模型调用很贵，判断也不一定收敛，不适合 Excel 那样来回迭代；跨时间这个思路适合。

### 提议：箭头分两种，触发只能往一个方向走

1. 每条依赖照实记下来，不管是不是互相依赖。箭头分两种：
   - 触发：A 有变化，同一轮里马上让 B 重判。用在影响来得快的那一头。
   - 参考：B 重判时读 A 的现状，但 A 变了不马上叫 B。用在影响来得慢的那一头。
2. 触发箭头不许成环，代码查。建依赖时模型写明快还是慢；新的触发箭头会闭成环时，代码不收，让模型指出环上最慢的那一条，把它改成参考，留记录。
3. 每一轮只顺着触发箭头走，先上游后下游，每条观点最多判一次，一定走得完。
4. 参考的那一头也不会丢：B 不管因为什么被重判，都会读到 A 的最新现状；另外 Pull 模式每天做一次“补判”：参考输入变过、自己还没重判的观点，各判一次（同样按触发箭头的先后，每条一次）。
5. 回声不算新依据：A 这次变，是因为前面 B 变了（重判记录里查得到起因），B 补判时读到 A，只当背景，不能拿它当理由再往同一边推，否则两条观点互相抬。
6. 来回翻的刹车：一条观点在没有新证据的情况下，补判时又翻回刚离开的那一格，就停在原处，标出来给人看。

### 三个例子

```
原油 ↔ OPEC+
  OPEC+ 产量 ──触发──→ 原油价格（增产，价格马上反应）
  原油价格 ──参考──→ OPEC+ 产量（OPEC+ 开会才调整，慢）
  OPEC+ 宣布增产：同一轮判产量、再判油价，结束。第二天补判产量（读到油价跌了），可能判“增产会放慢”。

美联储 ↔ 通胀
  通胀 ──触发──→ 美联储利率（美联储对通胀数据反应快）
  美联储利率 ──参考──→ 通胀（利率影响通胀要一年左右）
  CPI 公布：判通胀 → 判美联储 → 美联储换格，再触发两百家依赖它的公司（这是一棵往下散开的树，没有环）。

NVDA ↔ 云厂商
  云厂商资本开支 ──触发──→ NVDA 数据中心收入
  NVDA 收入（供不上货）──参考──→ 云厂商资本开支
  NVDA 收入往上走，是因为资本开支先往上走：第二天补判资本开支时，读到 NVDA 收入上去了，代码标“回声”，不能当成需求更强的新证据。
```

规律：宏观到公司、上游到下游，一般是触发；公司反过来影响宏观（比如 AI 投资拉动整体增长），一般是参考。所以跨公司、全球宏观的观点再多，触发箭头还是一棵往下散开的树，一轮一定走得完。

代价：慢的那一头最多晚一天反映；补判要花调用，要量。

## 第 29 步：环是依赖定义错了，不是机制问题；第 28 步撤回（讨论中）

Alex 说得对。环是从一个混淆来的：把“对方会对我这个变量做出反应”，当成了两个观点之间的依赖。拆开看：

- 依赖的意思，应当是“B 的答案要用到 A 的答案”：A 是 B 的输入，A 揭晓得不比 B 晚。
- 对方对已经发生的事做出反应（看到价格、看到数据、看到决定），那是证据，不是依赖。

按这个定义重画第 28 步的三个例子，环都没有了：

```
原油价格（2026 年均价）──依赖──→ OPEC+ 配额（2026 年中的配额决定）
OPEC+ 配额：不依赖“油价”这条观点；OPEC+ 看的是已经发生的油价，每天的价格是它的证据

美联储（2026 年末利率）──依赖──→ 通胀（2026 核心 PCE）
通胀：不依赖“美联储”这条观点；已经发生的加息降息是它的证据（利率影响通胀要一年左右）

NVDA 数据中心收入 ──依赖──→ 云厂商资本开支
云厂商资本开支：不依赖“NVDA 收入”这条观点；NVDA 的交货期、供货情况这些已经发生的事是它的证据

竞争对手：NVDA 和 AMD 的观点互不依赖；谁拿下了哪个大客户，是两边各自的证据
```

推出来的规矩：
1. 依赖只连输入：B 的答案要用到 A 的答案，才连 B → A。对方已经发生的事，是证据。
2. 两个问题互为输入（同一时期一起决定），说明问题没定义好：要么合成一个问题，要么只留对投资判断有用的那个方向，另一个方向的影响走证据。
3. 代码不收会闭成环的箭头，退回给模型改写：是把反方向改成证据，还是把两个问题合成一个，留记录。
4. 这样所有依赖本来就是无环的：宏观在上，公司在下，供应链从需求往供给一个方向走。第 28 步的“触发、参考两种箭头”“每天补判”“回声”都不需要了，撤回。

### 补上这一步：和观点一个形状

```
观点：候选观点 → 打开这个对象的文件夹（开着的两三条）→ 挂上／接续／新观点／不开／拿不准
证据：一条证据 → 打开它挂上的那条观点（下面没被替代的证据）→ 重复／替代／新的
```

| | 观点 | 证据 |
|---|---|---|
| 先找到哪 | 这个对象的文件夹：开着的两三条（主题用检索） | 它挂上的那条观点（抽取时已经挂好）：下面没被替代的证据 |
| 判什么 | 挂上／接续／新观点／不开／拿不准 | 重复／替代／新的 |
| 链 | 接续：美联储 2026 年末利率 → 2027 → 2028 | 替代：AMZN 资本开支指引 12% → 25% → 30% |
| 什么算现在 | 链上开着的那条 | 链上最新的那条 |
| 搜全库吗 | 不搜 | 不搜；也不拿证据去搜证据、再找观点 |

### 三种结果

```
一条新证据挂上观点 #k 以后｜它和 #k 下没被替代的证据比
├─ 重复：说的就是其中一条（转载；正文和表格里的同一个数；同一个人把同样的话再说一遍）
│   └─ 那条多记一个出处；证据不多，这条观点不重判
├─ 替代：让其中一条或几条过时
│   ├─ 同一个人后来改了说法或数：指引、预测、状态、时点数的新值
│   ├─ 官方证实或否认了一条传闻
│   └─ 新的这条算数；旧的标“被替代”，指向新的，留在历史里；重判
└─ 新的：别的都是：新的事、另一期的数、另一个人自己的说法或观察（说法相反的也是）
    └─ 加进来，和别的一起算数；重判
拿不准 → 当新的（最坏也就是现在的样子：两条都算数，重判自己看）
```

- 证据是一句话或一个数，替掉的只是那一句。卖方新报告改了收入预测，替掉的是它上一份里的那个预测；上一份里别的论据没被改，照样算数。

### 库里怎么存

```
观点 #k
└─ 连线 → 证据（只存一次）
           ├─ 出处：一个或几个（转载、重申都记在这里，各带发布日）
           └─ 被替代：指向替代它的那条（链：12% → 25% → 30%）
对上记录：每条证据和哪几条比、判了什么、为什么
重判读：#k 下没被替代的证据（每条带上它替掉的那条，看得到变化）＋这一轮的变化（旧 → 新）＋依赖的现状
```

还是只追加：被替代、多一个出处，都是新加的记录，旧的不改不删。“某天我们当时知道什么”，就是取那天以前的记录。

### 一条信息进来，库里动什么

```
一条信息
 ├─ 1 拿卡片（代码）：按对象编号拿开着的观点，加上一层依赖
 ├─ 2 抽取（模型，读全文）：证据挂到卡片上；卡片外的写便条
 ├─ 3 对上（模型，不读原文）：便条找观点（照旧）；每条证据和它那张卡片下没被替代的证据比：重复／替代／新的
 ├─ 4 写进库（代码）：照结果写；核对编号确实在那张卡片下、没被替代
 ├─ 5 重判（模型）：只判这一轮有替代或新的的观点；只多了重复的，不判
 └─ 6 通知下游：照现在的规矩
库里其余的观点和证据：一条不动
```

一条证据动的东西只有三样：它挂上的那一两条观点下的证据（加进来，或替掉旧的），这些观点的状态，依赖它们的观点。不搜全库。对上比的是证据的“一句话说清”（第 18 步第 2 处、第 25 步第 4 条），两边都是这一句，所以不用读原文；抽取的卡片照旧不带证据和状态（D41）。

代价：每条信息多一次不读原文的短调用（原来只有便条才对上）；只多了重复的观点，省掉一次重判；重判读的东西变少。

| 对象观点 | 挂在能交易的对象上（公司、加密货币、商品）；五格是强烈看多、看多、中性、看空、强烈看空 | NVDA 中国区收入 |
| 主题观点 | 挂在主题上（宏观、政策、行业）；五格是一条轴上的五种结果，用结果命名，没有看多看空 | 美联储利率：大幅降息……大幅加息 |
| 梯子（ladder） | 这个问题所有可能的答案，固定五格（对象观点标看多看空，主题观点用结果命名）；由模型在建观点时定，定了到期以前不改；各格不重叠、盖住所有可能，到期时正好一格成立；每一格是一个是或否的条件；没有“部分”，“部分”要单独写成一格；只有两种结果的事按程度分成五格；中性跟什么比，写在那一格的条件里 | 涨 50% 以上／涨 10% 到 50%／变动在 10% 以内／降 10% 到 80%／降 80% 以上 |
| 数字的梯子 | 同一个数在写明的那一年的几段区间，由代码判；到期日就是这个数公布的那天；写明是一段时间的数（收入）还是时点的数（政策利率） | NVDA FY27 中国区收入同比 |
| 事件的梯子 | 同一件事到期那天可能处在的几种状态，写清是哪个阶段（宣布、签署、生效、执行）；由模型判是或否，只看“发生的事”，写明依据 | 全面禁止／要许可、基本不发／附条件发／普遍发／不再要许可 |
| 现在在哪一格 | 事实，只由“发生的事”这一层的证据定；到期那天就是答案；一段时间的数在答案公布前没有这个位置，时点的数由代码按最近公布的值定（记下是哪天的值） | 2025-08：附条件发 |
| 状态 | 我们认为到期会在哪一格；是判断，由模型挪：每次都从这条观点的全部证据、加上它依赖的观点的现状重新判，不在上一个状态上加减；证据一样，状态就一样；每次记下哪天、依据哪几条证据 | 看到 8-K 以后：强烈看空 |
| 证据 | 信息里的一句话或一个数，客观记录，只存一次，带出处和层；本身不带方向 | NVDA 8-K：“H20 出口中国要许可证，预计计提约 55 亿美元” |
| 连线 | 一条证据和一条观点之间的线，记这条证据把这条观点往哪边推；由重判那次调用写；同一句话可以连几条观点，各推各的 | 8-K 里的计提 → NVDA 中国区收入：推向强烈看空 |
| 出处 | 证据连回管道的那根线：上游编号和版本、哪一段、原文那一句 | 8-K 的申报编号、第几段 |
| 层 | 证据是哪一种：发生的事、当事人说的、第三方看法、传闻；只有发生的事能动“现在在哪一格”，四层都能推状态，推多远由模型判；独立来源按原始来源数 | 8-K 里的计提是发生的事；“知情人士称”是传闻 |
| 依赖 | 一条观点指向另一条观点的箭头：B 的答案要看 A；箭头上记一个方向（A 的哪一头对 B 是看多；两条主题之间就是同向或反向）；看起来要“先好后坏”，说明中间还有一条观点没写出来，要拆出来；箭头按种类读：数字的观点钉住年份（那条关了读它的答案，还没建就等着，建出来自动连上），事件的观点顺着接续往下走；A 换了格、或者 B 读的那条换了，才通知 B，不搬证据，由模型重判 B；B 每次读的是哪一条、哪一版记在重判记录里；不能绕成环 | NVDA 中国区收入 ──放松那头看多──→ H20 这一档芯片对华出口许可 |
| 接续 | 同一样东西的下一条观点接着上一条，连成一条链，存血缘；一条最多被接续一次；接续的那条五格方向不变，门槛可以重定；接错了追加一条撤销；新一期的依赖照上一期的挪一年，由模型确认 | 美联储 2026 年末利率 → 美联储 2027 年末利率 |
| 对上 | 一次模型调用，不读原文：每个候选观点是已有的哪一条、新的还是拿不准；每条证据推的是哪几条观点 | AMD 的 8-K：候选选中已有的出口许可那条 |
| 关掉 | 一条观点结束的三种方式：出答案；答不出（写明原因，不算准不准）；并入另一条（查重发现重复）；期末已过、答案没出的叫“等答案”，不占今年、明年两条的名额 | NVDA 不再单独披露中国区收入 → 答不出 |

不再用的：单独存的检验条件（证实条件和证伪条件）由梯子代替；“前提”改叫依赖；“驱动”这一层由问题本身代替；证实和证伪由“拿答案对状态”代替。

### 设计逻辑

1. 观点是一个问题，不是一句断言。所以观点长什么样，不看哪条信息先到；反方向的说法也有地方放，就是把状态往另一头推，不用另建一条观点。
2. 梯子的每一格都写成看得见的结果，由模型在建观点的时候写好，到期以前不改。什么事实会证明我们错了，事先就写在上面，事后挪不了球门；模型判的是“这件事落在哪一格”，判得确定。
3. 事实和判断分开放。“现在在哪一格”只有发生的事能动；状态是我们的判断，各层证据都能推，每次都从全部证据重新判，写明依据，由代码核对这些证据确实挂在这条观点下。证据一样，状态就一样，晚到的和修正过的信息不会因为处理先后不同而得出不同的状态。
4. 到期那天，“现在在哪一格”就是答案，拿它对状态，就知道判得准不准。
5. 一个观点只看一件东西：一个数，或一件事的状态。既要数字又要事件的、两部分可能往相反方向走的，都拆成两条，用依赖连起来。
6. 和管道的连接：每条证据的出处指向管道里的一条信息。从一条观点能查到推过它的全部信息，从一条信息也能查到它推过的全部观点。
7. 对象观点和主题观点分开：结构一样，只有五格的意思不一样。同一件世界上的事，对不同的对象可能好坏相反，所以主题观点不说好坏，好坏由每个对象依赖它的箭头来说。
8. 去重：观点的身份是“对象 + 看的是什么”，不含日期。新来的候选观点和这个对象还开着的观点看的是同一样东西，就合并：只把证据挂过去，到期日和五格都用已有的。怎么认是不是同一样东西，由模型在这个对象还开着的观点里挑，写明理由。已经关掉的不合并，开新观点；新观点从现在的情况开始（回答旧观点的那份信息、依赖的观点的现状），不搬旧证据。
9. 依赖的箭头只有一个方向；被依赖的观点换了格才通知，没换格不通知。
10. 链和箭头：同一样东西一条接一条连成链，存血缘。数字的箭头钉住年份，不会断；事件的箭头顺着链走，记录只追加，链也不会断。新主题观点（不接续谁）建出来时，把全部开着的观点过一遍，补上该有的箭头。
11. 只追加：观点的问题、五格、到期日写下就不动；对上、重判、接续、关掉、并入都是新加的记录，带分发序号。“某天我们当时怎么判”就是取那天以前的记录；晚到的信息收到时重判，不倒改过去。判卷用第一次公布的值。
12. 一条信息引起的变化算一轮：先做完挂证据、建观点、接续和补箭头，再按依赖先后重判，上游这一轮判完下游才判，每条观点每轮只提交一次。

### 会影响到的冻结模块

抽取交出的东西要变：大多数信息只读出证据，少数信息才提出一个候选观点；提示词第 5 块从“这些对象已有的驱动”改成“这些对象已有的观点”（只给看的是什么，不给状态）。对上和合并仍在观点库（D33）。抽取已经冻结（D37），等观点库定下来以后再记一条新决定。

还会改到的已有决定：D26（观点库的结构）、D27 和 D33（对上和写进库）、D29（最终判定怎么关观点）、D31（晚到的信息、依赖的连法）。

## 暂时放着的问题

- 共识：现实里每个观点都和市场已经定价的比。照第 6 步，共识可以是同一把梯子上的第三个位置：市场认为到期会在哪一格。
- 催化剂：数字观点的到期日就是它的催化剂（第 9 步）；事件观点到期以前的中间日期（比如规定的生效日、征求意见截止日）还没有地方放。
- 什么样的问题算关键问题，每个对象几条：现实里每只股票只盯 2–3 个。去重只管住同一个问题问两遍，管不住问太多不同的小问题；整份清单的去重也靠这一条成立（第 11 步）。
- 建之前要在存下的信息上量（第 11 步）：每个对象开着几条观点；“新的”判得准不准；候选顺序打乱以后结果变不变；热点观点半年积累多少条证据。
- 利率、汇率、指数的期货能交易，但名单把它们放在主题下（D11，已冻结），它们价格的看多看空没有地方放。
- 拿不准是同一条还是新的时，先建新的、再定期查重来并，还是先并进最像的那条（第 11 步）。
- 事件的“同一件事”边界：什么算接续，什么算新的，要拿真实案例定（第 13 步）。
- 退出名单的观点算不算成绩（第 13 步）。
