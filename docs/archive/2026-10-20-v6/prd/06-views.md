## 一句话

系统的核心。一条观点是一个问题、一把梯子和一个到期日，写下不改；证据把我们的判断往两头推，到期拿答案对一下，就知道判得准不准。抽取交来两样东西，在这里各走一条线、走法一样：候选观点和搜出来的几条已有观点比，由模型判是哪一条、接续，还是开新的；证据和它那条观点下已有的证据比，是重复、替代还是新证据；只是重复的，不重判。

## 为什么这样设计

- Alex 给这个模块定的要求：“store the theses, the evidence, and the ladder in a very, very clear data structure manner that has linkages to whatever is passing through the data pipeline.” 观点、证据、梯子各有清楚的结构，每条证据都连回管道里的一条信息。
- 观点是一个问题加一个状态，不是一句断言（Alex：“这个 hypo 更像是一个 thesis with a state”）。反方向的说法不用另建一条观点，只是把状态往另一头推。
- 梯子事先写死，每一格是能核对的结果：什么事实会证明我们错了，建观点时就写在上面，事后挪不了球门。现实里的对照：卖方的牛、基准、熊三种情景，买方事先写下的止损条件，超级预测者要求每个问题有明确的判定标准。
- 状态是判断，由模型判，要尽量确定、只按事实（Alex：“这个基本要 deterministic 一点，模型的设置 temperature 要让他基本不会幻觉，只是基于事实来评价”）：每次从这条观点下没被替代的全部证据重新判，不在上一次的基础上加减；替代按这句话是哪天说的排先后，晚到的旧说法不会把现在算数的拉回去。
- 对象观点和主题观点分开（Alex：“有些事情不一定对所有人都是 bull / bear，有可能完全相反”）。主题观点只说世界会变成什么样，好坏由依赖它的对象观点自己说。
- 一条观点就是一个问题、一把梯子、一个到期日，里面不再分几期（Alex：“一条观点一定是有一个明确的 ladder 和到期日，这样才构成一个观点”）；到期日定在争论见分晓的那天，一般 6–12 个月，中间的季报是证据。
- 对上像人查东西：先搜出几条可能的，再判是不是同一条（Alex：“If I have a view, I go search it up. If something matches, then it's just the same view. If nothing matches, then essentially it's a new view, or it matches weekly, then it should be a new view”）。判的是模型，代码不替它判（Alex：“I just want LLM to do the matching”）。是同一条就并进去，日期用已有的（Alex：“已经存在的观点就 merge，日期遵照之前已经存在的期限”）。
- 证据和观点走一样的路（Alex 问过：“It's not clear to me how this logic is similar to thesis”）：先找到要比的，再和它比。候选观点比的是搜出来的几条已有观点，证据比的是它那条观点下搜出来的证据。不比的话，一条观点下的证据只增不减：2 月的“资本开支涨 12%”和 4 月的“改成 25%”并排放着，重判每次都得自己从一堆里分出哪条过时了，分完也不留下。
- 重复、替代在进库时判一次、记下来，就是让模型自己给证据做加和删（Alex：“这个难道 LLM 不能自己 append delete evidence 吗”）；被替代的只是不再算数，留在历史里，不删。只是重复的不重判，别人转述一遍，不用再调一次模型才知道什么都没变。
- 只有是或否的问题用两格，不硬分五格（Alex：“如果只有是否就不用硬分，可以 binary”）。
- 连不连依赖由模型判，像分析师一样写出“这条观点的结果要靠哪几条观点的结果”；看起来互相依赖的两个问题，是观点没起好（Alex：“我觉得这个应该是 thesis 的定义问题”）。防绕圈由代码管，会绕成圈的箭头不收，退回给模型改（Alex：“你自己要有 circular dependency avoidance 机制”）。
- 先用通用大模型做对上，让系统跑起来；每次都记下来，人标一部分，以后训练一个更快的小模型接手（Alex：“let's do a general LLM at this point because we need to make it work first … a logging system … human label … train a small model classifier that's faster”）。

## 结构

<!-- generated: structure -->
```
观点库
├─ 对象 → 名单里的公司、加密货币、商品、主题
│   └─ 观点 → 一个问题 + 一把梯子 + 一个到期日（写下不改；梯子五格，只有是或否的问题两格；同一个对象、看同一样东西，同一时间只开一条）
│       ├─ 状态 → 这条观点处在梯子的哪一格（证据把它往梯子的一头或另一头推，模型按事实判）
│       ├─ 连线 → 证据（证据只存一次，带出处和层；往哪边推记在连线上；被替代的证据留在历史里，不再算数）
│       ├─ 依赖 → 别的观点（箭头带一个方向：对方的哪一头对它是看多）
│       └─ 接续 → 上一期的观点（同一样东西一期接一期，连成一条链）
└─ 只追加的记录 → 对上记录、重判记录、关掉记录、标注（每一步都新加一条，不改不删；想知道某天当时怎么判，就翻那天以前的记录）
```

## 两种观点

<!-- generated: kinds -->
| 种类 | 属于什么 | 梯子的格 | 例子 |
|---|---|---|---|
| 对象观点 | 能交易的对象：公司、加密货币、商品 | 五格：强烈看多、看多、中性、看空、强烈看空；只有是或否的问题两格：看多、看空。说的是对业务好还是坏，建的时候定，以后不变 | NVDA FY27 全年中国区收入，比 FY26 会怎样？ |
| 主题观点 | 主题：宏观、政策、行业 | 一条轴上的几种结果（五格；只有是或否的问题两格），用结果命名，不说好坏；好坏由依赖它的对象观点各自的箭头说 | 美联储 2026 年最后一次议息后的目标利率上限，比现在会怎样？（大幅降息……大幅加息） |

同一件世界上的事，对不同的对象可能好坏相反：降息对以太坊是看多，对 JPM 的净利息收入是看空。所以主题观点不说好坏。对股价的看法，是我们的状态和共识（市场押在哪一格）差多少；共识怎么记还没定。
<!-- /generated: kinds -->

## 梯子

<!-- generated: ladder -->
```
两种梯子（区间示意）
├─ 对象观点（数字） → NVDA FY27 全年中国区收入，比 FY26｜五格：对 NVDA 的业务是好是坏（到期 = FY27 年报的财报日）
│   ├─ 强烈看多 → 涨 50% 及以上
│   ├─ 看多 → 涨 10% 及以上，不到 50%
│   ├─ 中性 → 涨不到 10%，或降不到 10%
│   ├─ 看空 → 降 10% 及以上，不到 80%
│   └─ 强烈看空 → 降 80% 及以上（基本归零）
└─ 主题观点（事件） → 2025-04 那条规定管的这一档芯片（H20、MI308 等）对华出口许可，到 2026-04-15 处在哪一格｜五格：一条轴上的结果，不说好坏（以那天已经生效的规定为准）
    ├─ 第 1 格 → 全面禁止，不再受理许可
    ├─ 第 2 格 → 要许可，一个都不发
    ├─ 第 3 格 → 要许可，发了，但有附条件的
    ├─ 第 4 格 → 要许可，发了，都不附条件
    └─ 第 5 格 → 不再要许可
```

1. 每把梯子五格：对象观点是强烈看多到强烈看空，说的是对业务好还是坏；主题观点是一条轴上的五种结果，用结果命名，不说好坏。只有是或否的问题用两格，不硬分五格：对象观点的两格是看多、看空；主题观点的两格用结果命名，比如“到期前签署了”“没签署”。
2. 每一格写成一个能核对的结果：可以是一个数落在哪段区间，也可以是一件事到了哪一步。格和格不重叠、不留空，到期时正好一格成立：涨 50% 及以上、涨 10% 及以上不到 50%、涨跌都不到 10%、降 10% 及以上不到 80%、降 80% 及以上，每个边界只属于一格，到期拿到实际数，一定落进其中一格；写成“涨很多、涨一点”就对不出来。没有含糊的“部分”：部分做到的，写清楚是什么，单独成一格（“发许可，但附条件”）。中性跟什么比，写在那一格的条件里。
3. 一把梯子只放一种东西，一个观点只看一件东西：既要数字又要事件的，拆成两条，用依赖连起来；两部分可能往相反方向走的（H20 这一档和 Blackwell 这一档），也是两条观点。
4. 梯子由模型在建观点时定，定了到期以前不改；后来并进来的候选观点，梯子和到期日都用已有的。
5. 数字的观点写明哪一年。今年就是这条信息进来那年，到 12 月 31 日；明年是下一年，到 12 月 31 日。公司的数按它的财年：信息进来时所在的那个财年是今年，下一个是明年。同一个数，今年、明年最多各开一条，超出的不开；到期日就是这个数公布的那天。
6. 到期日定在这个争论见分晓的那天，一般 6–12 个月；中间的季报是证据，不另开观点。
<!-- /generated: ladder -->

## 状态

<!-- generated: positions -->
|  | 是什么 | 谁来判 | 例子 |
|---|---|---|---|
| 状态 | 这条观点处在梯子的哪一格：我们的判断，证据把它往梯子的一头或另一头推 | 模型判，温度调低，只按事实。每次从这条观点下没被替代的全部证据（每条带上它替掉的那条，看得到变化）、加上它依赖的观点现在的状态和理由重新判，不在上一次的基础上加减；写明依据哪几条证据。这一轮只多了重复的证据、依赖也没变，就不重判 | 看到 8-K 以后：强烈看空 |

- 每次判断都写明依据：模型按固定格式交回判断，其中一栏写它根据的是哪几条证据，写证据的编号，比如“依据：e12、e15”；因为它依赖的观点变了而重判的，也写那几条观点的编号，比如“依赖：#1”。
- 代码查表核对：每条证据存进库时有一个编号；库里记着每个观点下有哪些证据、每条有没有被后来的说法换掉。代码拿依据里的编号去查：证据是不是这个观点下的、有没有被换掉；观点是不是它依赖的那几条。都对，这次判断写进去；有一个不对，这次判断不收，记下原因，让模型重判一次。只查有没有，不管判得对不对，就像查脚注里的页码书里有没有。
- 想知道某天当时怎么判，就翻那天存下的判断记录，不重新问模型；再问一次，模型可能答得不一样。
<!-- /generated: positions -->

## 证据分四层

<!-- generated: tiers -->
| 哪一层 | 例子 | 能做什么 |
|---|---|---|
| 发生的事 | 官方动作、公布的数、已经完成的交易 | 能定哪一格成立，也能推状态 |
| 当事人说的 | 公司指引、管理层表态、官员讲话 | 只能推状态 |
| 第三方看法 | 卖方、媒体分析、专家 | 只能推状态 |
| 传闻 | “知情人士称”、没有出处的说法 | 只能推状态 |

- 推多远由模型判，写明依据；层不给固定分数。
- 独立来源按原始来源数：二十家媒体转述同一条独家，是同一条证据的二十个出处，算一份。
- 层看是谁确认的：“知情人士称商务部开始发许可证”是传闻；商务部或公司确认以后，确认的那条是发生的事，替代那条传闻；传闻还是传闻，留在历史里。
- 证据只存一次，本身不带方向；往哪边推记在证据和每条观点之间的连线上，由每次重判写。同一句话可以连几条观点，各推各的。
<!-- /generated: tiers -->

## 依赖：箭头怎么读

<!-- generated: dependencies -->
```
B 依赖 A｜A 是哪一种观点？（箭头带一个方向：A 的哪一头对 B 是看多；两条主题观点之间是同向或反向）
├─ 数字的观点 → 钉住年份（例：JPM 2027 全年净利息收入 → 美联储 2027 年末利率）
│   ├─ A 开着 → 读 A 的状态和理由
│   ├─ A 出了答案 → 读 A 的答案（答案本来就是 B 要的输入，不算断）
│   └─ A 还没建 → 箭头先等着（A 建出来时连上，B 重判一次）
└─ 事件的观点 → 顺着接续往下走（例：NVDA FY27 全年中国区收入 → 这一档芯片对华出口许可）
    ├─ A 开着 → 读 A 的状态和理由
    ├─ A 关了，有接续的 → 读接续的那条（记一笔）
    └─ A 关了，没有接续 → 读 A 的答案，标“只是历史”
```

- 主题观点不说好坏，好坏由每个依赖它的对象观点自己的箭头说：降息那头对以太坊是看多，对 JPM 是看空。
- 箭头只有一个方向。看起来要“先好后坏”，说明中间还有一条观点没写出来，要拆出来：钢铁关税抬高国内钢价是一条路，拖垮下游用钢需求是另一条路。
- 观点和观点之间只有一种关联：依赖。B 依赖 A，就是 B 判断时要看 A 的结论。B 判断时看两样，分开放：直接讲 B 的证据；它依赖的观点现在的状态和理由。A 的结论对 B 起的作用像证据，但不当证据存：证据是外面发生的事、别人说的话，A 的结论是我们自己的判断，当成证据，系统会自己说服自己。
- 一句话只算一次：讲 A 的话只算 A 的证据（同一条信息里新提的两条候选观点也一样，一句话只连到它直接讲的那条），B 通过 A 的结论知道这件事；直接讲 B 的，才算 B 的证据；B 不依赖 A 的，讲 A 的话也直接算 B 的证据。依赖谁只在建 B 的时候定，所以不会出现先算给 B、后来又通过 A 再算一次。
- 什么时候通知 B：A 的状态换了格，或者 B 等着的 A 刚建出来、箭头连上了。别的时候不通知。
- 连不连依赖，由模型判，像分析师一样：写出这条观点的结果要靠哪几条观点的结果，各往哪个方向推。已经发生的事是证据，不连：OPEC 看着今天的油价定产量，今天的油价是“OPEC 产量”这条观点的证据，不是依赖。
- 防绕圈：每加一条箭头，或者一条箭头顺着接续换到下一期，代码先查会不会绕成圈（A 靠 B，B 又靠 A）；会的话这条不收，退回给模型改。看起来互相依赖的两个问题，是观点没起好。
<!-- /generated: dependencies -->

## 接续：同一样东西一期接一期

<!-- generated: chain -->
- 同一样东西的下一条观点接着上一条，连成一条链：美联储 2026 年末利率 → 2027 年末利率 → 2028 年末利率。链存的是血缘，箭头怎么读见上面。
- 一条只能有一个下一期：FY26 后面只接一条 FY27，不能冒出两条。
- 下一期的梯子方向不变：上一期第一格是“强烈看多”，下一期也是；每一格的门槛可以重新定。依赖它的观点认的是“哪一头对我是看多”，方向一反就乱了。
<!-- /generated: chain -->

## 进库：候选观点和证据各走一条线，走法一样

<!-- generated: shape -->
|  | 候选观点 | 证据 |
|---|---|---|
| 去哪比 | 搜索引擎从整个观点库搜出的前 N 条 | 在它那条观点下的证据里搜出的前 N 条 |
| 判什么 | 是哪一条（或它的一部分）、接续、新观点，还是不开 | 重复、替代、新证据 |
| 链 | 接续：美联储 2026 年末利率 → 2027 → 2028 | 替代：AMZN 资本开支指引涨 12% → 25% |
| 什么算现在 | 链上开着的那条（数字可以今年、明年各开一条） | 没被替代的那些（证据的替代也连成一条链） |
| 搜什么 | 整个观点库，开着的、关掉的都搜 | 只搜它那条观点下的，不搜全库 |
<!-- /generated: shape -->

## 一条信息进来，怎么写进库

一条信息走一轮，按顺序号一条一条来。模型只做第 4、7、8 步，其余是代码。

<!-- generated: intake -->
```
抽取交来的证据和候选观点（一条信息一轮）
  ↓ 1 核对出处（代码）：出处在处理记录里查不到的不要，记下原因
  ↓ 2 收证据（代码）：重试不重复存；上游修正版只换它自己那一处出处：它只是转述的，不动原来那条证据；它本身是原始来源的，新版的句子照常对上，改了的就替代原句
  ↓ 3 搜索（代码）：搜索引擎叠在观点库上（像 Elasticsearch，语义搜索或关键词，怎么搜还没定）。候选观点搜整个观点库，开着的、关掉的都搜，取前 N 条（N 写在 Config，先定 10）；证据只在它连到的那条观点下的证据里搜，取前 N 条；连在候选观点上的，等候选观点有了去向再搜。搜出来是空的，也照样交给第 4 步
  ↓ 4 对上（模型）：模型不读原文，先判每个候选观点是清单里的哪一条（或者它的一部分）、接续哪一条，还是新观点（对不上，或者只是有点像，就开新的），太大太杂的、超出今年和明年的数字观点不开，写理由；每条证据和它那条观点下搜出来的证据比，是重复、替代还是新证据。这些在同一次调用里判完。候选观点并进了已有的那条，它带的证据接着在那条观点下搜，为它再叫一次模型比
  ↓ 5 核对（代码）：编号必须在清单里，或者是那条观点下的证据
  ↓ 6 写进库（代码）：各对象自己的队列写，先写主题，再写对象；重复只多一个出处；替代按说的时间排（这句话是哪天说的），后说的算数，先说的标“被替代”，晚到的旧说法不加进来，只在处理记录里写一笔；被替代的证据还连着别的观点，新的那条也连过去；原始来源自己的修正版里找不到、也没被新句替代的原句，算删了，标“被替代”；对上那一刻看到的变了，这部分重新对上
  ↓ 7 连依赖（模型）：新观点挑它依赖哪几条，写明方向；代码先查会不会绕成圈，会就退回给模型改
  ↓ 8 重判一轮（模型）：这一轮有新证据或替代、它依赖的观点换了格、或者它等着的观点刚建出来，重判：先判上游，再判下游，每条这一轮只判一次；只多了重复的不判；换了格的再往下通知
```

## 第 4 步对上：候选观点的去向

<!-- generated: outcomes -->
| 去向 | 什么时候 | 写什么 |
|---|---|---|
| 并进已有的 | 候选观点看的就是那条观点看的东西，或者是它的一部分（“H20 在中国的收入”是“中国区收入”的一部分） | 只连证据，证据再和那条观点下的证据比；梯子和到期日用已有的 |
| 接续 | 同一样东西的下一期：数字的下一年；事件的那条已经关了，要接着看 | 建新观点，记接续 |
| 新观点 | 对不上，或者只是有点像：Blackwell 这一档对华许可，不是 H20 这一档 | 建新观点，梯子和到期日从此定死 |
| 不开 | 太大太杂，一条里捆了几件可能往相反方向走的事：“美国对华芯片管制会怎样”；或者数字的观点超出了今年、明年 | 不建；它的证据如果也连在具体的那条上，照常算数；只连在它身上的不存 |

- 搜只用来找出前几条可能的，是不是同一条由模型判：“H20 对华许可”和“Blackwell 对华许可”很像，却是两条；看多和看空的两种说法，是同一条。
- 关掉的观点也搜得到：FY26 那条关了，FY27 的候选观点进来照样搜到它，模型判成接续。

## 第 4 步对上：证据的去向

<!-- generated: evidence-outcomes -->
| 去向 | 什么时候 | 写什么 |
|---|---|---|
| 重复 | 说的就是那条观点下已有的一条：别人转述；正文和表格里的同一个数；同一个人把同样的话再说一遍 | 那一条多记一个出处；证据不多一条，不重判 |
| 替代 | 和已有的一条是同一件事的前后两个说法：同一个人后来改了说法或数（指引、预测、状态）；官方证实或否认了一条传闻；原始来源自己出了修正版，改了原句 | 按说的时间排（这句话是哪天说的），后说的算数，先说的标“被替代”，留在历史里，重判；晚到的旧说法（同一件事已经有更新的）不加进来，只在处理记录里写一笔，不重判 |
| 新证据 | 别的都是：新的事、另一期的数、另一个人的说法（说法相反的也是）；拿不准也算新证据 | 加进来，和别的一起算数；重判 |

- 证据只和它那条观点下的证据比，不拿证据去搜全库：观点先定好（抽取时连上的，或者候选观点对上的那条），再在这条观点下没被替代的证据里搜前 N 条，交给模型比。和观点一个形状：候选观点比的是从整个观点库搜出来的，证据比的是从它那条观点下搜出来的。
- 一条证据连几条观点，也只存一条：和这几条观点下的证据一起比一次。
- 被替代的证据还连着别的观点，新的那条也连过去，那些观点也重判；不然那条观点手里只剩一个过时的说法。
- 证据是一句话或一个数，替掉的只是那一句：卖方新报告改了收入预测，替掉的是它上一份里的那个预测，别的论据照样算数。
- 对上不读原文，比的是证据里“一句话说清”的那句；拿不准算新证据，最坏也就是两条都算数，由重判自己看。

|---|---|

## 先后、同步和血缘

<!-- generated: order -->
- 只有信息能产生证据；观点之间只传通知，不传证据，所以观点不会自己证明自己。
- 每条观点只有一个写入者：主题观点由主题的队列写，对象观点由对象的队列写；同一条信息先写主题，再写对象。
- 先后按顺序号排，不用电脑时钟。一条信息只读顺序号比它小的信息留下的状态，加上这一轮里它自己已经写下的；结果要和一条一条按顺序处理完全一样；并行时读到的东西在提交前变了，就重新做一次（D31）。
- 一条信息引起的变化算一轮：先做完连证据、建观点、接续和连依赖，再按依赖先后重判。上游判完才判下游，下游读的是上游这一轮刚判完的状态；每条观点这一轮只判一次。全局的观点（比如美联储）连着很多观点，它先变，跟着它的再各判一次。
- 只追加：观点的问题、梯子和到期日写下就不动；对上、重判、接续、关掉、标注都是新加的记录，带顺序号。
- 时间线只往后加，不回头改：观点的每一次变化，按我们什么时候知道的往后记。晚到的信息，同一件事已经有更新的说法，它就不算数，不加进观点，只在处理记录里写一笔“过时，没用”；讲的是我们不知道的事，照常算，记上它真实的日期。分这两种由模型比证据时一起判，不另加规矩。
- 同一条信息的修正版只换它自己那一处出处：它只是转述的，不动原来那条证据；它本身是原始来源的，改了的原句由新句替代，删了的标“被替代”。连着变了的证据的观点各重判一次；过去的重判记录不改。
- 失败：每条信息记下做到哪一步，从失败的那一步重试，重试只替换自己上次的结果；多次失败的放进人工复核池。
- 两头都能查：从一条观点查到推过它的全部信息；从一条信息查到它建过的观点，和它作为出处的全部证据（重复的也查得到）。

存在哪、用什么数据库，建的时候定。

## 验收标准

- 每条观点都有问题、梯子和到期日，建好以后这三样不再变；梯子五格（只有是或否的问题两格），每格一个能核对的结果，格和格不重叠、不留空。
- 数字的观点写明哪一年；同一个对象的同一个数，开着的不超过今年、明年两条；事件的同一件事，开着的只有一条。
- 候选观点先由搜索引擎从整个观点库（开着的、关掉的）搜出前 N 条，再由模型判；证据只在它那条观点下的证据里搜。
- 每次对上都留一条对上记录：给模型看了什么、原始返回、Config 版本、谁定的；模型给的编号不在清单里、也不是那条观点下的证据的，代码不收，记下原因。
- 每条证据的对上写明是重复、替代还是新证据；重复只多一个出处，不重判；替代的旧证据标“被替代”，不删。
- 一条证据连几条观点也只存一条；被替代的证据还连着别的观点的，新的那条也连过去。
- 只有这一轮有新证据或替代、它依赖的观点换了格、或者它等着的观点刚建出来，才重判；每次重判写明依据哪几条证据（因为依赖的观点变了而重判的，也写那几条观点）；只有“发生的事”能定哪一格成立。
- 数字的箭头钉住年份，事件的箭头顺着接续走；依赖不绕成圈。
- 一条信息引起的一轮里，先判上游，再判下游，每条观点只判一次。
- 记录只追加：任何一条观点、证据、连线、对上记录都查得到来历；从一条信息查得到它建过的观点，和它作为出处的全部证据。
- 时间线只往后加，不回头改：晚到的旧说法，同一件事已经有更新的，不算数，只在处理记录里写一笔；讲新事的照常算，记真实日期。修正版只换它自己那一处出处：转述的修正版不动原来那条证据，原始来源自己的修正版，改了的原句由新句替代，删了的标“被替代”。
- 每次对上都记下来；被代码退回的和随机抽的几条交给人标。

## 还没定的

<!-- generated: open -->
- 搜索怎么搜：用语义搜索、关键词还是两样一起，怎么排先后；建的时候在存下的信息上试过再定。前几条先定 10，试的时候再调。
- 共识：市场押在哪一格；对股价的看法就是我们的状态和共识的差距。共识怎么记还没定（D30 原来定的是由代码按每个独立第三方来源最新的立场算）。
- 观点的颗粒度还没定，要专门定：一部分就并进大的那条，太大太杂的不开，可到底多大算一条，现在说不清。要紧的那一块要单独成一条（NV 中国区收入很关键，不能并进总收入）；太粗的话，观点会全变成财务指标，这不行。要让模型清楚知道这种抽法和颗粒度是错的。先做一次完整的调研：从对冲基金的角度看，一条观点到底长什么样，什么该合、什么该拆。
- 什么样的问题算关键问题，每个对象几条（现实里每家公司只盯 2–3 个）；去重管不住“问太多不同的小问题”。
