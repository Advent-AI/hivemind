## 一句话

系统做的事，就是建立、更新和关掉一个观点库：上游不断把带着分类结果的信息推进来，抽取用资深对冲基金分析师的视角，对着这些对象已有的观点把每条信息整份读完，交出两样东西：连到已有观点上的证据，和已有观点管不到的候选观点；观点库再各自和已有的比：候选观点并进已有的、接续、开新的，或者不开；证据是重复、替代还是新证据。一条观点是一个问题、一把梯子和一个到期日，证据把我们的判断往两头推，到期拿答案对一下。

## 为什么重建

旧系统是按日期主动去拉数据、一批一批处理的。同一件事的规则散在很多地方：信息的类别在 9 个模块里各有一套定义，配置有五层覆盖，时间有好几套时钟。结果是问“某类信息进来会怎样”，要读好几处代码才说得清。新系统从头设计，每件事只在一个地方决定。

## 系统的边界

- **上游（不归本系统）**：取得材料、按分类规则贴好标签（分类结果、相关对象、发布时间等），推送进来。以后再谈。
- **本系统**：从“分发”开始，到观点库、最终判定和 Pull 模式。
- **测试**：用一段测试代码，把测试库里的旧数据按发布顺序推进来，走和正式运行完全相同的路；Pull 模式用回放的时间。

信息走的路：

```
上游（取得材料 + 分类）→ 分发（编顺序号）→ 抽取（只读）→ 观点库（搜索、对上、写进去、重判）⇄ 对上标注
                                                              │ 到期的观点
                                                              ▼
                                     Pull 模式（到期）→ 最终判定 → 写回观点库
```

旁边的几条线：

| 从 | 到 | 是什么 |
|---|---|---|
| 研究对象名单 | 上游 | 推哪些对象的哪几类信息 |
| Config | 抽取、观点库、最终判定 | 用哪版模型设置 |
| 观点库 | 抽取 | 已有观点的问题和看的是什么：相关对象开着的观点，加上它们依赖的观点，写明谁依赖谁（提示词第 5 块） |
| 观点库 | 对上标注 | 每次对上的记录；人标的结果和以后的小模型回到对上 |
| 分发、抽取、观点库 | 人工复核池 | 查不到的、建议新增的主题、多次失败的 |

## 两种工作方式

| | 信息流 | Pull 模式 |
|---|---|---|
| 谁触发 | 有信息推进来 | 到了约定日期，或按固定时间 |
| 谁主动 | 上游推，系统接着处理 | 系统主动去做 |
| 做什么 | 把信息读成证据和候选观点，各自和观点库里已有的对上，重判证据变了或依赖变了的观点 | 到期的观点定答案 |
| 看不看日历 | 从不看 | 系统里唯一按时间做事的地方；“现在”从外面传进来 |

## 基本原则

1. **从观点出发。** 系统的核心是观点库；读什么、存什么，由观点需要什么决定，不先把财报读成一大堆数。
2. **观点是判断，证据是客观的。** 观点是模型（分析师）写的；谁在哪条信息里说了什么，是证据。只有信息能产生证据，观点之间不互相证明。
3. **每条都带出处。** 每条观点、证据和每一次变化都写明来自哪条信息的哪一处，能回到原文去查。
4. **信息流由信息推动，不由日历推动。** 没有新信息进来，信息流这一边就什么都不做；按时间做事只在 Pull 模式。
5. **先后由顺序号定。** 每条信息进来时编一个顺序号；一条信息只读顺序号比它小的信息留下的状态，加上这一轮里它自己已经写下的，结果和一条一条按顺序处理完全一样。时间线只往后加，不回头改：晚到的旧说法，同一件事已经有更新的就不算；讲新事的照常算，记真实日期。
6. **只有研究对象名单决定处理什么。** 名单写明研究哪些对象、每样看哪几类信息；上游只推这个范围，推进来的都处理。
7. **身份放在“看的是什么”上。** 同一个对象、看同一样东西，同一时间只开一条观点（数字按年，今年、明年各一条）；是不是同一样东西，由模型在搜索引擎搜出的前 N 条里判；搜索只用来找出前几条，当不了裁判。证据也一样：先定它去哪条观点，再和那条观点下已有的比，是重复、替代还是新证据，不拿证据去搜全库。
8. **问题和梯子事先写死，到期拿答案对。** 每一格写成能核对的结果，建观点时定，到期以前不改；记录只追加，关掉的观点、被替代的证据也留在库里。
9. **查不到、规则判断不了的不猜。** 放进人工复核池等人看。
10. **不存原材料。** 原材料留在团队自己的库里，凭编号去取。

## 和旧系统的区别

| | 旧系统 | 新系统 |
|---|---|---|
| 数据怎么进来 | 按日期主动去拉 | 上游推进来，来了就处理 |
| 怎么处理 | 一批一批跑，按天推进 | 一条一条处理，由信息推动，按顺序号排先后 |
| 信息类别 | 9 个模块各自定义 | 16 个类别，一份规则 |
| 处理什么 | 配置、命令参数、多个 preset 层层覆盖 | 只有研究对象名单决定 |
| 时间 | 好几套时钟 | 信息流只看发布日；Pull 模式的“现在”从外面传进来 |
| 原材料 | 自己存一份 | 不存，凭编号去团队的库里取 |
| 财报 | 每次刷新把每家公司的财报全部拉下来，拆成一条条数存着，再列给模型去形成结论 | 和别的文件一样整份交给模型，读成观点和证据，不存数字仓库 |
| 观点 | 越长越多、改写后分不清是不是同一条、从来不退出 | 一个问题、一把梯子、一个到期日，写下不改；同一样东西只开一条，并进已有的优先；到期拿答案对 |

## 还没设计的

人工复核池的处理流程；上游怎样取得材料和分类，以及退回的信息怎样通知上游；每一类提示词的具体写法（建的时候试过再定）；观点库还没定的几项（见 06-views.md），其中观点的颗粒度要先调研：从对冲基金的角度看，一条观点长什么样；最终判定和 Pull 模式按观点库的新设计重做。
