# 分发

## 一句话

系统的唯一入口：每来一条信息，依次问四个问题，决定它的去处。

## 为什么要有它

旧系统里，“一条信息该怎么处理”由四个地方分别决定：日常步骤表、按取数渠道写死的文字/数据分流、按正则换模型设置的路由文件、9 个模块里的类型集合。新系统把这件事收成一棵决策树。

## 做什么 / 不做什么

- 做：检查信息完整不完整；查以前处理过没有；看分类结果；按文字或表格交给模型或程序；把有问题的放进人工复核池。
- 不做：不看信息讲的是谁；不按类别过滤（推进来的都在研究对象名单的范围内）；不决定研究什么；不按日期做任何事。

## 决策树

- 一条信息进来 → **问：信息完整吗？**（看有没有写明：谁发的、哪天发的、属于哪一类、上游给的编号）
  - 不完整 → **退回**：这是上游的问题，同时放进人工复核池
  - 完整 → 查处理记录，**问：以前处理过吗？**（同一个编号、同一个版本）
    - 处理过 → **跳过**：上游重发或测试重跑时，不重复花钱
    - 没处理过 → 看分类结果，**问：分类结果是什么？**
      - 不合格 → **不处理**：写明原因；对照表里查不到的，放进人工复核池
      - 不算材料 → **不处理**：比如别人已经算好的指标、文件目录
      - 重复 → **并到原来那条**：算原来那条的另一个出处，不再处理一遍
      - 属于某一类 → 看形式，**问：文字还是表格？**
        - 表格 → **程序读**：直接读出数字
        - 文字 → **模型读**：整理成一条条事实

## 说明

- 灰色框：到这里就停了，不处理。最下面两个框：交给程序或模型。
- 不看信息讲的是哪家公司或哪个主题。推进来的信息都在研究对象名单的范围内，所以不再问“这一类要不要处理”。
- 程序读还是模型读，由信息是表格还是文字决定，不需要人来选。
- 对照表里查不到的新指标，照常往下走，同时放进人工复核池。

## 例子

| 情况 | 去处 |
|---|---|
| 上游重发了同一条 Apple 业绩稿（同编号、同版本） | 跳过 |
| 10-K/A 修正版（新版本） | 照常处理 |
| 一条新闻缺发布日期 | 退回，同时进人工复核池 |
| 数据商算好的市盈率 | 不处理（不算材料） |
| CPI 数据（表格） | 程序读 |
| FOMC 声明（文字） | 模型读 |
| 带了未登记发布系列的新指标 | 按作者类型归类后照常处理，同时进人工复核池 |

## 验收标准

- 每条信息恰好落到一个去处。
- 同一编号、同一版本的信息第二次进来，一定跳过，不重复调用模型。
- 文字一定交给模型，表格一定交给程序。
- 判断过程中不读信息的相关对象。
- 不完整的信息退回，并出现在人工复核池里。
- 没有信息进来时，分发不做任何事。

## 还没定的

- 无。模型读时用一套设置还是每类一套，属于 Config。
