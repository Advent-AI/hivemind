# Pull 模式

> 状态：未设计（只列已经确定的方向） · 更新：2026-10-16 · 依据：docs/DECISIONS.md D12、D13、D14
> 设计页：docs/system-design.html › New › Pull 模式。本文和 DECISIONS 不一致时，以 DECISIONS 为准，并改本文。

## 一句话

和信息流的方向相反：不等信息进来，而是到了约定日期，或按固定时间，系统主动去查某个结论的条件满足了没有。

## 已经确定的方向

- 这是系统里唯一按时间触发的地方；信息流那一边从不看日历。
- 触发方式有两种：结论里某个条件到了约定日期；或者按固定时间（cron）定期检查。
- 由系统里的 agent 主动去查证据。
- 和上游推送不是一回事：上游推送只负责把信息送进来，不叫 Pull。

## 例子

- 某个结论写着“如果 Apple 下一季 iPhone 收入同比转负，结论就不成立”。到了下一季财报之后的约定日期，系统主动去查这个数字出来了没有、满不满足条件。

## 还没定的

- 哪些结论、哪些条件需要到期检查或定时检查（由研究结论的设计决定）。
- 主动查到的信息，要不要也走分发进来。
- 查不到数据时怎么记（按工作规则，应是“没有数据可验证”）。
