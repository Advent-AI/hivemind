# 分类（上游完成）

> 状态：第一版已冻结 · 更新：2026-10-16 · 依据：docs/DECISIONS.md D1、D8、D9、D11、D15、D16、D19
> 设计页：docs/system-design.html › New › 分类（上游完成）。本文和 DECISIONS 不一致时，以 DECISIONS 为准，并改本文。

## 一句话

上游给每条信息贴好标签再推给我们：它属于哪一类（共 16 类）、是文字还是表格、讲的是哪家公司或哪个主题。本文是贴标签的规则：上游照着贴，我们照着检查。

## 为什么要有它

旧系统里，“这是什么类型的信息”在 9 个模块、12 个集合里各有一套定义，互相对不上。新系统只有这一份规则，下游只读类别和它的属性，不再各自定义。

## 做什么 / 不做什么

- 做：给每条信息一个结果（一个类别、并到原来那条、不算材料，或不合格）；标明讲的是谁；规定每条信息要带哪些字段。
- 不做：不用模型判断；不决定这条信息要不要处理（那是研究对象名单）；不读正文里提到的公司（那是模型抽取）。

### 各类别的定义

- **T1 业绩发布**：一个财期（季度、半年、全年）的业绩发布。文字：8-K 里 Item 2.02 那一段点名的附件（业绩稿、股东信、CFO 解读、Update deck），6-K 里写明是财期业绩的附件，交易所的业绩公告，来源标为“业绩”的文件。表格：业绩当天公布的数字和指引（业绩表、指引历史）。月度经营数据不在这里，归 T6。同一份业绩稿的转载，并到原件。
- **T2 定期报告**：文字：10-K、10-Q、20-F、40-F、ARS 及修正版（/A，注明它替换了哪一版），交易所的年报、中报、季报，来源标为“定期报告”的文件。表格：这些报告里的 XBRL 数字，数据商整理的标准化报表和分部数据（注明出自哪份报告）。是年报还是季报，只是一个属性。
- **T3 法律与资本市场文件**：不管谁提交的：委托书（包括代理权争夺双方的材料）、融资、并购、要约收购（包括收购方、私募发起的）申报及修正版；SEC 规定编号 2、3、4、10 的附件（并购协议、公司章程、证券和债务工具、重大合同）；交易所通函；来源标为“法律”的文件。读法：读出条款和各方的主张，主张算提交方说的。
- **T4 电话会文字稿**：公司在讲的会议文字稿：公司自己办的（业绩会、投资者日、公司播客），在投资者会议上的发言（券商会议），以及 425 申报里的并购电话会。媒体办的活动归 T7。在哪开的、谁办的、谁整理的文字稿，都只是属性。
- **T5 演示材料**：公司发布的幻灯片或 PDF 演示稿：8-K 里 7.01 项和 425 申报里的演示稿、IR 网站上不属于业绩 8-K 的 PPT。
- **T6 公司其他发布**：文字：申报里不属于前几类的（8-K 正文、业绩那一段没点名的附件和其他项、其余 6-K、给 SEC 的回函、延期申报通知），以及新闻稿、经营更新、ESG 报告、新闻室、博客、IR 和产品页面、公司官方社交账号的帖子。表格：公司自己发布的补充资料和月度经营数据（IR 网站上的 Excel、CSV）。
- **T7 新闻**：媒体发的内容，除了评论和分析：新闻报道、访谈、播客文字稿、媒体自己办的活动（比如 WSJ Tech Live）、媒体账号的帖子；综合、财经、行业媒体都算。没写栏目的按新闻算。评论和分析栏目归 T8；媒体登记过的发布系列按系列归类（比如 Reuters 的经济学家调查归 T8）。
- **T8 观点与分析**：有作者的观点和分析，不管作者是谁、多长、发在哪。文字：卖方和独立研究、评级机构、行业研究、智库和学术、官方和国际组织的预测、展望和研究（IMF 世界经济展望、CBO 预算展望、央行工作论文）、投资者（基金信、做空报告、申报里写给董事会的信）、媒体的评论栏目、个人的帖子和长文，以及你自己的投资备忘录。表格：分析师预测和修正历史、投资评级、目标价、一致预期、信用和 ESG 评级、经济学家和官方机构的预测（包括 GDPNow 这种实时预测）、投资者情绪调查（一群人看法的汇总，和一致预期一样）、行业估计、上传的“预测表”模板。观点和估计算作者说的，不当成已经发生的事；作者是你自己的，只当作要跟踪的观点，不当作证据。
- **T9 访谈记录**：分析方记录的对话：专家网络的访谈、你约的管理层会面和渠道调研。形式是逐字稿或纪要。话算原来说话的人说的，记录的人只是属性。公司自己在讲的活动归 T4。
- **T10 官方行为与记录**：官方发的、不属于别处的都归这里。文字：监管、法院、立法、行政、交易所的正式文件和程序记录（裁决、审批、召回、法规、制裁、出口管制、关税、合同授予、听证会和庭审文字稿、SEC 意见函、法院案卷）。表格：政府公布的记录（合同、游说、政治献金、专利、诉讼案卷信息、召回、海关提单）。官方的预测、展望和研究归 T8，统计数据归 T11。官员在任期内的个人账号也算官方（比如总统在社交平台上宣布关税）。里面的说法算原来说话的人或提交方说的。
- **T11 宏观政策与统计**：文字：登记为货币政策或统计的发布内容，不管谁发的：央行关于货币政策和经济形势的材料（声明、纪要、讲话、点阵图、褐皮书），统计发布稿（官方的 CPI、非农；民间的 ISM PMI、ADP 就业、密歇根消费者信心）。表格：衡量整体经济或整个行业的统计和政策利率，官方民间都算，每条都带它是哪天发布的（数据会修正，旧版留着）；权重不公开、我们自己算不出来的合成指标（领先指标 LEI、金融条件指数）也在这里。市场上的利率和汇率归 T12；针对具体公司、产品、地点、链和协议的测量归 T15。
- **T12 市场价格与成交**：能交易的东西的价格和成交：股票、ETF、期权链、期货、利率、汇率、商品、加密货币、信用利差和 CDS、预测市场；分红、拆股这类公司行动，股本。
- **T13 持仓与资金流**：市场参与者的持仓和资金流：Form 4、13D/G、13F、144 的表格版本，空头持仓、融券费率和使用率、ETF 和基金的资金流、CFTC 持仓报告、加密货币的大户和“聪明钱”持仓。
- **T14 日历**：已经排好的日期：财报、投资者日、发布会、宏观数据发布、央行会议、法院和监管的截止日、指数调整、解禁和代币解锁、期权到期。
- **T15 第三方测量**：数据商测到的、针对具体公司、产品、地点、链和协议的实际活动：刷卡、App 使用、网站流量、搜索、客流、卫星和航运、招聘、价格抓取、评论、链上活动（链和协议的使用量、收入）。是测出来的，不是估的：机构的行业估计和预测归 T8；衡量整体经济或整个行业的统计归 T11。
- **T16 参照数据**：公司和资产的身份、行业分类、公司结构、供应链关系、指数成分和权重。研究对象默认都不看这一类；身份对照由上游用来认出信息讲的是谁。

## 判断顺序

1. 先检查：缺必填信息、对象代码写得不对、没有文字可读、系统自己的产出 → 不合格；以前收过的同一内容 → 并到原来那条。
2. 表格数据：不逐条判断。每个数据集接入时，在数据集表里登记一次属于哪一类（一个接口返回好几类内容的，按字段分开登记），之后每条都直接用这个类别；没登记的数据集 → 不合格，放进人工复核池。
3. 文字，而且是申报文件（SEC、交易所、法院）：查这个系统的表格代码表，不管谁提交的；表里没有的代码 → 不合格，放进人工复核池。
4. 其余文字，发布方登记过这个发布系列：查发布系列表定类别（只可能是 T8、T10、T11），不管作者是谁。带了系列名、但表里没有的（新指标）→ 放进人工复核池，这条照常往下判。
5. 其余文字：先看作者是哪种（查作者表，看发布那天是否在有效期内；查不到就用渠道的默认类型），再看栏目或形式定类别；官方作者没登记发布系列 → T10；判断不了作者是哪种 → 不合格，放进人工复核池。

## 对照表：分类时要查的四张表

| 表 | 拿什么查，查出什么 | 例子 |
|---|---|---|
| 数据集表 | 数据集 → 类别，或“不算材料” | 日线行情 → T12；财务报表 → T2；ISM PMI、领先指标 LEI → T11；GDPNow → T8；技术指标、恐惧贪婪指数 → 不算材料 |
| 表格代码表（每个申报系统一张） | 表格代码 → 类别；8-K 和 6-K、425、持股类表格光看代码定不了，按规则再分 | 10-K → T2；DEF 14A → T3；8-K → 看里面有哪几项、哪些附件 |
| 发布系列表 | （发布方，系列）→ T8、T10 或 T11；任何发布方都能登记，T10 只给官方 | FOMC 声明、褐皮书、ISM PMI → T11；IMF 世界经济展望、CBO 预算展望 → T8；OFAC 制裁公告 → T10 |
| 作者表 | 作者 → 作者是哪种（公司、媒体、分析方、官方、个人），每条有有效期；查不到用渠道的默认类型 | Reuters → 媒体；Morgan Stanley → 分析方；IMF → 官方；总统个人账号在任期内 → 官方 |

- 四张表放在同一份 JSON 数据文件里，正式运行和测试读同一份。改了表，就是分类的新版本。
- 前三张查出来直接是类别，不经过中间名称。作者表查出来是作者的种类，不是类别：同一个作者会落到不同类别（Reuters 的新闻归 T7，评论栏目归 T8），还要看栏目、形式或发布系列。
- 登记的原则（数据集表和发布系列表一样）：统计数据，官方民间都算 → T11；央行关于货币政策和经济形势的材料（声明、纪要、讲话、点阵图、褐皮书）→ T11，央行的研究和工作论文 → T8；预测、展望、研究 → T8；行动和记录 → T10，只限官方。衡量整体经济或整个行业的 → T11；针对具体公司、产品、地点、链和协议的 → T15。
- 读文件时只检查一件事：查出来的值必须有效（数据集表：16 个类别之一或“不算材料”；表格代码表：类别或规则；发布系列表：T8、T10、T11 之一，T10 只给官方；作者表：5 种作者之一），不对就不启动。
- 表里没有的（新数据集、新表格代码、新发布系列、新作者）不猜，放进人工复核池，由人登记。
- 代码和对象的对照（比如 AAPL 对应 Apple）不是分类的表：它不决定类别，只用来认出信息讲的是谁、检查研究对象名单。分类在上游做，这张表也归上游管，以后再谈。

## 讲的是谁（相关对象）

1. 对象有四种：公司、加密货币、商品、主题（和研究对象名单一样）。一条信息可以讲好几个对象，也可以一个都没有。
2. 讲的是谁，只看渠道给的对象代码（申报对象、申报人、数据字段、渠道标签、上游为它推的、上传时写明的），再加上作者本人——只限作者是公司的时候（通稿算发稿的公司，公司自己讲的会议算这家公司）。每个对象都写明为什么挂在这条上。代码的种类或理由不在规定范围内、或者是空的，整条不合格。
3. 代码按种类分开写，因为同一个代码在不同种类里可能指不同的东西：公司用 CIK、股票代码、名称；加密货币用加密代码；商品用商品代码；主题用主题库的编号。
4. 主题只有两个来处：上游为这个主题推来的，或者上传时写明的；不从正文里猜。
5. 只看代码，不读正文，也不看网址：代理申报机构的编号会出现在网址里（旧数据里 Amazon 有一份 8-K，网址里是代理机构的编号 1104659）。
6. 公司、加密货币、商品的代码去参照数据里查：CIK 补足 10 位；股票代码按发布那天的对应关系查（FB 在 2022-06-09 以前是 Meta，之后不是）；名称只认登记过的别名。主题编号去主题库里查。查不到的原样留着，记为“查不到”，这条信息照常处理，等登记后再补。
7. 作者不是公司的时候（媒体、分析方、官方、个人），作者不算这条讲的对象；申报人和申报对象都留着，写明谁是谁（比如 13D 里，激进投资者是申报人，被持股的公司是申报对象）。
8. 正文里顺带提到的公司或主题，不在这里标；模型读的时候在具体事实上标。
9. 重复的并到原来那条时，讲的对象取两边的合集。讲的是谁不影响类别。不合格的和“不算材料”的，不标对象。

## 时间规则

1. 时间只看“哪一天”：每条信息按纽约时间算是哪天发布的；几点几分不参与任何判断，同一天的信息不分先后。
2. 每条信息只有一个时间：它的发布日。内容讲的是哪段时间（比如哪个财季）只是属性。系统里没有“今天是哪天”这个概念。
3. 渠道晚了几天才拿到，不另外记。任何规则都不看电脑时间；我们拿到它的时间只用来留底。
4. SEC 文件按 EDGAR 受理那天算发布日（纽约时间），不按法定申报日。
5. 重复的并到原来那条后，发布日取最早的那天：市场最早在哪里看到，就从那天算知道。
6. 修正、更新、重述、编辑、类别改了，都是新版本，旧版本留着，不覆盖。
7. 没有发布时间的信息放不到时间线上，不合格。

## 分类规则

1. 类别按“信息是什么”分；是文字还是表格、多长、发在哪、从哪个渠道来，都只是属性。同一类信息可以是文字也可以是表格，形式只决定由模型读还是程序读。
2. 每条信息只有一个结果：一个类别、并到原来那条、“不算材料”，或者不合格并写明原因。判断只用固定规则和对照表，不用模型。
3. 作者是对内容负责的一方，不是转发它的渠道：通稿平台、转载站、文字稿供应商、数据商、社交和投稿平台、EDGAR 上的代理申报机构、你的上传，都只是渠道。
4. 作者是哪种，先查作者表；查不到就用渠道的默认类型（新闻索引默认是媒体，通稿默认是公司，社交、投稿和 newsletter 平台上的账号默认是个人）；两样都定不了才算不合格。有没有登记过，记为属性。国际组织（IMF、世界银行、OECD、OPEC、WTO）算官方。
5. 作者表里每一条都有有效期，按发布那天查，按任期算、不按影响力算：同一个账号在任期内算官方，任期外（竞选期间、当选还没就职、卸任以后）算个人。
6. 发布系列先于作者：登记过的发布系列按表归类，不管发布方是官方、民间、媒体还是公司（ISM 的 PMI 报告 → T11，Reuters 的经济学家调查 → T8，CBO 预算展望 → T8，CBO 月度赤字数据 → T11）。
7. 会议、访谈这类口头活动的文字稿，按谁办的定作者：公司办的、在投资者会议上发言的算公司；媒体办的算媒体；听证会、庭审算官方；专家网络办的算专家网络；你约的会面算你。
8. 申报文件先查表格代码表，不管谁提交的：每个申报系统（EDGAR、交易所、法院案卷）一张列全的表；修正版（/A）和原表格同一类；表里没有的代码不合格，放进人工复核池，登记后再收。
9. 8-K 里只有 Item 2.02 那一段点名的附件才算业绩发布；同一份 8-K 的其他附件各按自己的类型判断。
10. 一份申报的正文和每个附件各算一条信息；带 XBRL 数字的申报另外产生一批表格记录（T2），注明出自哪份申报；持股类申报（Form 4、13D/G、13F、144）用表格版本，归 T13。
11. 以前收过的同一内容（指纹相同，或和原件对得上），并到原来那条，算原来那条的另一个出处，类别跟原来那条一样。
12. 同一种内容不因作者、长短而换类别：作者是谁（券商、评级机构、媒体评论员、投资者、个人、你自己……）、多长、发在哪，都只是属性；长短只决定怎么切开来读。观点和估计算作者说的。
13. 手动上传必须写明是哪种文字或用的哪个表格模板，没写的不合格；系统自己的产出不算信息。
14. 一个表格接口返回好几种东西的，按东西拆成多条；别人算好的指标、文件目录不算信息。
15. 文档里引用别人的话，在具体事实上算原来说话的人说的；文档本身的类别不变。
16. 只是附带情况不同的，记为属性：渠道、平台、长短、摘要还是全文、在哪开的、谁办的、年报还是季报、是不是持仓、是不是高管、有没有登记。

## 不算信息的东西

- 别人算好的指标：用我们已有的信息就能自己算出来的（估值倍数、因子暴露、技术指标、用价格或成交算出来的情绪指标，比如恐惧贪婪指数），数据商给的一律“不算材料”。我们自己算不出来的（权重不公开，或底层数据拿不到）按它是什么归类：领先指标 LEI、金融条件指数 → T11；GDPNow 这种实时预测 → T8。
- 文件目录（EDGAR 文件列表、新闻搜索结果）：只用来找到信息，本身不算信息。
- 没有文字的音频、视频、图片、扫描件：不合格；只能通过文字稿进来（T4、T7、T9、T10）。
- 系统自己的产出（报告、导出、被转载的内容）：不合格，免得自己引用自己。
- 股票池、观察列表属于研究对象名单；你自己的持仓、交易、盈亏和投资授权不算信息，放在哪以后再定。

## 验收标准

- 仿真 `python3 docs/system-design/simulate_classification.py` 全部通过：旧系统 412 条真实材料、161 个手写例子、24 个“讲的是哪家公司”的例子，脚本里的类别和设计页一致。
- 每条信息只得到一个结果；判断过程不用模型。
- 对照表文件读入时，查出来的值都有效；有一个无效就不启动。
- 上面的边界例子每一条都要成为测试样本。现在仿真只覆盖公司，宏观、加密、商品、主题的样本还没有加，这是已知缺口。
- 股票代码按纽约时间的发布日查。现在的仿真用的是 UTC 日期，和这条规则不一致，以后改代码时要改。

- 你自己的持仓、交易、盈亏和投资授权放在哪。
