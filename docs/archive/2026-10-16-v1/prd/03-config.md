# Config

## 一句话

只管一件事：模型读文字材料时，用哪个模型、哪一版提示词。

## 为什么只剩这一样

旧系统的配置有五层覆盖，几个 preset 并存，同一个功能由两处开关一起决定，看配置文件看不出实际跑的是什么。新系统里，研究什么、看哪几类信息归研究对象名单；信息本身的情况由分类给出；做事的顺序和失败处理由程序决定。Config 只剩下人必须亲自选的模型设置。

## 记了什么

| 内容 | 说明 | 怎么来 |
|---|---|---|
| 版本号 | 每改一次设置，就是一个新版本。 | 改设置时生成 |
| 校验码 | 由整份设置算出来的一串码。每条处理记录都写下它，事后能查到当时用的是哪一版。 | 系统自动算 |
| 模型设置 | 模型读文字时用哪个模型、哪一版提示词、按什么格式输出、想得多深。一套定下来就不再改，要改就换一套新的。 | 人来定 |

## 规则

1. Config 只管这一样设置。信息本身的情况（属于哪一类、哪天发的、讲的是谁）由上游分类给出；做事的顺序、失败了怎么办，由程序决定；研究什么、每样看哪几类信息，由研究对象名单决定。
2. 不设预算和并发上限。
3. 改任何一处都生成新版本，旧版本原样保留，不在旧版本上叠加修改。
4. 设定里引用了不存在的模型设置，或者缺了必填的内容，整个版本不能用，也不会拿它去处理任何信息。

## 例子

- 换了一版提示词：生成一个新版本。之后模型读的文字都用新版本；以前的处理记录仍然写着当时用的旧版本，能查到。

## 验收标准

- 每条处理记录都写下当时用的 Config 版本号和校验码。
- 设定里引用了不存在的模型设置，或缺了必填内容，整个版本不能用。
- 改任何一处都生成新版本，旧版本内容不变。
- Config 里没有“处理哪些类别”，也没有预算和并发设置。

## 还没定的

- 所有类别的文字共用一套模型设置，还是每个类别各一套（以后再谈）。
