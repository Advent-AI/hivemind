# Distilla 考察：一个粗颗粒版长什么样，差在哪

2026-10-22。Alex 说 Distilla 是他想做的东西的一个粗颗粒版，数据有局限、没有 lineage、对用户体验没有洞察、数据偏 commodity，要我考察。我用它的 MCP 口把结构摸了一遍，用 AMD 看内容（不用 NVDA，免得把 7 月以后的事漏进 POC）。下面是它有什么、缺什么、我们能拿它当什么用。

## 它有什么

| 东西 | 长什么样 | 看到的例子 |
|---|---|---|
| company_drivers | 每家一行，一张表：类型、话题、因果关系、支撑事实、现在还是过去。支撑事实是带日期的句子，没有文件链接。整行原地覆盖，updated_at 2026-10-21 | AMD 十条：AI 基础设施需求、Nvidia 竞争、自研芯片、供应链约束、产品路线、战略合作、服务器 CPU 份额、ROCm、PC 周期、出口管制 |
| executive_summary | 每家按六类生成 HTML：业务、财务、管理层、行业、近期表现、技术面。定期重新生成，每次一份新的快照 | AMD 8 月 4 日、8 月 11 日、9 月 16 日各一批 |
| ku_cell | 知识单元，几百种模板（产品、供应商、客户、产能、监管…），每格一段 JSON，带 as_of 日期和 prompt_id | AMD 的产品线、供应商、下游市场，各一格，描述性 |
| price_explanation | 单日大涨跌一段模型写的解释，没有引用 | NVDA 7 月 8 日：富士康 AI 服务器 +39.8%、Sharon AI 的 GB300、44 个上修… |
| file | 财报 PDF、电话会文字稿、合并文件、新闻，带发布时间。新闻的公司标签不可靠 | NVDA 的 Transcript 5-20、Filing 8-26 |
| standard_event | 财报事件，带模型写的财报摘要 | NVDA Q1 FY27 摘要：收入 816 亿、指引 910 亿、中国按零算 |
| consensus_data_point | 卖方一致预期，按周存快照，按财期查 | NVDA Q2 收入：5-15 870 亿，5-22 915.6 亿，之后到 7-24 只漂 0.3% |
| financial / valuation | 财务科目、估值倍数 | 标准数据 |
| public library | 卖方研报和播客的摘要，带券商、作者、日期、公司标签；研报没有全文 | Citi 9-28 AMD 收购 World Labs：评级、目标价、估值法、风险，三段摘要 |
| screen_drivers / screen_earnings | 按 driver 或财报评论跨公司筛 | 没试 |

## 它缺什么，对着我们的设计一项一项看

| 我们设计里的东西 | Distilla 有没有 | 差在哪 |
|---|---|---|
| 一个问题（争论），不是一个话题 | 没有。driver 是「话题 + 因果关系」：「AI 基础设施需求」「出口管制」 | 话题判不了对错。「出口管制」永远是一个话题；「中国区今年能不能从零起来」才有答案 |
| 梯子：事先写死的几种结果 | 没有 | 没有梯子就没有「现在站在哪」，只有一段话 |
| 到期日 | 没有 | 没有到期日就没有结算，永远开着 |
| 状态和每次变化的记录 | 没有。driver 整行覆盖，只留一个「现在 / 过去」的标记；摘要是一份份快照 | 问「这条 2 月怎么判的」答不了；问「哪份文件把它推下去的」答不了 |
| 证据分四档 | 没有。支撑事实里公司说的、媒体说的、模型推的混在一起 | 「知情人士称」和「公司公告」在它那是一样的字 |
| 每条证据的出处 | 没有。句子里有日期，没有文件编号、没有原句 | 这就是 Alex 说的没有 lineage |
| 依赖：主题到公司、公司到公司 | 没有。每家一张表，表之间不连 | 富士康的财报动了 NVDA 哪件事，它说不出 |
| 到期定格、记分 | 没有 | 它永远不会说自己错过 |
| 给 agent 的事件 | 没有，只有查询 | agent 要每天来问 |
| 用户、注、记录 | 没有 | 它不认识任何用户，这一点和我们的 Hivemind 一样，是对的 |

一句话：Distilla 做的是「把文件读成一段段描述」，我们做的是「把文件读成一个个会结算的问题的状态」。它的 driver 表就是颗粒度调研里说的那个失败样子，话题不是问题；它的原地覆盖就是没有 trail。

## 我们能拿它当什么用

- **当上游**。它的 file、standard_event、consensus、public library 都带日期、带类别，正好是我们分类里的 T1、T2、T4、T8、T11、T14 的来源。研报摘要尤其有用：第三方看法那一档的证据，带券商和日期，我们自己拿不到研报全文。
- **当市场读数**。一致预期按周的快照，是「市场押到哪」的替身之一，也是测「我们的状态比一致预期早几天」的尺子。
- **当对照组**。它的 driver 表和财报摘要就是「裸用模型一次性读」能做到的上限；我们的 POC 要证明的，正是多出来的那几样：问题、梯子、日期、分档、出处、状态历史、定格。

## 它给我们的两个警告

1. 它把 driver 做成话题、原地覆盖，大概不是不懂，是因为做成问题加记录要贵得多、慢得多，而且会被打分。这是我们成本和时间上的风险。
2. 它有一个现成的、覆盖美日港韩 A 股的管线。要是它加上问题、日期和记录，就是我们。它和 Simply Wall St、四五家 2026 年的 thesis tracker 创业公司一样，离我们只差一步。慢的只有记录这一样。
