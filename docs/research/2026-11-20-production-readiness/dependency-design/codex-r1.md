## 5. Daily order, propagation and cost

**Decided.** If both questions are due to be judged, judge the one being read first. If only the reader is due, it gets the latest available conclusion. If the question being read reports a changed conclusion, queue its eligible reader once in the same round. A change to a key figure counts inside the same rung. A resumed round recovers the queue from judgements already committed at its sequence number. Closed questions and questions without their own evidence are ineligible. Ordering and propagation must use the same current target, including after a successor takes over. Today `topological` can fall back to input order on a cycle, which makes the write-time check essential. [D51](/Users/lchingen/hivemind/docs/DECISIONS-log.md:1265) · [Order](/Users/lchingen/hivemind/src/hivemind/views/judging.py:102) · [Queue and resume](/Users/lchingen/hivemind/src/hivemind/views/judging.py:266)

For an isolated pair, the increase is **zero or one accepted judge call per day**. It is zero if both were already queued, the upstream conclusion did not change, or the reader is ineligible. It is one if the link is the sole reason an eligible reader is queued. Initial binding or moving to a successor can also queue that reader once. Retries and any wider chain are separate. At the published Luna rates of **$0.10/M input, $0.01/M cached input and $0.50/M output**, one extra call the size of old-2’s September 20 Data Center call would cost an estimated **$0.0056** before cache discounts. Existing calls that receive the line also incur its added input tokens. [Rates and usage calculation](/Users/lchingen/hivemind/src/hivemind/model.py:26)
