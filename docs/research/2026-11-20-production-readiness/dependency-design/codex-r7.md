**Two blockers remain.** Version 4 closes the write-record gap, but the harness lock does not stop an ordinary v118 writer, and the proposed serial replay gives the harness neither the item sequence at the transport boundary nor a place to inspect the link immediately after commit.

## Blockers

1. **Protect the harness store from ordinary writers.** Rejecting `jev-links` in the two CLIs stops those CLIs from launching v119. It does not stop either CLI from opening the same SQLite file under v118, which §0 expressly allows. `live_lock.acquire` is advisory, and ordinary replay does not take that lock. Mark each scratch ledger as harness-only before the run, and have ordinary replay refuse writable access to it under either configuration. Preserve read-only inspection. Test the refusal with the v118 CLI pointed at an unfinished harness ledger, before routing or writing an item. 2. **Use the existing `day_runner` seam for the July transport and inspection.** The test plan currently says `day_runner=None`. In that mode, replay calls `round.run` internally and then proceeds to the next item. `jev.ask` gives the transport only the request, which has no sequence number. After `round.run` returns successfully for seq 148, inspect the committed links before processing the next item or starting the day’s judging.
