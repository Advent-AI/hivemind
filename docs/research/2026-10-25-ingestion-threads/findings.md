## 2. 定位到哪里了

两份新样本均沿这个路径失败：

1. 原文 → 抽取：读出 3 个候选观点、3 个持续业务主线；每个观点都交了归属。
2. 原出处检查 → 保留这些观点；不是原句、年份或引用被筛掉。
3. 身份比对：请求同时允许旧 g 编号、本篇 t 编号、空串。两份回答的 6 项全部是 `id == target_thread_id`。理由是在说明“这个观点属于这条主线”，没有做我预期的“新建用空串”。
4. `resolve_threads` 沿本篇编号递归查根，认定自己引用自己是循环；原写入器尚未运行，整篇无最终写入。

直接机制是混合了两种不同工作：识别同一持续对象，以及让模型画一串通向最终编号的指针。主线不是因果依赖；为它加这套指针和防环，使一个本来意思清楚的归属答法变成整篇失败。形式检查确实守住了我写的合同，但合同本身使业务表达更难了。

schema 只把 target_thread_id 定成字符串；它没有在模型输出时排除本行自己的编号。代码最后拒绝不等于模型看见的是一个清楚、容易满足的选择。这不是再加一句“禁止自己指自己”就已经证明能解决的事。

### 零调用的决定性复现

对两份真实回答的副本，只把 6 个自己指自己的目标改为空串，其他候选、证据、名字、范围、比对决定全部不变。通过同一个 dispatch → sift → matching checks → writer：

| 副本 | 原答 | 只改目标格式后 |
|---|---|---|
| 样本 1 | 拒绝，0 个观点入库 | 3 个观点、3 条主线、3 条成员关系入库 |
| 样本 3 | 拒绝，0 个观点入库 | 3 个观点、3 条主线、3 条成员关系入库 |

这覆盖 **2/2 格式失败、6/6 自引用决定**。它证明第一篇卡在格式边界，不证明自动后续归组，也不覆盖超时。原实验目录和验收结果未修改。

## 3. 哪个方向保留，哪个要去掉

应保留：**抽取时先表达正在发生的持续业务过程，再保留其中独立的判断问题。** 例如 Rubin 产品准备、2026 出货、2027 客户工厂部署可以在一个持续过程里，各自仍有自己的证据和期限。已有研究中，持续故事与单个事件分开的做法支持这个建模思路，但不替这个产品证明效果。[EACL 2021 论文](https://aclanthology.org/2021.eacl-main.198/)

应去掉：让模型在本篇临时组之间填写通向另一个组的指针。它不增加金融研究含义，却需要根、空串、循环等额外规则。

**下一项建议是改身份输出合同，不是再换一种聚类算法。** 让比对直接交出“哪些本篇主线是同一个对象，复用哪个已存组，或者新建”。同一个结果中列出本篇成员，代码分配永久编号并保留观点归属。这样能表达同篇不同叫法，也不用本篇组互相指向。旧编号只能选已展示的库内编号；本篇编号只出现在输入成员里。模型负责是否相同，代码负责编号和写入。

这项建议会替换 D144 已登记的身份合同，当前没有实现或另跑一臂。它也不能靠本轮的零调用格式修复宣布成功。下一轮仍须真正让出货 → 客户部署 → 后续风险通过，且不混入出口政策、Groq 等其他过程。上层投资论点的撰写和结论仍是另一层，主线名字本身不是主论点。

## 5. 设计同步

逐模块按 PRD README 的四个问题核对：

| 模块 | 影响、例子与验收 |
|---|---|
| 研究对象名单 | 不增加对象；主线不是名单主题；原例子、验收不改。 |
| 分类 | 沿用原全文和类别；主线是在抽取中表达，不从上游标签猜；原例子不改。 |
| Config | 仍为原模型设置和搜索 N；没有新模型调用种类；预算仅是隔离研究约束。 |
| 分发 | 继续用顺序号、完成后跳过；未完成不冒充成功；原例子不改。 |
| 抽取 | 仅实验补充改为持续业务过程和必填归属，指向观点库合同；冻结正文保持原路径。 |
| 观点库 | 仅实验补充记录本次身份、成员、证据读取及失败；没有把未通过规则写成正式采用。 |

| 人工复核池 | 实验失败只留在实验目录，不增加正式复核机制。 |
