# 按持续业务主线入库：先认同一件事，再保留独立观点

状态：D144 授权的隔离研究。先审设计、用真实存档演算，再跑固定样本。正式流水线和封存库不改。

## 要改的核心

把观点正在讨论的持续业务过程记成一个有身份的对象。这里叫“研究主线”。例如“Vera Rubin 从产品准备到客户落地”是一条主线；出货时间、SK 工厂上线时间、供货风险是不同观点或证据。主线从第一条观点开始存在，后来的内容识别它的身份，不需要重新论证两个结果是否互相导致。

抽取每次写一个新观点时，必须同时交出它属于哪条主线。比对原来就负责认是不是已有的东西，现在分别认两种身份：观点是不是同一个可判断的问题；主线是不是同一个持续业务过程。代码按抽取已写的引用连接两者。没有第三次调用，没有抽完以后全库分组。

主线本身没有梯子和看多看空结论。它是以后上层论点的稳定内容范围。本次不把一个目录名冒充已经写好的投资论点。

## 两次失败的完整计数与机制

对 D142 的三个组织流、D143 的三个控制和三个新流共 27 个文章事件逐项读取原答字段、实际展示集合和入库组。只比较新观点同组的核心事件：

- D142 三次 SK 抽取全写出关联，三次比对都分开，0/3 同组。初始 7 组中 3 组的问题逐字等于底层观点的问题；最终 10 组中 5 组逐字相同、9 组单成员。单成员本身不是错误；把主线定义为单个到期问题才使后来的不同问题进不来。
- D143 三个新流：SK 都看见旧出货观点并写出新部署观点；两次 associations 为空，一次有内容，1/3 同组。首篇分别开 7、3、7 个观点，却只得到 1、0、0 个组。把组放在可省略的额外关系数组里，使独立观点可以成功入库而完全没有组织归属。
- D143 三个新控制也只有 1/3 同组。不是模型固定能力的精确估计；同一设计跨样本波动明显。

确定的机制是身份对象和输出责任不完整：旧版本要求比对额外推断组成员；新版本去掉这一步，却仍让主线身份与成员都可省略。D143 要求每次创建有依据的共同论点，混入了比识别同一产品进程更难的任务。最后一句是请求审查给出的解释，不是已经独立证明的模型心理过程。

## 外部研究读到了什么

[流式跨文件指代消解，COLING 2010](https://aclanthology.org/C10-2121/) 把新出现的实体描述连接到已经存在的实体身份，特别区分同名不同对象和同一对象不同叫法。借鉴的是“识别持续身份，再保存引用”，不是靠字符串相等定身份，也不照搬其算法。

[事件驱动新闻流聚类，EACL 2021](https://aclanthology.org/2021.eacl-main.198/) 区分持续新闻故事与细粒度事件，并把新内容与已有故事比较；它也指出碎片化需要单独衡量。这里借鉴故事与具体事件分开，以及同时看错误合并和错误拆分。其训练模型、数据集与本项目不同，论文效果不等于本系统效果。

[Zep/Graphiti 原论文 §2](https://arxiv.org/html/2501.13956v1#S2) 先抽取并识别实体，再把事实写成已识别实体之间的关系。其社区增量更新仍可能偏离全量结果并需要刷新，所以本次不采用社区传播来承诺稳定研究主线。

[GraphRAG 官方索引说明](https://microsoft.github.io/graphrag/index/overview/) 的基本路线是抽取实体和关系，再检测社区、写社区报告。这个任务要在现有入库步骤保留明确归属；引入整套社区和报告流程没有必要。

以上支持本次设计选择，不证明金融论点等同于实体或新闻故事。后者仍须由真实文章实验验证。

## 合同与边界

抽取保留原 evidence 和 candidates。新增 `threads[{id,name,scope}]`，描述本篇出现的持续业务主线；每个候选观点增加非空 `thread_ids`，只引用本篇 threads。允许一个观点明确连到多条主线，不强迫所有观点属于一个公司目录。每条主线必须有候选观点引用；引用集合由代码检查。已有观点带上已存主线的名称和范围，帮助本次读原文；不给状态或组总结。

主线 name 是持续业务过程的短名，scope 说明涉及的产品、项目、市场或政策过程及追踪的进展。不同日期、里程碑或客户落地问题不自动成为不同主线；只共享公司名也不自动同组。范围不等于一个 yes/no 问题，不为它另造梯子、到期日或证据论证。

原出处筛选完成后，只把保留候选观点引用的本篇主线送去比对。按 name+scope 在已存主线中搜索前 10 条，搜索不按公司隔离。匹配模型在原调用里交出 `thread_matches[{id,target_thread_id,reason}]`，对每个本篇主线恰好一项：选本条搜索展示的旧编号，或空串表示新主线；也可引用本篇另一条主线，说明两种描述指同一条。代码解析这个引用到旧编号或本篇新主线的根，自己指自己、绕圈和未知编号均不收。没有最终成员的根不建立。模型没有成员列表可改。代码不按名字相等认身份，不强行选搜索第一名。

原候选身份、原证据匹配和必要的第二次证据匹配不变。写入时先用原写入器取得真实观点和证据编号，再建立或复用主线，按候选观点引用写成员关系。只有最终保留的观点使主线落库；空组不写。主线不复制证据编号，也不另建来源表。详情通过成员观点的真实 evidence_links 读取证据，按所看顺序号过滤；原句合并、替代沿用原证据表。没有实际证据连线就返回空证据，明确没有证据，不把候选观点 evidence_ids 中的引用当作已存来源。成员另记本次 input_id，表示这次抽取作了归属决定。

每个组/观点只存一次；同一观点被不同主线的后续候选归入时可新增有来历的成员关系，不改其观点身份。新成员或底层 changed_views 会标主线更新；只多出处不触发。没有新候选观点的风险文章沿已有成员关系更新，不需要重写组决定。所有最终观点、主线、成员和处理完成记录在同一事务里提交。

## 旧决定

D33“抽取只读；比对和写进库在观点库”保留。D44“是不是同一样东西，全由模型在比对时判”应用于两个不同身份，不让同一个问题的身份规则兼任主线定义。D51 的依赖规则保留，主线成员不生成依赖。D143“新组至少两个不同观点”不继续使用：持续业务对象第一回出现就要能取得身份；是否错误碎片化按后来的相关观点有没有复用它来测。D133 保留原生英文输出和封存库只读。

## 状态 × 事件

所有写入按分发顺序号排序，证据日期仍从原文来；不按电脑时间分组。

| 进入状态 / 事件 | 转移、写入与日期 |
|---|---|
| 空库 / 第一篇 | 原抽取交主线与观点；搜索为空时比对选新主线；同事务建立身份、成员和来源。 |
| 已有主线 / 后来的不同里程碑 | 原抽取写不同候选观点；主线匹配复用旧身份；观点仍分别通过原身份检查。 |
| 已有主线 / 无新观点的证据 | 不做主线创建决定；原证据写入后根据 changed_views 找已有主线。 |
| 候选观点归入已有观点 | 引用解析为已有观点；成员去重；来源取实际写入的证据。 |
| 候选观点接续 | 引用解析为新一期观点；主线身份单独匹配，不按日期自动切组。 |
| 候选观点被原筛选去掉或不开 | 不以它创建组或成员，记录未保留的结果；其他有效部分照原流程。 |
| 新主线没有最终成员 | 不建立空组。 |
| 同篇两个主线描述其实相同 | 比对引用同一个本篇根；代码合并身份，不合并它们的不同观点。循环引用拒绝本条写入。 |
| 成员没有实际证据连线 | 详情返回空证据；input_id 仍显示归属决定的来源，不虚构支持证据。 |
| 缺归属、未知引用、匹配漏项/重复项 | 本条失败；原答保留；零最终写入，不修原答、不补样。 |
| 相同 input_id 重送 | 原分发跳过，零模型调用、零新增组成员。 |
| 晚到旧文章 / 新 input_id | 本次顺序号记录新增信息；原证据替代仍按原始说话日期，不回改旧图。 |
| 外部调用失败或提交前崩溃 | 最终写入回滚；已开始请求不自动重发；保存失败位置。 |
| 重启 / 输入或配置变更 | 完成文章跳过；代码、输入、配置指纹不同拒绝复用目录。 |
| 两范围 / 另一写者 | 实验单写者串行；每样本独立库；主线搜索不限制对象。正式并发队列不在本次。 |
| 终态 | 固定样本结果和每步图留档；语义验收失败则停止，不另调一臂。 |

## 新路径 × 原检查

原句检查、证据去重、季度和年份、梯子、对象名单、观点身份、依赖防环、证据第二次匹配、先主题后公司、最终事务和分发去重全部仍运行。组身份只增加一次原比对调用的结构化输出，不绕过原观点检查。主线不能使本来不开的观点落库，也不能把自身当作客观证据。

## 固定实验和预算

沿用三篇原始全文与顺序：2 月 25 日 NVIDIA 电话会、7 月 24 日 SK 公告、8 月 12 日 Network World 汇总。三份独立新样本各配一个新鲜 D143 控制；每篇正常抽取和比对，预计 36 次调用。原有第二次证据匹配按需执行。仍是 gpt-6-luna、原抽取/比对思考设置，上限 48 次及 $8 估算，不提升上限。

先用真实存档候选观点模拟新增必填归属、引用检查、身份解析、搜索、写入和后续证据路由，并故意删归属和破坏成员写入，证明检查会失败。必须先跑 scripts/preflight.py；原数据检查分布变了则先诊断。

核心语义标准不变：三份新样本中，出货和 SK 部署是两个独立观点且属于同一持续主线，财务/税务等不相关观点不被塞进 Rubin；原句风险成功保存时沿已有关系触达该主线，ID 不变；重复 input_id 零调用。逐项读原答，同时报告底层抽取遗漏或原句拒绝，不能当作分组成功。

为检验不只记住 SK，核心三个新样本归组全部成功后，额外给新臂各进一篇未参与前两次实验的原文：`gnews:f2bbeb9e369dca841a5a0381`，2026-08-05，Musk 所述 Starmind 的 Vera Rubin NVL72 卫星 2027 年发射计划。作为晚到的第 4 条，预计另 6 次调用；不改变前三条比较。只检验新出现的相关里程碑是否复用已存主线及保持独立身份。这个补充没有旧臂对照，不叫额外比较实验。核心失败则不运行补充，不据结果另换文章。

不预先放入组、不在提示词写 NVIDIA/Rubin/SK、不用标题字符串算通过。固定原句 e7/e55/e724/e519 在各文章的位置是追踪起点；沿实际 evidence_links 与成员表认结果，同时人工查看全部组名、范围与成员。三个样本不足以证明全行业泛化；没有主线评分、上层论点合成或线上迁移。

## 设计审查的两处修正

第一轮发现：同篇两种主线描述需要能归到同一新身份，已加入本篇引用及防环解析。另一个发现是候选观点的 evidence_ids 不保证实际连到了这条观点；读了原 sift 和 writer 后，对前两轮全部原答的 80 个候选观点证据引用计数，有 1 个未连到所称候选观点。但实际 57 个新建观点都有本轮真实证据连线。处理方式是删去主线的证据复制设计，只沿原证据连线读来源，不补另一套校验/修补映射。

追加文章采用单独命令：前三篇全部完成后先读核心结果和所有成员；只有三个新样本同组且没有无关成员时，才按原计划执行追加文章。否则停止。这不是见到失败后选择新样本。

## 付费前的实现检查

11 项针对性用例通过；连同原测试共 84 项通过。真实三篇文章上的手写回答只证明接线，不证明模型能自动归组，结果在 `poc/reports/2026-10-25-ingestion-threads-free-01/`。三个故意破坏的副本都被抓到：忽略旧身份后出现两个组，漏写成员后为空，过早提交后回滚留下新观点。首次测试里曾试图删除只追加表中的连线，被存储规则拒绝；改用真实的新建无证据成员验证空证据读法，没有放松存储规则。

完整请求审查：保留原抽取对可判断观点的限制，仅把持续业务对象作为独立输出；匹配中“同一时期、同一结果”的规定仍只管观点，新增身份规则明确管主线。移除了旧版必须有两个成员、必须解释结果间联系、由抽取直接决定永久组身份的任务。不再重复存证据。不要求模型看到未提供的旧组；主线搜索结果是其可选旧编号集合。原文、对象和财政时间上下文沿用原路径。

系统提示词合计从 3,482 字符 / 640 token 减到 3,447 字符 / 637 token（o200k_base）。抽取从 2,272 / 419 减到 1,817 / 337；匹配从 1,210 / 221 到 1,630 / 300，是将持续身份识别移到原身份决定处。没有新增模型调用。schema 增加了必填引用和独立身份结果，以代码拒绝漏交和未知编号；没有把结构检查堆到提示词。
