从原文，到可持续更新的研究判断

每一步收什么、交什么，以及怎样做到：留下重要信息，合并同一论据，保留反证，避免重复计权。

待评审草案 · 不是已实现的完整流程逐步 I/OVera 例子需要你 review 的选择

三个不同的东西：来源记录＝谁说了什么；研究论据＝这些材料共同说明什么；研究问题＝我们持续跟踪什么。
多了一条来源，不自动等于多了一份独立支持，也不自动新建研究问题。

01 · 模型＋代码读原文 → 来源记录 02 · 数据库列问题 → 按需取全 03 · Jev比较关系 04 · 分析模型取舍、合并、归位 05 · 代码保存研究更新 06 · 判断模型更新研究判断

这里的顺序是一份可讨论的方案。Vera 实验没有证明 Jev 必须前置；它先给比较意见，不能直接决定丢弃或合并信息。

01 / SOURCE

读清原文

模型提取；代码校验引用
新接口已实现 · 实测仍未通过
输入

完整原文、段落/句子编号、报道方、发布日期、研究对象。

不输入已有研究问题，避免为了归位改写原意。
输出

来源记录 S：摘要、说话者的原文引用、时间短语及角色、证据类别、原文定位。

代码补来源 ID、版本和 quote；缺失的发言日保留未知，不拿报道日填上。
目标效果

保留主体、数字、条件及相反意见。原文只说“计划”，不能变成“已发生”。

引用存在由代码检查；摘要和归属是否正确仍需语义验证。
02 / RETRIEVE

列问题，取全资料

两次只读数据库操作
新入口 · 1,114 个历史输入取全验证
输入

2a：输入的研究对象、配置的主题、处理前的序号。
2b：第 3 步选中的目录内问题 ID。

查询不看摘要前几个词。两次读取固定在同一历史状态。
输出

2a：范围内完整开放问题目录及直接依赖。
2b：所选问题全部有效证据、出处、前一版本、最近判断和依赖。

不取前十，不静默截断；超出大小预算明确失败。现行库没有整理后的论据汇总。
目标效果

Vera 的旧测试限制和商业化风险不会因词语不相似而被筛掉。

验证了 28,918 次问题展开和 1,047,953 次证据读取。只证明取全；第 3 步的相关性选择仍需验证。新入口尚未替换生产默认。
03 / COMPARE

比较关系

Jev
已实跑 · 仍有误判
输入

先读来源记录 S ＋ 2a 问题目录，选择相关问题。再调用 2b 取全这些问题的资料，比较新旧来源。

顺序是 2a → 问题选择 → 2b → 来源比较；这个新选择入口尚未验收。数据库读取本身没有模型调用，读取结果送入模型会占输入 token。
输出

关系意见 R，每项带对象 ID 与分数：

① 对旧问题：直接结果 / 业务线索 / 背景 / 无关 / 不确定。
② 对旧证据：同一陈述 / 修订 / 不同。

目标效果

辅助定位可能的去向和重复来源。

不删除、不覆盖、不因“不同”而自动建卡。Vera 中 Jev 三次仍把新测试判为重复。
04 / SYNTHESIZE

取舍、合并、归位

分析模型
部分实跑 · 输出需扩展
输入

S ＋ C ＋ R，并可回看完整原文。

不能只读 Jev 标签；必须比较新旧内容，保留不同条件和反证。
输出

研究更新提案 U：去向、更新哪个论据、合并后的表述、新增了什么、支持/反对来源、限制及来源是否独立。

去向：更新已有问题 / 提议新问题 / 仅作背景 / 暂无法判断。每条来源都记录处理结果。
目标效果

同一论据持续更新，不随报道数量膨胀。重复报道只增加出处；新条件留下；矛盾并列解释。

新问题必须说明独立研究价值。实验只做了去向与自由文本整理，尚未完成此结构化合同。
分支：只有第 4 步提议新问题时，才再检查“问题是否相同”。

输入：拟议问题 ＋ 相关旧问题 → 输出：同一问题 / 同一问题的新期间 / 不同问题 / 无法判断。

同一问题回到第 4 步归位；不同问题还须满足重要性与完整建卡合同（问题、结果范围、期限等），不能仅因不同就写入。这个分支尚未实跑，不是第 3 步“来源对问题”比较的替代品。

按事实的分量调整判断，不按报道条数加分。新测试不能自动推导出新增收入。

用 Vera 走一遍

新材料：公司内部估算称，Vera 在四类 agentic 工作负载上，每核性能最高达到 AMD Venice 的 1.5 倍。库里已有 CPU 收入问题 v5，以及较早的性能说法 e652。

本轮第 2 步实际展开 v5 的 95 条有效证据：保留 AMD 反向主张 e647，并取回旧前十列表漏掉的 e111/e488/e649（测试限制）、e653/e654（市场规模、收入兑现与重复计算风险）。这些材料已取回；下方的整理后写入仍未实现。

实际结果 · 新流程各跑三次

目前做到了哪里

  • 三次都更新 v5，没有另建 Vera 收入卡。
  • 三次都保留了新测试记录；没有被旧摘要覆盖。
  • 后续仍读 96 条平铺证据，没有读到整理文本。
  • 一次整理错误地说原文没有列明具体工作负载。

只测一条固定抽取结果和固定旧内容；不代表召回、全文抽取或整体质量通过。

第一步仍失败在哪里

实际新回答：期间变模糊

原文：It has started fiscal 2027 on a stronger note in this segment, with networking revenue tripling year-over-year to $14.8 billion.

模型摘要：Nvidia networking revenue tripled year over year to $14.8 billion in fiscal 2027.

final / motley.1.candidate / p013o03。丢掉财年开头的限定，孤立读取容易被当作全年收入。原文引用仍正确，JSON 也合法。

建议改变的处理方式 · 尚未采用

第一步只选择有意义的原文片段，代码复制原句和必要上下文；摘要留作审计，不独立充当下游事实。后面的分析步骤对原文、旧证据和条件一起作判断。

这会改变现行抽取 PRD 的“独立摘要”与匹配 PRD 的“读取摘要而非全文”边界，需先确定合同再测，不能改完判法就宣布通过。

需要你 review 的三个设计选择

1 · 保存什么？

建议同时保留原始来源和持续更新的研究论据。第 6 步必须能读到论据及其来源，而不是继续只有证据列表。

涉及新的读写合同
2 · 什么才值得新建问题？

建议以独立的重要业务判断为条件。一个新产品、一个新数字或较窄的范围，本身不够。

重要性标准需确认
3 · Jev 有多大决定权？

建议只给关系意见。是否保留、怎样合并，由能读完整新旧内容的分析步骤负责。

是否需要它仍待对照验证
