# D147：读全文时直接决定归属，匹配不再重判

第一版抽取归属变体已完成；当前合同见 retained-membership-plan.md。

## 已定位的原因

直接分组格式修复后，sample-2-threads 的第二篇仍建了另一个组。原始输入已经展示 g3“Vera Rubin product rollout”；本篇 t1 是“SK Telecom–NVIDIA AI factory rollout”。模型解释为不同客户部署，所以 destination=new。搜索找到了，抽取保留了，写入正确执行了选择。失败在问题本身：两个过程不是同一件事，不代表其中一个具体观点不属于另一个过程的研究范围。

因此不实施 required-choices-plan.md。它只能修复空数组，不能修复这一次真实失败。保留该草案作为未实施记录，不把它算一次实验。新合同移除所有组身份匹配字段，从根本上移除自指、遗漏的第二次决定和错问身份。

## 一条路径

1. 原分发给出顺序号。按全文的词从全局组名称/范围索引取前 N 个组，不按公司过滤；这里只是检索，不由代码判定归属。N 沿用原配置 search_top_n。
2. 抽取读全文、原已有观点与已存组。每个候选观点必填 thread_ids，至少一个。它可以直接引用展示的 g 编号，也可以引用这次 threads 声明的新 t 编号。一个观点可属于多个组。抽取判断的是观点是否属于组描述的业务过程，不是两个过程描述完全相同。
3. 新 threads 只声明没有合适已存组的持续业务过程；同篇多个相关观点共用该本篇编号。代码检查引用闭合、不得重复、所有新声明须被引用。已存组不重写名称与范围。
4. 原筛选去掉不合格观点。原匹配只决定观点身份、依赖、证据身份，不接收或返回组字段。代码按原观点最终编号保存抽取决定的归属。原 evidence_links 是证据来源的唯一所有者。
5. 原观点、证据、组、成员与完成标记在同一个事务提交。只有新成员或 changed_views 才影响组；只更新旧证据的文章沿已有成员更新，不需要再输出组。

例子：第一篇建“Vera Rubin rollout”，包含出货问题。第二篇读到 SK 工厂用 Rubin，直接把工厂上线问题的 thread_ids 写为这个旧 g 编号。出货与工厂仍是两个观点，归属只决定一次。费用和毛利率问题不能因为同公司加入 Rubin。

## 与之前合同的区别和决定

D33 的抽取只读不变，实际写库仍由观点库负责。D44 观点身份仍由原匹配模型判断。D51 因果依赖不受影响。D143 曾让抽取决定可省略 associations，两个保留观点才建组；现在每个候选的归属必填，组能从一个观点开始。D144/D147 的组描述身份匹配在本变体被删除；并不改变生产或历史实验。

全局全文 FTS 只是本次隔离 POC 的检索实现。三个核心来源都涉及 NVIDIA；不能据此宣称跨行业或大库召回已通过。新增模型调用为零；不生成主论点，不改 UI/MCP/Idea。

## 状态 × 事件

顺序一律使用 dispatch sequence，证据日期保留原发布/说话日期。

| 状态 / 事件 | 行为与写入 |
|---|---|
| 空库首篇 | 展示空组清单；抽取声明新组及候选引用；原筛选/匹配后只保存有最终成员的组。 |
| 已存组 + 后来里程碑 | 全局检索后由全文抽取直接选择 g；原匹配保留独立观点身份；同事务加成员。 |
| 多个相关候选 / 多个业务范围 | 共用 t 或 g；每个候选可引用多个组，代码不猜同义、不合并名称。 |
| 找不到合适组 | 抽取新声明，清楚记录这是模型选择，不默认塞进第一个组。 |
| 候选筛除 / 不开 | 不写该候选的成员；没有最终成员的组不创建。 |
| 候选归已有观点 | 原二次证据比对照常；成员引用最终观点编号，不用本篇编号。 |
| 仅旧观点新证据 | threads=[]；沿 changed_views 更新其现有组。 |
| 未展示 g / 未声明 t / 空归属 / 多余新声明 | 本地核对拒绝；保留原答；不补填。 |
| 写入途中失败 | 全部本篇最终写入回滚；原开始记录保留。 |
| 超时 / 拒答 / 中断 | 不自动补样，记录未完成；其他独立流继续。 |
| 同 input_id 重送 | 原分发跳过，不发新调用，不新建成员。 |
| 晚到文章 | 新顺序号入库，原发布日不变；历史快照不回改。 |
| 配置/代码/输入改变后恢复 | 指纹不符拒绝；新的开发变体用新目录。 |
| 两范围 / 另一写者 | 检索不按对象过滤；隔离数据库串行，正式多队列不在本次范围。 |
| 实验结束 | 按既定原句追踪和语义要求报告每个样本；失败不改测量标准。 |
