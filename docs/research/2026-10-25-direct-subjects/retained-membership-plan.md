# D147：只保存实际引用的组，移除不影响产物的拒绝条件

单字段 schema 变体的第二篇已有两份正常提交。第一份选择了有效的旧 g1，同时声明了一条未被候选引用的新 t1。旧校验仅因这条未引用声明就拒绝整篇。它没有改变观点归属，也没有造成重复、空引用或无效引用。

逐个读者追踪：raw.threads 先在 process 中按筛选后 candidate.thread_ids 过滤；write_threads 再按真正保留/归入的观点建立 bindings，并且只为这些 bindings 使用的定义写新组。没有读者使用未被引用的定义。因此“每个声明必须被用到”不是产品需要的约束。原写入路径本来就能忽略无最终成员的声明，早一层再拒绝反而挡住了正确的旧组归属。

修改只去掉 validate_extraction 的未引用声明拒绝。继续拒绝缺失/空/重复/未展示/未声明的引用；继续拒绝重复的新定义编号、空名称和范围。不删除或补填原始模型答复。原来的保留候选过滤照旧决定哪些新定义进入写入器。已有完整引用的组与观点写入完全不变。

这不是修改通过标准。仍要求原句、两个独立观点、共同 Rubin 组、真实风险流向、无错误混入全部成立。改变的是接受哪些不会影响产物的附带声明，PRD 实验合同同步明确“只写有实际成员的组”。

## 状态与读写影响

| 状态 / 输入 | 结果 |
|---|---|
| 全部声明有引用 | 与之前逐字段相同。 |
| 未引用声明，其他引用合法 | 保留模型原答；原 used 过滤不传该声明给写入器；其余照常。 |
| 引用本身重复、空或非法 | 同原规则拒绝；本修复不为该类放行。 |
| 引用该组的候选被原文筛掉或匹配不开 | 原写入器不创建无最终成员的组，与之前相同。 |
| 崩溃、重送、晚到、配置变化、多范围 | extraction-membership-plan.md 原表不变。 |

| 值 | 所有者 / 读者 |
|---|---|
| raw.threads | 模型原答留存；校验定义唯一性和必填文本；不要求每项都成为产物。 |
| retained threads | 原 process 按保留候选的引用过滤；仅 write_threads 读取。 |
| memberships / evidence_links | 原写入器、原读取；没有改数据形状。 |

新执行模块合并当前抽取归属、单模式引用 schema 与这条校验修复，避免以运行时替换或捕获异常实现。旧实验代码和失败目录均保留。新库从空重放已有原答，Calls 必须逐字核对实际请求；只对没有存档的新步骤发调用。每个重用原答标 reused_from，不重复计费，不称为新模型样本。三份旧第二篇的模型选择仍是原有三份；这里只是实际跑通它们。

先在真实第一份失败上移除校验的 scratch 副本证明能保存两观点一组且不保存空 t1，再保留所有非法引用的负例，并以重新加回该拒绝为破坏测试。全局仍同一 48 次/$8 上限，无新增样本、模型或 provider。核心全过且剩余预算允许才做原来登记的追加文章。
