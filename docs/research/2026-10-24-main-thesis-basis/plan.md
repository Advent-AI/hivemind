# 先处理依据、后写总结：两条主线验证

状态：固定实验已完成，结果见 [findings.md](findings.md)。只做隔离研究，不接生产。

## 核心假设

把出处交给代码保管，把当前支持、反证和未解决依据分别保留，再生成总结，可以避免“编号重新拼错”和“总结漏了，agent 也看不到”。不改模型、不扩大研究问题、不重抽取。

例子：Rubin 的系统验证进展和供应链延期风险都在当前输入里。必须分别处理这两条依据；总结是否引用它们，与它们是否保留在 agent 能读到的当前依据中，分开检查。

## 原样保留的输入与对照

- 直接读取上一轮封存快照 `poc/reports/2026-10-24-main-thesis-replay-01/input.json`，校验原库与快照指纹。Rubin 66/379/532，Capex 379/552/584，两个问题及候选观点完全不变。
- 三个独立样本；同一 OpenAI / gpt-6-luna / low reasoning。每个样本有独立调用档案。最多 42 次 HTTP 尝试，仓库单价估算上限 $8，不重试、不补样。依据逐项处理的输出较长，单次上限沿用首轮调用器的 7,000 token。
- 18 次依据处理：两范围 × 三时点 × 三样本。每个时点重新审视全部当前依据，并显式给出新增、保留、移出当前集合的清单。不给旧总结或旧解释，避免继承旧文案。这不是大库上的低成本增量算法。
- 只在最后时点生成总结：6 次新方法、6 次独立直接综合对照。对照使用相同当前数据、同一来源标识和同一总结合同，区别是没有逐项处理的依据表。
- 两种最后卡片各做 6 次 agent 探针，共 12 次。合计 42 次。旧实验作为故障案例，不作为本轮独立控制。

## 数据合同：来源与作用分开

| 内容 | 唯一写者 | 完整规则 |
|---|---|---|
| 来源记录 `source_eN` | 代码 | 一条 evidence 只出现一次；附原文、原属性及当前所有真实 view/judgement 来源路径。来源路径不声称这些观点都支持总论点。模型不填写 view/evidence/judgement 配对。 |
| 当前来源集合和变化清单 | 代码 | 从每个时点当前观点的已引用证据构造；按来源标识比较新增、保留、移出。移出只表示当前判断不再引用，不表示事实被推翻；旧记录保留。 |
| 依据处理行 | 模型 | 每个当前来源恰好一行：来源标识、supports/challenges/context/irrelevant/uncertain、理由。作用指向问题中的业务路径，不是证据最初挂在哪个观点。所有标识都是输入闭集；不生成新事实或总分。 |
| 当前依据表 | 代码 | 处理行与固定来源记录连接；五种作用分开保留。irrelevant 不放入 agent 阅读卡片，其余都保留，不能由总结的引用选择二次删除。 |
| 总结 | 模型 | 当前结论、带来源标识的论据、限制。新方法只读当前依据表；对照读当前原始快照。两者都不读旧总结。 |
| Agent 卡片 | 代码 | 新方法：总结加全部非 irrelevant 依据；对照：总结加其实际选择的来源。标清每条来源的已有来源路径。输入规模差异计入成本，不声称算法变量完全相同。 |
| Agent 答复 | 模型 | 每个既有 facet 回答当前状态及关键限制/风险，只引用卡片实际可见来源标识；空引用允许表示不足，但不算下钻已覆盖。 |

对同一 evidence 的多条来源路径只保留一次原文，不计多票。模型可以判断它影响总论点，但不能由此新增底层 evidence→view 关系。每次来源选择由代码恢复原来的 view/judgement/evidence，消除旧实验的 32 处配对拼接这一类错误；不因此宣称选择语义正确。

完整性由必填键的对象 schema 表达：每个当前来源标识都是一个必填键，值只有作用和理由，禁止其他键。模型不负责抄一遍来源 ID 清单；重复行在这个表示里不可表达，缺键或未知键由 schema 拒绝。

## 观察项与停止规则

1. 来源与覆盖：全部当前来源是否有且只有一次处理，引用是否在可见闭集内，来源路径是否与快照一致。可由代码证明，不当作语义准确率。
2. Rubin 风险：e724 在三个最后依据表中被如何处理；总结和 agent 是否表达延期风险，是否区别“风险”与“已发生延期”。不给模型这个预期或特殊标记。
3. 出货/部署/收入：沿用三个 facet，检查是否把计划当实际、是否把 CPU 和 Vera 两种收入口径相加。
4. Capex：是否保留约 $800B 为预测，是否把行业支出直接当 NVIDIA 收入；v94 是否被误当行业支出下降的反证。
5. 控制自身差异：逐个报告三个样本，不定综合分数、不用代码找某个词就宣布正确。没有用户确认的语义 gold，以下是对既有故障的人工诊断，不作正式准确率验收。

出现语义失败只记录，不在同一轮改提示词、添特例或换模型。结构失败保存原答并停止该依赖链；独立控制仍跑。分清“依据被标成无关”“依据存在但总结没说”“卡片有但 agent 没说”，不再全称为同一个遗漏。

|---|---|
| 未准备 / 开始 | 新日期目录；锁定代码、输入、配置、原库指纹；只读固定 cutoff 内的数据 |
| 已准备 / 免费预检 | 重放旧 23 份原答引用 census，确认 32 处；对六个当前集合逐项检查；真实来源正例、缺行/重复/错误引用突变必须被拒绝；跑仓库 preflight |
| 初始时点 | 当前来源全部是新增；处理每条来源，保存这个 cutoff 的依据表 |
| 后续时点 / 有新证据或判断 | 代码提供来源变化清单；模型逐条重新审视当前集合，不读旧文案；保存新表，旧表不改 |
| 同一内容重读或无关序号 | 相同请求只重放；当前来源内容和观点判断未变则当前依据可以复用；本轮不另测语义重复判断 |
| 来源移出或输入修正 | 不在新表的活动集合里；保留旧版本，不宣称被否定。已锁定实验的输入修正须新目录，不能混进原样本 |
| 返回合法 | 保存完整行及来源路径；最后时点才做总结、agent；历史 source_seq 不冒充实际发布时间 |
| 返回非法 / 外部失败 | 保存失败，停止本链，不发修复请求，不发布半张表；继续独立对照 |
| 中断 / started 尚未完成 | 拒绝自动重发；已完成步骤只重放；不确定请求保留预算预留 |
| 重启或另一写者 | 整轮独占锁；校验输入/代码/配置指纹；不一致拒绝，两个范围串行执行 |
| 全部完成 | 统计所有样本、拒绝及未执行路径；不改变正式系统 |

## 运行前检查

只读计划审查未发现严重阻塞。六个真实快照合计 274 个来源实例，完整键集合正例通过；缺键、未知键、未来来源和卡片外引用都被拒绝。旧 32 处错误配对全部用固定来源恢复为真实出处，不代表原来 32 句语义都错。19 项相关测试通过。三个代码突变（删除总结未选的反证、恢复错误出处、取消来源闭集）分别被决定性断言抓到。
