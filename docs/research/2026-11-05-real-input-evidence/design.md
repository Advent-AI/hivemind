## Inputs and readers

- Select eligible genuine articles before reading their outputs, with a clean held-out date slice, precise publication date, readable source, genuine reported speech, and report published before the article. Freeze an auditable manifest. Do not call previously read articles held out. Exclude future material leaking into a page, same-event repeats across the train/held-out boundary, and ambiguous source timestamps; print every exclusion and reason.
- The same article, initial real prior research state, source category, metadata, frozen prompt/schema, and time cutoff appear in both arms. The only experimental difference is an explicitly labelled excerpt or report text from a report already public as of that article. No facts after the article may enter either input. A real prior library must be traced back to pre-cutoff articles and contain none of the 22 seed rows; if this cannot be proven, use the empty-state stratum and label it, never substitute the seeded ledger.
- Unit: a source-faithful research matter in one article. Two independent readers write reference matters from each original article before any answer is viewed, using the signed standard and D228's investment-relevance and source-tier rules. Reference documents the source span, material business consequence, speaker, uncertainty, time, and whether material to existing research or a new idea. Resolve disagreement against sources; blind the readers to the arm when assessing answers. An output's longer quote may overlap both a kept and a non-kept matter; compare meaning and delivered unit, not substring count.
- Outcomes: core and supporting matters counted together for capture (D369), unsupported extra claims, factual/attribution/time/hedge errors, facts wrongly borrowed from the report and represented as news, investment reasoning completeness; followed independently through real quote checks, link checks, writer and actual downstream reader on a temporary ledger. Report raw answers beside source for every loss and meaningful extra. Measure cost and requests separately. A JSON/schema pass is not semantic success. Take multiple draws paired against a same-day fresh control; publish every draw, article, regression and uncertainty. Do not infer general improvement from one selected example or one company.

## Review round 1: revisions before implementation

An independent read-only review found five serious gaps. The following closes them at design level; an implementation review is still required before a change is accepted.

1. **No-seed entry is closed.** New replay CLI has no --seed option, creates no seed questions and runs no question-by-question baseline. v116 remains frozen as a historical configuration but is rejected on the new entry because its baseline depends on seeds. A new default configuration copies v108's extraction, matching and judgement settings and has no baseline. The legacy seeding library and frozen file remain only for historical evidence; they are not invoked by the active replay. An existing ledger whose views were created from seed inputs is refused without modifying it. The entry checks question origin identifiers against the supplied items database and refuses seeds and missing identifiers; this is not a full audit of the research history or its evidence. The experiment uses only a fresh empty ledger until every prior record and its date has been verified separately.
2. **No-home is measured, not quietly repaired.** A temporary real ledger with fake external services must demonstrate one source-backed candidate and evidence reaching the writer and reader, plus an unlinked evidence item being dropped with its reason. Compare model raw, quote/shape refusal, no-home, stored evidence and downstream read separately. No new parking list or generic retention rule is introduced.
3. **Precise comparison input.** In this pilot, treatment adds the complete, selected earnings release / CFO text as a distinct `[Earlier earnings report: background]` block after the article in the user message, with report date and source id; the control carries no such block. The frozen role and schema stay byte-identical. The only other difference is the new block. This is a changed request and is labelled an experimental arm, not the current production configuration. The original news text alone goes to quotation validation; report text must never be inserted into the `text` argument or accepted as an article quotation. Reader also checks whether summaries mistake older report facts for news. If a source does not establish its availability before the article, that case is ineligible. No same-day ordering is assumed.
4. **References do not become a second ruler.** At Alex’s explicit request, independent readers prepare a separate new source-anchored gold for the real-article study before viewing outputs, applying the existing signed standard without changing it. The new gold is model-authored and is not approved or usable for scoring until independently reviewed and signed by Alex under AGENTS §7.1. Business effect is a reviewer observation, not a new automatic rejection criterion. If the standard itself is unclear or readers disagree on the standard, stop rather than invent a rule.
5. **Paired state is immutable.** Each article's two requests use the same prior, verified article-created research-library snapshot for that date; each answer is applied to separate temporary ledger copies. A prior snapshot contains no seed input and all its records must predate the article. An empty library is a separate labelled stratum; it is not mixed with a history snapshot. No per-article result claims that a whole evolving 14-day ledger was tested.

Preselected candidates: candidate-articles.json, 12 IDs across six September and six October articles, selected by a fixed hash and category, not accepted for a send. Source availability, publication chronology, duplicate or syndicated story across splits and frozen-set exposure have not been established. The July 2 Singapore sample previously inspected was excluded: its stored page contains October 23–24 headlines. A 68-question sealed ledger contains no `seed:` origin but this is merely a structural census; source provenance and as-of restoration remain unverified. Do not infer safety from an ID alone. The 8-K May 20 and August 26 are reports visible in the source database, not yet approved as context for any sample. A successful design review must judge all five corrections and the live context selection before any send.

3. Reference readers see exactly the article bytes passed to the model after `MAX_TEXT_CHARS`, and the exact prior context that both arms see; note original hash and truncation. Check any truncation before inclusion.
4. No experiment run resumes: a failed call and its reason remain in the attempt log (transport failures can precede the model archive), and an explicitly recorded fresh draw starts with a fresh archive and identical immutable inputs. ## Review round 4: resumption and attribution

The initial no-seed experiment uses fresh per-arm ledgers and does not resume. Existing replay resume behavior is not changed or newly certified by removing seeded questions; in particular serial replay can reuse a handover after an input or configuration changed. Its redesign is not necessary to make a fresh no-seed run and is outside this change. A completed non-seeded ledger can still supply prior research, subject to existing backdating rules. The experiment makes no concurrent writes to the same store. Do not claim the production replay independently detects changed input when resuming.

Quote acceptance alone is not proof of correct attribution: reviewers compare the original model quote and saved quote, summary, speaker, date and uncertainty against both article and report, explicitly including a quote repaired to an article span whose added words or summary came from the report. Count/report these mixed-source mistakes separately. A dispatch intent without a terminal event is an unknown outcome, not a failure: retain its attempt identifier, count it and its unknown cost, and distinguish any explicitly recorded fresh attempt. Do not silently retry.

## Experiment transport: follow the real extraction path

A proposed custom one-attempt sender was independently reviewed and found to need a full separate dispatch, retry and cost contract. It is not built. The experiment is meant to test the product's extraction, so its live calls should use the existing production `model.call` / `openai_transport` with its current retry and serialization behavior, not a new sender. `openai_transport` makes at most three HTTP attempts in total, including the first send, and retries certain network and HTTP failures. A request that ends without a usable response is reported as a failed or unknown attempt and is not silently converted into a successful draw; actual HTTP retries are part of product behavior. Earlier attempts can have unknown cost even when the final answer succeeds. Read available usage from the raw response independently of answer validation and calculate using model.PRICES; missing usage and earlier uncertain charges are unknown, never zero. Each draw has a fresh archive so an identical request is not answered from cache. Freeze and verify the full request, configuration, universe, article and report identities immediately before a paid call; preflight first. The experimental call is still an altered request because it includes the report block. This design has not yet been independently reviewed or implemented for paid operation.

### Closed `items` field mapping for archived variants

The local database must have exactly the current 37-column `items` schema; if it differs, refuse rather than guess. For each variant: `input_id` = derived canonical identity; `text` = archive body; `content_sha256` = SHA-256 of UTF-8 `text`; `text_chars` = character count; `text_page` = null (the original archived HTML is retained separately, not misrepresented as a cleaned page); `text_article` = null. `published_at` = archived publisher timestamp; `publication_day` and `page_day` = the archived publisher's date (validated equal to the capture's UTC day and the original corpus day for these three); `retrieved_at` = capture timestamp; `day_source` = `archive_publisher`; `listing_day` = null.

`klass`, `category`, `publisher`, `publisher_type`, `authors`, `document_format`, `channel_category`, `media_type`, `language`, `object_identifiers`, `title`, `topic`, `tier`, `is_structured`, `has_readable_text` and `bootstrap` are inherited from the original record and marked inherited in provenance. These include classification metadata, not independently proven facts about the source. `channel` = `historical_archive`; `source` = `archive`; `coverage` = `unverified`; `feed` = 0; `copy_of`, `supersedes`, and `extra` = null. `cleaning` is deterministic JSON naming the derivation version, original source ID, capture time, HTML SHA-256 and any excluded widget SHA-256. Every mapped field except `input_id` is present in the canonical identity payload, along with the original ID, archive capture, archived HTML hash and derivation version; `input_id` is the hash of that payload, so it is not recursively included. If the source schema contains another field, refuse. These are extraction-only drafts, not inputs that pass the feed.


The variant's `source_uri` is the usable Internet Archive URL for that capture and original publisher URL; the original publisher URL is separately retained in the manifest. The experiment report explicitly shows “archived version”, archive capture time and the fact that publisher/classification metadata was inherited and not independently confirmed. The actual `bundle.item_lookup` must resolve the new ID to the archive URL and expected title, date and publisher. The report renderer must expose the separate provenance; passing the bundle lookup alone does not prove the reader sees those limitations.
