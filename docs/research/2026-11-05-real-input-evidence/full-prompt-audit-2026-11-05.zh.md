# 抽取输入逐条审计：v74i 对照真实产品原则

范围：用户要求检查并改造抽取 prompt。审核系统角色、10 种已配置分类、请求组装、输出字段说明、最后的检查，以及直接决定交接的代码。冻结的 v74i、标准 v5 和既有金标均不改。来源优先级为用户原话、D369–D371、已签抽取标准 3–5 节及其更正、05/06 PRD。D369 要求核心和辅助都捕捉、相关且逻辑清楚即可；D370 去掉 22 个预设问题和额外财报导入；D371 要追踪与研究相关的当下及未来财务信息。对旧版 gold 不修改也不以新口径重算。

## 先说结果

不能确认现有 prompt 完全符合。一个需要验证的结构风险是同一请求同时做四件事：读出值得记的事实、判断是否值得单独研究、拟出完整问题和结果区间、把证据分配给问题。不能仅凭案例断言任务多是丢失的根因。标准 5.1 允许依据还没有出现在库里的问题判断重要性；输出及交接却只认本次问题或已展示的问题，没有任何归处就丢。这样，如果没有已有问题且该次回答没有提出合适候选，前面抽对的事实也无法交接。当天试跑另有 5 条证据已通过交接，但仅关联的候选随后未被接收，未能写入；这是不同的后续丢失路径。这是现有架构 D209 的后果；改提示词可改善提问和关联，但不能保证没有问题时仍保存信息。不得以重写 prompt 的名义悄悄改这条产品行为。

已验证案例：微软原始请求主体只含 ai-capex，展示 23 个主题问题，没有微软收入题；新版 pilot 抽出下一季度指引但没提出收入题，代码以 no home 丢掉。NVIDIA FY2028 预测一组同样写出但没题；当天较早的题因为日初快照不可见。实验每篇一组、一次采样，不能证明单句导致该结果。

## 角色 prompt 每条指令

下表将一条长句中不同要求拆开审，原文完整保存在 `src/hivemind/prompts/role-v74i.txt`。每项标出判断依据，风险是请求阅读上的风险，除非写明已有 trace，不当成已证明原因。

| 第1段：给当日日初问题及收证说明 | D251/D264 | 保留当前真实快照和日期，不假称包含当天刚开题。 |

| 第1段：四个开题理由；已开题的重复由匹配合并 | D184、D258 | 保留。必须区分“可以提出同题候选再由匹配合并”与“强制为每个数字开题”。 |
| Evidence 第1项：公司实际数字、指引、决定及三个例子 | §5.1 第1类 | 保留，按价值和增量判断；例子只是示范，并非固定财务指标清单。 |
| Evidence 第2项：客户/供应商/对手/伙伴行动及经营数字 | §5.1 第2类；D240 | 保留；规模、日期、名字有一个可帮助识别，缺其中一项不自动否决。例子应跨行业。 |
| 同项：动作可以已做、已定、计划或进行中 | §5.1、第5.3背景边界 | 保留原有状态，不推断已执行。 |
| 同项：仅描述既有采用/合作及其好处是背景，另列新披露经营数字 | D250 第1条 | 保留但与 closing 背景行合并，避免两处独立决定；客户新采用或新整合仍可留。 |
| Evidence 第3项：具名方对公司或行业的新主张、预期 | §5.1 第3类 | 保留，不因无数字、遥远或有条件而自动丢；满足标准条件的估值要保留假设、推导和日期。 |
| Evidence 第4项：政策/监管决定或步骤，仍有效的也算 | §5.1 第4类、§5.3 | 保留。 |
| Evidence 第2项：从头读到尾、八条就是八条 | D199、§5.1 | 保留。它是完整性目标，不是每个数字都要保留。 |
| 同项：四类只是常见形式，是否重要另判 | §5.1 | 原文前一句又说 `A material statement is one of four kinds`，会让人误读为封闭条件；合并成“常见形式，判断仍用分析师标准”，不扩张标准。 |
| 同项：写入本周笔记、能改变某个问题答案、不被拒绝清单排除 | §5.1、§5.3 | 保留，但明确问题可尚未出现在列表；不能把 no shown question 等同不重要。 |
| How evidence 第1项：一条记录一件事；引文逐字；摘要写谁、什么、多少、期间 | §5.4、D199 | 保留；同一事件的相关条款和增长率不机械拆碎；上下文可说明指标，但不得编数字。 |
| How evidence 第2项：说话人、原始方及日期，四种来源层 | §5.4–5.5、D220 | 保留字段和四层；优先未证实/匿名，再确认事实、当事人陈述、第三方；不得把记者自己的解读升级成管理层陈述。 |
| How evidence 第3项：只用文章信息，计划不当成承诺 | §5.4 | 保留；研究员的逻辑推断不得冒充原文说法。 |
| Which questions 第1项：四类开题理由 | §3–4、D184 | 保留模型判断和现行枚举；`industry_aggregate` 是现行 schema 名，标准的 shared_quantity 扩展尚未建成，不能伪称价格类已可这样开。 |
| 同项 main_driver：承载价值的年度量或主营产品节点，可未指引 | §3 A/B | 保留跨行业逻辑。只列分部、毛利、capex 可能使模型对总收入犹豫；原标准没有禁止总收入，不能指示“所有公司必开收入题”。依据是否是主要投资判断判断。 |
| 同项：行业合计、政策步骤、约束义务和 18 月 | §3 C–E、D185 | 按现行 schema/代码保留；义务是否足以改变收入、利润、现金或信用风险仍需判断（§3 C），不能只因类型就开。 |
| Which questions 第2项：单个数字/财务行/目标/具名客户项目本身不开题 | §4 独立投资意义 | 保留意图，合并进题目判断流程：单有数字不等于没有资格；如果它涉及承载价值的年度量且有独立投资意义，可以按主驱动开题。模型在两次事后解释里把分析师全年预测理解成不足以支持收入题；属线索，不证明当时内部原因。 |
| 同项：客户购买/部署一般是供应商需求或产品证据；改变供应商现金/信用风险例外 | §4 不开清单 | 保留原意，不能为了缩短改成无条件开题或“项目一律不重要”。 |
| settled_by：可公开核对来源；不同措辞/估计非不同问题 | §3–4、D184 | 保留；识别是否为旧库问题最终归匹配，不应在抽取阶段自行省掉值得追的候选。 |
| 年度量今年或明年；节点是状态和截止日；不能把远期量伪装成事件；待决政策未写日期用财年末 | §3–4、D185 | 保留候选限制；证据可以远期、季度或不完整，候选限制不能误用于证据。 |
| 季度数/指引等不开独立题 | §4 不开清单 | 必须放在“开题限制”而不是“删证据”；用户 D371 明确当前和未来财务信息可作相关问题证据，时间段本身不是丢弃理由。 |
| 题目一量一期间/一事件、能独立下注才拆 | §4、06 梯子 | 保留，不以能拆字段等于独立问题。 |
| 问句、可核对、资产/主题、英文、具体档、五档或事件是非两档、不重叠不留空、到期日 | §3–4、06 梯子 | 保留实际 schema 和代码要求；这些是输出格式，不应混作材料是否重要的条件。具体题目表达能否合格需通过代码检查。 |
| Research groups：正在进行的一件事、候选声明、公司财务行一般不带组 | D149/D165 | 保留；代码写的 `[Research groups] None yet` 不是数据库真的没有组，而是本请求没展示已有组。不得据此声称库为空。 |
| Identity：measure、scope、basis、unit、event type、年度区间、lo/hi 上下限 | schema 和代码；06 梯子 | 保留与现有结构兼容，单位金额写全、下界含上界不含；不要把代码检查当作语义正确保证。微软 3911 亿落错档是判断步骤，未在本次假称已修。 |

## 结尾检查逐行

| 原始行 | 依据 | 处理 |
|---|---|---|
| 先问增量；仍有效指引、预测、计划不因为复述而删；缺失日期/规模、传闻、远期、条件不单独删 | §5.1–5.3、D240/D243 | 保留，提醒还须按重要性与具体边界判断。 |
| 背景：只描述已有使用或无新步骤的旧合作 | D250 第1条 | 保留；新步骤和新披露经营数字例外。 |
| 常识和一般风险 | §5.1、D243 | 保留；具名价格/租金/订单移动、带期间的预测、新市场份额例外。 |
| 产品细节、跑分、公司或第三方普通比较 | D250 第3条 | 保留；竞争对手对本公司的比较、客户新采用、发布延迟取消或配置变化等不能按此行删除，仍须做重要性判断。 |
| 没新事实或推导的一般评价 | D250 第4条 | 保留；有新计算/事实的解读、具有假设、推导和日期的条件估值，及公司确认原计划仍有效是例外。 |
| 无数字/决定的政治战略态度 | §5.3 | 保留；政策步骤仍判断。 |
| 股价、持仓、市值 | §5.3、D243 | 标准把在研公司的估值倍数、市值和孤立目标价列可选；现 prompt 拒绝 market value 是过窄但属于可选，不等于必留缺陷。D369 没有改变可选边界；D371 也不能自动把可选旧实际数或市值改成必留。 |
| 与公司市场无关的别家公司事项、仅同生态 | D250 第2条 | 保留；客户、对手和供应商的相关信息，可由分析员识别逻辑连接，不要求文章明说。 |
| 同一篇同一事实合并，保留完整条款；同一计划的独立交易分开 | §5.3、D199 | 保留；不同来源的记录各自保存，但可被匹配识别为同一说法；判断时合并展示尚须先通过标准规定的风险测量。 |
| 页脚、作者简介、广告 | §5.3 | 保留；不把附加的其他文章当正文。 |

## 分类、字段与请求拼接

| 部分 | 每条审计 |
|---|---|
| T1 财报 / T2 定期报告 | T1 read 明写实际数字、分部及指引；T2 read 写实际与分部数字、风险和业务变化，未明写指引；与 §5.1 一致，不能因 D370 禁止“额外导入”而忽略作为正常文章输入的财报。 |
| T3 合同 / T4 电话会 / T5 演示 | 合同条款、管理层回答、目标和资本配置；归属和条件按 §5.4–5.5，保留。 |
| T6 公司发布 | 新合作、投资、担保及条款；已有客户清单不等于新进展，保留 D250 边界。 |
| T7 新闻 / T8 评论 | 新闻区分原始来源；评论保留有事实或计算的分析及其理由，不能把观点当事实。用户自己 memo 的判断应提候选、可无证据（05 PRD、D59），但目前 role/T8 没显式这条例外；代码只免除候选证据要求。过去 40 篇为 T7 35、T8 5，均非 self，无法证明这类行为已正确。 |
| T10 正式行动 / T11 经济与政策 | 保留决定、日期、影响对象、官方数据、变化和指引；数据/观点分层。 |
| 其他类别 | 配置只注册以上10类；构造函数对分类字典未命中的类别回退为 T7 文案，但正常配置加载会拒绝缺少该分类条目的设置，不能简单声称这些类别已被正常配置支持。非新闻套用新闻文案的风险未验证。 |
| `[Subjects]` | 数据来自上游；微软只有 ai-capex 是输入事实，不是默认财务问题。不能因看见文章主体就擅自改变上游 universe；库可展示的公司问题受此影响。 |
| `[Open questions]` | 始终日初快照，主题全列；当天新问题不可见。`[Research reference]` 的量只是参考，不是白名单。 |
| research groups | 无历史组明细显示；候选申报本次组，由代码后续对照。不要把 `None yet` 理解成库里真的没有组。 |
| 字段 quote、one_line、speaker、original_who、original_day、tier、event_time | 原文准确性、完整含义、时间和来源由 §5.4–5.5 管。代码验证引文存在但不证明摘要、数字、归属正确；无效 links 被过滤，同引文的 links 合并，候选无存活证据会被丢，随后仅指向该候选的证据也会被丢；人工读来源。 |
| 字段 links | schema 正文在 `placement.FILING_RULE_ROOT_FALLBACK`：已有题取最窄相关问题并可另加同答候选；不是仅因同公司/生态关联；无其他期间对应题时可用同量不同期间，另有收入回退：无更具体关联题时，影响需求、供给、竞争或定价的内容放入其期间的公司总收入题。此回退有已记录的宽泛归档风险；只允许展示的题和本次候选，空是合法输出，但交接随后丢弃。 |
| candidate 字段、区间和枚举 | schema / `sift` 校验类型、时限、已有证据、题目档位形状；并不保证候选真实重要，也不能保证判断的档位选对。 |
| CLOSING | evidence_ids 为候选证据 ID，links 为题 ID，可为空；两者不同，只有改 evidence_ids 不会让 no-home 证据被交接，已用微软存档验证。 |
| 总长度与裁剪 | role 11028 字符、closing check 6591 字符；额外分类、schema、文章和日初题库不同请求各异。代码在 400000 字符处截文章；上次 40 次抽取 0 篇超限，不能说所有输入都完整。 |

## 还需验证与设计边界

1. 做新的隔离版本，旧 prompt / gold 不动。统一证据→独立的投资问题→关联/输出的工作顺序，保留标准的例子、边界、原文依据及来源层，不给公司或指标写死。对完整请求审查，不靠不断叠加单句。
2. 不把已有问题缺失、同日题目看不到、上游缺主体误写成 prompt 能保证修好。保留用户要求和 D209/D251 的真实限制；若需要改变无归处证据去向或日初快照，是产品行为选择，不能悄悄改。
3. 执行时每个不同的控制/试验请求逐字固定；源、日期和原始问题列表固定；先免费回放和假传输，再比较真实请求。逐条审计尚需补齐以下细则并经复核，不能以初稿宣称已完全审完。新版本不等于已接受或默认上线。旧标准的评估只对其衡量范围下结论，用户 D369/D371 的后续要求另行标注。

## 补充：原句细则与直接交付边界

| 原句或字段 | 对照结果 |
|---|---|
| 未签约的 binding obligation | 提交是非题；检查日须在文章之后、最多 18 个月，保留 D185。 |
| 已承担的 binding obligation | 一笔或一个计划的问题问下一份年报的义务金额；不能把自身借款、自己的租赁、已完成或没写规模的投资当这个开题理由；原文事实是否仍是证据另判。 |
| 来源、人群、预测、措辞不同 | 原角色将它们一概写为同题；标准对“同一结果可同时裁决”和“同一共同量的人群变化”的条件更细，是否同题由匹配最终判断。角色句过于概括，不能推导所有不同人群都同一题。 |
| 研究组别名 | 实际 prompt 要产品/项目/计划名称及相关方，不能只放公司名；需要组有具体事项，不因公司存在自动产生。 |
| 百分比 | 字段里的 73% 应写数值 `73`，不是 `0.73`；币额写完整。 |
| 来源层次优先 | 文章标明匿名或未证实首先按传闻；正式行为、已公布实际数字、已完成交易或报道的公告为事实；公司指引等为当事人陈述；分析师/媒体/专家判断为第三方；其他无来源为传闻。混有事实和计划时按主要说法定层并把次要性质写进摘要。原角色列出四层但未明确规定混合记录按主要说法分层、保留次要性质；这是对标准的提示词遗漏，运行中的损失数量尚未验证。T5 分类的一句“演示材料都是当事人陈述”可能过于笼统，是否与具体事实冲突需逐项验证。 |
| T1 read | 实际与分部数、指引、管理层解释、前期变化、新客户产品与风险；每条仍经过 §5.1 与 §5.3。 |
| T2 read | 实际与分部数、风险与业务描述变化、诉讼、客户集中度、贸易限制；没有明确要求指引。 |
| T3 read | 价格、对价、交割条件、时间、各方陈述与诉求、担保融资金额与条款；是否重要仍按标准。 |
| T4 read | 管理层回答及措辞变化、指引、供需产能客户地区毛利竞争、分析师追问重点；说话人分别标。 |

## 原始字段抽样（一次回答，非整体正确率）

在这天 40 份原答的 163 条证据中按 `sha256(input_id + ':' + evidence_id)` 固定排序，逐条读最前 15 条的引文、摘要、说话人、原始来源、原始日期、层级和事件时间。结构不是语义正确的证明：例如 `gnews:8f8a2d115ab834c7026aefd1/e6` 的原文同时给出管理层 70% 预期、市场 44% 共识和无约束超 100% 条件；摘要保留了数字，但 `original_who` 只写管理层、`original_day` 填报道日 2026-08-29，原文没有明确管理层在哪天说，不能确定该日期。`gnews:e361f3a156675e76a24baf91/e9` 把“一天之后”的时间写为 2026-08-28，原文需结合上下文及日历检查，不可凭文章发布日期替代发言日。这些只说明抽样中需特别核查日期与混合来源，不推断整体错误率。

## 跨组件实际冲突：研究组

角色的 research groups 一段要求公司自身财务行默认不带组，**除非该行本身追踪某件正在进行的事**；而 `extraction.GROUPS_INSTRUCTION` 每次在 user 文本中写“leave group_refs empty for a company's own financial lines”，没有这个例外。PRD 06 和 `views/groups.py` 允许模型明确引用一个组时自身财务行加入该组，代码不让它单独创建新组。两处文字因此有冲突；实际误导多少候选尚未清点，不能仅凭词句宣称运行失败。当前草案未改变代码写出的 user 文本，所以这个冲突**尚未解决**。若修正，需要对真实用户请求做新版本，不是只替换 role 文件，并验证新路径、已有组与孤立财务行。
