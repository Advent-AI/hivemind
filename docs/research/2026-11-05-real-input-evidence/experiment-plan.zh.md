# 财报是否帮助从真实新闻抽取 evidence：实验草案

**状态：准备中，没有对照结果。** 本文件是实验方案，不是已完成的测试或已签字的金标。当前三篇示例的原文和标注均未完成审查，不可用于打分。

## 要回答的问题

给模型一篇真实新闻时，同时给它新闻之前已公开的财报，是否让它更完整、准确地找出新闻中与投资判断有关的 evidence？有没有引入错误？

例如：新闻说某个客户采用 NVIDIA 基础设施。要检查是否保住客户、具体动作、计划还是已发生，以及这个动作的限定。不能把财报中只出现过的收入数字写成该新闻说的事实。

## 先准备什么

1. **真实文章。** 从预先确定的文章池选取，不先看模型答案挑文章。核对来源、发布时间、历史版本和正文是否完整。记录所有排除项及原因；不能用事后更新的页面冒充当天文章。题材必须包括值得记录的新闻和普通噪音，不能只选财报相关的文章。
2. **当时可见的财报。** 只取文章前已公开的报告。SEC 财报页面的表格要保留，不能使用丢失表格的纯正文。记录文件、发布时间、全文和哈希。当前预览采用 8 月 26 日的 EX-99.1 全页；是否加入 CFO 文档仍需在固定实验前确定。
3. **同一个研究库起点。** 两组必须读同一份、文章当时已有的库。当前能可靠构造的是空库，适合测试初次覆盖；有历史库的真实场景要先逐条核实来源及时间，不能拿未经核实的旧库充数。两种情形分别汇报。
4. **金标。** 在看任何对照答案之前，由两位独立读者读完整新闻和当时财报（财报只做背景），按已有抽取标准及你的新决定 D369，列出原文里值得保留的研究事项、逐字原文、来源与理由；核心和辅助不必严格分档。记录不该保留的代表性杂音。分歧对着原文和标准解决；标注由 AI 完成就明确写 AI，不冒充人工。你确认后冻结，记录哈希。现有 golden-v5 保留不改。
5. **留出测试集。** 一开始就保留模型本次实验没有看过的文章；任何调试只用开发集。不能把前几轮看过结果的文章宣称为新鲜测试集。

## 两组怎样比较

| 输入 | A 组：不加财报 | B 组：加财报 |
|---|---|---|
| 新闻、类别和当天研究库 | 相同 | 相同 |
| 抽取模型、系统提示词、输出格式 | 相同 | 相同 |
| 财报 | 不给 | 在新闻之后明确标为此前公开的背景，提供完整约定版本；不把它当成新闻原文 |
| 引用检查 | 只查新闻原文 | 也只查新闻原文 |

先用假模型验证两份实际请求只有财报块不同，检查假传输收到的请求顺序，验证财报独有的一句话不能作为新闻引文。再用保存的真实输入和旧答案做免费预检。每篇每组独立发送三次，A、B 在相近时间运行并分别保存每一次请求、原始回答、错误和成本。实际发送沿用生产传输：网络失败等情况下最多发送三次，包含第一次发送；中途失联的尝试可能已经被处理；即使最后成功，之前尝试的费用仍可能未知。可取得的用量按费率计算，未知用量和费用单独报告，不能假定为零。

## 结果怎么读

每篇文章的每一件研究事项，从左到右检查：

**金标里应有 → 模型原始回答 → 代码检查之后 → 实际写入 → 后续读取得到。**

按你的新决定，核心和辅助合在一起看是否捕捉，不为两者边界扣分。对每一次抽取，查看遗漏、错收、事实和数字、时间、人物、语气和来源；特别检查有没有把财报旧事实写成新闻中的新事实。核查“引用通过”是否只是代码裁掉了拼接进去的财报部分，而摘要仍被污染。

同时标出由于没有问题接收而被丢掉的 evidence。这样才能区分“模型没抽到”和“系统抽到了但没保存”。所有漏项、明显错误和有代表性的命中都逐条看原文与实际输出；数字只做索引，不代替阅读。

**如何下结论：** 只在相同文章、相同金标和相同库起点下比较每次结果；同时展示改善、退步、错误和调用成本。两篇、一家公司或一次发送只能作诊断，不能证明普遍有效。对于没有财报之前背景也能解释的新闻，不强行假设财报应该产生提升。
