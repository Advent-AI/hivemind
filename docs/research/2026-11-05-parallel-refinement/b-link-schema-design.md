# First refinement: restore the existing-evidence link definition

## Diagnosis and change

The POC changed the existing-evidence schema `links` description from the production filing rule to “IDs of supplied existing questions this evidence can inform; never a candidate ID.” This removed the meaning of “inform,” while the system still says “using … the link-field rules”. In the stored Q3 case a forecast linked to v2 while its stated assumption had `links: []`. The model's continuation said it looked for a question about the assumption itself. This is an observed one-case trace plus a model account, not a measured population mechanism. The saved B system already mentions indirect connections and preserving conditions, so stripping the detailed field definition is a testable hypothesis, not a proven cause.

Change **only** the `links` description in B's JSON schema. Keep the existing B system and user messages, schema type/property order, source, question snapshot, model and all checks byte-for-byte. Supply the existing signed standard's relation test at the field that owns linking, including the original v74i fallback to a company-wide question when no narrower question takes a material business driver. Explain that a forecast's material assumption/condition can inform the same question if it changes how the forecast is interpreted; preserve the uncertainty. A common word or company alone is not a connection. No candidate IDs in B. This does not open any new question, save orphan evidence, add financial lines, hardcode examples, introduce a closed relevance list, or change the frozen ruler. It restores detail that was lost in splitting the old filing instruction; growth is justified because the older description was removed, and the output format otherwise changes its meaning without telling the model.

Exact proposed description:

> The questions this statement is filed under, decided after you have decided it is evidence: the id of the narrowest open question in [Open questions] whose answer this statement makes more or less likely, as that question's own figure, step or estimate or through the demand, supply, competition or pricing behind its answer; compare the specific questions before a company-wide revenue or margin question and take that one only, never a broader question beside it; a shared company, industry, event or ecosystem is not a connection, and the statement need not repeat the question's words (a variant, sibling or other name of the subject counts); whoever says it, and even when it gives no period, basis or exact amount, because the weight is judged later; an estimate for another period or population of a question's quantity is filed under it when no open question covers that period; when no specific question is connected, a statement that moves the demand, supply, competition or pricing behind the company's results goes to the company-wide revenue question of its period. A relevant quarterly actual or forecast can inform an annual question. A material assumption or condition of a forecast can inform the same question when it changes how the forecast is understood; preserve its uncertainty. Use only the supplied existing question ids; empty when no question is connected, however important the statement sounds.

Trace: standard §5.1 information that changes an answer; D248 other period may be evidence; D369 clear indirect logic and retain supporting; v74i `placement.FILING_RULE_ROOT_FALLBACK` owns narrowest and broad root. Whether a statement qualifies still belongs to the model and later independent source review; no `if China` or similar shortcut.

Use a fresh archive for every send. The full held-out golden-v5 test (30 later articles) has no historical sequence in this saved ledger: do not label a stale 2026-08-29 snapshot as their latest library. If the new arm introduces a material false connection, loses a previously preserved matter or misstates a condition, record and diagnose each raw regression before any next arm; if the change gains the condition but causes material losses elsewhere, do not call it an improvement. ## State, readers, checks

Each send starts from a frozen request and a separate archive. Preparation → control/treatment in flight → validated answer → original evidence sift → existing-question handover → trace report. On missing source, snapshot, schema or provider response it refuses; an exception produces failed/incomplete, never an empty result. A crash preserves partial distinct archives and is never silently resumed. Inputs never change during a run; a corrected source or config gets a new frozen experiment. The experiment is read-only on article/ledger snapshots and never writes a research library; future writer/matcher/judgement are out of scope.

Both descriptions fill the same existing schema type and evidence fields and use the same code's quote, link, narrowest-parent and no-home checks. Schema is built in production insertion order; `model.call` sends the frozen wire. A fake positive checks one valid existing ID; negatives check an unknown ID, invalid quote, schema mismatch, and a failed call. Output and archive record per-lane identity and source. Before send: `scripts/preflight.py` with writable backup, compare known refusals/skips; run fake on exactly frozen requests; independent read-only review of this design and complete assembled wire requests; record version/hashes and token/character changes. No product rollout claim.

## Full-wire review corrections before freeze

The independent full-wire reviewer found that the prior POC's closing check omitted the signed standard's explicit optional status for clearly retold past actual figures and actively rejected company market value even though the standard calls it optional. Both comparison arms receive the **same** common alignment: the closing says a clearly retold past actual may be kept or omitted, current guidance/forecasts keep their usual weight, and a covered company's market value or standalone multiple is optional. This is an adapted experimental control; it is not byte-identical to the earlier POC control or production. It does not turn any optional record into a mandatory one or override B's requirement that evidence inform an existing question. The compared arm difference remains only the B `links` field. Growth and these common edits are included in the request audit and tested on full bytes.

The reviewers disagreed whether an unattributed reported comparison of a competing chip with the covered company's chips falls under the competitor-comparison exception or a third-party-comparison exclusion. The article says only “reportedly”; it does not identify who produced the comparison. Treat its attribution and resulting keep/reject decision as disputed, and do not use it as a positive or negative treatment success until source attribution is verified. This preserves the signed distinction; no new standard is invented. Micron's reported revenue cannot be ruled out solely because its indirect margin effect is not quantified: relevance and §5.3 still require case-by-case judgment.

The fake positive uses a real source quote and real existing question only as a structural contract probe; it is not an assertion that the fake quote is economically relevant to that question. The runner separately reports distinct multiple IDs in raw outputs and handovers, rather than choosing a home. Negative controls include an invalid schema response saved as a failure and the actual scheduler's stop-on-first-failure behavior; already-dispatched calls can finish. Frozen assets include source-only reader A, independent reader B (not fully blind; see its disclosure), source-map corrections and the preflight transcript. Those files are copied/hashed before send; a human reviewer still makes semantic judgments without treating the map as gold.
