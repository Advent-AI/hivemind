## 两次调用如何交接

```text
文章 + 主体及来源类别 + 已有问题和其真实口径
          ↓                                    │
B-read：找有研究价值的文章事项                  │
          ↓                                    ↓
每项原文、摘要、来源、时间       B-link：逐项决定对哪些已有问题有帮助
          └─────────────→ 检查链接和原文 → 交接
```

B-read 看同一份问题表，先判断文章事项是否能帮助其中的问题，但不输出具体链接；这是为了保留标准要求的相关性判断。B-link 看到全部 B-read 事项、同一篇原文与原有问题快照，逐项返回链接或空列表；它应遵循现有字段的最窄适用问题规则，且不允许造新事项或问题。代码按位置给事项唯一 ID，校验引文存在、B-link 的 ID 与所列事项一一对应、链接只指已有问题；保存模型原始链接与现有检查之后的链接，手读判断两道无上下级关系的题是否同时合理。没有链接按现有 D209 丢弃。不能因相同引文自动合并不同事项；明确标注离线 handover 原型不会去除语义重复，任何效果只到交接之前，不能宣称已入库。摘要中的主体、期间、条件、不确定性必须与原文逐条人工或独立读者核对；引文存在不代表摘要正确。

## 执行边界

| 情况 | 行为 |
|---|---|
| 文章为空、问题快照无问题或读取失败 | 保留失败和原始请求/响应；不把空回答伪装成成功 |
| B-read 空列表 | B-link 不发送；报告无证据 |
| B-link 缺 ID、重复 ID、无效问题 | 失败并保留原回答，不自动补写或重发 |
| 两阶段的文章、问题快照或运行身份不一致 | 失败，不联接；绑定源 sha、问题快照 sha、B-read 请求 sha、B-read 原始回答 sha 到 B-link 记录 |
| 条目不在原文 | 只在实验结果记录拒绝，实际可用结果不能包含它 |
| 一项无链接 | 标明 no home 并丢弃，不伪造连接 |
| 运行中代码、数据或 prompt 变化 | 停止；不在运行中编辑 |
| 以前的 prompt / baseline | 原始请求和结果不改；没有重新跑旧大方案 |

发送前，完整写出两份 prompt、user payload 和 schema，独立审查它们承接标准并与代码检查兼容；用同一次、同篇、同快照的 fake 正反控制，拒绝错配/缺项/无效链接。先前 preflight 有拒绝和跳过，逐条如实报告。若读取漏掉关键金标、关联改变意思或交接检查失败，则停止，不自动进入下一轮。读取、关联两次输出每项都保存，最后阅读每个可关联的有用金标事项在何处消失、错误关联及不应保留的信息，并核对来源日期和条件。两次调用产生的延迟和 token 一并报告。A1 与 B-read 可并行；测试 B 本身先不重跑 A，A1 的旧结果只作为上下文。被试文章已用于开发，不是 held-out；这个试验最多决定是否值得继续，不是生产验收。
