# New-question lane: candidate IDs are an identity contract

In the 4-article first POC the new-question lane proposed two candidates. One used `c1`, one used `n1`; both passed the model schema and handover because the schema defines candidate `id` as unrestricted string. The runtime `placement.CANDIDATE_ID` recognizes only `^c\d+$`, while a research-group ID is `n1`, `n2`, etc. This is an identity mismatch, not an importance or investment judgement. Actual `n1` candidate survived in this draw; it did not cause an observed orphan record.

A stored-answer counterfactual exposed a concrete risk. Change its declared supporting evidence to a different, source-backed but unlinked record: code first accepts candidate and both quotations; the supporting record drops as no-home, the candidate loses its surviving evidence, but a linked record retains `n1` because handover's candidate test only recognizes `c` plus digits. Repeating the identical counterfactual with `c1` drops the now-orphaned evidence. This is a proof of a conditional defect, not evidence the condition occurred in the real run.

In an isolated research harness, add `pattern: ^c[0-9]+$` to the A candidate `id` schema; this is an ASCII subset of the existing runtime recognition, which accepts Unicode digits too; the experimental boundary also checks the complete string with Python fullmatch, since `$` may match before a final newline. Do not change model importance rules or add a company-specific rule. A group keeps `n[1-9][0-9]*`; candidate and group IDs therefore cannot be confused. The evidence links are still candidate IDs in A and the unchanged B outputs existing question IDs. Retain per-lane IDs until each is checked; do not silently rewrite old answers, infer semantic equivalence from IDs or bypass a schema refusal. Because the original `n1` answer is not schema-valid under this fixed contract, it is a refusal in stored replay, not a successful result. Retest with injected fake c1 and n1 responses, the real handover and the `c1`/`n1` counterfactual; no retry on a provider refusal.

This identity change concerns only the A experiment. It does not address the source-to-thesis economic quality or guarantee evidence survives later actual matching and writing, both of which need their own real traces. The user's current instruction authorizes strengthening this split POC, not deployment or modification of the frozen production prompt. Before any paid send, independent review of schema, all full request blocks and fake tests; latest library input must be frozen and identical to comparisons. No new gold, no update to the existing frozen ruler, no code changes while any paid run is live.

## State × event and affected readers

| State / event | Input, resulting state and reader |
|---|---|
| No call / article known | Freeze source, pre-item question snapshot and original schema, then separately build the experimental schema; no live library writes. |
| `cN` candidate, valid quote and support | Existing checks evaluate it and evidence keeps its candidate-local link until later matching; the POC stops at checked handover. |
| `nN` or other nonmatching candidate ID | Provider/local schema refuses the whole invalid answer, writes the original response and error, marks item incomplete; it is not an empty/no-question answer. |
| Bad quote, bad candidate or lost evidence | Existing sift and handover operate unchanged; the `cN` reference is removed when its candidate ceases to exist and no-home evidence is dropped. |
| One parallel lane fails | Mark the item incomplete and preserve the other response; do not combine into a success or retry silently. |
| Later candidate matches an existing question | Real matcher/writer remains untested by the local handover; no claim this fixes evidence delivery in that later path. |

Readers of the new candidate ID are schema validation, extraction.sift, extraction.file_reading, matching.build_lists, writing and any evidence link; group IDs remain a distinct namespace and archive retains the original response. The historical one-draw results are not retroactively rescored. Validate new path against each original schema/quote/period/ladder/group/link check with a valid source-backed cN answer; independently review the complete request and negative controls. A closed ID contract decides identity only, not what deserves a thesis.

## Independent identity review and correction

Candidate IDs must also be unique within one answer: two distinct questions named `c1` pass the pattern but matching/writing maps can overwrite one, and a surviving duplicate can keep a lost question's evidence linked. The experimental adapter will reject the complete response if any candidate IDs repeat, before sift or join; it will not rename either candidate or silently choose one. It will also require `re.fullmatch(r"c[0-9]+", id)` for every candidate; JSON Schema pattern alone does not guarantee a Python full-string match for a terminal newline. The accepted set is ASCII `c` followed by one or more ASCII digits, including `c0`; Unicode `c١`, `c1\n`, `n1`, and duplicates are invalid. This is deliberately a subset of the runtime recognition (`\d` includes Unicode). The provider receives the schema pattern; after a received response the adapter enforces fullmatch and uniqueness before handover. Each refusal is explicitly recorded and the item remains incomplete; no silent retry or rewriting. A transport failure records the error and “no response”, whereas a received malformed/schema-invalid response is preserved in its full per-call response file. The underlying archival response column may truncate, so its value is not our only raw copy.

The decisive synthetic controls use two distinct candidate questions with the same `c1` ID: refuse both a case where both would otherwise survive and one where only one would survive. Positive control uses two distinct valid `c1`/`c2` IDs; format negatives include `n1`, Unicode digit, and terminal newline. Also run the original source-backed n1/c1 orphan counterfactual and check the underlying current code before any user-facing claim. This general namespace invariant owns identity, not the importance or number of questions. The actual stored two candidates are distinct across different articles, so this duplicate risk is code-derived, not a frequency claim about this run.
