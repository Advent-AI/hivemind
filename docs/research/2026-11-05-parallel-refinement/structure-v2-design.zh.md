## 变量与证据

- A 两组：A0 为上轮保存在 `poc/data/parallel-restructure-small-2026-11-05-v1/manifest.json` 的原样请求；A1 重排 A system 的找新问题任务块、加入跨行业例子，并合并与其重复的两段说明；schema、user、文章、模型与题库字节相同。独立审查要求补回“其他问题不变时，候选单独变化是否改变业务判断”，并指出担保例子虽换行业仍紧贴已看文章；已改为不同的零售与医药例子。A 从 12,409 变为 12,443 字符（+34）；新增的独立意义比较与跨行业例子和压缩掉的重复语句相抵，其他标准边界保留。实际 token 在调用后从使用量报告，字符不作 token 估算。
- B 三组：B0 上轮原样；B1 只给实际存在的 `key.basis` 的问题附上口径；B2 在 B1 上重排 B system 中找已有证据的任务块，并合并两段重复说明。B system 从 5,221 变为 5,104 字符（−117）。B1–B0 测输入，B2–B1 测结构；不给未知/n/a 造口径。不读取当时不存在的未来内容。
- 先选上轮同两篇真实开发集文章，和各自已有题库的八、十题，A/B 不互相看回答。三次独立调用在各 arm 旁有 fresh control，旨在观察抽样波动；这是 2 篇 × (2 A + 3 B) × 3 次 = 30 次调用，上轮原结果也保留。不是全 bench、盲测或生产接受。
- 同一文章跨两路的有帮助 matters 按一个文章事项计数，core+supporting 合并，optional 中立，not-kept 的输出单独记。`same_matter` 字符匹配只做查找线索；独立模型读者以原文、完整请求、原始回答和交接查全每个漏失、匹配、无家/引用丢失和来源日期，不将单次数字当稳定差异。B-only 分数不冒充 A+B 总召回。
- 假设 A1 更好识别不同结果、减少越界候选而不漏同结果去重；B1 使模型至少看到真实口径而不把有逻辑的跨口径信息当无关；B2 更清楚保留来源与单独事项而不丢已有证据。任一反例先查原文和结果，不凭得分继续盲改。
- 样本从已保存原始请求重建而非读取变动题库；核对文章、题库内容和 source snapshot 哈希、模型、token 上限、schema 与 wire key 顺序。中断/无响应/格式失败即记录，不静默重试。独立子进程审查完整设计和请求后才能实际发送；没有第二把 gold。

## 独立设计审查后的边界

第一轮只读审查在 `structure-v2-design-review.zh.md`。它确认缺口径和同引用合并均有真实代码证据，但指出单个非 GAAP 到 GAAP 的关联不自动错误；两个样本只涵盖 3 个文章×问题条目显示 GAAP，无法证明未知、非 GAAP、间接关联的普遍行为。A 提前用已有库排除候选可能让匹配无从纠正，但这是 Alex 要求的当前两路分工；本次报告该风险，不改成另一种架构。B1/B2 与 A0/A1 的实际可见输入不同；观察新增口径而非谎称两路全都看到完全相同字段。五组各三次共 30 次，A0/B0 是本次新鲜对照。独立语义读者如可推断组别，明确说非完全盲读。
