# 测试起始题库：2026-11-05 用户纠正

Alex 明确要求：从指定日期开始测试前，先提取或还原截至该日期之前的研究状态，建立 cold-start 题库；再用该起始库抽取后续文章。不能把一个空库当作这类测试的正常起点。过去移除的 22 个预设题是另一回事；移除它们不是取消真实材料形成的起始研究库。

例子：从 2026-08-29 开始测试，就先从之前已可获得的真实材料建立或还原截至 08-28 的题库，记录主题、原始来源和可获得时间，并检查没有从测试起点之后借入信息。之后按实际运行规则逐步更新，逐篇保存模型真实看到的状态。每篇评测依实际输入题库判同一主题是否已存在；同一主题已存在则不重复开，否则应开；有帮助的证据能否进入已有主题另外核对。不能用期末题库代替输入当时的题库。

实际情况：空库的三文章财报对照只是空库诊断，不能回答上述真实起始库下的效果。2026-08-29 的一天试跑复制了 v34 截至 08-28 的历史账本 68 题；它不是空库，但并未充分验证逐题来源日期和库的完整性，不能称为经过验证的 cold-start 基准。`../2026-11-05-real-input-evidence/design.md` 记载一个数据库标为 2026-07-02 的文章页面包含 2026-10 的标题，单凭数据库日期不足以证明历史信息可在当时获得；这不是说已证实每道题都污染，也不能据此声称这道页面一定产生了题。最近 7 月 6 日的四篇诊断使用历史账本当时 8/10 个已有题，但未证明题库完整或历史来源合规；其上下文时点也与产品日初快照不同，不能作为合格起始库的端到端验收。

下次开始测试前，需要先确定起始日期和研究范围，准备该日前的材料和起始库，审查来源和时间，固定库快照，再运行后续文章；匹配同主题的评分以每次实际输入为准。保持冻结金标与历史成绩不变；尚未实施或运行新的 cold-start 建库或新评分器。本记录只纠正测试设计和过去结论，不表示产品代码或默认行为已经改变。
