## 标准及比较

标准是冻结 golden-v5 / 问题标准 v3（AGENTS §7.1），不改。来源：`05-extraction-standard.html` §3–4，`06-views.md` Four evidence tiers，90 题分析 §1。保留四个判断：影响业务/投资、不同已有问题且有独立含义、时间和核对来源有根据、引用不扭曲来源。对应分类：公司主要驱动或核心产品节点、公司承担的重大义务、跨公司共同量、监管政策阶段；不把每条财务线、季度指引、普通客户进展自动开题。题目必须按原文支撑的期间/事件写，不能把预测写成完成；未知日期不能编造。

四篇保存的真实 dev 文章（非 held-out），已有快照取同一保存数据：`gnews:085b1e1a1543437edb9756d6`（担保，8 题）、`gnews:4d1b1ca014068fb532f116b3`（客户竞品，10 题）、`gnews:795ea94e1100415a67fd1a96`（产品延期，10 题）、`gnews:3df0bbc8aff2c1d008bc0a32`（股价/行业评论，10 题）。这些是以前重建的文章前快照，并未证明包含当时完整题库；全为 NVIDIA，不能证明跨行业泛化。初测每篇一次，先读原文与全部原始回答；此前保存的 A1 三次只用两篇作为历史对照，其他文章未有相同 A1 对照，不当作公平比较。金标问题要先与各自已有快照逐条核对（例如已存在的产品问题），不能把已覆盖的问题算漏开；产品 `launch` 是否等于开始出货尚不明确。`may_open` 单独标示，不判必开；`must_not` 检查内容而非文案匹配；金标没有判断的额外观点需按来源/标准单独读，不自动判错。

## 执行与约束

实际请求构成：简短 system + 真实文章 + 真实已有问题（含原始 ID、题目和说明）+ 固定 fiscal-year context；schema 只给候选及各自证据。四篇各一个模型回答为定位缺陷，不用作稳定或总体有效性结论。现有 transport 对网络故障最多尝试三次，因此四个请求最多 12 次 HTTP 尝试，服务端已处理但响应丢失时可能重复计费。先保存完整请求、原文与问题快照、schema、精确 wire hash；伪造 JSON、不存在的引用和空观点假控制，preflight 读历史拒绝/跳过；独立只读审查完整请求与标准。每次保存原始响应、未经代码修补的输出与验证后的输出。查每道题和每条证据是否被文章支持、是否已在库中、是否值得独立追踪；用户说 pass 的情况必须计入。新 POC 不改变没有题时生产如何处理已有题证据；B 是独立任务。

模型输出需要带本篇原文中支持其新题的证据；没有可引用证据的候选只标为未完成，不凭代码猜证据或另开题。日期不确定则明确未知或标明研究员检查时点（规则允许的情况）；未找到可核对来源则不把它当作成功开题。一次模型答复不能说明为何漏题；若要改写或进一步实验，先追溯实际答案与模型自己的事后解释，并报告局限。

独立只读审查发现产品节点、期限、相同事件不同截止日及证据广度的边界不完整；已据冻结标准 §3–5 补足。完整请求审查又发现空白引用误判、无有效证据仍报告成功、财年文字与共同量的自然年冲突；已更正检查和输入。四篇、四次回答不会单独证明泛化或历史库完整性。
