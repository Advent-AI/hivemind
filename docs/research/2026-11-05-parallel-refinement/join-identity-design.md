# Experimental join: unique IDs without changing the investment judgment

## Input, output and scope

Each real article runs the user's two tasks concurrently on the identical source and pre-item question snapshot: A returns new candidate questions and their article evidence; B returns evidence for existing questions. Both raw provider responses remain immutable with their SHA and original local IDs. The experimental join creates an in-memory, old-handover-compatible set for actual downstream-code replay; it does not publish, modify the product or claim production acceptance. Do not silently mix answers from different articles, snapshots, dates, draws or executions.

The new reason for the join design is observed: B treatment draw 3 returned 14 different source statements with the same local ID; `matching.build_lists` reduced 14 statement/question pairs to three dictionary keys. Separately, an A candidate had ID `n1`, outside the existing `c`-digit candidate recognizer; a source-backed mutant showed its stale evidence link can survive candidate loss. Both are identity failures, not questions of analyst judgment. An independent review of the B-only repair found that giving B `e1` can still collide with A `e1` downstream and A candidate `evidence_ids` must be remapped too.

## Exact transformation

1. **Before lane checks:** A's received JSON must meet its schema and experimental `c`+ASCII-digit candidate-ID fullmatch/uniqueness check. A's evidence IDs must be unique within its answer: A candidate `evidence_ids` can point to them, so a duplicate would make the author's reference ambiguous. Refuse the entire A lane before any guessed rename; preserve its full raw response and mark the item incomplete. This is an identity-only refusal. In B, no candidates can refer to evidence IDs, so code creates distinct temporary IDs in source order before running old checks; record `(raw answer SHA, B, source-array index, raw ID, temporary ID)` for every record. Raw JSON is never mutated.
2. Run the existing schema/sift/source/ladder/period/group/link checks and `file_reading` **independently** for each lane, on the same historical item and snapshot. Save raw, lane-local checked results, all drops and repair actions. A links may only refer to its own surviving candidate IDs; B links only to supplied existing question IDs. A lane failure means the item is incomplete and no combined success is handed downstream.
3. At join, allocate code-owned ASCII `e1`, `e2`, … across A surviving evidence followed by B surviving evidence. Each ID's scope is this specific article/snapshot/draw/answer-pair. Keep mappings back to `(lane, raw answer SHA, source ordinal and original id)`; raw IDs can repeat across B records, so raw ID alone is never a mapping key. Rewrite every A candidate's `evidence_ids` from the **surviving checked A records** to those records' new IDs. Keep candidate IDs and question links intact. Refuse missing or ambiguous surviving A evidence references rather than mapping them to a B record. Evidence links to candidate or existing question remain untouched. B has no candidates to rewrite.
4. Build old `Handover(evidence, candidates, dropped, call_id, request_sha256, cached, cost_usd, new_groups)` with the renumbered checked records, original A candidates/groups and B evidence. The metadata identifies this as an isolated joined pair, not an actual single model call. No combined call or live write. Check every evidence ID unique and every A candidate reference points to an A record; no link equals another lane's evidence identity. Exact same quotations across lanes are **not** silently collapsed or claimed as independent confirmation. Record all exact overlaps, attribution and targets. A later human/semantic matcher must determine whether same-quote records are one fact, and different quotations can also express one fact. This existing untested product question prevents calling this a production-ready join.

## Outcomes and downstream reader checks

- The real matching-list builder sees globally distinct evidence IDs and each candidate's corrected evidence IDs. The actual writer's checked decisions are keyed by joined IDs, not lane-local IDs.
- With a synthetic outcome `new`, the existing writer can create A's candidate and file its A evidence, while B goes to its independently checked existing question.
- With a synthetic outcome `merge`, the writer uses A's remapped evidence ID and existing destination in `second_pass`; B remains an independently identified record even if it targets that same existing question.
- With `skip`/rejected, the existing writer drops evidence whose only home is that candidate (D209); B remains eligible for its own existing question. No promise all A evidence is delivered.
- If A and B carry the same quote under different destinations, the replay must show exactly what the old writer stores and flag potential duplicate counting. It may not invent a new deduplication rule or pretend the two records are two independent facts. Actual candidate matching and semantic deduplication are not simulated model quality.

## State × event and value × reader

| State/event | Treatment and reader |
|---|---|
| Before source | Freeze source bytes, item seq, exact question snapshot, exact two prompt/schema versions and pair identity. No reader uses a later ledger. |
| Two calls in flight | Each has a distinct archive; the peer result is not in either request. Each raw response or failure is persisted. |
| Provider failure/schema refusal/invalid A duplicate ID | Save the received bytes if any, preserve success in the other lane, stop this item as incomplete; no combined output and no retry disguised as empty evidence. |
| B has duplicate or empty model IDs | Assign one distinct temporary ID per B array position; source article and question links stay unchanged; preserve the original mapping and answer SHA. |
| A evidence ID duplicate or candidate ID duplicate | Refuse A because candidate references do not identify one thing. No guessing or rewriting. |
| Sift drops/repairs evidence | Keep lane raw answer and actual per-lane checked result; remap only surviving evidence and surviving A candidate references. |
| Both lanes succeed | Generate deterministic globally unique joined IDs in A-then-B order for the same pair; output a mapping, not a new semantic decision. |
| Candidate new / merge / skip | Real writer replay on scratch with explicit synthetic checked outcome, and source/target verification; candidate-only evidence is dropped on skip. Never modify user's research ledger. |
| Crash / another item / later run | Retain incomplete pair, no silent automatic resume; new pair identity and frozen snapshot for any changed source or later article. |

Readers: the provider schema, A candidate-to-evidence fields, each lane's sift and no-home checks, joined candidate-to-evidence fields, `matching.build_lists` `(evidence_id,view_id)` dictionary, matching candidate lists, `writing.write` decision dictionaries/returned evidence IDs, audit packet and later reader. Changes to local IDs require mapping each reader. Stable article/source and model request IDs are not reassigned. Code does identity and never decides importance.

## Tests before any use

Before implementation, a read-only reviewer checks every row and identity mapping. Offline on the original 60 B answers, compare source quotes, one_line, source, tier, time, question links and drops after the same existing checks; count all differences and confirm only IDs / ID-bearing log messages change. On the actual 14-collision case the real `matching.build_lists` lookup goes from 3 keys to 14, with all 14 source facts and links intact. Positive A `c1/e1` and B original `e1` must not collide; a mutant that leaves them equal must fail. Test A duplicate evidence IDs, duplicate candidate IDs, invalid group/period/ladder/quote, missing candidate reference, B unknown question link and no-home. Test same quote in both lanes with distinct source conditions: no lossy merge, original source remains inspectable. Use a scratch SQLite copy and real `writing.write` with explicitly synthetic `new`, `merge`, `skip` decisions; verify source, question destination and no orphan, and inspect any duplicate storage. Test first failure, no response, peer success and incomplete pair. Fake model inputs are structural only and never used to judge materiality. No live sends, default change, new benchmark or edits to frozen gold in this work.

## Independent design review: corrections required before coding

### 1. Trace every original position and reference

For each immutable raw lane answer, keep raw answer SHA and source-array index, original local ID and the full original record. A lane must have unique raw evidence IDs before any candidate-to-evidence reference can be interpreted; candidate IDs must also be unique. Before sift, classify each raw candidate evidence reference as **present in A**, **absent from A**, or **ambiguous because of a duplicate**. Duplicate is a refusal before any check. An absent original reference is explicitly logged, and old code's filtering behavior may remove it; do not turn it into a B reference by matching a new generated ID. A reference whose source record existed but later failed quote/schema/other checks is recorded separately as *present then refused*, not as originally absent.

After the actual per-lane sift, record for each source-array position: kept under lane ID, merged as same quote into another lane-local ID (with that ID), refused with the old reason, or no-home. Follow alias chains if any; preserve the original quote and fields even when old sift repairs or merges them. For each original A candidate reference, record its final surviving target (after alias resolution), its drop reason, or the candidate's refusal. Only then can surviving checked A candidate IDs map to the joined IDs; a surviving candidate referencing a truly missing/ambiguous record refuses the experimental join, not a normal same-quote merge. The test must contain a real A same-quote alias and both absent vs present-but-refused references.

### 2. Bind one execution, inputs and decisions

A lane result is never joined merely because its lane name and `ok` status match. The caller provides a unique execution ID for that run (different even if all input/output bytes repeat), article input ID, dispatch sequence, publication day, exact full question-snapshot SHA, each lane's exact ordered wire-request SHA and raw response SHA. Code checks both lanes' item ID, sequence, day, snapshot SHA and execution ID match, and each request/answer hash matches its own saved bytes before joining. The pair ID is a hash over a canonical structure containing all these values and the unique execution ID. Model outputs are untrusted data, never tool instructions. Reconstruct and bind each checked matching-decision envelope to this exact pair ID and the joined record/target ID sets. Before legacy writer calls, reject a decision or second-pass result from a different pair, article, snapshot or execution even if `e1` happens to occur in both. Preserve the writer's internal ID shape only within this strictly validated boundary; no claim that production writer itself performs this binding.

### 3. Require explicit merge outcomes in the experimental replay

At a synthetic candidate `merge` into a shown existing target, enumerate every surviving A evidence record linked to that candidate and require an explicit checked second-pass outcome for **each** `(joined evidence ID, final target)` before `writing.write`. Do not use the legacy writer's fallback of assuming a missing result means new evidence; a missing, refused, unknown or wrong-pair result makes the replay incomplete. Validate B's first-pass evidence decisions similarly for each distinct existing destination; validate candidates for new/merge/skip and all evidence destinations, not only example `c1`. `new` directs candidate evidence to the newly created view; `skip` drops evidence that had no other surviving home; when an evidence record has several legitimate targets the test verifies one result per final target and preserves the potentially different decisions. These are guard conditions for a *research harness*; they do not claim current production behaves that way. The decisions used in this proof are explicitly synthetic and no matcher model is run.

### 4. Same source across the lanes and downstream consequences

The existing matching rounds occur before writing, so one lane's output cannot see a same-run record from the other in the store. The actual writer can store both records even if both draw on the same quotation; a `repeat` still stores a new piece and adds a relation. The scratch replay must enumerate the reader-visible stored evidence and links separately for: exact same quotation / same final question; same quote / different questions; different source or condition with similar words; different quotes that may describe the same matter. Treat an exact source repeat as **one source**, never two independent confirmations, but do not silently collapse evidence or decide semantic identity from string/amount alone. Record whether the existing writer stores 0/1/2 records and what it shows under each question. A reliable cross-lane deduplication or source-count policy remains an explicit open issue and blocks production acceptance until defined and tested; the experiment does not add one by implication.

### 5. Frozen database state, not a fabricated history

The saved ledger database is from the end of the earlier run. A list reconstructed at article sequence does not rewind its full database: the real matching-list builder searches current views and reads current evidence and writer checks current identity. The immediate proof is therefore explicitly a **structural replay against an end-state scratch copy**, never an as-of-article history. Every scenario starts from an independent SQLite backup of the same named, hashed database; no scenario reads the previous scenario's writes. Any future quality/end-to-end claim at a historical date requires either the true whole database snapshot from then or proof all database reads are reconstructed at that exact sequence; this experiment does not claim it has that.

Mutants: another execution's decision envelope fails pair-ID binding; missing second-pass decision fails before writer; lane swap or altered snapshot SHA fails; synthetic same-quote aliases preserve every source position; duplicate A IDs refuse while duplicate B IDs are uniquely assigned. Tests use actual old sift, `matching.build_lists` and `writing.write` only with temporary copies and explicitly synthetic decisions. A separate blind design review checks these corrections before implementation.

## Original-response validation order

A and B's **unmodified raw responses** first pass their own model schema. B `id` must be a string: a numeric ID cannot become valid merely because the adapter would replace it. Only after raw B passes does the experimental adapter assign unique temporary IDs; duplicate/empty **string** IDs remain accepted for renumbering. For A, validate its experimental schema and fullmatch/unique candidate identity and unique evidence IDs before any renumber or candidate-reference interpretation. A schema, source or identity failure is an incomplete lane, not an empty success. The actual POC `model.call` already validates provider responses, but stored-response replays must explicitly apply the same order.

The blind design reviewer found no remaining design blocker for the structural scratch implementation. The real writer treats a statement as a whole: one `repeat` destination can influence its handling at other destinations, so the test must inspect the actual stored evidence, source relation and every question link, not just the input decisions. No code repair or historical acceptance is implied.

## Implementation review: defects to repair before relying on the join

An independent review of the first isolated implementation found that caller-provided hashes alone did not prove the request matched the saved article/snapshot: a B request from another article, a changed lane, and changed item metadata could be accepted. A genuine pre-registered pair plan must be built **before** the calls, including complete item metadata, lane names, exact request hashes and snapshot/body hash; verify each actual request is rebuilt from its configured system, user and schema and that its user block actually contains this exact article header/body and question snapshot. The reader must supply the stored pre-call plan, never reconstruct it from a response after the fact. A unique execution ID distinguishes identical repeated calls. Pair provenance remains bounded by what the local capture recorded; hashes alone cannot prove a provider independently signed which request produced an answer.

The first implementation also treated an arbitrary dictionary as a checked decision. The scratch replay boundary must accept only the paired synthetic raw decisions, validate their schema, and invoke the actual `matching.check` on the actual generated matching lists and scratch connection before any writer call. A real matching decision may use a candidate target discovered in `lists.candidate_lists`, not necessarily a question that was shown at extraction. Check second-pass decisions through the same actual evidence checks on the target's actual lists. Fail the experiment for any schema refusal, matching refusal, omitted per-target decision or missing second pass; do not silently accept the writer's default. `repeat` and `replace` targets must really have been shown and eligible. Bind the result and both passes to the registered pair/execution before writing. The hypothetical checked decisions are not model results.

The first A provenance trace also reported a reference as kept when its candidate was dropped but another candidate kept the evidence. The corrected trace must record the candidate's independent final status and reason; a refused candidate's reference cannot be reported as a delivered joined reference, even if the evidence itself survives for another candidate. Require negative tests with an invalid candidate and another valid candidate referencing the same evidence.

A first scratch test demonstrated only record counts for one same-quote case. It did not prove source-count deduplication, all exact destinations, different-source/condition cases, or how one `repeat` decision affects a multi-target record. The fixed tests must inspect actual rows and all targets; until then, do not describe the join as safe or say a reader counts the source once. Identify the end-state DB copy by hash, not as historical state. Verify provider failure/peer success, candidate and evidence ID collisions, missing/bad second pass, unknown target, wrong-request, changed lane/publisher, and stale pair before writer. One corrective class at a time, on copies, and no new calls while the ruler is in dispute.
