# 结构性复盘：这些问题为什么反复出现（2026-10-25 凌晨）

Alex：「认真审视为嘛我会有这些问题，看看整个系统设计和机制是不是有明显的短板或是没有思考到的地方，甚至结构性的错误」。
下面是我的判断，每条都带今晚和封存数据上的数。这是一份发现，不是工单：改哪一条由 Alex 定（AGENTS 授权与范围）。

## 一句话

系统把「这是不是同一件东西」和「这件东西重不重要」都交给模型去读自由文本来定，而且是在流水线的五个关口上都这样；
观点本身在库里是一段文字（`looks_at`、`question`、梯子条件是中文句子，380 格里 270 格是靠正则去解析的金额句），只有
对象、种类、到期日、年份是结构化的键。所以今晚看到的每一个问题，其实是同一个问题的不同侧面。

## 同一个病，六个症状

| 症状（今晚的数） | 在哪个关口决定 | 谁定、靠什么 |
|---|---|---|
| 开了 9 条产品琐事观点，H200 许可 0 条（60 篇材料提到它） | 开不开观点 | 模型，按「有日期 / 有指引」这种能核对的机械规则；系统里没有「这件事对持仓重要不重要」的概念 |

另一个层面的数：94 条观点里 52 条没有任何依赖边（62 条边只碰到 42 条观点）。idea 路线想靠「图」给出相关观点，但图本身
是模型顺手写的、很稀。

## 不是问题的部分

只追加、按天截止、顺序号、请求指纹存档与重放、四层证据、一天一判——这些经得住：第三遍 0 失败，重放逐字一致，同一句
话同一天问两次答案一样。产品的立意（把一个判断变成能核对、能结算的问题）也不是问题。问题是产品立意之下的数据模型比产
品需要的薄。

## 更深一层：流水线是「按文档驱动」的

今天的形状：来一条信息 → 模型读它、提出候选观点 → 模型判它是不是已有的 → 写入。覆盖面因此跟着语料走，不跟着投资者
的问题走：H200 许可出现在 60 篇材料里，但没有一篇「给了指引」，所以一遍跑下来没有它；GeForce NOW 新游戏有日期，所以
有它。这和 AGENTS §8、「thesis-first」的原则相反：数据路径应该从观点需要什么出发，而不是从数据有什么出发。

并排画出来（新机制要和它平行的旧机制放在一起看）：

```
现在：  信息 ──模型读──▶ 候选观点（自由文本） ──模型比──▶ 身份 ──写入──▶ 库
建议：  每个对象一张「要盯的量」清单（分析师定、代码持有）
        信息 ──模型读──▶ 证据，连到清单上的量；候选观点只在通过门槛时提出，并带键
        键 = 对象 × 量（闭合清单）× 期间（归一化的起止日）× 口径 × 单位；主线 = 宇宙里的一等对象（产品线 / 项目 / 客户，带别名）
        身份 = 键相同（代码）；归属 = 别名命中（代码，模型确认）；idea 的直接观点 = 键查找
```

## 一条结构性规则（三处落点）

**观点有键，键由代码持有，模型只填键、不定身份。**

1. **量的键。** `looks_at` 之外加闭合字段：量（每类一张小清单：总收入、分部收入[分部]、毛利率、营业费用增幅、税率[口径]、
   资本开支、出货/产能、事件{发布、许可、审批、交割、部署}）、期间（FY2027 → 2026-02-01..2027-01-31 这样的起止日，财年
   和自然年自然合并）、口径（GAAP / 非 GAAP）、单位；梯子每格写数字上下界，不写句子。效果：重复是键冲突（代码查）；
   idea 的直接观点是键查找；解析器消失；英文迁移对梯子不再是问题；清单外的量进复核池而不是直接开。
2. **主线是对象。** 宇宙里公司和主题之外加「主线」（产品线、项目、客户），带别名，像现在公司带别名一样。归属 = 证据
   原句或问题里命中别名，代码连、模型确认或补充。五轮归组实验要模型稳定地「选对编号」，正是让模型做本该代码做的事。
3. **重要性门槛可以半结构化。** 每个对象一张「要盯的量」清单（分析师给，像别名一样放在 universe.json）：清单内的量模型
   提出就开；清单外的进复核池，人或代理看过再开。琐事观点由构造消失；H200 许可这类不「给指引」的事因为在清单上而被
   盯住。清单是产品知识，不是模型判断。

## 对今晚重跑的含义（Alex 定）

一周小跑先跑完、读完。整晚重跑若按现在的数据模型跑，会再产出一个自由文本的库，下一步给观点打键时要迁移一次（94
→ 大约 150 条，量不大，不致命）。两个选项：A，今晚照跑，拿到新鲜的中文数据给演示，之后打键迁移；B，先定键和主线对
象的设计（一天），再重跑一次就位。我的倾向是 A 跑小、B 定方向：一周数据足够看规则效果，整晚的钱留给打键之后的那一遍。
