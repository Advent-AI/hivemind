# 第一阶段：把原文说清楚，再交给分配步骤

状态：2026-10-27，受 Alex 委托的独立研究。本文是候选合同，不是生产合同，也没有开始新的模型实验。范围只有 D339 的第一阶段；不修改分配步骤、冻结模块、旧实验和原标签。

第一阶段需要加强的不是 JSON 是否完整，而是每句话属于谁、时间指什么，以及摘要是否仍是原文的意思。

例如，原文说“11 月，Burry 指责折旧少计；一位匿名 Google 架构师在 2024 年估计 GPU 寿命为一到三年”。不能补出“2025 年 11 月”，也不能把记者自己的背景判断一并记到架构师名下。逐段都有输出只证明模型填完了表，不证明做对这三件事。

## 已存回答的普查与机制

输入固定为 D339 的三篇文章和 18 个 split 来源回答，其中 9 个 DeepSeek 回答来自同一响应内的分片合并。它们不是重新请求的模型样本。共有 553 条来源记录。`audit.py` 按样本、段落、记录路径重放；`audit.json` 保存每例的摘要、引用、字段、来源文件散列和成本。标注由研究代理阅读原文给出，不是 Alex 确认的 gold；程序核对这些标注仍对应原记录，不假称自动语义判卷。

| 问题类 | 已观察范围 | 机制 | 最便宜的证据与边界 |
|---|---|---|---|
| 已知报道方仍由模型重写 | 18/18 个回答均让模型生成 speaker；553 个记录单元 | 输入已有 publisher，却输出自由字符串；媒体、作者、被引者混用 | 普查所有 speaker 的精确值；代码直接带入 publisher 可取消这 553 次自由生成，不证明原说话者判断正确 |
| 一条包含不同来源的判断 | CoreWeave p007o02，6/6 个回答；另有 028/p008o01 | “一条或紧密相连的比较”允许把相邻内容捆在一起，单个 original_who 承载不了两个来源 | 对照完整原句；共同引用不能作为共同身份。不能靠要求仅填一个姓名证明已经拆好 |
| 未写出的年份 | Burry 5/6 个记录；另有 021 的 October 季度两条，2/12 个机会 | 日期是自由文本；“可明确推导”没有定义推导集合 | 只接收原文中的时间短语能拒绝新增年份；仍不能阻止摘要另加年份 |
| 把事件日当发言日 | ROW p008o01：012、021、034，3/6 个回答 | original_day 没要求指出哪句话说这个人在哪天说话 | “June 1”确实在原文，但指达成协议。原文匹配仍会放行错误角色，必须语义判断 |
| 匿名专家分类冲突 | CoreWeave p007o02，6/6 为 third_party_view | 提示同时说“外部分析”用 third_party_view、“匿名说法”用 rumour，没有优先规则 | 这是合同歧义，不把 6 条直接判错；需明确匿名身份与消息是否未经确认的关系 |
| 标题重复正文 | CoreWeave 004、015、026 的 p001o01，3/6 个回答 | 自然语言要求“不重复标题”不等于有代码去重依据 | 标题合同信息在 p006o01 再述；不能泛化成删标题，因为别篇可能只有标题有某条信息 |

这些类可重叠，不能相加当错误率。开始时间仅能定位到这次固定实验；没有推断历史全量频率。已有 18 个核心意思的覆盖指标没有衡量全部 553 条摘要是否添漏信息。此次没有把它改名成“准确率”。也没有发现或声称已经排除全量主体错换。

原链路：`study.py:prepare` 把报道日、publisher 和分句后的全文放进请求 → `source.txt` 同时要求摘要、归属、日期推导、类别 → 模型 → `source_observations` 只查 JSON、逐段二选一和句子范围 → 按原文位置复制 quote → 分配输入。日期、姓名与摘要不需要受 quote 支持也能通过旧检查。`audit.py` 用真实回答上的改坏副本证明这一点。

## 候选输入与输出

输入只有固定版本的清洗原文、稳定段落/句子编号、报道方、报道日和研究主体。研究主体只说明为什么读文章，不授权把客户或竞争者的数据改成研究主体的数据。原文版本和编号由代码生成。第一阶段不看现有观点列表，也不决定接到哪个观点。

维持每段一个容器：要么有观察，要么给出没有业务内容的理由。单条观察只承载一个归属；可以是同一来源的紧密比较，但若两部分来自不同的人或记者自己的解释，必须分开。条目边界仍是语义任务；不做“一句必定一条”。同一句支撑两条不同判断完全合法。

候选模型输出（例子取 CoreWeave p007 的真实原文）：

```json
{
  "p007": {
    "empty_reason": "",
    "observations": [
      {
        "first_sentence": "s01",
        "last_sentence": "s01",
        "one_line": "Burry accused hyperscalers of understating depreciation by $176 billion between 2026 and 2028 by extending GPU useful-life assumptions to five or six years despite roughly annual new Nvidia architectures.",
        "claimant": {
          "kind": "named",
          "mention": {"paragraph": "p007", "sentence": "s01", "text": "Michael Burry"}
        },
        "time_mentions": [
          {"role": "statement", "source": {"paragraph": "p007", "sentence": "s01", "text": "November"}},
          {"role": "event", "source": {"paragraph": "p007", "sentence": "s01", "text": "between 2026 and 2028"}}
        ],
        "tier": "third_party_view"
      }
    ]
  }
}
```

这里只展示一条，完整响应仍包含输入的所有段落。完整接受集合由 `contract.py` 的动态 JSON Schema 与验证器定义；顶层仅接受输入的全部段落，每层拒绝额外字段。`one_line` 非空；空段理由和 observations 互斥。句子范围须在本段并正向。引用片段允许指向全文中别段的有效句子，以解释代词或承接前文；text 必须是那句中实际存在的非空原文。

`claimant.kind` 的含义：named 是原文明确命名的人或组织；anonymous 是原文明确描述但未命名的来源；article 是文章自己陈述、没有另外指定来源；unresolved 是上下文不足以确定归属。前两种必须引用原文称呼，后两种 mention 必须为 null。它们不是实体注册表，不自动合并“公司”“黄仁勋”“Nvidia”。姓名引用真实不等于这个人确实说了这条判断。

`time_mentions.role` 只有 statement 和 event。前者指原始说话/发布发生时间；后者指判断中的事实、计划、预测或比较覆盖时间。没有就给空数组。保留 November、last August、the next five years 等原文，不生成标准日期，也不拿报道日补原始发言日。模型不能在字段里自造年份；摘要补年份仍属摘要错误。精确到哪一级就保留哪一级。

`tier` 暂保留旧四值以展示接口影响；匿名专家的取值规则未定，因此整套合同尚不能当作最终模型实验配置。倾向：匿名只说明不知道是谁，不自动把一个专业判断变成传闻；消息是否未经确认另按原文判断。要先由主任务明确这一处语义，再冻结提示和测量。

代码补齐：来源版本、请求版本、响应序号、本响应内记录号、quote、原文位置、publisher、publication_day。`speaker` 不再由模型填写。记录号只标识这个响应的这条记录；下一响应中相同编号不表示同一判断。相同 quote 不合并，同一个人也不自动合并。这里只限定数据含义，没有新增缓存、存储或全局去重机制。

摘要必须保留实际主体、数字单位、期间、限定条件、实际与计划、说话归属。本文没有新增一个可伪装确定性的 subject/ticker 字段：这些约束仍需对照原文语义检查；要测它们必须先冻结评价方式，不能靠正则关键词宣称满足。

## 决策与验证边界

已核对 D339 的有界研究：只做固定文章、固定预算的来源/分配拆分试验，没有授权推进生产；本候选也不推进。D338 的组合提示试验没有证明生产方案；D62 的采样约束和 D162 的既往拆分结果不能被这 18 个来源回答推翻。原研究文件和标签保持冻结。

相关决策的原句及其限制：

- D62：“Extraction variance is fixed in the prompt, not by sampling several times”。本次重放不拼多个回答，也不建议通过反复抽样选最好的一份。
- D162：“最终仍交现有证据、候选观点及归属，不增加产品数据层”；其结果为 “the registered comparison failed end to end”。本文的新形状只在隔离研究中成立；是否采用新消费合同必须由主任务决定。
- D339：“Repeated outputs never vote or combine”；“The source/routing preservation contract and a balanced routing measure are proposed next decisions, not adopted product changes.” 本文不把候选接口悄悄升为已通过的产品合同。

本轮能用零成本证明：旧结构检查接收不受原文支持的日期/姓名；候选精确引用检查拒绝相应新增字符；正常原文短语通过；日期角色放错、摘要改坏仍会通过结构检查。删除精确引用检查的副本必须让它的反例测试失败。

本轮不能证明：新提示让模型抽对更多、少漏更多、稳定拆对来源，或在新文章上更准。因此不报候选模型准确率，不启动付费请求。`source-v2.txt` 是替换式草案，长度与原提示在 `audit.json` 一起记录；若模型实验被批准，必须冻结匿名语义、来源完整性/归属/摘要三个分开的判法，并按至少三次新控制对三次候选比较。旧回答不能当新控制。

大小与速度：这次离线检查只读 18 个原响应、553 条记录，不加载凭证、不发网路请求；运行时间实测记在 audit.json。未来模型实验不提高原 12,000 输出 token 上限，不扩文章样本数和预算；提示字符数不能增长。完整请求 token 与延迟尚未测量，不能因提示缩短就声称总成本下降。

## 本轮实际验证

执行 `python3 docs/research/2026-10-27-source-contract-v2/audit.py`：18 个原始响应全部重建为原有 553 条记录，包含全部 9 个 DeepSeek 分片响应；与保存的 observations 逐值相等。11 个反例分别证明额外键、缺段、倒序范围、空段冲突、错误引用及枚举等会被拒绝。删除引用存在性检查后，“新增年份”反例不再被拒绝，其断言失败，说明该检查确实抓住了所述错误。

这不是候选模型效果的实验。候选示例只覆盖一条 Burry 判断和两条共用原句的 Intrator/Kress 判断，其余段落明确作为结构测试省略，不据此计算内容覆盖率。特意改坏摘要、改错时间角色的例子仍通过，显示边界没有被藏起来。

18 次旧来源调用的估算成本合计 $0.063999452；本轮新增调用和费用均为 0。原提示 1,998 字符，候选草案 1,782 字符；token 未估成实测。原文、响应和请求的散列保存在 audit.json；原实验不被改写。

接下来只有两个需明确的语义选择：是否采用“引用原文时间而不让模型生成标准日期”的来源接口，以及如何解释匿名专家的 tier。建议前者采用；后者不要仅因匿名就改成 rumour。摘要、归属、时间角色的评价方式需要先确认，再冻结候选、开新对照实验。本子任务没有启动该实验。
