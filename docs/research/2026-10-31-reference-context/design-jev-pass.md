# 过一遍 Jev：进到判断那一步的杂音有多少（2026-10-31）

Alex："这边原本是 Jev 在做的是不是 … did you look at the end-to-end pipeline? … isn't Jev doing this already?" 然后"可以我们来看一遍"。

封存的三个月运行里，Jev 的匹配步把 4,298 条证据中的 2,023 条标成"同一说法"、121 条"修订"。所以抽取留下的东西不是全部进判断：挂到题上的证据先过 Jev（同一说法 / 修订 / 新的），没挂上的去归档步（D207 一个家最窄的题；归不进去的存在 `unplaced_statements`，不给判断看）。

`jev_pass.py`：按天走一遍顺序运行的答案和它自己的账本，每条挂到开着的题上的陈述，按产品匹配步的写法（`jev_matching.piece_state / piece_question / PIECES / THRESHOLD`，列表按 `matching.rank_evidence` 排、取 `search_top_n` 条）问 Jev 和这道题下已存的每条的关系。每条带金标类别。Jev 按 `model.PRICES` 计价，每遍不到 2 美分。

## 结果（每遍平均，三遍）

| | SEQ-v53R | SEQ-v68a | SEQ-v70 |
|---|---|---|---|
| 留下的陈述 | 502 | 465 | 408 |
| 挂到开着的题上 → Jev | 93 | 144 | 117 |
| 其中 Jev 判"同一说法"（不再进判断） | 33 | 47 | 36 |
| 其中进判断为新证据 | 58 | 94 | 79 |
| 进判断的新证据里：金标核心或辅助 | 31 | 55 | 49 |
| 进判断的新证据里：金标不收 + 没列中的杂音（估） | **13** | **20** | **13** |
| 没挂上 → 归档步 | 408 | 320 | 292 |
| 没挂上的里：核心或辅助 | 167 | 131 | 129 |
| 没挂上的里：金标不收 + 没列中的杂音（估） | 124 | 96 | 84 |

（"没列中的杂音"按两位读者抽样的占比估：v53R、v68a 用 27%，v70 用 17%。）

## 读到的
1. **经挂接进判断的杂音每遍 13–20 条**，已经在 Alex 的"20 以内"附近。Jev 捕到的"同一说法"几乎没有金标不收的（0–1 条）：杂音不是重复，是第一次出现的废话；Jev 管的是重复，这两件事不重叠。我之前说"重提这一类 Jev 已经解决"，在这两周的冷启动数据上只对了一部分：被重提的旧事在运行前就有，库里没有可比的。
2. **杂音的大头在"没挂上"那一堆**：每遍 290–410 条，里面杂音 84–124 条，但也有 130–167 条核心和辅助。它们全部交给归档步。所以产品里杂音进不进判断，取决于归档步给不给它们一个家。D207 的归档调用对核心归对 9/9/9，但对杂音归不归，当时没量。
3. 版本之间的差别在这个口径下变小：v53R、v68a、v70 进判断的杂音 13 / 20 / 13，差在几条之内；三版的区别主要在"挂上多少"（93 / 144 / 117）和"没挂上的堆有多大"（408 / 320 / 292）。

## 下一步（要量的）
把没挂上的那堆过一遍产品的归档调用（`placement.py`，一篇一次，每遍 118 次约 0.2 美元），数：归进题里的杂音多少、归不进去存起来的多少、核心和辅助有没有被归错或归不进。这才是"进到判断那一步的杂音"的完整数。
