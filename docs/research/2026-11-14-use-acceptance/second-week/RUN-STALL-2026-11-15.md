## 2. The state of the frozen run

The call in flight waits on a connection whose other end is gone (the machine was asleep for an hour and a half). Nothing will
arrive on it, and nothing tells the program so. The program waits as long as the call's timeout allows, and that timeout is
**the whole run's remaining time**: about seven hours of machine-awake time, ending at the same moment as the run's own
eight-hour limit. So if the run is simply resumed, it sits on that call until its limit and then stops for good, with no retry.
**As it stands, the frozen run cannot finish.** The first step cannot be resumed inside the runner (D449 gives one redo, from the
start).

## 3. The defect, counted on stored data (AGENTS §1)

- **Mechanism.** `clean-arch/step1/live.py`, line 90: each call is sent with `timeout=remaining`, the run's remaining seconds.
  Production's transport waits 180 seconds for a call and tries three times (`model.openai_transport`). The new system's retry
  of a lost connection (D488) handles a connection that fails with an error; a connection that goes silent never errors, so the
  retry never starts. The design of D488 (`NETWORK-RETRY-DESIGN.md`) has no row for a silent connection or for the machine
  sleeping during a call.
- **The class.** Every call of the new system's first step whose connection goes silent: a sleeping machine, a dropped network
  that leaves the connection half open. One instance so far (this run). It could not have shown before: the earlier runs'
  network failures were errors.
- **What a bound would cut.** Over the 53 stored traces of the first step (4,718 answered calls): the longest answered call took
  220 seconds; 7 calls in 5 runs took longer than 180 seconds; none took longer than 600. A bound of 600 seconds a call loses
  no answer ever stored and turns a silent connection into a lost one, retried within ten minutes. A bound of 180 seconds, as
  production's, would have cut 7 real answers (each then sent again).
- **The process error.** The run was sized against money and calls; the state-by-event table of the launch had no row for the
  machine sleeping. A paid run of two hours on a laptop its owner may close needs that row.

call's wait (600 seconds on the stored evidence), a test and a mutant, and the two missing rows in the retry design's table.
