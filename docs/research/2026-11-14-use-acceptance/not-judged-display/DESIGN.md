# D397's "shown beside the answer as not judged" on the product's page: design version 3 for the council (D569; rounds 33 to 35), 2026-11-16, $0

**Requirement.** D397 (Alex: "只判主要那件 (Recommended)"): a topic that asks more than one thing gets one judged question, and
"every other part of its wording is listed and shown beside the answer as not judged". The new system stores those parts with
their reasons (`clean_ladders.checked_answer` → `ladder.not_judged`, `[{part, why}]`, written with the view in the same call,
`ladder_adapter.open_thesis`); the product's page never shows them (no reader of `clean_ladders` in `src/` or `poc/ui/`).
On the fortnight's store: 12 questions, each with exactly one ladder row; 10 rows list one or two parts (12 parts in all), 2 list
none; the one topic with no ladder has no question and no page.

**Path, one owner per layer** (`docs/poc/thesis-ui.md`, Ownership):

| Layer | Change |
|---|---|
| `src/hivemind/bundle.py` `view_bundle` | `not_judged`: the view's ladder row's `[{part, why}]` (an empty list when the row lists none); `None` when the store has no `clean_ladders` table, and, tested apart, when it has the table but no row for the view (a question opened before rows were written, or by another writer). **Refused** (an error, never `[]` or `None`): a row whose answer is not JSON, a written ladder whose `not_judged` is not a list of `{part, why}` strings, or more than one row for one view. **Before the view's creation the field is suppressed:** with an `as_of` at which the view's creation sequence is not yet visible, `not_judged` is `None`, whatever the caller (the library and selection writers already leave such a view out; `idea.py` calls `view_bundle` directly). The view's other fields keep their present behaviour |
| `poc/ui/src/model/thesis.schema.json` (closed, `thesis-ui/2`) | an optional `notJudged`: `null` or an array of `{part: string, why: string}`; `validate.generated.js` regenerated by the build's own step |
| `poc/ui/src/adapters/bundle.js` | `not_judged` → `notJudged`, copied as given, for library, selection and Idea responses alike |
| `poc/ui/src/model/thesis.js` `snapshotThesis` | the one date filter of the UI: `notJudged` is `null` on a day before the question's `created_day`, the list from that day on; the drawer, opened by `openThesis` at the selected day, reads the snapshot |
| `poc/ui/src/components/thesis-detail.js` | a section "Not judged" beside the current assessment, and in the same place when there is no assessment yet (the parts belong to the question from its opening); one line a part with its reason, both escaped as text; only when the list is not empty; sentence case and separators by `thesis-ui.md#presentation-rules` |
| `docs/poc/thesis-ui.md` | the drawer's row and the contract paragraph; the supported combination below |

**Compatibility, decided:** the page and the bundle writer are built and served from one repository (`poc/ui/dist` and the
service); the supported combinations are a new page with a new export and a new page with an older export (the field optional).
An older built page reading a new export is not supported: a coordinated upgrade, recorded in `thesis-ui.md`. Raw bundle readers
(HTTP `/library`, `/theses`, MCP `thesis_library`, `thesis_bundles`, `idea.py`'s cards, `scripts/mock_data.py`, `mock_build.py`) receive
one more key; none declares a closed output schema (searched `src/` and `scripts/`).

**Value × reader.** `not_judged` in the bundle: read by the adapter only; HTTP `/library`, MCP `thesis_library` and the standalone
page share the bundle writer, so all three carry it; no judging request, closing or matching reads the bundle (they read the store),
so no judgement can change. `notJudged` in the dataset: read by the drawer only.

**New path × old checks.** The closed schema refuses unknown properties: the field is added to it, not slipped past it. Older
datasets without the key validate (optional). The UI's verify scripts and the 200 KiB budget run as before. Production's ledgers
yield `None`: their pages do not change.

**Prior decisions.** D397 (the requirement); D38 (production splits instead; untouched); D275 (the library integration's tables;
this adds one value row); D163/D368 (English presentation).

**A store the page can read.** The fortnight's stored draw predates the writer's processing records (no steps, no completed days):
the page cannot list it. It is replayed at $0 through the accepted writer into a new folder, every judge request answered from its
stored archive by identity (as `carried-run/closing_replay.py` does, ending at the last article day), and checked before the browser:
every judge request answered (as many as the stored draw made), every judgement equal to the stored draw's, the ladder rows equal
to the stored rows, processing records and completed days present.

**Proof ($0).** (1) Tests of `view_bundle` on temporary stores: a real row (`v7`'s two parts), an empty list, a store without the
table, a store with the table and no row for the view, and the three refusals (bad JSON, a non-list, two rows); a mutant that drops
the field and one that turns a refusal into `[]` each fail. Visibility: through `library()` absent before the creation day, present on it
and after its closing; through `view_bundle` directly (as `idea.py` calls it) `None` before the creation day and the list on it. (2) The UI: schema and adapter with and without the key (library, selection, Idea); `snapshotThesis`
gives `null` before `created_day` and the list on it; the drawer, opened through `openThesis` at a day before creation, shows no
section, and on a later day shows it for a non-empty list with and without an assessment, escapes markup in a part, and shows
nothing for `[]` or `null`; the existing verify scripts and the 200 KiB budget. (3) The real page on the replayed fortnight store, served on the host as
the README says, read in a browser: `v7`'s drawer shows its two parts beside the answer, `v2` none, on two dates; a production
ledger's page unchanged. (4) The extension proof (19 of 19) and the full suite: no judging path moved.

**Falsifier (D569):** if a row cannot be tied to its shown question and time, or the page cannot show it without touching a judging
path, stop and return the contract.
