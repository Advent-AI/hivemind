**No-go on version 5.** The revised search and disk tests address the earlier concerns, but the proposed copy check still opens the database it is meant to protect, and the store identity can collide.

1. **Preflight cannot first inspect a live database to decide whether it may open it.** Checking SQLite journal mode requires opening the input; hashing a live database also reads it. That conflicts with §9’s instruction not to open a live run’s database. It also treats *every* non-WAL input as safe, although the existing production writer uses rollback-journal mode and can be live too. The check needs trusted information external to the candidate database, with a safe path for historical inputs, before preflight touches it. [Contract, row 7](/Users/lchingen/hivemind/docs/research/2026-11-14-use-acceptance/live-service/OPERATING-CONTRACT.md:114), [AGENTS §9](/Users/lchingen/hivemind/AGENTS.md:431).

2. **The proposed store identity is not unique across replacements.** A replacement at the same path can have the same first processing-step sequence and day. Under that case, the design may reuse staged vectors from a different store, contrary to its stated replacement rule. Give each store an identity that changes on replacement, and test two stores with the same path, first sequence and first day. [Contract, index identity](/Users/lchingen/hivemind/docs/research/2026-11-14-use-acceptance/live-service/OPERATING-CONTRACT.md:72).

3. **The retry rule contradicts itself.** It first says staged rows are reused only when their target day matches, then says rows from the older day are reused for a newer target if their text is unchanged. Specify one rule and test it, including what must still match besides text. [Contract, retry](/Users/lchingen/hivemind/docs/research/2026-11-14-use-acceptance/live-service/OPERATING-CONTRACT.md:79).

4. **Orderly shutdown needs a busy-reader case.** Changing a WAL database to `journal_mode=delete` may fail while service readers hold connections or transactions. Specify whether the writer waits, leaves the store in WAL and reports an incomplete shutdown, or does something else; test an active reader at shutdown. A WAL store left by an orderly shutdown must not be mislabeled as necessarily live or crashed. [Contract, finished writer](/Users/lchingen/hivemind/docs/research/2026-11-14-use-acceptance/live-service/OPERATING-CONTRACT.md:118).

The in-memory visible corpus is a concrete answer to the ranking concern; its equality claim still needs the planned test. The separate filesystem-full test also properly narrows what the database-full test proves. P1 remains a proposed decision, not permission for live operation. [Contract](/Users/lchingen/hivemind/docs/research/2026-11-14-use-acceptance/live-service/OPERATING-CONTRACT.md:64).

CONSENSUS: no, because preflight’s safety check itself touches the candidate database, and store identity, retry, and shutdown behavior remain unresolved.
