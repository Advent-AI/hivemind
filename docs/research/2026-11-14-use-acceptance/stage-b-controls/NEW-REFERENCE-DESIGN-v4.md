# A new reference for the final-answer test's control line (D658, D660): design, version 4, for council review ($0; nothing run)

**In one line:** answer the 15 control questions as the new system asks them, with the system's quoted reference stripped. The material and the
brief are the frozen ruler's own; the readers are two, of two families, with no file or tool access. Events are answered and compared on their
three outcomes. Every disagreement goes to Alex with the third readers' reasons. Alex signs and the reference is frozen; only then are the judge's
stored answers scored on D428's line, with null baselines reported beside it. The generators, templates, permitted inputs, checks and scorer are
all fixed by sha before the first reader runs.

Version 4 answers the round-3 reviews: Codex (`council-codex-3.md`, thread 01a1ebb0-9724-7e51-a979-bae88cb9cba9) and the Claude family
(`council-claude-3.md`). It also carries Alex's three rulings (D660). Changes are listed in §14.

## 0. The structural rule that closes the fitting class

The orchestrator (Claude) and the council have seen the stored judgements, so no step may rest on their not having seen them.
- **Fixed by sha before step 2** (`manifest-v1.json`):
  - every generator, template and check;
  - the permitted inputs (§3);
  - the scorer and its tests;
  - the reader models and tool versions;
  - the side-drawing seed.
- **Every text a participant sees** is generated by that fixed code from permitted inputs. The participants are the readers, the third readers,
  the material-shown readers and Alex at signing. The text is kept with its sha.
- **A step refuses** when a manifest sha differs.
- **A manifest re-issued after step 2 voids every reader output made under the old one.**
- **Every launched session** (participant, attempt, start, end, outcome, output sha) is appended to `launches.jsonl`. A void session stays recorded.
- **Every participant works inline,** with no file or tool access, from an empty working directory (§4). Its log is checked.

## 3. Permitted inputs, built by code (`build_control_reference.py`)

- **Stored inputs, hashed into the manifest:**
  - `mapping-runs.json`;
  - the three draws' `views.sqlite` and `archive.sqlite`;
  - the run record that selects each completed attempt (`stored_judgements.py`'s inputs);
  - `packet-v1.json` and `reader-brief.md`.
- **Two frozen extracts,** hashed:
  - `questions-v1.json`, shown to the readers;
  - `judge-inputs-v1.json`, kept in `keys/` and never shown. For each control it holds every evidence entry the judge's requests listed on or before
    2026-07-14, with the request day, and the last judgement's rung position and day. The shown-check readers get only the evidence entries.
- **Each question's closed key set:**
  - `id`;
  - `kind`:
    - `figure` when every rung has `lo` or `hi`;
    - `event` when the rungs are exactly Yes, Ruled out and Still open with no bounds, or exactly Yes and No (the two-outcome form the writer also
      makes, D409);
    - anything else refuses the build;
  - `question`, `due_day` and `year` (from `views`);
  - `unit`: `checked_answer.ladder.figure.unit` for a figure, read as that one key and no other; `yes/no` for an event;
  - `rungs`: position, label, condition, lo and hi.
- **The stripping rule (D660).** Code removes the trailing parenthetical the ladder writer appends to a figure's middle rung (`ladder_step.py`
  `write_view`). It has exactly three forms:
  - " (no reference figure when the question opened)";
  - " (the amount last reported when the question opened: "…")";
  - " (the reference when the question opened: "…")".

  Code records each removal: control, rung and the removed text. It then refuses any condition still containing "question opened" or "reference
  when", and checks that every condition's remaining text still states its bound in words. Facts checked today: six such rungs among the controls,
  two a draw (u1 v1, v4; u2 v4, v7; u3 v1, v6). The reason: readers must find the market's expectation in the material themselves, as the old
  reference was written, and not share the judge's anchor. The questions, labels and bounds are system output shown by design (D658: the system's
  own questions).
- **Refused, stopping the whole build** and returning to the council:
  - a figure without exactly 5 rungs, or with a gap, an overlap or an unbounded middle rung (all six are contiguous with 5 rungs today);
  - a missing view, rung or unit.
- **The judgement-text check.** No participant-facing file may contain:
  - any run of 8 consecutive words from any stored judgement's reason for these views, compared case- and space-insensitively;
  - any key outside the closed key sets.

  Which rung was chosen exists only in `judge-inputs-v1.json`.

## 4. Readers (step 2)

- **Two readers,** A (Codex) and B (Claude family).
- **One inline prompt each,** built in the frozen reader-A runner's shape (`run_reader_codex.py`, `prompt_for`):
  - `reader-brief.md` byte for byte;
  - the packet as text;
  - the 15 questions;
  - the output instruction;
  - "Do not read any file or run any command: everything you may use is in this message."
- **The output instruction** (fixed in the manifest) adds two things to the brief's shape:
  - `decisive_items` holds 2 to 6 distinct item ids (ruler-v1 §1.5);
  - for an event, `outcome_on_due_day` is the label of the rung **you expect to hold on the question's due day**, judged by each rung's own
    condition (D660). It must be "Yes" exactly when `yes_no` is true.
- **How each runs**, from a new empty directory outside the repository, with no project instructions or memory:
  - **A:** `codex exec -s read-only --ephemeral --json -C <empty dir>`;
  - **B:** `claude -p --output-format stream-json --verbose --no-session-persistence`, every tool disallowed, from `<empty dir>`.
- **Recorded in the manifest:**
  - the user-level instruction files the tools still load, by path and sha;
  - the model names and tool versions.
- **A void session** has any tool, command or file event in its log, an unreadable log, a non-zero exit, or output that cannot be parsed. It is
  rerun once fresh. A second void makes its questions unresolved, to Alex.
- **Validity schema** (code, fixed now), one object per question:
  - **keys, exactly:**
    - `question_id`: c01 to c15, each once;
    - `no_view`: boolean;
    - `reference`: object with `text` (string), `value` (finite number or null) and `items` (list of ids);
    - `implied_outcome`: object with `text` (string), `low` and `high` (finite numbers or null), `yes_no` (boolean or null) and `items` (list);
    - `direction`: above, in_line, below, yes or no;
    - `confidence`: high, medium or low;
    - `decisive_items`: list;
    - `against`: object with `text` (string or null) and `items` (list) or null;
    - `reasoning`: string;
    - `outcome_on_due_day`: for an event only, one of that question's rung labels.
  - **When `no_view` is true,** every other field may be null or empty.
  - **Otherwise:**
    - a figure has `low` ≤ `high`, both numbers, `yes_no` null, and `direction` from above, in_line or below;
    - an event has `yes_no` boolean, `low` and `high` null, `direction` yes or no consistent with `yes_no`, and `outcome_on_due_day` consistent
      with `yes_no`;
    - `decisive_items` holds 2 to 6 distinct ids;
    - every id anywhere exists in the packet.
  - **Code cannot check the scale of a number** (420 for $420bn passes). A scale slip shows up as an A–B disagreement and is ruled there.
  - **An invalid row** is asked again once by the fixed template, which names only the invalid fields and the rule each breaks. If it is still
    invalid, the question is unresolved and goes to Alex. A reader unable to cite 2 items is unresolved; it is never pressed to cite more.

## 5. Reconcile (step 3)

- **Agreement**, by code:
  - a figure: the two closed ranges [low, high] intersect;
  - an event: `outcome_on_due_day` equal;
  - both no_view: they agree, and the reference is no_view (not exercised);
  - one side no_view: a disagreement.
- **The proposed reference is reader B's answer** (D262). That the judge (gpt-6-luna, OpenAI, as is reader A) shares A's family is a supporting
  observation, not a rule.
- **Every disagreement goes to two third readers,** one of each family, inline and logged as in §4.
  - They see the brief, the packet, the question and both answers with their reasons, on sides drawn by the manifest's seed (as the Stage A third
    readers, `collect_readings.py disputes`).
  - Each rules A, B or **neither**; "neither" carries its own answer in the §4 schema.
  - A missing or invalid ruling is asked again once; still missing, unresolved.
- **Nothing is replaced automatically.**

## 6. Alex signs (step 4)

- **Who signs.** Only Alex; signing cannot be delegated (AGENTS §7.1; D592). The council has seen the judgements. While he is inactive, the line
  waits.
- **The signing page** `control-reference-v1-for-signing.md` is generated by the fixed generator, in plain English. It shows:
  - D660's three rules with their effect;
  - the 15 questions with the stripped text recorded;
  - each proposed answer with its items;
  - every disagreement with both answers and both rulings;
  - every no_view, invalid or unresolved row.

  It shows no judge answer and no chosen rung. The judgement-text check runs on it.
- **The presenting message** is the page's fixed summary line. Claude adds no recommendation on a disputed question. Any reply to Alex during
  signing quotes the page only.
- **His choices per question,** a closed set. He may pick:
  - a **valid** answer of A, B or a third reader (an invalid row cannot be picked);
  - his own answer in the §4 schema, which code validates;
  - **leave out** (no_view);
  - **reject**, which excludes the question with his reason recorded and its status kept.
- **A question without a choice blocks the freeze.** If Alex declines to sign, nothing is scored, and that is recorded.

## 7. Freeze (step 5)

- **`control-reference-v1.json`** holds:
  - `reference_version: 1`;
  - both readers' sha256;
  - each question's source (A and B agree, or Alex's choice in his words);
  - the stripping record;
  - the label model-authored.
- **Its sha** goes to `control-reference-v1.sha256`, the decision record, and a frozen-file test (`tests/test_frozen_control_reference.py`, as
  `test_frozen_rulers.py`).
- **The scorer** reads the sha from that file and refuses a mismatch.
- **Never edited.** A later defect becomes a dated correction record, printed with every score.

## 8. Material shown (step 6, after the freeze)

- **The brief.** `control-items-brief.md`, fixed in the manifest: the items part of `control-reader-brief.md` word for word ("Search the entries
  for the figure or the fact; do not mark an item shown because a related item is"), with the same-question and same-due parts removed.
- **The readers.** Two readers, one of each family, inline and logged as in §4. Each sees a control's reference decisive items and the evidence
  entries from `judge-inputs-v1.json`.
- **The rule is unchanged:** every request on or before 2026-07-14. Its limit is disclosed: an item shown in an earlier request may be absent
  from the last request whose answer is compared (`STAGE_B_READING.md`).
- **Disputes go to third readers** of each family, who rule without the two answers (`control-reader-brief.md`). A split is `unresolved`,
  reported apart from `not_shown`.
- **A failed or invalid packet** is asked again once; still failing, unresolved.
- **Before scoring,** the outputs' shape and the frozen reference's sha are checked. A failure stops the scoring; it does not exclude controls.

## 9. The count (step 7, `control_reference_count.py`, fixed in the manifest with its tests)

**Exclusions** (listed with the reason, never counted):
- not built;
- no judgement on or before 2026-07-14;
- the reference is no_view, left out or rejected;
- fewer than 2 decisive items;
- an item not_shown;
- an item unresolved (reported apart).

**Agreement:**
- **a figure:** the band of the last judgement's rung, [lo, hi), overlaps the reference's [low, high] (the frozen scorer's half-open rule,
  `score_judgement.py`);
- **an event:** the label of the last judgement's rung, resolved from its stored position through the question's rungs, equals the reference's
  `outcome_on_due_day` (D660).

**The verdict is D428's line.**
- **MET:** at least 8 controls counted and all but one of them agree.
- **MISSED:** at least 8 counted and two or more disagree.
- **UNEXERCISED:** fewer than 8 counted. The report names each exclusion's cause.

**Reported beside the verdict, never changing it (D660):**
- **Null baselines.** Each is paired with the judge on its own available controls. For each, print the controls it covers, the judge's agreements
  there, the baseline's agreements there, and "above", "equal" or "below". A baseline available on no control prints "unavailable".
  - **Figures, lookup:** the rung containing `reference.value`. Unavailable when the value is null or no rung contains it.
  - **Figures, middle:** rung 3 of 5. For figures with a stated reference the ladder puts that value in the middle range (the ladder request, line
    16); for the others it is the model's own centre, which is disclosed.
  - **Events, always Yes;** and **events, always Still open** (on Yes / No events, always No).
- **The line against reader A:** the same counted controls, A's answer in place of the reference. A's no_view, invalid or unavailable answers
  are not counted. The denominator is printed. It is a sensitivity reading: material shown was checked against the reference's items, not A's.
- **The A–B disagreement rate.**
- **Per matter:** for each seed question id (q04, q07, q08, q09, q13, q16, q18), its counted controls and agreements.

## 10. Predictions, written before any reader runs

- **The old reference's 8 of 15 with every item shown is a historical count, not a bound.**
- **An unexercised result** may come from no_view, invalid or unresolved references, missing judgements, unresolved shown checks, or delivery. The
  report names which.
- **A missed result** is specific to this reference, these questions and these stored judgements.
- **Most A–B disagreements will split by family.** On 9 of Stage B's 12 splits, each third reader sided with its own family's first reader; those
  splits were on judgement verdicts.

## 13. What it does not measure, and its weak points

- **Not measured:** whether the right questions were opened (D1); delivery beyond the shown filter (D2); the judge's daily path.
- **Model-authored.** Alex's signature is the human vote, and the noise is printed.
- **One stored run, on the luna configuration's questions:**
  - MET shows the line met on these 15. It does not pass Stage B, which also missed the strictest last-answer reading.
  - MISSED stops the line before further spend (D355).
  - UNEXERCISED names its causes.
- **Tuning exposure.** If a miss leads to a judge change (D263), these 15 become tuning data, and the next application must be on unseen questions.

## 14. Changes from version 3

- **D660's three rulings:**
  - events are compared on three outcomes, with no "cannot tell" exclusion (every question counts);
  - the stripping is now his rule;
  - the baselines no longer gate the verdict, which is D428's line.
- **The event answer** is the rung expected to hold on the due day, each rung's own condition governing.
- **Two-outcome Yes/No events** are accepted.
- **Fixes to the build:**
  - the unit path is `checked_answer.ladder.figure.unit`;
  - six stripped rungs, not three;
  - the third suffix form is added, and each removal is recorded;
  - a figure must have exactly 5 rungs;
  - the judgement-text check is defined (8-word runs).
- **The manifest** now covers the archives, the run record, `judge-inputs-v1.json`, the reader models and tool versions, and the user-level
  instruction files.
- **Readers run from an empty directory** with no project instructions or memory. The launch record is append-only, and a re-issued manifest voids
  reader output.
- **The rule now freezes generators, templates, inputs and checks,** not every later output, whose shas are kept.
- **The validity schema is closed key by key.** Both readers being no_view is defined. Scale is not code-checkable, and that is stated.
- **Overlap:** closed for reconciliation, half-open in the count.
- **Signing:** the page carries D660's rules; only valid answers can be picked; reject records a status; a missing choice blocks the freeze; the
  presenting message is fixed.
- **Freeze guard:** a frozen-file test.
- **Failure states:** interruption, sha or shape failure before scoring, and manifest re-issue are added. The shown-check limit is restated
  correctly.
