# A new reference for the final-answer test's control line (D658, D660): design, version 7, for council review ($0; nothing run)

**In one line:** answer the 15 control questions as the new system asks them, from the frozen ruler's own 14-day material and brief.
- **The questions** reach the readers with the system's quoted reference stripped.
- **The readers** are two, one of each family. They work in closed environments with no file or tool access.
- **Events** are answered and compared on their three outcomes.
- **Every disagreement** goes to Alex with the third readers' reasons.
- **Alex signs and the reference is frozen.** Only then are the judge's stored answers scored on D428's line, with null baselines reported beside it.
- **Fixed by sha before the first reader runs:** the generators, templates, permitted inputs, environments, checks and the scorer.

Version 7 answers the round-6 reviews: Codex (`council-codex-6.md`, thread 01a1ebb0-9724-7e51-a979-bae88cb9cba9) and the Claude family
(`council-claude-6.md`). Earlier versions are in `NEW-REFERENCE-DESIGN-v2.md` to `-v5.md` and `review-v6/`. This version's changes are in §15.

**Every text a participant sees is written out word for word** in `templates/`, and the items brief is `control-items-brief.md` in this folder:

| Template | Use |
|---|---|
| `shape-additions.md` | Shared by every answering text: the two additions to the brief's shape |
| `reader-output-instruction.md` | The first reader session; an array is parsed |
| `ask-again.md`, with the closed reasons in `ask-again-reasons.json` | A fresh session for one invalid row; one object is parsed |
| `third-reader.md` | The third reader; one object is parsed |
| `third-reader-ask-again.md`, with `third-reader-ask-again-reasons.json` | A fresh session for an invalid ruling; one object |
| `control-items-brief.md` | The material-shown readers |
| `items-ask-again.md`, with `items-ask-again-reasons.json` | A fresh session for an invalid shown-check answer; one object |
| `signing-summary.md` | The message presenting the signing page |

All are reviewed with this design and fixed in the manifest.
- **The parser.** An array is parsed from the first `[` to its matching `]`, as the frozen runner's `parse()` does. An object is parsed from the first
  `{` to its matching `}`. Anything else is unparseable, and the session is void.

## 0. The structural rule that closes the fitting class

The orchestrator (Claude) and the council have seen the stored judgements. No step may rest on their not having seen them.
- **Fixed by sha before step 2** (`manifest-v1.json`):
  - every generator, template and check;
  - the permitted inputs (§3);
  - the reader environments, with their models and tool versions (§4);
  - the side-drawing seed;
  - the scorer and its tests.
- **Every text a participant sees** (readers, third readers, material-shown readers, Alex at signing) is generated by that fixed code from
  permitted inputs. It is kept with its sha.
- **A step refuses when a manifest sha differs.** A manifest re-issued after any step voids every artifact that depends on the old one: reader
  outputs, rulings, the signature, the frozen reference and the shown-check outputs. The void is recorded.
- **Every launched session** (participant, slot, attempt, start, end, outcome, output sha) is appended to `launches.jsonl`.
- **No output is dropped without trace.** From the moment step 2 starts, every voided reader or third-reader output is printed on the signing page
  beside its replacement, with the reason it was voided. This applies to a void session, an invalid row that was asked again, and every output
  voided by a manifest re-issue. So no one, the council included, can choose between sets of readers' answers unseen.
- **Every participant works inline,** with no file or tool access, from a new empty directory outside the repository. Its environment is closed as
  §4 states, and it is checked from its log's first event.

    - " (the amount last reported when the question opened: "…")".

  - **What is checked:**
    - code refuses any condition that still contains `when the question opened: "`;
    - every stripped condition's remainder must equal the writer's own interval text for its bounds (`interval_text(lo, hi, unit)`).
  - **Facts checked read-only today,** on the six figure controls' middle rungs:

    judge's anchor.

  - a figure without exactly 5 rungs, or with a gap, an overlap or an unbounded middle rung (all six have 5 contiguous rungs today);
  - a missing view, rung or unit.
- **The judgement-text check** (source-aware, run on every participant-facing file before it is shown):
  - **Words.** Text is normalised by Unicode NFKC and lowercased. Every character that is not a letter or a digit becomes a space, and the text is
    split on spaces. So quote marks and full stops never decide a hit.
  - **The runs checked:** every run of 8 consecutive words of every stored judgement text for these 15 views. That means the `judgements` columns
    `reasons`, `reference`, `implied_outcome` and `why_changed`.
  - **A hit** is a run present in the file and **absent** from the file's permitted source.
  - **The permitted source is defined per stage:**

    | Signing page | all of the above, plus the stored rungs before stripping and the removal record, the third readers' rulings that passed the checks, every voided output (§0), and Alex's amendments |

    So the removed quotation can only appear on Alex's page, and voided outputs only there.

  - **A hit stops the step and goes to the council** (§12). Any output it voids is printed as §0 states.
  - **Tested before step 2, at $0,** on every kind of participant-facing file:
    - a real reader prompt;
    - a third-reader prompt and a signing page, both built from placeholder answers that pass the schema;
    - a shown-check prompt.

## 4. Readers (step 2)

- **Two readers:** A (Codex) and B (Claude family). Each gets one inline prompt in the frozen reader-A runner's shape (`run_reader_codex.py`,
  `prompt_for`). The one change is that each question also carries its `year`, which `prompt_for` leaves out. Readers see the year. The prompt holds:
  - `reader-brief.md` byte for byte;
  - the packet as text;
  - the 15 questions;
  - the output instruction;
  - "Do not read any file or run any command: everything you may use is in this message."
- **The output instruction** is `templates/reader-output-instruction.md`, word for word. It replaces the frozen runner's one-line output paragraph,
  keeping its words, and adds two things to the brief's shape:
  - `decisive_items` holds 2 to 6 distinct item ids (ruler-v1 §1.5);
  - for an event, `outcome_on_due_day` is "the label of the one rung of that question that you expect to hold on its due_day, judged by each rung's
    own condition" (D660). It is "Yes" exactly when `yes_no` is true.
- **How each runs.** Each session gets a new empty directory outside the repository, with the environment closed and pinned in the manifest.
  - **A (Codex):** `codex exec --skip-git-repo-check --ephemeral --json -s read-only -C <empty dir> -m gpt-6.1-terra -c
    model_reasoning_effort=high -c features.memories=false -c memories.use_memories=false -c memories.generate_memories=false -`.
    - The model and effort are the operator's Codex defaults as of today (`~/.codex/config.toml` lines 1–2), pinned so they cannot move.
    - Probe (2026-11-17, a one-word prompt): the events were thread.started, turn.started, item.completed (agent_message) and turn.completed, with
      no command.
    - **Memory control.** Probe on the same day with the same command. The question was "what do you remember about a project called hivemind,
      its judge, its gold, or Kyber? If you remember nothing, reply exactly NOTHING".
      - **With memories on,** it answered from memory: "a collision judge … a golden-v5 evaluation baseline".
      - **With the three flags above,** it answered "NOTHING".
      - **Before step 2 and before each later reader step,** this probe runs with the reader's exact flags. A reply other than "NOTHING" refuses
        the step.
    - **Pinned in the manifest:**
      - `~/.codex/config.toml` by sha (c6641827… today);
      - the names and shas of the 11 skills in `~/.codex/skills`;
      - the absence of `~/.codex/AGENTS.md`;
      - the Codex version.

      A launch refuses on any difference.
  - **B (Claude family):** `claude -p --output-format stream-json --verbose --no-session-persistence --setting-sources "" --strict-mcp-config
    --tools "" --disable-slash-commands --model claude-opus-5-5`, from `<empty dir>`.
    - Probe (same day): the init event shows tools [], mcp_servers [], skills [] and slash_commands []. The only plugins are the four built-in
      ones (cc-plugin-agents-md, cc-plugin-telemetry, cc-plugin-privacy, cc-plugin-plugin-authoring). The auto-memory path is keyed to the empty
      directory and is empty.
    - The user-level `~/.claude/CLAUDE.md` may still load. Its content is checked, not only hashed. Today it holds exactly two lines:
      "- Always use descriptive variable names" and "- Run all commands without asking me" (sha 7ec744d3…). Neither bears on an answer. The
      manifest stores that exact content, and a launch refuses if it differs.
- **The first event is checked against the manifest:**
  - for A, no event comes before turn.started other than thread.started;
  - for B, the init event's model, tools, mcp_servers, skills, slash_commands and plugins equal the pinned values.
- **A void session,** a closed set:
  - for A, any item type other than `agent_message` or `reasoning` (so any `command_execution`, `file_change`, `mcp_tool_call` or `web_search`),
    or any event type outside thread.started, turn.started, item.started, item.updated, item.completed and turn.completed;
  - for B, any content block of type `tool_use`, or any event type outside system/init, assistant, user, rate_limit_event and result;
  - for either, an unreadable log, a non-zero exit, a first event that does not match the manifest, or output that cannot be parsed.
  - **Slots.** Every launch has a slot: participant, step, question set and attempt kind. The attempt kinds are `first`, `rerun-after-void` and
    `ask-again-<question_id>`. Before any launch, `launches.jsonl` is read, and a slot that already has a completed or running session is not
    launched again. An ask-again is its own slot, so a completed first session never blocks it.
  - A void session is rerun once fresh, in its own `rerun-after-void` slot. A second void makes its questions unresolved, and they go to Alex.
  - **An interrupted session** is a slot with a start and no end when its step resumes. It is recorded as `interrupted` and counts as a void, so it
    uses the single rerun.
- **Validity schema** (code, fixed now), one object per question.
  - **The keys, exactly:**
    - `question_id`: c01 to c15, each once;
    - `no_view`: boolean;
    - `reference`: `text` (string), `value` (finite number or null), `items` (list of ids);
    - `implied_outcome`: `text` (string), `low` and `high` (finite numbers or null), `yes_no` (boolean or null), `items` (list);
    - `direction`: above, in_line, below, yes or no;
    - `confidence`: high, medium or low;
    - `decisive_items`: a list;
    - `against`: an object with `text` (string or null) and `items` (list), or null;
    - `reasoning`: a string;
    - `outcome_on_due_day`: present for an event only, absent for a figure; one of that question's rung labels, or null when `no_view`.
  - **When `no_view` is true,** every other field may be null or empty.
  - **Otherwise:**
    - `reference.text`, `implied_outcome.text` and `reasoning` are non-empty;
    - a figure has `low` ≤ `high` (both numbers), `yes_no` null, and `direction` above, in_line or below;
    - an event has `yes_no` a boolean, `low` and `high` null, `direction` yes or no consistent with `yes_no`, and `outcome_on_due_day` consistent
      with `yes_no`;
    - `decisive_items` holds 2 to 6 distinct ids;
    - every id anywhere exists in the packet.
  - **Scale cannot be checked by code** (420 for $420bn passes). A scale slip may show as an A–B disagreement. When both readers make the same
    slip, it passes unnoticed; only the signing page, which prints each range with the question's unit, can show it.
  - **An invalid row** is asked again once by `templates/ask-again.md`, in a new session.
    - That session gets the brief, the packet and that one question, and the template, which carries the shape additions. The template lists only
      reasons from the closed set `templates/ask-again-reasons.json`.
    - The reader's earlier row is not shown, so it judges afresh, as in the established Stage A ask-again.
    - If the row is still invalid, the question is unresolved and goes to Alex.
  - **Fewer than 2 decisive items is never asked again.** The question goes straight to unresolved, so a reader is never pressed to cite more.
    More than 6, or a repeated id, is a shape error and is asked again.

## 5. Reconcile (step 3)

- **Agreement, by code:**
  - a figure: the two closed ranges [low, high] intersect;
  - an event: `outcome_on_due_day` is equal;
  - both no_view: they agree, and the reference is no_view (not exercised);
  - one side no_view: a disagreement.
- **The proposed reference is reader B's answer** (D262). That the judge (gpt-6-luna, OpenAI) shares reader A's family is a supporting
  observation, not a rule.
- **Every disagreement goes to two third readers,** one of each family, inline and in the closed environments of §4.
  - They see the brief, the packet, the question, the output instruction, and `templates/third-reader.md` with both answers as Answer 1 and Answer
    2, on sides drawn by the manifest's seed. This is the Stage A third readers' practice (`collect_readings.py disputes`).
  - Each rules "1", "2", **"neither"** or **"cannot decide"**. The seed's key maps "1" and "2" back to A or B.
    - "Neither" carries its own answer in the §4 schema, validated by the same code.
    - "Cannot decide" carries its reason with item ids. It goes to Alex like any split; it does not exclude the question.
  - An invalid ruling is asked again once by `templates/third-reader-ask-again.md`, with its closed reasons.
  - A missing or invalid ruling is asked again once; if still missing, the question is unresolved.
- **Nothing is replaced automatically.**

## 6. Alex signs (step 4)

- **Who signs:** only Alex. Signing cannot be delegated (AGENTS §7.1; D592), because the council has seen the judgements. While he is inactive,
  the line waits.
- **The signing page** `control-reference-v1-for-signing.md` is generated by the fixed generator, in plain English. It shows:
  - D660's three rules and the kept no-reference notes;
  - the 15 questions, with the stripped text recorded;
  - each proposed answer with its items, printed in the question's unit;
  - every disagreement, with both answers and both rulings;
  - every no_view, invalid or unresolved row;
  - every voided output beside its replacement (§0).

  It shows no judge answer and no chosen rung. The judgement-text check runs on it.
- **The presenting message** is `templates/signing-summary.md`, its English and Chinese lines filled with the counts only. Claude adds no
  recommendation on a disputed question, and any reply to Alex during signing quotes the page only.
- **Agreed questions** (A and B agree under §5) are listed with B's answer as proposed. His one signature over the page confirms them, and he may
  change any of them by the closed set below. **Disputed, invalid or unresolved questions** each need an explicit choice.
- **His choices per question,** a closed set:
  - a **valid** answer of A, of B or of a third reader (an invalid row cannot be picked);
  - his own answer in the §4 schema, which code validates;
  - **leave out**, which makes it no_view;
  - **reject**, which excludes the question; his reason is recorded and its status kept.
- **A disputed, invalid or unresolved question without a choice blocks the freeze.** If Alex declines to sign, nothing is scored, and that is
  recorded.

## 9. The count (step 7, `control_reference_count.py`, fixed in the manifest with its tests)

**Exclusions,** each listed with its reason and never counted:
- not built;
- no judgement on or before 2026-07-14;
- the reference is no_view, left out or rejected;
- fewer than 2 decisive items;
- an item not_shown;
- an item unresolved, reported apart.

**Agreement:**
- **A figure:** the band of the last judgement's rung, [lo, hi), overlaps the reference's [low, high]. This is the frozen scorer's half-open rule
  (`score_judgement.py`).
- **An event:** the label of the last judgement's rung, resolved from its stored position through the question's rungs, equals the reference's
  `outcome_on_due_day` (D660).
- **"The last judgement"** is the one with the highest `judgement_id` on or before 2026-07-14, as in `control_theses.py` and `score_judgement.py`.
- **The "fewer than 2 decisive items" exclusion** cannot fire under §4's validity rule. It is kept as a guard against a signed own-answer that
  slipped past.

**The verdict is D428's line:**
- **MET:** at least 8 controls counted, and all but one of them agree.
- **MISSED:** at least 8 counted, and two or more disagree.
- **UNEXERCISED:** fewer than 8 counted. The report names each exclusion's cause.

**Reported beside the verdict, never changing it (D660):**
- **Null baselines.** Each is paired with the judge on its own available controls. For each, the report prints the controls it covers, the
  judge's agreements there, the baseline's agreements there, and "above", "equal" or "below". A baseline available on no control prints
  "unavailable".
  - **Figures, lookup** (ruler-v1 §1): the rung containing `reference.value`. Unavailable when the value is null or no rung contains it.
  - **Figures, middle** (D660's example): rung 3 of 5. For figures with a stated reference, the ladder puts that value in the middle range (the
    ladder request, line 16). For the others it is the model's own centre, which is disclosed.
  - **Events, always Still open** (D660's example). On a Yes / No event it is always No: the status quo.
- **The line against reader A:** the same counted controls, with A's answer in place of the reference.
  - A's no_view, invalid or unavailable answers are not counted, and the denominator is printed.
  - It is a sensitivity reading: the material shown was checked against the reference's items, not A's.
- **The A–B disagreement rate.**
- **Per matter:** each seed question id (q04, q07, q08, q09, q13, q16, q18) with its counted controls and agreements.

## 10. Predictions, written before any reader runs

- **The old reference's 8 of 15 with every item shown is a historical count, not a bound.**
- **An unexercised result** may come from no_view, invalid or unresolved references, missing judgements, unresolved shown checks, or delivery. The
  report names which.
- **A missed result** is specific to this reference, these questions and these stored judgements.
- **Most A–B disagreements will split by family.** On 9 of Stage B's 12 splits, each third reader sided with its own family's first reader. Those

## 11. What it does not measure, and its weak points

- **Not measured:** whether the right questions were opened (D1); delivery beyond the shown filter (D2); the judge's daily path.
- **Model-authored.** Alex's signature is the human vote, and the noise is printed.
- **One stored run,** on the luna configuration's questions.
  - MET shows the line met on these 15. It does not pass Stage B, which also missed the strictest last-answer reading.
  - MISSED stops the line before further spend (D355).
  - UNEXERCISED names its causes.
- **Tuning exposure.** If a miss leads to a judge change (D263), these 15 become tuning data, and the next application must be on unseen questions.
