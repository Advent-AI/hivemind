# Haiku 第一步日期实验：发送前登记

2026-10-29。针对已读过的 15 份 Haiku 答案、89 条筛后记录：[全量日期清点和逐项核对](2026-10-29-haiku-date-review-v2.json)。其中 36 条原发言日缺乏原文支持、27 条有支持、12 条待定、14 条筛后为空；选例且含重复，不代表全周。全部 v38 的 98 个请求都要求写发言日但未说明未知如何表达，并提供发表日期。用户确认内存预测、AMD 比较、收入增长和云厂商支出的分析价值；这些具体目标不再由模型自造标准。

**假设：**写清“只有原文能确定原始发言日才填写，否则留空”，可减少把报道日冒充发言日，同时保留已知日期。模型续问说它曾把发表日当作替代，但收入续问漏读原文，故自述只能是线索。此实验只改变第 1 步里一个日期要求，不改变模型、分类准则、schema、其他步骤或产品配置；不宣称修复证据内容或整条系统。

## 具体改动与冲突检查

两组请求由生产 `extraction.request_for` 和 `model.build_request` 从 `poc-v38.json`、原始文章、`poc/universe.json` 生成，再用相同 Anthropic Messages 外壳发送给 `claude-haiku-5-5`。对照组保留生产 v22 系统文本；实验组仅将系统提示中的英文句子 `Identify the speaker and, for a retelling, the original speaker and statement day.` 替换为 `Identify speaker and original speaker. Set original_day only when the item establishes the original statement date; else leave it empty.`。保持所有其余文本原样，包括两条引用要求。对整个请求和 schema 做逐字检查：两个 system 只改变日期句，其他内容、字段顺序和样本上限相同；要求用来源文章证明日期，不要求引句本身必须包含日期，允许结合文内“昨天/周三”和发表日计算精确日期，不推测“上周”的具体哪一天。

系统提示长度由 9456 增至 9510 字符；增加 54 字符的原因是 schema 必填字段未说明可用空值，而 D203 明确未知应留空；不同时删改无关规则，保持单一变量。正式发送前记录 Anthropic count_tokens API 的每篇输入 token。所有版本使用同一个 8000 输出上限和 low effort；schema、sift 调用均照 v22 生产，丢弃原因逐条记录。无完整答复或 schema 错误单列，不能算对错；不能因丢弃一条其他记录就判整篇无效。

## 事先固定的七篇与目标

开发四篇分别是上一轮用过的内存 `gnews:fbce0469dbb5b33e2c34a0f5`、AMD `gnews:55b3b854d30ecb73679c2088`、收入 `gnews:71df54965281684cc500960f` 和政策 `gnews:f9e7da6ddbf890fa64baf922`；已看到结果，不能当未见。固定四个未知原日期目标：SK hynix 的 2027/2030 预测；AMD 对 2.4/3.3 倍的估计；收入文章中管理层云厂商支出预测；同篇分析师的 82%/41% 收入预测；对这些原始发言人，原文未给出原始发言日，应留空。政策文章两项已知：财长的 Tuesday 相对 2026-07-24 Friday 为 2026-07-21；白宫顾问的 Wednesday 为 2026-07-22。每项存在与原意仍需人工核对，不能以日期字段单独证明事实完整。

独立测试文章在本实验任何发送前选出：从已存 v38 同周 T7/T8 请求中筛出含原发言人但至少一个日期未知的文章，排除之前 Haiku 五篇、旧 20 篇候选参考和原抽取金标，限 7,000 字符，按随机种子 20261029 排序（23 篇符合）。先读排序前几篇原文：按投资相关性跳过纯消费显卡电源规格文章，不以模型新回答为筛选依据，取 `gnews:f8191f5bb960d79e47c73d6c`、`gnews:ad47330f25c9d5ff84ced7e2`、`gnews:2957e5c79a365952140c8cce`。筛选用旧 Luna 输出的字段存在性，不是随机全周样本。这三篇不是之前 Haiku 抽取对照的样本，也未用于本实验日期句的设计。研究者先读完原文并固定目标：

- 云厂商支出：NVIDIA 预计大型云厂商下一年支出超过 1 万亿美元，原文未说 NVIDIA 原始发言日期，不能把报道的 2026-07-07 直接当成原发言日；保留预测来源和期限。
- Valar：文章说 Valar 在 **Wednesday afternoon** 宣布与 NVIDIA 探索 30 MW 数据中心，文章发表日 2026-07-01 为周三；这次声明可写 2026-07-01。保留“探索”而非已建或已签投入使用。只用于日期保真，不因此把这条升级为用户确认的核心事实。
- DeepSeek：Reuters 引述三名熟悉计划的消息人士称 DeepSeek 开发推理芯片；原文没有这名消息人士或 Reuters 最初发言的具体日期，报道日期 2026-07-07 不是证据。保留消息人士的传闻属性，不能写成 DeepSeek 确认。

每目标每次回答只记一次，完整引用和摘要按原文语义由 Codex 实读；原发言人有误、日期不是来源支持的日子、或猜精确日，记日期错误；没提目标记未抽出，原发言人与记者叙述无法区分记待定；已知日期留空也记日期缺失。不同记录同一事项应逐条检查，任何一个实质错误不能被另一条正确结果抵消；附证据 ID。没提供目标内容的答案不得借无日期被算作成功。三个未见文章在每种配置下只测一次（每篇三个独立样本，作为同一配置的一次测试），不把它们用于改写提示词或据此连续调参。

## 比较与判定

每篇每组各三次，共 42 次独立新发，最多 8 并发，带日志与 pid，无重试。分别报告每项 3 次的原始可评分数、日期正确/错误/缺失/待定及未抽出，重要内容是否完整保留、原文引用是否支持、题外输出和数量、运行成本及失败次数；重点事实而非所有不相干的东西一票同权。发展集参照已有三次基线：内存、AMD 的目标都在 3/3 被错误赋发表日，收入分析师目标也 3/3；新鲜对照需要在三项中每项至少 2/3 复现被报道日冒充的错误，否则该项说明对照不稳，不作治疗成功结论。实验组要在这些能评分的目标中消除所有不支持日期，并在已知日期上不比同轮对照少正确；重要目标召回不比对照少，不能靠不抽取或把所有日期置空拿到高分。三个测试文章独立报告，不与开发混在一起宣称全面通过。

发送前保存所有源文本哈希、请求字典与字节散列、参考说明和样本分组，并用已存真实回答及缺字段突变验证生产 schema 和筛选；原始已存案例的日期标记由人核对，不用字符串匹配代替语义。运行一次 v38 preflight，核对 98、841、831 和已知历史账本例外；检查凭证、机器和网络。用官方 token count 接口计每份请求。每请求输入预留 `max(3×token_count,3×wire_bytes)+16384`，输出预留 8064，按 Haiku 的高档价格在预留输入超过 100k 时计；合计超过 $0.60 则停止，不能提高。并发最多 8，独立进程、pid 和 log；用量缺失按全预留计，输入/输出/价格档超过预留则停止发送尚未发送的请求，在途继续如实记录。预算为估算，不是服务商的硬上限。

如果实验方向无效，回到完整请求与原始回答追查，不把目标叫作完成；如测试或标准自身出错先纠正测量，并保留旧记录。四步目标持续进行，但这一轮仅测第一步日期；不调 Jev、归档、故事页或第四步。

## 复核后的明确口径与实验条件

[只读复核 v1](haiku-date-arm-review-2026-10-29.txt)提出逐字差异、raw 与筛后、不可判断、对照自身波动及旧检查的问题；本版逐项解决，第一版保留。预测发表日这一类在 89 条中按筛后计 36 条缺少支持、27 条支持、12 条待定、14 条空；原始值和筛后值必须分别记录。每条目标证据保留原始 `original_day` 和筛后 `original_day`；原始值非空但被格式检查改空，算“模型猜/写了无法接收的日期、产品置空”，不能算模型主动留空。任何一条相关证据有不支持的日期，即该次目标日期有错误，不能被另一条正确记录抵消。

逐项内容合同：内存需 SK hynix、2027 最严重和持续至 2030，预测性质；AMD 需 AMD 估计、BofA 转述、100 kW、2.4 倍与 3.3 倍及预测属性；云厂商支出需 NVIDIA 管理层、2026 年 $650bn 及 2027 年超过 $1tn；收入需分析师预测、2026 剩余时间 82% 和 2027 年 41% 且是收入；财长需拟调查是否盗用及制裁能力；白宫顾问需谁指称 Moonshot Kimi K3 蒸馏 Anthropic。各个引用必须支持同条摘要的核心信息，拆多条时每条各自的核心摘要有相应引句。收入的数字句没有 revenue，单引它不算引用完整。新测试文章的三个目标需上段规定的主体、主要数字/事件与不确定性，并引用能支持它们的原文。对于每次：完整 = 全部核心内容及各自支持引用；部分 = 有目标但少关键内容或引文不支持；未抽出 = 没有目标；错误 = 原意、来源、期间、是否确定等有实质错误，优先于部分；无法判断单列。日期分数与内容完整各自报告，不把正确留空当作内容完整。

每目标每组计划三次。调用失败、截断、schema 拒绝、未抽出和来源不清都单列；日期比较至少要求每组有 2 次目标被抽出且来源可判，否则该项不可判断。对开发中 SK、AMD、收入三个已知历史错误，新对照各至少 2/3 仍有未经支持的非空原日期，才认为此特定症状复现，否则只报告波动，不声称该项改善。政策的两个已知日期新对照各至少 2/3 能保留正确日期；若不满足，则该项不可用于否定或证明实验。对全新文章，没有旧 Haiku 对照；新对照三次的目标是否出现、日期和内容结果逐次完整列出，若没有至少 2 次有效目标，或同一项其余两次结果不一致，即该项结果为探索性，不宣称稳定改进。开发组实验候选要求各症状目标没有不支持原日期、已知日期正确数不低于有效的同轮对照、五类用户已确认事实完整及引用支持的次数不低于同轮对照；实验组不得以缺失目标赢分。若任一条件不满足，本次日期实验不达标。独立测试各项及内容原样公布，不被并入开发分母；样本少的局限如实说明。

发送前旧检查：用可识别的历史真实回答作正对照，逐条记录经过 schema 和 sift 的数量；分别制造（1）删必填字段，证实 schema 拒绝；（2）把真实 quote 替换为原文不存在的字符串，证实 sift 标注并剔除该条；（3）复制同一 quote 为第二个不同证据 ID，证实重复合并；（4）把一个原发言日改成非法的月份文本，证实 sift 置空并保留该证据。每个反例都要先证明未突变对照通过，且检查 judged>0；保存输出，任何失败停止发送。v38 完整 preflight 仍执行并单列已知例外。
