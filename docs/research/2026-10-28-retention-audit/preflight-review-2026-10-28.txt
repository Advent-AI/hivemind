The proposed repair fixes the v38 first-stage count, but the design has serious gaps before it can claim faithful replay.

For example, an archived article can still be found by its ID after its text or publication date changes. The proposed checks would accept the record, but the replay could then keep or drop different statements.

1. **The item is identified but not verified.** The sift checks quotes against the item text, dates against `publication_day`, and candidates against `publisher_type`. It also uses the category to select the prompt version. The design refuses a missing or unidentifiable item, but does not say what happens when those values have changed. Compare the available archived request fields with the item and refuse a mismatch; explicitly account for text beyond the request’s 400,000-character limit, which the request cannot verify. See [extraction.py](/Users/lchingen/hivemind-extraction-quality-2026-10-28/src/hivemind/extraction.py:615) and [request construction](/Users/lchingen/hivemind-extraction-quality-2026-10-28/src/hivemind/extraction.py:393).

2. **The shown-ID recovery needs a closed boundary and a v22 rule.** Current preflight searches the entire request for view-shaped lines, including article text. An article line that looks like a view could therefore be mistaken for one. For v22, production explicitly passes empty shown-view and group sets; the replay should do the same. For older versions, identify the actual request blocks, distinguish an empty block from a malformed or unidentifiable one, and refuse ambiguity. See [preflight.py](/Users/lchingen/hivemind-extraction-quality-2026-10-28/scripts/preflight.py:34) and [extraction.read](/Users/lchingen/hivemind-extraction-quality-2026-10-28/src/hivemind/extraction.py:472).

3. **The promised historical coverage would miscount v17 answers.** Version 17 stores statements under paragraph entries and `extra`. `sift_with_groups` flattens them, but preflight’s produced count reads only the top-level `evidence` list. Leaving that tally unchanged can report more kept than produced and a negative drop count. Count the flattened answer for both the denominator and the sift. See [flatten_account](/Users/lchingen/hivemind-extraction-quality-2026-10-28/src/hivemind/extraction.py:220) and [preflight’s tally](/Users/lchingen/hivemind-extraction-quality-2026-10-28/scripts/preflight.py:90).

4. **“Kept” must name the stage.** The proposed 831 is kept by `extraction.read`, before the separate placement call. D209 says placement can then drop an unfiled statement with reason `no home`. Label the result as the *pre-placement sift*; it does not measure the final handover or its placement drops. See [extraction.file](/Users/lchingen/hivemind-extraction-quality-2026-10-28/src/hivemind/extraction.py:488) and [D209](/Users/lchingen/hivemind-extraction-quality-2026-10-28/docs/DECISIONS.md:2643).

There is also a limit to the word *historical*: the sift uses the supplied universe to resolve objects and periods, and runs the current code. The configuration checksum alone does not prove those are the original inputs or rules. The report should say it is replaying stored answers through the **current checks**, with the universe used identified. Cached answers can also have been originally archived under an earlier configuration, because cache lookup is by request identity. See [model.call](/Users/lchingen/hivemind-extraction-quality-2026-10-28/src/hivemind/model.py:211).
