# 归档实验：期初分析问题能否留住有用信息

假设：使用测试开始之前财报能支持的七个分析问题，能为竞争、供应和需求证据提供归宿，同时仍然挡住无关内容。

只测归档一步。两组使用同一篇文章、同一份已保存的抽取回答、同一时刻显示的原问题、同一个归档提示词及配置。实验组唯一增加七个问题；对照不加。两组各独立发送三次，每次的归档独立。保存每次请求和回答；不启动整条产品流程，也不把实验问题写入产品账本。

七个问题的支持材料、原文和日期已固定在 [prestart-driver-hypothesis](prestart-driver-hypothesis-2026-10-28.json)。来源是 2026-05-20 财报和电话会，晚于测试起点才出现的 ACP、Sharon 或 Firmus 不写入初始问题。它们是实验用的宽问题，不冒称已经是有到期日和结果范围的正式论点。

## 状态和检查

| 状态或事件 | 做法 |
|---|---|
| 原始文章及存档存在，配置与请求匹配 | 原样重建归档请求；生产构造器得到的请求哈希必须一致 |
| 控制组 | 原问题与原答案，重新发送三次 |
| 实验组 | 原问题后增加七个期初问题，其余内容和结构不变，重新发送三次 |
| 原回答为空或没有归档调用 | 报告该篇不适用，不伪造一次成功 |
| 调用失败或答复不完整 | 保留失败及原因，不能按未归档或成功计数 |
| 原始抽取已遗漏、引用已被检查拒绝 | 不冒称归档修复了它 |
| 本篇自己的候选问题 | 对照原运行保留的候选链接；不在此实验中修改候选准入或匹配 |
| 费用 | 开始前按每个请求的输入字节与最大输出计算保守上界，超过 $0.60 不发送；不增加既有试验上限 |

## 固定评估

使用已有 20 篇、33 条事实、25 条核心事实参考，不按实验结果改参考。实验问题与已有问题对每条参考事实的可接受归档目标已先登记在 [prestart-expected-homes](prestart-expected-homes-2026-10-28.json)。只数原抽取完整写出且通过引文检查的事实；比较两个组每一次放进适当问题的数量。不能由归档解决的原始遗漏单列。

同时用原有逐条标签数本次实际发送的有用、背景、垃圾分别归档多少；检查所加问题是否把背景或垃圾重新放进来。每条结果附文章和原记录编号，并读出错误去向。语义标签是 Codex 标注，五篇此前已看过，三次结果只代表这批文章和这一步。

评价模型必须至少三次对照、三次实验；缓存重放只是代码验证。若对照自身波动不允许判断，报告不确定，不用单次胜出作为成功。要声称整条路提高，还需在用户明确允许的范围内另测产品路径；本实验只报告归档阶段。

## 计分边界（发送前固定）

20 篇的历史归档请求是各篇当时的状态，不声称这些旧问题都在 7 月 1 日已存在。比较只回答：在这些历史状态上添加七个期初可提出的宽问题，是否改变归档。

基准事实不扩充。原抽取完整且其全部记录实际出现在归档请求中的事实，才有可能由这一步找回；这是抽取检查之后、归档之前的人群，不能用最终是否写入来筛选。事实有多条记录时，每条都必须进入该事实事先登记的可接受问题才算正确；每个事实最多计一次。33 条事实和 25 条核心事实为固定总分母，也单列归档前可处理的人数。原来通过后续检查的候选链接沿用原记录，但新增问题的归档并不等于最终写入。

新增问题较宽，是否符合重要性仍按原先的固定参考和标签判断：归档了不在原文参考中的背景或垃圾不加分，分别报告数量及原文。三次对照和实验逐次列示，不把单次差异视作确定提升。任何请求缺失、回答缺项或返回未知问题编号均单列失败，不能算成功。模型输出由独立存档保存，实验只发送一次、不重试，预算按全部请求字节和最大输出上限估算。
