The revised design still has **four serious gaps** before the calibration can be run. For example, a response can receive the right label while citing an unrelated fragment from the same article, and the current citation check would not catch why the citation fails to support it.

1. **The control prompt is not an executable frozen request.** The design says the API control will use the original prompt and receive the six articles directly. But the [original prompt](/Users/lchingen/hivemind-extraction-quality-2026-10-28/docs/research/2026-10-28-retention-audit/economic-judge-prompt-2026-10-29.txt:1) tells the judge it may read only a particular `/tmp` file. The API model will not have the old Codex session’s file access. The revised design does not specify the exact message that resolves this conflict or the complete request settings. That leaves the fresh control underspecified and may make it ask for an unreadable file. See the [design](/Users/lchingen/hivemind-extraction-quality-2026-10-28/docs/research/2026-10-28-retention-audit/direct-judge-trial-design-2026-10-29.md:47).

2. **Citation correctness is still reduced to finding text in the article.** The [trial rule](/Users/lchingen/hivemind-extraction-quality-2026-10-28/docs/research/2026-10-28-retention-audit/direct-judge-trial-design-2026-10-29.md:51) checks that a quote is a substring of the corresponding article, but does not require it to support the claimed meaning or cover the relevant parts. For case **a**, an unrelated phrase from the revenue article could satisfy that check while the label is `core`; a quote containing only one growth rate could also miss the other. The design correctly keeps the label score separate from content errors, but it needs a separate support-and-coverage judgment before reporting citation correctness. Its earlier statement that the “nine items passed” after three 9/9 label scores is also broader than that score establishes.

3. **Control mappings are still not auditable or fully accounted for.** The [revised rule](/Users/lchingen/hivemind-extraction-quality-2026-10-28/docs/research/2026-10-28-retention-audit/direct-judge-trial-design-2026-10-29.md:53) usefully distinguishes complete matches, partial matches, ambiguous matches and omissions. It does not require the reviewer to preserve the supporting fact or facts and the reason for *each* mapping, nor specify the denominator or final score when an item is partial or ambiguous. Consequently, two reviewers can produce different eight-item results without a record that resolves the difference. This leaves the original finding about subjective, unregistered mapping open.

4. **The $0.60 cap is not yet proved as an execution bound.** The arithmetic in the [budget](/Users/lchingen/hivemind-extraction-quality-2026-10-28/docs/research/2026-10-28-retention-audit/direct-judge-trial-design-2026-10-29.md:55) is correct **if** the stated input-token and price assumptions hold: $0.58518 for six calls. But the design limits request bytes and assumes another 1,024 input tokens for protocol overhead; it does not establish that this covers every billable input token for the actual API request. Only $0.01482 remains across all six calls. Therefore the document does not yet demonstrate that execution cannot exceed $0.60. It should bound the actual billable input for the frozen request and reserve against the applicable rates before sending. I did not contact the provider to verify current prices.
