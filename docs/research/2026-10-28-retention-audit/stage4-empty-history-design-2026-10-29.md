# 历史材料为空时，关系交由程序填写

2026-10-29，发送前。第四步的三个关系 `same_claim_as/revises/opposes` 只允许指向历史材料。当前模型还看得到同篇其他材料；当历史为空时，却仍被要求生成这三个字段，导致它有时把同篇编号写进历史字段并被拒。过去 [182 个保存的研究回答](stage4-empty-history-census-2026-10-29.json)中，87 个请求没有历史材料；7 个回答有不合法关系（均为 Luna，来自 NN 和科学工作流两个文章），95 个有历史材料的回答未出现该类无效编号。采样重复，不是总体故障率。

离线在存档副本上删去空历史的三个关系、由程序补空列表，7/7 原关系拒绝翻转，所有其他内容不变；其余 80 个空历史回答的关系本就全为空，95 个有历史回答不碰。已知案例及反向变异控制见[脚本](stage4-empty-history-census-2026-10-29.py)。这只证明给定答案的代码处理，不证明模型发送后的经济内容或同篇事实语义正确。

## 唯一改动与边界

- 输入中 `stored_pieces` 为空时，实验组从输出 schema 删除三个历史关系字段，让程序在收到结构答案后补上三个空列表；原系统提示、源文章、同篇材料、catalog、其他输出字段及既有关系检查均不变。原始模型回答与补全后的回答都保存。
- 如有一条或多条历史材料，schema、输出、关系检查及发送的字节全部与对照相同；不删除字段，也不自动改模型关系。只对本次研究程序测，不改产品路径或冻结模块。
- 同篇材料依然给模型阅读，补空不代表它们属于同一说法，也不丢弃原文；但程序不替模型决定同篇说法是否相同。必须读回答是否完整保留新材料、是否错把不同说法合并及是否声称独立来源。源文章自身混入推荐或不准确日期时，要按原始网页标记，不能用格式通过掩盖。

这是将代码已知的“没有历史材料时无法引用历史材料”移出模型。Anthropic 的[结构输出文档](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)不支持 `maxItems: 0` 等数组上限；本方案直接不在空历史请求里要求字段，避免依赖不受支持的约束。引用有无有效之外的逻辑和事实仍须人工模型阅读。

## 先固定案例、来源和结果

每篇每模型新鲜对照与实验各三次，2 模型、2 条件、4 篇，共 48 次；保守预算及所有在途请求不超过 $0.60。前两个案例放在计划首位，避免前序错误使它们未测；出现结构、用量或传输异常即停止新派发、保留在途结果。

| 案例 | 原始依据和标记 | 测什么 |
|---|---|---|
| Valar 能源，新增第四步目标保留例 | [原文参考](stage4-empty-history-valar-reference-2026-10-29.md)，此前 v38 已抽取，经济意义未由用户裁定 | 30 MW 为考虑中的数据中心，不能变成已建成；100 kW 为反应堆已发电，不等于 30 MW 数据中心；源码为空历史。 |
| Sharon，用户标准，已有历史材料 | 用户明确是供需辅助；六年、72 MW、最多 4 万 GPU 是重要条件 | 请求字节在两组必须完全一致；不能将 Sharon 的条件说成 NVIDIA 已确认保证金额。历史问题目录未涵盖用户指定的供需目标，不能将本研究视为正确归属或最终留存。 |
| 科学工作流，已见开发例 | Anthropic 说 Claude Science 使用 NVIDIA BioNeMo；现有预处理将推荐内容误拼正文，具体集成声明日期未确立 | 历史字段拒绝是否减少；技术集成及未知收入是否保留；不把推荐当作该篇事实或把文章日期当声明日。 |
| NN 液冷，已见开发例 | NN 的 47 台设备为 NVIDIA 机架液冷供给；来源是 NN | 历史字段拒绝是否减少；主体、数字及相关性是否保留；区分同篇同源和同一说法。 |

不按 `background_only` 本身断定成功或最终保留；每次按具体原文和回答手工记录事实、来源、关系、用户标准以及未知项。此实验的方向性成功需要：Luna 在科学工作流的三次新鲜对照中复现历史编号拒绝，实验组该类拒绝为零；Valar 不把计划写成已实现；新结构对已有历史的请求确实与对照相同，内容不出现明显退步。如果对照自己未暴露故障、结构中有其他拒绝、历史样本或来源判断不完整，则只能报告样本结果，不能宣称修复整体。对 Haiku、Luna 分开计数；3 次是重复发送，不是 3 个事件；新来源参考是模型作者判断。

## 读写与状态

| 值 / 读者 | 原结构、新结构与当前产品 |
|---|---|
| 请求中的历史和同篇材料 | 源自既有归档、历史序号及研究 reader；两个条件完全相同，模型均可读；同篇不自动写入历史 |
| 三个历史关系 | 空历史实验由库补 `[]`；有历史及全部对照由模型写，保持原检查；下游研究读取补全的原格式，原模型返回另存 |
| 金标与来源参考 | 仅研究阅读者读取，不送进模型；Valar 不是用户人工金标 |
| 锁、预算、原始返回 | 已审核的发送器记录并停止异常；单个进程独占结果目录，不重发；不写产品或生产模型默认 |

| 状态 / 事件 | 处理 |
|---|---|
| 未发送、来源或代码变化 | 拒绝旧摘要，需新目录冻结；不覆盖 |
| 新／旧条件回答成功 | 保存真实请求、模型原始结果和统一结构答案；检查身份与原结构 |
| 非法关系、格式、传输或用量异常 | 不发新请求，收完在途并记录未发送项；不自动重试 |
| 已完成或次日配置变化 | 当次结果不可修改；下一次新目录、新预算和预检 |
| 两个进程冲突 | 独占 worker/attempt；拒绝第二次派发 |
