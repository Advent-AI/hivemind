# Haiku 第一步日期实验：发送前登记

2026-10-29。针对已读过的 15 份 Haiku 答案、89 条筛后记录：[全量日期清点和逐项核对](2026-10-29-haiku-date-review-v2.json)。其中 36 条原发言日缺乏原文支持、27 条有支持、12 条待定、14 条筛后为空；选例且含重复，不代表全周。全部 v38 的 98 个请求都要求写发言日但未说明未知如何表达，并提供发表日期。用户确认内存预测、AMD 比较、收入增长和云厂商支出的分析价值；这些具体目标不再由模型自造标准。

**假设：**写清“只有原文能确定原始发言日才填写，否则留空”，可减少把报道日冒充发言日，同时保留已知日期。模型续问说它曾把发表日当作替代，但收入续问漏读原文，故自述只能是线索。此实验只改变第 1 步里一个日期要求，不改变模型、分类准则、schema、其他步骤或产品配置；不宣称修复证据内容或整条系统。

## 具体改动与冲突检查

两组请求由生产 `extraction.request_for` 和 `model.build_request` 从 `poc-v38.json`、原始文章、`poc/universe.json` 生成，再用相同 Anthropic Messages 外壳发送给 `claude-haiku-5-5`。对照组保留生产 v22 系统文本；实验组仅将系统提示中的英文句子 `Identify the speaker and, for a retelling, the original speaker and statement day.` 替换为 `Identify speaker and original speaker. Set original_day only when the item establishes the original statement date; else leave it empty.`。同一条提示里保留原先的 `Copy its quote verbatim.` 和 `Write generated descriptions in English.`，删除重复的 `Copy quote exactly from the source, without translation.`：这只是去掉重复引用要求，且仍明确原文逐字复制。对整个请求和 schema 做逐字检查：两个 system 仅有这两处差异，其他内容、字段顺序和样本上限相同；要求用来源文章证明日期，不要求引句本身必须包含日期，允许结合文内“昨天/周三”和发表日计算精确日期，不推测“上周”的具体哪一天。

系统提示长度由 9456 降到 9453 字符，正式发送前记录 Anthropic count_tokens API 的每篇输入 token，不通过扩大 prompt 掩盖损失。所有版本使用同一个 8000 输出上限和 low effort；schema、sift 调用均照 v22 生产，丢弃原因逐条记录。无完整答复或 schema 错误单列，不能算对错；不能因丢弃一条其他记录就判整篇无效。

## 事先固定的七篇与目标

开发四篇分别是上一轮用过的内存 `gnews:fbce0469dbb5b33e2c34a0f5`、AMD `gnews:55b3b854d30ecb73679c2088`、收入 `gnews:71df54965281684cc500960f` 和政策 `gnews:f9e7da6ddbf890fa64baf922`；已看到结果，不能当未见。固定五个未知原日期目标：SK hynix 的 2027/2030 预测；AMD 对 2.4/3.3 倍的估计；收入文章中管理层云厂商支出预测；同篇分析师的 82%/41% 收入预测；对这些原始发言人，原文未给出原始发言日，应留空。政策文章两项已知：财长的 Tuesday 相对 2026-07-24 Friday 为 2026-07-21；白宫顾问的 Wednesday 为 2026-07-22。每项存在与原意仍需人工核对，不能以日期字段单独证明事实完整。

独立的测试文章在任何本实验 Haiku 发送前选出：从已存 v38 同周 T7/T8 的请求中，筛出含原发言人但至少一个日期未知的文章，排除之前 Haiku 五篇，用随机种子 20261029 排序；取前三篇 `gnews:9e0d5b0d6b3e603c60340128`、`gnews:ad47330f25c9d5ff84ced7e2`、`gnews:d4c5dc540392f8df39aee250`。选择用了旧 Luna 输出的字段存在性，不是随机全周样本；这三篇没有出现在之前的 Haiku 对照或本实验提示词修改中。研究者先读完原文并固定目标：

- ACP：文章说 NVIDIA **July 1** 发布 AI Compute Partnership；将 NVIDIA 本身这次发布标为 2026-07-01，不能以报道发表日 2026-07-03 替代。若只是作者自己在 7 月 3 日叙述、并非 NVIDIA 当天的公告，按实际说话人分别核对。
- Valar：文章说 Valar 在 **Wednesday afternoon** 宣布与 NVIDIA 探索合作，文章发表日 2026-07-01 为周三；这次声明为 2026-07-01。其他过去的发言日期不得因此填成同一天。该案例用于日期保真，不据此重新裁定其投资价值。
- Kyber：文章说 SemiAnalysis 报道 Kyber 由 2027 延至 2028，但没有明确这份报告具体发表日期；被归为 SemiAnalysis 原始报告的记录应留空，文章 2026-07-06 是新闻发表日。若模型只归于文章作者而非 SemiAnalysis，保留不确定并单列，不擅自当作成功。

每目标每次回答只记一次，完整引用和摘要按原文语义由 Codex 实读；原发言人有误、日期不是来源支持的日子、或猜精确日，记日期错误；没提目标记未抽出，原发言人与记者叙述无法区分记待定；已知日期留空也记日期缺失。不同记录同一事项应逐条检查，任何一个实质错误不能被另一条正确结果抵消；附证据 ID。没提供目标内容的答案不得借无日期被算作成功。三个未见文章在每种配置下只测一次（每篇三个独立样本，作为同一配置的一次测试），不把它们用于改写提示词或据此连续调参。

## 比较与判定

每篇每组各三次，共 42 次独立新发，最多 8 并发，带日志与 pid，无重试。分别报告每项 3 次的原始可评分数、日期正确/错误/缺失/待定及未抽出，重要内容是否完整保留、原文引用是否支持、题外输出和数量、运行成本及失败次数；重点事实而非所有不相干的东西一票同权。发展集参照已有三次基线：内存、AMD 的目标都在 3/3 被错误赋发表日，收入分析师目标也 3/3；新鲜对照需要在三项中每项至少 2/3 复现被报道日冒充的错误，否则该项说明对照不稳，不作治疗成功结论。实验组要在这些能评分的目标中消除所有不支持日期，并在已知日期上不比同轮对照少正确；重要目标召回不比对照少，不能靠不抽取或把所有日期置空拿到高分。三个测试文章独立报告，不与开发混在一起宣称全面通过。

发送前保存所有源文本哈希、请求字典与字节散列、参考说明和样本分组，并用已存真实回答及缺字段突变验证生产 schema 和筛选；原始已存案例的日期标记由人核对，不用字符串匹配代替语义。运行一次 v38 preflight，核对 98、841、831 和已知历史账本例外；检查凭证、机器和网络。用官方 token count 接口计每份请求。每请求输入预留 `max(3×token_count,3×wire_bytes)+16384`，输出预留 8064，按 Haiku 的高档价格在预留输入超过 100k 时计；合计超过 $0.60 则停止，不能提高。并发最多 8，独立进程、pid 和 log；用量缺失按全预留计，输入/输出/价格档超过预留则停止发送尚未发送的请求，在途继续如实记录。预算为估算，不是服务商的硬上限。

如果实验方向无效，回到完整请求与原始回答追查，不把目标叫作完成；如测试或标准自身出错先纠正测量，并保留旧记录。四步目标持续进行，但这一轮仅测第一步日期；不调 Jev、归档、故事页或第四步。
