## 定位这次拒绝

本篇 `incoming` 是 Anthropic 称 Claude Science 通过 BioNeMo 工具连接具体模型的说法；同篇 `item:e1` 是更宽的 Claude Science 与 NVIDIA 科学模型集成说法。它们原始来源同属 Anthropic，但记录的粒度不同。同源不自动等于相同说法；`same_claim_as` 目前的研究合同只允许历史材料 ID。当前模型输入同时给了本篇其他材料，但 prompt 只说对每个**存量**材料分类，输出 schema 对 ID 是任意字符串，最后代码才按历史 ID 拒绝。目标序号之前历史目录为空，这次不能衡量有历史时的归类。

从本轮可确认：Luna 5/6 次把同篇 ID 送进历史字段，检查都拒绝；这不是 Haiku 或结构新方案的 5/6 错误率，也不是已接入产品的损失。不能直接放宽检查将两条合并：是否同说法需要先按原文判断，代码也必须明确同篇和历史材料各归谁处理。值得进一步检验的根因是**输入同时包含两类材料，但输出字段的合法范围对模型只在检查时被执行**；这个假设需要单独的对照，而不是事后把错误归给模型或提示词。
