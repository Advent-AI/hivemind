# 分析师金标准 v5

**标准看能否保住投资判断所需的完整意思，不以复述多少细节评分。先判断信息是否有助于理解业务、市场预期或投资观点，再分别检查有没有保留原意、能不能核查。引用不完整不等于判断错误；真实的时间、金额、主体或确定性错误也不能因为信息有用而放过。**

Alex 于 2026-10-29 要求立即订好标准。本版按用户最新授权纠正 v4 将附带细节写入必要原意的问题，取代 v4 的当前使用地位，作为已列案例的人工／模型逐条阅读标准；不把这组开发案例叫全周金标，也不把模型新增判断叫 Alex 原话。所有已列来源按保存文本判断“文章说了什么”，不是证明现实世界的真实性。旧数据、旧实验和旧分数原样保留，不能把改尺后的分数写成系统提升。

## 一、什么值得留

| 等级 | 定义 | 例子 | 验收中的用途 |
|---|---|---|---|
| core 核心 | 直接改变收入、利润、融资风险、需求或关键产品进度判断 | 收入增长预期；客户资本支出；供应瓶颈 | 必须单列漏失和失真，不能靠更多次要信息抵消 |
| supporting 有用辅助 | 支持／反驳上述判断，或给出可检验的估值假设 | AMD 比较；Omniverse 许可；EPS 与倍数组成的条件估值 | 单列覆盖与失真；不要求每项独立开页 |
| optional 可选背景 | 可帮助解释市场预期，但省略也不损害主要论证 | 财报后股价反应；单次涨跌 | 留下或省略均不扣选择分；误说成业务因果仍算失真 |
| exclude 不应作研究证据 | 与判断无关的模板、广告，或用户已明确不要的内容 | 作者介绍；指定新加坡案件概况 | 记录误收，不能因此说其他段落也都无价值 |

价值不由数字多少、是否官方、是否远期、是否已有问题页、是否与投资方向相同决定。一个真实的风险反例可比十个支持观点的数字更重要。合理推断需写明依据和条件；估值结论需区分假设与观察。具名预测、匿名报道、监管指称都可有用，可信程度另看。不要求输出与参考措辞、条数或 tier 枚举完全相同。

`reference.json` 中每项已固定等级、依据、必要内容和常见失真；未列信息不能默认算垃圾，记为 `unreviewed`，先读原文判断，不能加进当前分母。Alex 明确指定的案件排除不推广成排除所有监管风险。本次授权由 Codex 订定的等级标 `analyst_judgement`；用户判断及其有限解释单独标明。

## 什么是必要原意

每项 `required` 都必须说明：删掉后会改变哪项业务判断、估值计算、风险、适用范围或证据的可信性质。`reference.json` 的 `materiality_basis` 逐项写出理由。

必须保留的是经济意思：谁的判断、什么业务或指标、多少、哪个期间、什么条件、是预测还是已经发生。不是每条都机械填这六格；仅适用于该条且影响意思的部分才必需。原始估计者和可信性质不能丢，例如 AMD 自己的模拟结果不能说成独立实测。

中间转述机构、普通发言场合、附带商品全名可以放在来源记录，不要求摘要重复。漏这些一般不降低原意评分；如场合本身改变法律效力、发言权限或明确的新旧关系，则其重要区别仍须保留。虚构来源细节依然算记录错误，不能用“附带”免责。

同一事项拆成几条或合在一条不影响得分；跨句引用能共同表达原意即可。只有原文全文包含必要含义、输出却没有，才算输出遗漏。摘要明确说错时不能靠引文替它洗成正确。

## 二、每项分开记四件事

1. **选择 selection**：`kept`／`omitted`。同一事项拆几条、合几条，只计一次。相关条目必须列出 ID；不靠关键词重叠判断命中。
2. **原意 meaning**：`correct`／`partial`／`wrong`／`absent`。此栏专指内容表达：读可见的摘要、明确关联的条目和引文；结构化日期等另列 issues，避免把理解与记录混成一分。参考项 required 中的必要主体、动作、指标、期间、条件和确定性齐全是 correct；context_not_required 只是帮助理解，不另加漏失处罚；少内容但未说反是 partial；金额、期间、归属或确定性被改错是 wrong；没保留是 absent。原句短而摘要有原文支持，不降低原意评分。摘要与其引文相互矛盾，或相同事实的矛盾版本并存，记 wrong，不挑最好的一条掩盖。
3. **可核查 traceability**：`sufficient`／`needs_context`／`unsupported`／`absent`。引用及明确关联的本篇上下文能支持摘要是 sufficient；需回原文相邻句补全是 needs_context；引用错误来源、原文也不支持且未标明推断是 unsupported。已标明的推断核查其前提和推理，不要求原文逐字写出结论。句子被拆开不扣分；真实结论也不能用无关引文顶替。
4. **记录问题 issues**：独立列 `original_date`、`period_conflict`、`attribution`、`certainty`、`wrong_source`、`duplicate`、`missing_context`、`unsupported_inference`、`other`，并写依据、发生字段、严重程度 `material`／`record_only`。原发言日未知却填写文章日期是记录错误，不能因此说预测没有被保留；若它改变先后关系或新旧证据判断，记 material。金额、预测期间、付款与承诺、事实与推断混淆属于 material。语义与影响决定严重性，不由枚举名称单独决定。

例：摘要正确写收入增长，但短引文缺“收入”前句 → kept、correct、needs_context；错误原发言日另列。摘要改成别的财年 → wrong。摘要说“原文未说明指标”，而上下文明确是收入 → wrong。FY2028 EPS 与清楚标条件的估值不因远期自动扣分。

## 三、统计不能再混成总分

- 核心／辅助分别报告：应保留 N 项，正确 C、部分 P、失真 W、缺失 M；四项之和等于 N。`选择覆盖率=(C+P+W)/N` 只代表有输出；`正确原意覆盖率=C/N` 才代表完整传达原意。另列每个 material 问题及受影响事项数，不把它藏在覆盖率里。correct 只表示内容表达正确；带有 material 问题的记录不能称为可直接使用。
- `误收率=被保留的 exclude 事项数 / 本次明确评过的 exclude 事项数`。可选背景留或不留不计错。此比例不是全部输出的垃圾率。
- 核查充分、需上下文、不受支持分别计数；记录问题按类计数。没有总体“全对才 1 分”的乘积，也不设置可互相抵消的加权总分。
- 分母为零报 `not_exercised`。遗漏待评案例、未知标签、丢失来源、重复计一个事项都拒绝出分。未评输出必须显式计数，不能声称全量精度。没有随机代表性样本，不能推算全周精度／召回。
- 已看过模型回答的本版案例全部是开发／回归；不声称留出。以后比较新改动：固定本版，配同期原版，至少三次，逐次报告；真正的新来源需在看到新模型答案前建立独立参照。

## 四、错误归到哪个环节

| 看到的问题 | 判断位置 | 不能归咎于 |
|---|---|---|
| 输入把推荐文章当正文传入、网页本身错了 | 来源输入 | 模型投资判断 |
| 原文有必要信息，抽取省略或改错；或无视输入中明确的推荐区标记 | 抽取 | 没有问题页 |
| 信息有用但没有对应问题 | 问题覆盖 | 抽取垃圾 |
| 正确问题存在但未展示 | 读取／查找 | 分配判断 |
| 正确问题已展示，仍归错或丢弃 | 分配判断 | 抽取 |
| 已决定保留但没写入 | 写入 | 模型理解 |

步骤 1 只评原文→记录；步骤 2–4 必须附该时点真实问题列表、可见证据及最终写入记录。本版给语义归属，不虚构 v 编号；没有这些输入就 `not_exercised`，不是整条系统通过。信息可留但暂时无页，应标问题覆盖缺口。Google Cloud 合成一个研究事项，可以由多个证据片段支持；不等于所有财务项目必须合成一页。

## 五、使用和变更

`reference.json` 是语义参照；`sources.json` 保存来源及其摘要校验值；`calibration.json` 用真实回答和明确标示的修改对照验证边界。`check.py` 只检查数据完整性并报告参考与校准案例数量，不冒充语义评委。审读者必须读原文及全部相关输出，给理由与 ID；自动代码不得凭引用重叠、正则词表或条数判投资价值。

变更事件：新说法＝本次 unreviewed，不能改分母；发现来源错误＝标记该项不可评并公开分母变化；用户纠正＝新版本保留旧版；发现同一事项＝合并计数但保留所有原条目；只改引用格式＝只改核查维度；尚无路由证据＝下游 not_exercised。本版冻结后新实验不得就地改标准。

本版就绪仅指这些案例可据此逐条判断。没有给产品新设自动拒绝门槛，也没有把历史实验追认为通过。当前任务完成标准：来源都能定位，用户十一项决定全部映射，校准正反例符合上文，检查拒绝损坏数据，独立审读无严重未解决问题。

## 与抽取要求对齐

抽取的验收使用同一把尺：先读完一篇，保留与业务、估值或风险判断直接有关的陈述、具名预测、条件论证和反证；读到文末才停止。不是看见公司名或数字就收，也不是没有现成问题页就丢。每项说清有关主体、指标／行动、期间与条件；不知道的内容保持未知。远期只影响不确定性，不自动取消投资价值。

已知反向要求按本版判不合格：role-v22 把指定新加坡案写成必收例子，与 G05 冲突；直接排除作者估值计算，与 G14 冲突。两者不能再拿来作为评委判错的依据。此记录规定抽取应达到什么，不表示运行中的旧提示已经改好。

日期要求也不混用：文章发表日、原发言日、预测覆盖期间分别解释。原文能可靠确定的相对日期可换算；无法确定不能填报道日。建问题时的财年规则不得改变原文中尚未明确的期间。省略可查的发言场合与编造精确日期是两回事。

本版保留 16 项和原等级，不增加模型总分；四处要求调整见 [全量逐项审计](change-audit.md)。旧版本和旧分数保留。新实验不能为了改善成绩再就地修改本版。

校准共 23 例：5 个原始回答、18 个明确标记的构造对照；这不是 23 次新实验或人工金标。独立审读及处理见 review.txt、review-resolution.md。
