The design has **two serious gaps** for this six-call comparison. For example, two requests could carry semantically equivalent text in different byte order, or a complete-looking answer could say it did not read an article; either can make the comparison misleading.

1. **Identical input bytes are not fixed as a condition.** The [design](/Users/lchingen/hivemind-extraction-quality-2026-10-28/docs/research/2026-10-28-retention-audit/deepseek-judge-trial-design-2026-10-29.md:22) requires the same system and user content and “actual semantics,” and says to inspect request bytes. It does not require a byte-for-byte comparison of the common message content and schema before sending. That matters because the saved request contains an ordered, compact JSON string inside the user message. The provider-specific outer fields must differ, but the common content can still be compared byte for byte against the frozen request and between providers.

2. **The handling of uncertain refusal is missing from the scoring contract.** The [design](/Users/lchingen/hivemind-extraction-quality-2026-10-28/docs/research/2026-10-28-retention-audit/deepseek-judge-trial-design-2026-10-29.md:5) excludes refusals and incomplete outputs, but does not say to inspect **every output field and API status**, or to hold a sample unscored when it is unclear whether the model refused or read the full article. The [final direct-trial design](/Users/lchingen/hivemind-extraction-quality-2026-10-28/docs/research/2026-10-28-retention-audit/direct-judge-trial-design-2026-10-29.md:61) and its [latest review](/Users/lchingen/hivemind-extraction-quality-2026-10-28/docs/research/2026-10-28-retention-audit/direct-judge-trial-independent-review-v5-2026-10-29.txt) explicitly require both. Without that condition, nine structurally complete items could receive a score even if a reason says an article was not read.
