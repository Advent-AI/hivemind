# 第四步能力对照：发送前草案

2026-10-29。目标是分别测 Haiku 和 Luna 在三个用户裁定例子上读新内容、旧问题和旧证据的能力；这不是产品已接通的第四步，也不是完整流水线验收。不改产品、提示或用户参考。三个案例均已用于诊断，都是开发例，没有真正未见的用户金标；不能推算全周质量，也不能把它们叫作留出集。下一轮提示修改前仍须事先准备独立未见案例和参考。

## 固定输入和工作范围

使用 [三例历史输入](stage4-user-case-context-2026-10-29.json)：当时原文、原抽取、历史目录和目录中全部问题的完整证据。原句不得截短；用输入发生前的序号，不用后来问题或证据。新内容连同同篇其他抽取结果一并展示，防止单条脱离上下文。使用既有 D201 第四步研究提示和输出格式；不增加用户案例的答案或例子。三例各发三个新鲜 Haiku、三个新鲜 Luna，共 18 次；不给 Jev 意见，因为只测第四步阅读，此项不评价第三步。两边明确发送的文本和 schema 相同，但供应商可能注入不同的结构化输出指令；不能称为模型看到的全部指令相同。

历史目录完整展示是研究条件：不是说全部证据相关，也不是最终产品接入方案。D201 旧程序每次只读已有链接的问题，这里故意从全部目录和完整历史展开开始，以测它能否自行辨别可用内容；没有修改历史实验结果。用户原判断依据、原文和历史问题对照后固定下表；其他信息由模型或本次评阅者判定，不是用户裁定。

## 计分单位和硬边界

每次回答只对指定目标计一次；一次回答拆成多条不加分。每个模型的分母都是每例三次；超时、截断、无效格式单列，不当作无误。先独立读每份回答、所给资料和理由，再统计；同时保留无法判断和不同解释，不能只靠字符串匹配。评阅者是模型，不是独立人工金标。

| 固定案例 | 必须判断的用户裁定 | 错误的例子 | 不作强制判断 |
|---|---|---|---|
| Sharon e6 | 六年、72 MW、最多 4 万 GPU 是供需的辅助线索；不能表述为 NVIDIA 担保金额 | 写成 NVIDIA 承诺 72 MW 或把这项容量当作美元担保金额；把它说成与供需无关 | 当时没有供需问题，用户没有裁定新建哪一个投资问题；不要求强开页面，也不把无页误记为选错已有页 |
| NVL72x2 e3 | SemiAnalysis 报道备选架构取消，属于产品进度；不同于 Kyber 本身 | 说 NVL72x2 就是 Kyber NVL144；把传闻说成公司确认；断称对产品进度无关 | 用户没有指定必须挂 v11 或 v13，关联和精确页面分别记录，不以其中某一个编号机械给分 |
| 新加坡 e8 | 四家公司被控的案件概况不留 | 为此事项提出新投资问题或当作投资证据；把案件去向和 NVIDIA 责任写成已确立 | 只裁这条案件概况，不判断该文章所有其他内容 |

每例分开记录：原意与来源、投资分类、是否将目标错误放入问题、在没有合适问题时如何处理。没有问题时，说明“无目标”和“信息不重要”是两种不同理由；仅因没有问题而丢弃，不能算正确识别垃圾。第四步原 schema 没有直接表达“有价值、暂无问题”的专门动作；如回答无法表达则记为合同限制，不把它伪装成模型答错或自行新增产品机制。该测试不能证明内容最终被存入产品：研究程序没有写入器。

## 预算、验证和停止

发送前：原始案例、给模型的完整文本、schema、参考和脚本保存并做哈希；检查每例历史输入、正反例和空白数据会失败。先重放现有 preflight；对两家请求计算或保守预留输入、输出费用，包括 Haiku 超 100k 输入的全量高价，并保持每个实验最高 $0.60，不靠执行中追加预算；并发不超过 8。先请求精确或近似 token 数，预留超上限就缩小测试而不是提高上限。调用失败、截断、语义含糊都如实记录，不静默重发；原始回答和各次用量均留存。分别阅读两个模型的回答，比较控制组自身波动与模型差异；不能按多数票改变产品。结果不通过，只记录失败和每个环节原因，不继续对已见案例补提示。

## 明确的未解决项

本草案不改变 D209（无处可挂则丢）或 D201（新问题须有独立投资判断），也不解决重要信息没有合适问题时应如何保留。任何要改变上述行为的产品设计需先量化真实影响、核对已有决定及写入/读取边界。先进行只读审查，检查评分是否超过用户的裁定、历史是否完整、能否比较两家和成本是否可控；审查无严重问题才编写实验发送程序。

## 只读审查后的收紧（第二版）

[审查](stage4-baseline-review-2026-10-29.txt)列出 8 项严重问题。逐项处理如下；这是开发性诊断，不是普遍模型排名或产品验收。三篇均已见，不能冒充真正留出；新、事先写好来源参考的留出案例在未来任何更广泛的验收之前准备。

1. **构造请求并排除答案泄漏。** 仅发送：原始文章的 `text`、文章标题/来源/发布日期；当前目标的原始抽取字段 `id,quote,one_line,speaker,original_who,original_day,tier,event_time`；同篇筛选后的其他抽取字段；当时的完整历史目录、问题和完整已有证据；比较意见和历史论点均为 null。当前记录的 `status,drop_reason,final_links,final_status,stored_id,stored_links`、旧归档请求及旧回答、实验参考、案件类别名、用户判断均不得发送。其他抽取来自该篇归档的原始抽取回答和生产筛选，不从旧归档提示逆向提取。发送前把完整实际请求单独存档并逐字段核对；任何未识别字段拒绝试验。页面附带的后续推荐按原材料发送，但不将其当作案件事实。
2. **编号唯一。** 此次研究请求中把目标局部编号转为 `incoming`，同篇其他局部编号转为 `item:eN`，历史记录保留其账本编号 `eN`。保留离线映射和来源，检查三组编号无交集；拒绝将 `item:eN` 错当历史 `same_claim_as/revises/opposes`，引用 `incoming` 与历史 `eN` 分别解析。上版历史 16 个 fresh2 案例中 K02 的新 e1 与旧 e1 也撞号；K02 的保存回答没有引用它，不能据此推断那次实际造成错误。当前三例各有一次撞号，均已核实内容不同。
3. **评分只覆盖已裁定的含义。** 逐条报告：用户已裁定内容是否被明确承认；是否有与原文矛盾的确定性表述；用户已排除的新加坡概况是否作为投资支持或新问题。若只引用原始记录、不重述其所有数字，标“依据引用保留／文字未复述”，不能机械判漏；假称数量或主体才算事实错误。Sharon 可否作为融资问题的上下文、NVL72x2 对哪一个已开问题最合适，用户没有裁定，均为未评分观察。单次答案无法看出模型对价值的判断时记未知，不按 `action` 猜测。附原句与理由，由我作为模型逐条阅读；冲突或无法判定保留未知，不事后改参考。
4. **合同缺口单列。** `independent_sources` 只有 true/false，来源不足时不能据此声称已验证独立；`background_only`、`unresolved` 或空链接也不能单独说明它认为信息无价值。原输出没有承载某一判断时记合同无法表达，输出明确说错才标事实错误。本测试不以独立性做用户裁定分数。
5. **说明与原程序的差别。** 此诊断新增文章全文及同篇其他抽取、展开全部问题和完整原句；不传 Jev 意见、不传已有论点。旧研究程序不是这样。它无法证明原有实验、第三步或论点更新有效。
6. **独立取样。** 每次用直连服务发送完全相同的显式内容，不读本地回答缓存，也不向请求追加样本号，不重试；供应商自己的提示缓存可能生效并单列。逐次保存请求身份、原答、状态、耗时与用量。任何入库身份验证不依赖此诊断。
7. **冻结格式和费用。** 明确 `gpt-6-luna` Chat Completions、`claude-haiku-5-5` Messages，均使用与前期调用一致的原生 JSON schema 和 `medium`、6,000 输出 token；显式 system、user、schema 的字节顺序分别比对，不说两家的隐藏指令相同。发送前通过两家 token 计数得到每次输入估计，按三倍计数加 16,384 和 6,064 输出 token 做整批预留；Haiku 预留输入超 100k 时所有 token 按高档价格。18 次的预留总和必须低于 $0.60；不依赖旧 `model.call` 的缓存、重试或错误计费。使用或响应缺失时保留整次预算，异常则停止调度、等待在途并记录；这是保守估计，不是供应商保证的硬费用上限。全部在途也提前预留，不得超过额度。
8. **结果只作描述。** 按模型、案例和三次发送展示每个判定及未知、调用状态、费用和理由；模型自己逐条读原文。没有通过率阈值或普遍排名；即使某例 3/3 对 2/3，也只能陈述这九个已见样本。统计不能把输出格式完整当投资判断正确。新的精确模型可见请求还需在数据准备完成后逐字审查，再进行只读评审。

## 第三版：先登记两个未用于本轮设计的来源案例

[第二轮只读审查](stage4-baseline-review-v2-2026-10-29.txt)指出 D217 要求每个试验在发送前就登记新案例，而上一版只有三个已见例子。现加入两篇此前没有作为本轮第四步开发案例的来源：[发送前参考](stage4-holdout-reference-2026-10-29.md)和[历史输入](stage4-holdout-context-2026-10-29.json)。二者均经历过历史 v38 抽取，不是模型历史上从未读过的文章；参考由 Codex 编写、没有经用户逐例裁定，不可当人工金标。两篇各自的类别、时序、原意与不能推断的内容在参考中固定；不知道正确页面时不推断。

本版优先于上文涉及案例和次数的表述：3 个用户裁定开发案例和 2 个模型编写参考案例，各模型各 3 次，共计划 30 次。输出分两组逐案列举，不合并成具有总体意义的分数。原文、历史完整证据、原始抽取以及其他同篇抽取按第二版的字段合同构造；目标都统一命名 `incoming`，本篇其他记录使用 `item:eN`。若模型将本篇其他记录用于论点，单独记录引用及可解析性，不把它误当历史证据，也不能宣称现有产品写入器能解析。预算仍是整批 30 次的全部预留不高于 $0.60；若不能满足，先缩小实验并重新登记，不能提高上限。正式发送前先生成、核验具体请求，再只读审查输入和评分，确认无严重问题。
