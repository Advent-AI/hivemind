# 同一批事实：DeepSeek 与现有评委的比较

2026-10-29，发送前登记。Alex 要求快速试 DeepSeek；先试仓库此前测过的 `deepseek-flash`，此前比较后 Alex 选择继续用 Luna（D62），并未决定此次切换默认。只测评委的**给定事实判断**，不测抽取、页面归属或整条产品流程。使用上一轮已保存的[六篇全文、九个原句和提示](direct-judge-trial-2026-10-29/trial-request.json)，原意、schema 和 8,000 输出上限相同；各发三个新鲜回答。现有模型 `gpt-6.1-terra` 作新对照，`deepseek-flash` 作实验，分别调用各自官方 API，不修改产品默认配置。

Alex 澄清 2028 EPS 可以留但未指定权重，故九个候选继续原样给两个模型，第 b 项不计标签分；其余八项使用[新参考](gold-user-2026-10-29-v3/reference.json)的已有用户判断。模型收不到参考或分数。每次固定报告 8 项的标签、9 项的原文支持及逐字引文能否支持完整意思；任何拒答、缺项、重复 ID、未完结、解析失败和超时原样记下，不重发或当正确。未知意义与未知引用分别记不确定，不算整体通过。模型答得更多不等于好。将六次每项实际答案及原因保存，三个样本逐个报告，不只看平均。

两个 API 请求无法做到每个字段完全一致：OpenAI 使用 Responses API 的 `service_tier=default`、严格 schema、`reasoning.effort=xhigh`；[DeepSeek 的 Responses API](https://api-docs.deepseek.com/api/create-response/)使用其 `deepseek-flash`，不支持 `service_tier`，`xhigh` 映射为 `high`，不声称其思考强度与 OpenAI 等同。共同消息、完整原文、候选列表、schema 和输出上限不变；DeepSeek 对不支持的 `service_tier` 和 `store` 不发送，schema 的 `strict` 不假定受支持，返回后两边用同一代码检查。模型与供应商是这次要比较的条件，运行时差异会限制结论；即使 DeepSeek 较好，也不能声称它解决了源头遗漏、错误归档或重复页面。

**费用**：六次生成在发送前一次性预留，按标准价和最贵时段，整个比较低于既有 $0.60 上限。GPT 的相同请求已经由 OpenAI 计为 12,275 输入 token；三个样本每次按最高 $1.25/百万输入和 $5/百万、8,000 输出预留。DeepSeek 使用[官方价格](https://api-docs.deepseek.com/quick_start/pricing/)最高每百万 $0.30 输入、$1.20 输出；[官方 tokenizer](https://api-docs.deepseek.com/quick_start/token_usage/)对完整消息和 schema 的估算为 14,120 token（压缩包 SHA-256 `e7310d1dafe0a86d8a5629fe78a7c763760f651db9b8682718a1781dcd6fe495`）。为服务端额外格式及分词误差，DeepSeek 每次预留 `2 × 14,120 + 8,000 = 36,240` 输入 token，再预留 8,000 输出 token；三个样本合计约 $0.06142。GPT 三个样本最多约 $0.16604；两组总预留约 $0.22746。DeepSeek tokenizer 是估算而非服务端保证；发送前检视请求字节和预算，发送后将每次实际 usage 与预留对照，超限或缺 usage 标异常。失败请求也按完整预留，不重试；超时 180 秒。预检必须先重放存档，模型和密钥存在但不显示密钥；健康检查用计数或只读请求，不发送试题。

| 状态 × 事件 | 动作 |

| 全部结束 | 校验六份结果，逐条读含义、理由和引用，分别报告每次八项标签、完整引文和成本；未完成单列。 |

数据引用和请求构建以现有 JSON 实际内容为准，不依赖规范化后重新排序的归档 JSON。参考的原始事实、历史页面、用户权重与此次比较明确分离。已经发生的 5/8、7/8、7/8 只是旧样本；本次并行的新 OpenAI 对照单独报告。此前方案的预登记验收已停止；Alex 新明确要求比较 DeepSeek，本次是独立小实验。

[独立只读复核](deepseek-judge-trial-independent-review-2026-10-29.txt)指出两处需明确：发送前把两个请求各自的 system 和 user 消息逐字节对比已存请求，schema 内容也按相同键顺序序列化后逐字节对比；任一不一致即拒绝发送。提供商必要的外围设置单独记录。每份回答的 API 状态和所有字段都由人检查：明确拒答或没有读完使样本无效；无法判断是否拒答或读完时样本待审，不计分。不能因为九个 ID 都在就自动计分。复核也纠正了 D139 的误引，之前保留 Luna 的决定为 D62。
