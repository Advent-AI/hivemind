# 归组：模型按名字选主线，代码绑编号（2026-10-25，D152 起由 Claude 负责）

> 历史实验记录。D156 已用[当前验收定义](../2026-10-25-grouping-acceptance.md)替代下文的推广通过线；原实验结果保留，不再用关键词、旧关系保留或 2/3 宣称归组方案通过。

## 问题的类和机制

Codex 三轮（D147、D148、D150）在同一前缀（Rubin 出货 → SK 工厂）加第三篇原文上留下 24 份抽取原答、33 个归属引用：
5 个引用错（PC 芯片 → Rubin 的 g1 两次、PC → SK 的 g2 一次、OpenAI → SK 的 g2 两次），1 处漏归（OpenAI 没进
Rubin）。逐份读原答：5 个错引用里 3 个旁边已经声明了正确的新主线（t1 = "Windows PC SoC rollout"），却在 thread_ids 里
填了旧编号；另有 2 份把已展示的 Rubin 又声明成新主线 t1。机制是输出形状：定义写在一个列表，引用写在另一个列表，模型要
自己把抽象编号对上；编号都合法，代码查不出。写一句依据（D150）没有改变这一点。

## 合同（subject-names-v1，只改抽取答案的归属部分）

每个候选观点带 `subjects`（至少一项）：
`{existing: <已展示主线的名字之一 | "none">, new_name, new_scope}`。existing 是 schema 的枚举（展示了什么名字就只能选什
么），选了已有主线时 new_name/new_scope 必须为空；existing 为 none 时必须给新名字和范围。模型不写任何编号，也没有单独的
定义列表。代码投影回 D147 的旧形状：已有名字 → g 编号；新名字按归一化（大小写、空白、连字符）去重后依次给 t 编号并生
成 threads 声明；新名字归一化后等于已展示名字的，按已有主线解析并计一次「重复声明」。投影后仍过
`retained.validate_extraction`、原 sift、原比对检查、原写入，一个字不改。

## 状态 × 事件（只列变化的行；其余同 D150 的表）

| 状态/事件 | 行为 |
|---|---|
| 抽取答案到达 | 先过新 schema（枚举、必填），再投影，再过旧校验；任一失败 → 该样本记 failed，不重发、不补样 |
| 两个候选声明同一个新名字 | 一个 t 编号，两条成员 |
| 新名字等于已展示名字 | 解析为已有编号，记 redeclared_existing，不建新主线 |
| 展示的名字互相重复（搜索返回同名两条） | 前置条件失败，拒绝该次抽取（本次前缀里两条名字不同） |
| 选了已有主线却又填了新名字 | 拒绝（形状错） |
| 前缀两篇 | 逐字重放 D147 sample-2 的原请求，不发网络调用（与 D150 同） |

## 新路径 × 旧检查

旧检查全部保留：引用非空、唯一、只指向展示或声明的主线；sift 的出处检查；比对检查；写入事务；重送跳过；历史不变。新增的
检查只有 schema 枚举和投影规则。没有新的模型调用，比对仍不读归属。
