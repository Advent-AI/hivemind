## 1. 要解决的问题（实测）

- 冻结版 v108 跑 14 天（三遍，`poc/data/e2e-r9-frozen-v108-2026-11-03`）：总收入那道题第 14 天下面挂了 143 条证据。那天判断给模型看了 97 条，另有 46 条没给看，读的材料约 50 KB；没给看的那部分每天都在增加。一道题一天最多新进 27 条。
- 旧的三个月长跑（D358）：一道题挂了 1,768 条证据，一次判断要读 698 条、292 KB，模型写错证据编号，代码拒收，一天停了两次，整条运行只好停下封存。那次已经用了"只看最近的证据"的办法（judging-v5，D198），一样压不住。
- 现在模型往下一次判断带的，只有上一次结论的几行理由（中位数约 640 字，给模型看的最多 800 字）。跑几个月后，绝大部分证据看不到，"为什么这么看"只剩几行字撑着。可能的后果是忘掉早先的关键事实，或者被一批重复报道带偏；这一点还没量过。
- 14 天里，档位真正移动的只占重判的 9%–10%，来回跳的几乎没有（三遍共 1 次）。短期内判断是稳的；要防的是长期。

## 2. 要不要定期跑一遍更新？不要

卡片只在这道题被判断时更新，而且就在那次判断里一起更新。没有定时任务，也没有每周压缩、重写这类步骤。理由：

- 判断本来就是事件触发的：一天里有新证据挂到这道题、它依赖的题或主题的结论变了，它才会在当天收盘那轮被判一次（D63）；没有新信息的日子不重判（D356）。卡片跟着判断走，就自然遵守这条。
- 进来的消息流从不看日历（D12、D13）；只跟时间有关的事归"拉取模式"管，而拉取模式只做到期关闭（D356）。定时重写会把"看日历"带进判断。
- 没有新信息时重写卡片，等于让模型把同样的材料再抽一遍签：只会带来噪音和成本，还可能凭空改了看法（"重复不是新证据"，AGENTS §8）。
- 卡片自己的大小由格式上限钉死（第 4 节），不需要压缩。

页面上的状态和卡片是两回事。手动关闭、重开、到期关闭、某个主题不再在用，会改变页面状态，但不重写卡片：卡片保留的是"当时为什么这样判断"。

## 3. 机制：卡片和档位在同一次判断里一起写

每次判断，模型读：

1. 这道题上一版卡片；
2. 上一次的结论：档位和理由，只用来比较、决定"变没变"（与现在相同，06-views）；
3. 卡片引用的证据原句（卡片的"根据"），每条带原始说话人、原始日期，以及匹配时记下的关系（"同一说法""较新的版本"），这些关系照旧标为"匹配器的意见，未经核实"（D201）；"同一说法"只列出这次也给看了的证据，其余只写"另有 N 条转载"，所以这份清单不会越拉越长；
4. 上次判断之后新挂进来的证据（"新到的"）；
5. 它依赖的题的当前结论、在用的主题（与现在相同）。代码在拼请求时记下每个依赖题、每个主题当时是哪一次判断，存进卡片的 `read` 栏：卡片引用依赖题或主题时，指的就是这一次。

模型写出：

1. 档位、市场预期、证据推出的结果、判断理由（`reasons`）、是否"变了"及原因：这几项和现在一样，读它们的地方不受影响；
2. 推动方向：每个主题的推动方向（`theme_pushes`）和现在一样；证据的推动方向（`pushes`）只写卡片引用的那些证据（最多 40 条），不再对每条给看的证据都写；
3. 新一版卡片（第 4 节）；
模型不逐条写"新到的证据怎么处理"。哪些新到证据进了卡片、哪些没进，由代码按卡片的引用记下来，和判断记录存在一起（不进卡片，不会被下一次带着走）。这样模型要写的东西只随卡片大小变，不随当天进来多少证据变：财报日一天可能新到两百多条（`simulation.md` 第 4 节），三个月那次停机，正是模型在几十个证据编号里写错一个被拒收。

由代码从卡片推出、不再让模型另写的：`cites`（卡片引用的全部证据编号）和 `cites_views`（卡片引用的全部依赖题编号）。这样两处不会说法不一，现有读这两栏的地方（页面、导出、评分）照常工作。

不再给模型看的：其余所有证据。它们一条不删，都留在库里，用户页面照样能看到；只是判断时不再整堆摆出来。现在"最近 5 次判断以来到的 + 最近 10 次判断引用过的"那个窗口（D198），在新版本里由"卡片的根据 + 新到的"取代。

## 4. 卡片的格式（代码强制，闭合集合）

| 栏目 | 内容 | 上限（初值，按存档数据校准） |
|---|---|---|
| 支持的理由 | 每条：编号（k1、k2…）、一句话、引用（证据编号 / 依赖题编号 / 主题编号）、其中哪些是同一篇报道的转载、独立来源算几个 | 最多 5 条；每条最多 300 字、最多 4 个引用 |
| 反方的理由 | 同上 | 最多 5 条；同上 |
| 会改变看法的事 | 下一条决定性信息是什么（例：Q3 财报的数据中心收入） | 最多 3 条，每条最多 200 字 |
| 还缺什么 | 没核实、没有数据的地方 | 最多 3 条，每条最多 200 字 |
| 删掉的理由 | 上一版有、这一版没有的理由编号，各附一句原因 | 上一版删多少条就写多少条（最多 10 条），每条原因最多 200 字 |

和判断记录存在一起（不进卡片，由代码写）：

| 栏目 | 内容 |
|---|---|
| 新到证据的使用记录 | 每条新到证据：进了卡片的哪几条理由，或没进卡片 |

**来源是否独立由模型判断，代码不替它下结论**：同一说法不等于同一来源，匹配器的关系只是意见（D201）。代码给模型看每条引用的原始说话人、原始日期和匹配器的意见（标明未经核实）；模型在卡片里写出哪些是同一篇报道的转载、独立来源算几个；代码只检查它写的编号都是给看过的。代码自己只认一种确定的重复：引文一字不差、出自同一篇原文（AGENTS §2：代码只管"是不是同一个"）。独立来源数只要求至少 1，不设上限：一条依赖题或主题的结论本身就可能概括了几份独立报道（代码审查 r1）。

**修订和替代分开**：

- 修订（D202 之后的写法）：新旧两条都留着、都算数，卡片两条都可以引，请求里照旧标出"它可能是 eX 的较新版本"。
- 替代（D202 之前的历史数据）：旧的那条已不在用，不会给模型看，自然也引不了。

代码检查（不通过就退回重写一次，再不通过当天停下，可以续跑，与现在相同）：

- 卡片的每个引用必须是这次给模型看过的：证据看"根据"和"新到的"两个区块，依赖题看依赖区块，主题看主题区块（闭合集合；识别方式按新的区块重写，不沿用现在只认一个证据区块的解析）；
- 条数和字数不超过上限（由代码检查，不靠回答格式：现在的格式检查不执行条数、字数上限）；
- "删掉的理由"里一个编号只能出现一次；
- 转载清单里一个编号只能出现一次，而且标成转载的引用必须留下至少一条它所转的那份（不能把唯一的引用标成转载）；
- 理由编号由代码分配，模型不写新编号：模型对每条理由只说"保留 kX"或"新的"；代码给新的理由发下一个从没用过的编号（这道题的编号只增不减，删掉的永不再用）。一个编号只代表一条理由：理由的意思变了，就删掉旧编号（写明原因）、作为"新的"重写；只改措辞可以保留编号。上一版的每个编号，要么保留，要么列在"删掉的理由"里：没有一条理由会悄悄消失。"意思变没变"由模型判断，代码不替它判断；但代码会把同一编号前后两版的文字差别存下、在页面上显示，读卡片的人一眼看得出有没有偷换；
- 推动方向只能写卡片引用的证据，每条最多一次；
- 理由里说"这几条是同一篇报道的转载"时，写的编号必须都在这条理由的引用里；
- 现在已有的检查照旧：档位在范围内，市场预期和推出结果不能空，档位动了就得说"变了"，主题方向只能写给看过的主题。

由代码算、只用来显示的：两版卡片之间改了什么（逐条比对），供页面显示"这次改了哪里"。

## 5. 存在哪里、怎么写、谁读

写入：

- 新表 `arguments`：每次判断写一行（题号、对应的判断编号、序号、卡片内容、写它的提示词版本），同一题同一序号最多一行（和现在判断表的唯一约束一样）；只增不改，历次版本就是它的历史。
- 代码把每条新到证据的使用记录写进判断记录的新栏目。
- 判断记录、卡片、使用记录由**同一个写入函数在一次事务里写**：任何一步出错，先整体回滚，再记失败。现在出错时的失败记录会直接提交，所以必须先回滚，否则会留下"有判断没卡片"的半截数据，续跑时又因为这一轮已判过而被跳过。

读它的地方（全部要改到）：

| 读的地方 | 读什么 |
|---|---|
| 判断（`judging.build_prompt`） | 上一版卡片、它引用的证据 |
| 查某一天的状态（`service.state_as_of`）、历史（`service.history`）、变化列表 | 那一次判断对应的那一版卡片，不能拿最新的去解释过去 |
| 资料库导出（`bundle`）、给智能代理的接口 | 当前卡片和历史 |
| 前端转换和页面格式（`poc/ui/src/adapters/bundle.js`、`thesis.schema.json`） | 新增的卡片字段；现在的转换会丢掉新字段，格式检查会拒收未声明的字段，所以要一起改 |
| 到期关闭（`pull.py`） | 关闭记录写明最后一版卡片的编号；从没判断过的题没有卡片，照旧写"没有数据可核对" |
| 预检（`scripts/preflight.py`） | 格式检查（A 项）改为用存下的请求里自带的那份格式去核对每条回答，所以 v7 的回答按 v7 核、v8 的按 v8 核，冻结的 v7 格式不动。另新增一项：把存档里被采用的判断回答过一遍判断的检查（现在的预检没有这一项）。检查按那次请求当时的状态做：可引用的编号从存下的请求原文里读，上一次结论和上一版卡片取那次判断序号之前的，不能拿库里最新的（否则一份当时正确的"维持原档"会被后来的档位判成违规）。被拒收或写入回滚的那些回答，存档里没有记下它属于哪一轮，就报"无法核验"并计数，不猜 |
| 旧库读取（`store.open_read_only` 打开的历史库） | 没有 `arguments` 表时一律当作"没有卡片"，读的时候不建表 |
| 条件事件扫描（`poc/agent/conditions.py`） | 直接读判断和引用；旧栏目都保留，预计不受影响，实现时核对 |
| 研究工具的展开读取（`research_context.Reader.expand`） | 现在返回整行判断记录，且有大小上限；新加的"新到证据的使用记录"那一栏不放进它的返回，返回内容和现在一样 |

不受影响：抽取、开题与匹配；冻结的尺子和评分程序（它读判断表的题号、日期、档位，这些都保留）。卡片本身不在尺子量的范围里，所以要另请一个没写它的人来读卡片的质量（AGENTS §7.2）。

## 6. 每种情况下怎么走（状态 × 事件）

| 情况 | 做什么 | 写什么 |
|---|---|---|
| 题刚开，还没有证据（包括第一天的种子题） | 不判断（D59），没有卡片 | 无 |
| 题当天开、当天有证据 | 当天收盘那轮第一次判断，读它已挂的全部证据（新题最多一天的量），写第 1 版卡片 | 判断 + 卡片 v1 + 使用记录，同一事务 |
| 已有 v7 判断、还没有卡片的题（换版本后的第一次） | 从最近 10 次判断引用过的证据（新的在前，最多 40 条）、最后一次的理由，加上新到的证据起步，写第 1 版卡片；和以后每一版一样有上限（原来设计成读 v7 那天要读的全部，旧版第 59 天这个量是 589 条，会重演停机，见 `simulation.md` 第 4 节） |
| 这一次什么证据都不会给看（之前的判断都没引用过证据，最近也没有新到的） | 改为给看这道题最近挂进来的 40 条在用证据，并在请求里写明原因；保证每次请求都有理由可以引用的东西，不会因为无论怎么答都被拒收而停机（代码审查 r1） | 判断 + 卡片 + 使用记录 | 同上 |
| 某天有新证据挂进来 | 当天判一次，读上一版卡片 + 根据 + 新到的 | 判断 + 新一版卡片 + 使用记录 |
| 某天没有新证据 | 不判断（D356），卡片不变 | 无 |
| 依赖的题或主题结论变了 | 照现在的规矩排进当天这轮（新到的可能为空），卡片可引用依赖题、主题的结论，指向代码记下的那一次判断 | 同上 |
| 等着的依赖题终于建起来（D168 那种"等下一年的题"） | 照现在的规矩，依赖它的题当天排进这轮重判（新到的为空，新建的依赖题可能还没判过，请求里照现在写"还没判"） | 同上 |
| 两道题互相依赖（成环） | 与现在相同：代码按给定顺序先判其中一道；每张卡片引用的是它当时读到的那一版依赖结论（代码记下对应的判断编号）；续跑时已判过的不再判 | 同上 |
| 证据被修订（D202） | 新版本算"新到的"；新旧两条都留着、都可引用；请求标出两者关系（匹配器意见，未经核实） | 同上 |
| 历史数据里被替代的证据 | 已不在用，不给看，引不了 | 无 |
| 回答被代码退回 | 带着原因重写一次；再被退回，当天停下，可以续跑（与现在相同） | 什么都不写 |
| 写入出错或跑到一半崩溃 | 整个事务回滚后再记失败；续跑时这道题这一轮重新判 | 不会留下半截记录 |
| 手动关闭 / 重开 | 卡片不动；重开后下一次判断读最后一版卡片 | 无 |
| 关闭期间仍有修订挂进来，后来重开 | 修订照现在的规矩会挂到已关闭的题上，只是不安排判断。重开后第一次判断，"新到的"是上次判断以来攒下的全部（可能好几天）；从没判断过就关闭的题，重开后第一张卡片读它已挂的全部证据。这和 v7 在同样情况下读的量相同 | 判断 + 卡片 + 使用记录 |
| 到期日（D356） | 关闭；最后一版卡片就是结论的"为什么"；从没判断过的题没有卡片 | 关闭记录 |
| 下一期的接续题（D168） | 从空卡片开始，不继承上一期的卡片（不做特殊处理）；上一期的结论若是它的依赖，照常读到 | 无 |
| 当天跑到一半换了配置 | 并行跑法会被当天的清单拒绝；串行跑法（`--workers 1`）现在不拦。运行规矩：换版本只在两天之间做；每条判断和卡片都记着写它的版本，事后查得出。本设计不新增拦截 | 无 |
| 第二个程序同时写同一个库 | 运行规矩是一个库只有一个写入者；万一发生，同题同序号的唯一约束会拒绝第二条 | 无重复 |
| 判断换了新版本 | 卡片记着写它的版本；新版本第一次判这道题时，把旧卡片当作上一版读进来；卡片格式要变，就是新版本的决定 | 新版本的卡片 |

时间全部用程序自己的序号，不读墙上时钟（AGENTS §3）。

## 7. 大小：哪些不再涨，哪些还会涨

能承诺的：

- 卡片自己有上限：最多 10 条理由、每条最多 4 个引用，根据最多 40 条（现在每次判断引用的中位数是 7.5–8 条，最多 48 条）；其余栏目也都有条数和字数上限；
- 随题开得越久而越堆越多的老证据，从第 2 版卡片起不再摆给模型看；
- "同一说法"的关联清单只列这次给看了的证据，其余只写数目，不再随转载增多而变长（现在是全部列出，第 3 节）。

不能承诺的：整个请求的大小没有硬上限。下面这些仍会变：

- 新到的：通常是一天的进量，样本里一道题一天最多 27 条；这不是系统上限，财报日可能更多；关掉又重开的题，会是关闭期间攒下的量（第 6 节）；
- 依赖的题和在用的主题：每个公司问题都会看到所有在用的主题（D195），数量随库变大，与这次设计无关，也不在这次设计里处理；

模拟（`simulation.md`，按卡片记满 40 条估算）：v108 总收入那道题，第 14 天实际 50,396 字，换成卡片约 35,000 字，卡片记满后稳定在 33,000–36,000 字；14 天里全部判断的总读量反而多约 10%（卡片本身占地方，老证据还没堆起来）。旧版数据中心那道题，实际平时 106,000–223,000 字，换成卡片 41,000–62,000 字；财报日（2026-08-26，一天新到 255 条）实际 260,503 字，换成卡片 175,478 字；59 天总读量是原来的 70%。旧版的在用主题从 7 月 2 日的 1 个涨到 8 月底的 23 个。模拟只说明材料多大，不说明卡片写得好不好。

所以准确的说法是：读的材料不再随一道题开得越久而变大；它随新到的量和库的规模变化。三个月那次停机，来自老证据越堆越多（一次给看 698 条），这正是要去掉的部分；但不能保证以后任何一天都不会因为材料太大而停机。如果真发生，那是新到的量或主题数量带来的新情况，要另行追查原因，不在这次设计里预先加规则。第 10 节第 1 步先用存档估算，第 4 步用 60 天的运行实测。

## 12. 需要 Alex 决定的

1. **卡片由谁写。**
   - A（倾向）：判断在同一次调用里写卡片和档位，像分析师更新卡片就是给出看法本身；调用次数不变。
   - B：先单独调一次模型写卡片，判断再读它。两件事分开，但调用翻倍，判断还要多等一步，两次调用也可能说法不一。
2. **新证据给几次被看到的机会。**现在一条新证据在之后约 5 次判断里都看得到；卡片做法里通常只有进来那一次，那次没写进卡片，以后就再也看不到（`simulation.md` 第 4 节）。
   - 替代（只看一次）：读量最小（59 天是原来的 70%，最大一次 175,478 字），但第一次漏选就可能永久遗漏。
   - 折中（新证据在之后 3 次判断里都还看得到）（倾向）：多给两次机会，读量多一些（59 天是原来的 84%，最大一次 254,309 字），仍不随题开得越久而变大。
   - 叠加（卡片加上现在的窗口）：最保守，但老证据那部分还会涨，等于没解决问题。
3. **是否按第 10 节的顺序开始验证。**第 1 步不花钱，我可以先做；第 2–4 步每一步等你开口。
