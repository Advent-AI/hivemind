# Vera 单例实跑：先比较能否保住信息并避免多开卡

Alex 要求实际走一个 case。这是一个开发案例的诊断，不是验收或新金标。

固定输入：D341 保存的 v50 trace，源文 gnews:caf5e64df9edf2e567ad2813，写入前 seq 1085。只从已通过抽取的 e1 开始；e2 的引用拒收仍是上游缺陷。来源段落没有重新抽取。上下文固定为旧请求展示的 42 张问题卡及 10 条旧证据，不声称验证召回。

旧路：逐字重发 4391、4392、4393；用旧匹配代码及实际检查/写入代码在历史副本执行。新路：Jev 先判断来源与旧问题的关系、来源与旧证据的关系；Luna 再读原文、旧内容和比较结果，决定更新现有问题、另开问题、背景或无法判断。Jev 分数只是提供给下一步的意见，不直接执行删除或合并。

每路三次，不投票，不挑选。共最多 15 次单次 HTTP 请求；独立保守预算 $0.50，不重试，不增加前次预算。任一网络/用量异常停止。每份原请求、原回答、检查结果、写入结果均保存。研究继续使用既有 Jev 1.14.0 / gpt-6-luna low。

先看三个具体问题：是否仍多开 Vera 收入卡；新测试的内部估算、AMD Venice、四种 agentic 工作负载等限定是否保留在当前可读证据；是否把性能线索说成已实现收入或外部验证。后两项人工逐条读，不把字符串匹配当语义正确率。

## 状态和读写

| 状态/事件 | 行为 |
|---|---|
| 调用前 | 校验保存输入、跑 preflight、固定请求；源库只读 |
| 成功 | 保存原答，校验 JSON/引用，走实际 writer 的新副本 |
| 拒答/格式失败 | 记录本次失败，不修补答案，不重试 |
| 网络/崩溃/未知花费 | 保留预算占用，停止后续请求；不得自动重启 |
| 新问题/无法判断 | 保存提案，标记这条新设计尚未闭合；不伪造已入库 |
| 后续日期/改输入 | 本研究不持续写入；需另一个明确版本 |

| 值 | 来源 → 读者 | 约束 |
|---|---|---|
| 来源 e1 | 保存 handover → Jev / Luna / writer | 来源原字段不由整理模型重写 |
| 旧问题与证据 | 原请求 → Jev / Luna | 同一固定集合，无未来记录 |
| 比较分数 | Jev → Luna | 不能自行触发信息丢弃 |
| 动作/理由 | Luna → 校验 → writer 副本 | 所有目标 ID 属于展示集合；新问题先标未完成 |
| 新写入 | 实际 writer → 读取现行证据 | 保留原文及来源，报告多目标重复/替换行为 |

原路径检查：Jev.validate、model.check_schema、matching.check、writing.write 都实际执行；新路未实现候选新卡完整合同，因此若提出新卡只记未完成。没有通过的虚构默认值。

决策约束：D339 不证明路由精准；D340 没采用新入库合同；D341 指出题目不同不等于值得新建，以及证据合并会丢失限定。本研究不改变 D62、冻结产品合同和默认模型。
