# 入库关联的交接修正

状态：D143 固定实验已完成，自动归组 1/3，验收失败；不采用为正式流水线。见 [结果](findings.md)。

核心修正：读全文的抽取负责说明哪些不同问题共同回答一个更大的业务问题。比对只决定这些问题的真实编号。写入保存这个共同问题和成员，不再让比对重新决定它们有没有关系。

例如：“Rubin 能否从产品交付进入客户实际部署？”下面可以有“2026 下半年能否出货”和“SK 工厂能否在 2027 年上线”两条独立观点。它们各有自己的期限、证据和结论。同组不代表其中一条的结论必然导致另一条，也不把两条的证据抄到一起。

## 哪部分 PRD 改什么

- 05 抽取：在原有证据、候选观点之外，一次交出共同业务问题、成员、原文依据和关联理由。展示范围仍由现有对象及观点取得路径决定；已有组只随实际展示的观点提供。新增字段由代码定义。
- 06 观点库：在候选身份确定后，解析关联的成员编号；同一次事务写入组、成员、依据和逐项处理结果。比对不再生成另一套成员决定。组不是带梯子的新观点。
- 00 总览只指向这两处。Config、分类、分发、研究对象、状态判断、Pull、最终判定、人工复核池不改行为。MCP 和 UI 不在本次实验内。

## 旧决策和边界

D33：抽取只读，观点库负责比对和写入，保留。D39/D44 的同一观点身份规则不改。D51 原定“新观点的依赖在比对那一次一起挑”，保留；组成员不是依赖。D58 冻结由本次 D143 授权的研究补充修正，不把实验视作已经上线。D133：新输出英文，不重建中文封存库。D139–D142：只做隔离实验，不引入主论点打分、摘要、递归层级、全库聚类或额外模型调用。

## 完整合同

完整规则只写在 [06 观点库的 D143 实验补充](../../prd/06-views.md#d143-实验补充研究组的关联交接)，抽取的责任写在 [05 抽取](../../prd/05-extraction.md#d143-实验补充读全文时保留关联)。下表将这份规则展开为状态、数据读写和验收；模型字段由实验代码的封闭 schema 检查。

## 状态 × 事件

所有行以分发的顺序号排列；原文日期仍是证据日期，接收日期不代替原文日期。没有模型调用读取系统时钟来决定先后。

| 进入状态 / 事件 | 转移与写入 |
|---|---|
| 空库 / 第一篇文章 | 先建实际观点。没有两条独立观点的共同问题则不建组；有则同事务建组和成员。 |
| 有独立观点 / 后续出现相关问题 | 抽取列出新旧成员和共同问题；比对保留不同身份；同事务建组，旧观点也加入。 |
| 已有组 / 新成员或新的关联依据 | 抽取引用展示的组编号；只新增成员和关联来历，组编号和问题保持。 |
| 已有组 / 只有已有观点的新证据 | 不要求模型重写成员。按真实 changed_views 找受影响组。 |
| 已有组 / 重复原话或重复成员 | 保存应保存的出处；没有新成员或 changed_views 就不标组改变。 |
| 临时候选 / 归入、接续、新建、不开 | 分别换成旧编号、新编号、新编号、记录该关联未写入；不会留临时候选编号。 |
| 依据或候选被原检查去掉 | 原有效部分照常入库；每项受影响关联记录未写入原因，不当作成功。 |
| 未知引用 / 越过展示范围 / 模型拒绝 | 本条失败，原答保留；没有半条组写入，不修答案重采样。 |
| 写入中 / 外部失败或崩溃 | 原观点和组写入一起回滚。重放已存回答，不重发已开始的付费请求。 |
| 已完成 / 同 input_id 再到 | 原分发跳过，零调用，零新记录。 |
| 后续日期 / 晚到旧原文 | 原证据替代顺序不变；关联由本次顺序号记录，不倒写历史。 |
| 两范围或两个写者 / 同时执行 | 实验一个写者、一个独占目录，六个独立库依次执行。跨写者正式调度仍按原设计，本次不验证。 |
| 配置或输入改动 / 重启 | 指纹不符拒绝复用实验目录；成功条目跳过。 |
| 实验终态 | 保存每步图和逐项结果，明确成功、失败及未执行；不发布或改封存库。 |

## 值 × 写者 × 读者

| 值 / 写者 | 全部新增读者；检查 |
|---|---|
| associations / 抽取模型 | 引用检查、身份解析器；白名单形状、已展示编号、本次依据。比对不消费、不覆盖该决定。 |
| group_id / 组写入器 | 后续抽取上下文、组详情、受影响组计算；持久编号只由数据库生成。 |
| member_ids / 身份解析器 | 成员表、组详情；复用原 matching.Checked 与 Written 映射，新组至少两个不同最终编号。 |
| 原始证据编号 → 合并后编号 → 持久 evidence_ids / 出处检查和原证据写入器 | 关联依据表、组详情；必须是本条被接受并实际存下的证据。 |
| 逐项结果 / 组写入器 | 实验报告；每项恰好一个 written 或 skipped 和原因。 |
| affected_groups / 组写入器 | 本次处理记录和实验报告；只由实际新增成员及 changed_views 计算。没有新摘要任务。 |

## 新路径 × 原检查

原句出处、梯子、日期、对象名单、候选身份、证据重复/替代、依赖防环、主题先写、事务、分发去重都继续经过原函数。新关联不能让任何原拒绝对象重新写入。它不参与依赖图，也不触发依赖传播。新增实验关系表带外键；真实证据映射先从原始编号解析到出处检查合并后的编号，再取原写入结果的持久编号。相同原句被合并不等于依据被拒绝；测试覆盖关联引用被合并掉的编号。

## 先免费证明，再付费

免费证明用上轮三份真实 SK 原答与实际身份结果，把抽取已写出的共同问题保存成组：三个共同组均应包含出货与部署两个不同观点。既有提示中的窄组不沿用，因为该错误机制正是本轮替换对象。另用真实文章及临时库验证回滚、重复、ID 归入、依据被删、未知引用，并做删除成员写入和提前 commit 的突变。

付费比较：仍用三篇全文、三份独立样本、空库。控制是上轮的“抽取提示 + 比对重新分组”；新臂是本合同，其他抽取和身份检查相同。两臂各三次，不修失败样本。沿用 gpt-6-luna、原抽取与比对配置、最多 48 次调用及 $8 估算总额。新目录运行，封存库不改。先运行 scripts/preflight.py 和新增合同的存档重放。没有独立聚类或摘要调用。

固定核心验收：第二篇后，出货和 SK 部署是两个不同观点且同属一个有明确共同问题的组，三份新臂都成立；不能仅留一条关联而不形成组。第三篇若原句证据成功入库，必须沿成员关系指向该组，且组编号不变；若证据未被抽取或被原出处检查拒绝，单独报失败，不能宣称全链路通过。最后重送零调用。逐组人工核查有无无关财务成员；报告所有六个流、请求数、成本和完整请求 token。三份样本只证明这三篇，不证明跨行业或大规模稳定性。

## 运行前证明

两轮只读设计审查：第一轮发现原出处检查合并重复原句后，临时证据编号可能丢失；已把原始编号 → 合并后编号 → 持久编号加进读写表及测试。第二轮无严重问题。

三份旧原答用新合同适配后经过真实分发、出处检查、比对检查和写入器，3/3 成为实际共同组；这是代码证明，不是假装新模型样本。删除成员写入、提前提交事务、丢失证据别名三个突变都在预期断言失败。完整 73 项测试通过。第一个测试运行曾把原分发的 skipped 误写成 skip，读回函数后修正了测试；未改产品行为。

原 preflight 与上一轮逐项计数相同：1,142 份抽取原答，3,296 个抽取对象中 714 个原有拒绝；618 个比对记录中 22 个原有拒绝；32 项提示词枚举检查无缺失。它没有覆盖新关联合同，新合同由上面的存档适配和真实临时库检查覆盖。

提示词实测（o200k_base）：抽取从 1,831 字符 / 334 token 变为 2,272 / 419；比对从 1,971 / 363 变为 1,210 / 221。抽取增长的原因是将共享问题与依据的决定移到此处；比对删掉重新分组，合计减少 320 字符 / 57 token。不声称这是完整请求或费用的节省，完整请求随实际观点和证据变化。
