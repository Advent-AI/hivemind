# 关联交接修正：未通过自动归组验收

结论：代码能保存抽取给出的关系，但这版抽取合同仍不能稳定给出关系，不能采用为正式自动归组方案。

例子：三次新实验都读到了已有的 Rubin 出货观点，也都从 SK 公告开出了工厂部署观点。两次原答的 `associations` 是空数组。第三次才把两条放进共同组。后面的延期风险三次都存下并连回出货观点，但前两次没有 Rubin 组可更新。

## 实际改了哪里

[05 抽取](../../prd/05-extraction.md#d143-实验补充读全文时保留关联) 增加实验责任：读全文时交出共同问题、成员、依据及理由。[06 观点库](../../prd/06-views.md#d143-实验补充研究组的关联交接) 增加实验写入合同：比对只解决观点身份，写入器把关系解析到真实编号并保存，不再由比对重新决定组成员。设计页显示同一份规则，00 总览只补引用和用词。

这版仍明确标为实验，未改正式抽取、比对、写入、状态判断、MCP 或 UI。原封存库未变。

## 先做的免费证明

把上轮三份真实原答里已经写出的关系适配为新字段，经过真实分发、出处检查、比对检查和写入器，三份都形成了实际共同组。不同观点没有合成一条。这证明写入交接能工作，不能证明模型会稳定提供这些字段。

设计审查发现重复原句会使临时证据编号合并，已实现原始编号 → 保留编号 → 持久编号的解析。真实临时库检查覆盖引用、回滚、重复成员、归入后不足两个成员、重复文章。完整 73 项测试通过；删除成员写入、提前提交、丢失证据别名三个突变都被断言抓到。第一次测试把原分发的 `skipped` 拼成 `skip`；读回函数后修正测试，没有改产品行为。

免费产物：[三个存档模拟及突变记录](../../../poc/reports/2026-10-24-relation-handoff-free-01/summary.json)。它们是适配旧原答后的代码验证，不是新模型样本，也不声称请求逐字相同。

## 新鲜模型实验

同三篇全文、同 gpt-6-luna 和配置，三份配对空库。控制是上轮“抽取提示 + 比对归组”，新臂是“抽取直接决定关联 + 代码保留”。所有六个流都完成三篇，全部重送均被原分发跳过，零新调用。

| 流 | 第二篇后出货与部署同组 | 后续风险存下并连回出货 | 风险到达共同组 |
|---|---|---|---|
| 控制 1 | 是 | 否：原句检查拒绝 | 否 |
| 新臂 1 | 否：抽取没写关系 | 是 | 否：没有 Rubin 共同组 |
| 控制 2 | 否 | 否：原句检查拒绝 | 否 |
| 新臂 2 | 否：抽取没写关系 | 是 | 否：没有 Rubin 共同组 |
| 控制 3 | 否 | 是 | 否：没有共同组 |
| 新臂 3 | 是 | 是 | 是，组编号不变 |

固定要求是新臂三份都完成自动归组，实际只有 1/3，验收失败。控制这次也是 1/3，上次控制为 0/3；小样本波动已经明显，不能把一个成功例子叫稳定提升。成功那份共同问题仍接近把两个问题连成一句，还不是已经验证的高质量主论点。

第一篇后的观点数也不稳定：控制三份为 3、4、2，新臂为 7、3、7。因此这次不能单独量化组织字段对底层抽取质量的影响，更不能把一个样本的结果叫普遍提升。

实际 36 次请求，两臂各 18 次；合计估算 $0.561000。控制 $0.288395，新臂 $0.272605。控制输入 108,787 token、输出 15,241；新臂输入 111,148、输出 13,367。没有额外聚类或摘要调用，没有失败重采样。价格是仓库单价估算，不是供应商账单。

产物：[全部原答、输入与逐条图](../../../poc/reports/2026-10-24-relation-handoff-01/summary.json)、[固定原句追踪及计数](../../../poc/reports/2026-10-24-relation-handoff-01/measurements.json)。定位按 e7/e55/e724 在原始三篇文章里的字符区间，与实际保存的原句区间相交后，再沿 evidence_links 和组成员追踪；不是按观点标题猜。所有目的观点及引用原句也已逐项阅读。

## 问题在哪里

确定的机制：新臂 1、2 的 SK 原答都是 `associations: []`，而 `existing_theses` 明确含 Rubin 出货观点，新的部署候选与原文依据也都有效。因此不是搜索没给旧观点，不是出处检查删了关系，不是比对重新拆组，也不是写入丢了编号。空输出直接成为无组的有效结果。

请求审查发现，这版让抽取一步承担了“找到有关的业务对象”和“写出带依据的完整共同问题”两件事，还要求原文提供连接两个结果的理由。分组所需的同一产品关联，和结果之间的论证关系容易被混为一谈。这是对空输出原因的解释，尚未用独立对照证明，不能声称只改某一句提示词就能解决。

控制 1、2 的风险原答有内容，但少了原文逗号前的一个空格，原检查据此拒绝；没有为分组任务修改这个正式检查。新臂风险三份都成功，但样本太少，不能声称抽取质量提高。

测量脚本最初把“共同组被任意证据改变”误叫作“风险使组改变”，在六个流里会误报控制 1。现已分开两个值：共同组是否改变、已确认风险是否沿出货观点到达该组；这一个假阳性已修正，不重跑模型。

## 下一步只做什么

保留已验证的身份解析和同事务保存思路；不采用这版自动归组合同。下一项需要先重新定义抽取里最小的关联：例如先明确两条观点讲的是同一产品或计划，而不是要求每篇文章当场写成一个完整共同论点。共同论点怎样由这些关系形成，仍需单独确定，不能靠放宽检查或再加一轮全库分组掩盖。

本次固定验收失败后停止，没有续跑新提示词，没有替换失败样本。需要先讨论上述合同边界，再开始下一轮。
