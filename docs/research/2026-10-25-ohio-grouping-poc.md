原文及业务要求沿用 [Ohio 案例卡](../../poc/reports/2026-10-25-grouping-acceptance-01/ohio-case.md)。两篇全文来自 `poc/data/items-window-tags2-2026-10-24.sqlite`，顺序固定：

2. `gnews:bb0d23846735c94b7c1722d2`，T8，保存的发布日 2026-07-27。

不把正文日期重写进上游日期，不用摘要替换全文。两篇是开发材料，不称留出样本。业务标注由助手据全文整理，Alex 已同意继续此例，不称人工金标准。

起点：每次运行一个空观点库。归组版本另有两个参考组，名称和范围逐字取自 D147 `sample-2-retained/item2-result.json` 的 g1（Rubin 产品落地）和 g2（SK 韩国工厂），以 seq=0 的参考记录保存，不伪造任何成员或证据。它们不是预先给出的正确答案，Ohio 组必须自己建立。所有组都展示，故本次不测大库检索。

## 2. 版本及唯一流程差异

两版都用 `poc-v16`、中文 `role-v5`、相同研究对象名单、相同模型和原有出处、身份、证据、写入检查。旧实验英文 prompt 和名字投影不复用。相同名字不是相同组的凭证。

| 版本 | 抽取所见及所写 | 后续步骤 |
|---|---|---|
| control | 当前 `build_prompt` 和 keyed schema；按对象及依赖找已有观点 | 当前比对、检查和 writer |
| grouped | 同样的请求，加已存组及其成员问题；成员也列入可连证据的已有观点。候选带 `thread_ids`，新组在 `threads` 声明 | 比对只管观点/证据；原 writer 决定最终观点后，已有隔离组 writer 保存对应成员；下一篇读取刚提交结果 |

这比较的是完整的小段交接，不是单独证明编号比名字好。给下一篇看组的成员，是 D149 连续阅读的一部分。第一篇从空库走起，不借用缓存前缀。归组不增加模型调用；不得在比对阶段再让模型决定归属。

新增中文段只说明当前请求缺少的业务组织任务：持续的产品、项目或政策过程可以容纳不同问题；公司相同不够；复用已展示组，或声明新组；同组不等于同一问题、因果或依赖；只更新证据时无需新候选。没有 Ohio 专用提示。当前 prompt 已要求直接证据链接，组成员提供合法链接目标，不允许用组编号替代观点编号。

完整请求（system、user、schema）在调用前落盘。记录原版和归组版的字符数及本地 tokenizer 估算；新增任务必有增长，增长原因是原 schema 不具备表达归属的字段，不是对已存在指令再加质量口号。

## 3. 接受合同和读写表

schema 沿用当前 keyed schema，仅增加：新组 `id` 全匹配 `t[1-9][0-9]*`、非空 name/scope；候选 `thread_ids` 是不重复的非空数组，每项必须是已展示存储编号或本答新声明编号。新声明编号唯一。证据仍只链接展示的观点或本答候选。只保存最后确实成为观点的候选用到的新组。不开、不合法或被出处检查丢弃的候选不留空壳组。编号原样交接，不按名称合并。

| 值、来源与写者 | 所有读者及约束 |
|---|---|
| 组声明和引用：原答 → 新隔离运行器校验 | `sift` 保留候选字段；比对请求构造器不呈现归属；组 writer 用原引用和最后观点映射，审查器逐项核对 |
| 最终观点映射：现有 matching / writing | 原有证据、依赖、键写入；组 writer 只能连已经保存的观点；同批复用保留各引用 |
| 组、成员：已有隔离 `write_threads` | 下一篇抽取、`thread_detail(seq)`、最终逐项审查；不进入默认 API/重判，不生成依赖 |
| 证据和出处：现有 writer | 通过真实成员及 evidence_links 读取；重复保留出处，新的第三方判断不是重复消息 |
| 请求/原答/检查/结果：隔离运行器 | 本次审查和重放；完整性不等于语义正确；无候选不是自动失败或通过 |
| 预算：单进程调用封装 | 每次网络请求前持久化保留额；成功按 usage 估算结算；未知结果仍扣保留额 |

| 状态 × 事件 | 动作、保存和时间 |
|---|---|
| 开始前 | 新目录、冻结源码及输入摘要、配置；旧目录不覆盖；用原发布日、分发顺序号 |
| 未处理 / 已完成的相同输入 | 原 `dispatch.route` 分配序号 / 跳过；跳过不调用模型 |
| 读到第一篇 / 下一篇或后来日期 | 只读本库已提交记录；第二篇完整读取第一篇结果；不用墙钟作业务顺序 |
| 模型已返回 | 先归档原答；schema、引用及原 `sift`；丢弃原因逐项保存，不隐藏 |
| 比对拒绝 / 拒绝后的再提交 | 隔离试验在第一次拒绝停止该序列，不自动修答；与产品默认一次重试的差异明确记录，不把它报成产品最终失败率 |
| 写入中异常 / 进程中断 | 观点、证据、组、成员及完成标记同一事务；异常回滚；不自动重发不明结果的网络请求 |
| 已写完 | 从保存库读取并验证最终成员、证据及历史；第一篇历史在第二篇后不变；完成输入重送应跳过 |
| HTTP 失败、未知响应、预算不足 | 留失败记录；停止整个运行，不隐藏样本或提高预算；恢复需要新决定，不自动续跑 |
| 两个启动、另一写者 | 文件锁只准一个运行器；各样本独立数据库；本次不研究生产并发 |
| 配置/源码/输入变化或等待时输入被改 | 每个样本开始及结束核对摘要，不一致拒绝；本轮不解释新旧混杂结果 |
| 终态再次运行 | 完成/失败目录都拒绝重跑；原结果只读审查 |

| 新路径 | 仍经过的旧检查 |
|---|---|
| 带归属的 keyed 候选 | keyed schema、梯子、年度/到期、出处、链接、对象名单、身份、依赖环、同批复用 |
| 组内展示的跨对象观点 | 来自真实 view 记录；作为 shown_views 进入 prompt、出处检查和比对；不得凭组名称合并观点 |
| 没有候选，仅已有观点证据 | 原 evidence matching 与 writer；通过旧成员读取新证据，不能用零新成员否定它 |
| 未展示组/错误新编号/空声明 | 付费写入前明确拒绝；不自动修引用或按名称猜测 |

先前决定：D149「比对仍只判断观点和证据身份、依赖」；D155「先验证同次抽取的归属交接，再接入按分发顺序读写的新路径」；D156「三次样本不推断总体可靠率」。本次按此运行隔离 POC，不冻结新表示，不改变正式产品合同。

## 4. 六次运行与业务判断

顺序 control-1、grouped-1、control-2、grouped-2、control-3、grouped-3。每次两篇完整流，独立 archive，第一篇和第二篇都新调用。样本中途模型或技术拒绝记录为失败，不再调参补样本。语义统一在整轮固定样本结束后审查；严重错误使此配置不获推广，不设计下一轮臂。

每个样本分别核对，均附原答、拒绝原因、库内编号和来源：

| 编号 | 必须保留的含义 / 判据 |
|---|---|
| O1 | 第一篇留下 Ohio/OpenAI 项目融资研究；谈判或计划不能变成签署/支付/已建成 |
| O2 | 2500 亿担保不含芯片；最高 3500 亿芯片采购融资、预计超过 5000 亿项目总成本不得混成一个量。重要口径由证据保留即可，不要求三条数字观点 |
| O3 | 第二篇至少保留 Goldberg 对供应商融资风险的实质判断，保留作者与第三方性质，且能从第一篇的同一项目研究查到；仅保存金额转述不合格 |
| O4 | 第二篇的同一 WSJ 担保消息是新增出处，不是独立确认；检查最终 evidence/source 记录，不凭 prompt 写了规则算通过 |
| O5 | 归组版本的相关观点在同一持续项目下；所保留的第一篇重要问题与后续材料不得散落在互不相连的新组；组名、可选次级组数量不评分 |
| O6 | 不把该 Ohio 项目挂入 SK 专属或 Rubin 产品组；其他公司背景若另有研究，不强迫全篇同组 |

control 的 O5/O6 为未提供能力，不拿零组算通过；其余内容与证据要求相同。除了六项，还逐条列出观点的错误合并/重复、其它重要遗漏、多造问题及检查丢弃。助手按全文审查、非关键词打分，不生成一个掩盖失误的总分。

调用上限 30，保留额加实际估算总额上限 $1.50；每个请求按 UTF-8 请求字节数作为保守输入 token 数，加配置输出上限计价。每次只作一个 HTTP attempt，无隐藏重试。最长每请求 180 秒，整轮预计 4–15 分钟（估计，实际另报）；硬截止启动后 30 分钟，不在截止后启动新请求。一个归组序列与对照相同，通常 4–5 次调用，schema 增长须量出。价格沿用当前代码估算，不称账单实付。

调用前跑 `scripts/preflight.py` 并与 D155 保存结果逐项比；新字段的检查用已存真实非空回答和受控反例先过免费验证。小实验的测试覆盖：当前中文请求/键、空库新组、跨对象后续证据、拒绝引用、原子回滚、历史和重送；破坏写成员/扩大合法引用/不回滚应在副本中失败。所有 paid 请求、调用数、时长、成本和失败都保存。硬上限导致未完成就如实报告，不提高上限。
