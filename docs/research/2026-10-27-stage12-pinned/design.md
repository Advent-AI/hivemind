# 第一步保真，第二步取全

Alex 要求把第一、二步做实。本轮实现独立、可运行的两步入口；不把尚未实现的第三步选择、第四步合并或新观点写入冒充已经完成。

例如 Vera 的厂商性能测试，第一步留下厂商归属和测试条件；第二步先给出已有问题目录，选中 CPU 问题后，取回该问题全部有效来源，包含旧的测试限制和商业化风险。第二步不把相似词多等同于投资上重要。

## 已定位的原因与改动边界

D344 已普查 18 个回答、553 条来源、677 次旧匹配。D340 的明确失败类是混合不同说话者、补年份、把事件日当发言日。D344 的 2,369 个原文查询中 2,324 个超过 12 词；放开词数会恢复 342 条旧目标，也会丢掉 141 条，故不采用这个局部补丁。Vera 的五条限定/反证排在 27、31、46、63、92，旧前十列表没有它们。

采用 D340 的原文引用合同：报道方和报道日由代码复制；说话者和时间必须指回原文，时间不归一化、不补年；同句不同说话者各留一条，绝不按引用相等合并。匿名只说明身份未公开，专业判断仍是第三方观点；只有未经确认的事实指控才是传闻。摘要和时间角色仍是模型语义任务，必须用新回答检查，引用存在不能代替这项检查。

第二步拆成两个数据库操作：catalog 列出输入对象及已配置主题的全部开放问题（以及直接依赖的问题）；expand 接收目录内的明确问题 ID，返回其全部有效证据、每条全部来源、被替代的前一条、最新判断和依赖。第三步负责选择 ID，选择后的展开不是另一次模型调用。没有前十、关键词排名或隐式截断。这个合同保证范围内取全，不声称自动判断相关性或解决上游错误关联。

## 状态 × 事件

| 状态 | 事件 | 输出 / 转移 |
|---|---|---|
| 未准备 | 原文、版本、对象有效 | 固定请求，时间只用输入值 |
| 未准备 / 校验中 | 空原文、引用越界、形状错误、未知对象、超预算 | 整体拒绝，不交付半份材料 |
| 已发请求 | 返回 / 拒答 / 外部失败 / 崩溃 / 结束时未回 | 原回答归档后校验 / 无可交付结果；不自动重试 |
| 已有回答 | 再次采样、改输入或配置、次日执行、第二个范围 | 新响应身份；旧记录不变；不投票补齐 |
| 目录已读 | 选择目录内 ID | 以同一 before_seq 和只读事务展开 |
| 目录已读 | 非目录 ID / 空选择 / 大于大小预算 | 拒绝 / 明确零条完成 / 明确超限，不能视为搜索无结果 |
| 任意读取 | 后续写者追加、未来关闭/替换、日期变动 | 只读事务与 seq < before_seq 固定可见集，禁用墙钟排序 |
| 已完成 | 重读 | 同一历史输入与范围得到同一内容，ID 稳定 |

- 保留完整 JSON、逐段交付、正向句子范围、源文精确引用；新增受控来源与时间引用。无旧日期字段映射，没有报道日补未知发言日。

- D62 “Extraction variance is fixed in the prompt, not by sampling several times”：每次回答独立评分；三次是测波动，不投票。
- D162 “最终仍交现有证据、候选观点及归属，不增加产品数据层”：本轮新接口是研究入口，没有生产存储迁移。

- D344 “Neither stage is accepted as complete”：这轮须以实测结果更新，不能靠实现即宣布通过。

## 测量计划与预算

离线先用 D340 的真实反例测试新引用合同，再对全历史检索范围做取全比较，Vera 必须恢复五条已漏限定并保留已找到的 AMD 反证。对删除历史过滤和回退前十的改坏副本，测试必须失败。模型采用原 gpt-6-luna/low，三篇各三次新控制、三次候选，共 18 次；独立上限 $0.75，每次最多 12,000 输出 token，单次发送，错误停止。旧运行预算不改变。全部原 31 标签、已记录的归属/日期反例逐份读；没有新建 gold 或将结构率称为准确率。

原文上限 100,000 字符；目录 150,000 UTF-8 字节；完整证据包 1,000,000 UTF-8 字节。超过预算明确失败，不截断。离线目标单次目录/展开 < 1 秒，记录实际最大值、材料条数与字节数。模型 token、费用、延迟实测报告。若扩大范围触发超限，属于未覆盖工作量，不绕过限制。

## 首轮接口失败后的同预算修复

首轮收到三份回答，第四次（Motley 候选）HTTP 400 后停止。错误响应正文没有被旧 runner 保存，因此不声称读到了服务端的具体原因。离线发现三篇候选 schema 含 456、1,456、2,116 个枚举值；后二者违反官方 1,000 上限。共享 `$defs` 不改变接受的输出，只移除重复定义；请求构建时现在先检查枚举预算。[OpenAI Docs](https://developers.openai.com/api/docs/guides/structured-outputs) 明确支持共享定义并说明此限制。

首份候选 13 条记录也暴露提示遗漏：一条把已知公司的代词判为匿名；p010o01 把作者“旧容量没有更高价值用途”的论证标成 fact。p008o03、p009o01 混有事实比较和部署推论，列为待复核，不并作确定错误率。补回原控制提示里“作者论证属于第三方观点”的含义，并明确公司代词不等于匿名。新提示 1,840 字符，短于原 1,998 字符，不改变原文、标签或已记录的判断标准。

首轮已用/保留 $0.059875，旧 journal 不重开。修复轮单独固定 18 次新控制/候选，以剩余 $0.690125 为上限；两轮总上限仍为 $0.75。旧三份回答仅作诊断，不并入新对照。HTTP 错误记录经过脱敏的正文，仍不自动重试。新轮前再次运行离线预检。

## 定位由代码写，不让模型重复填写

修复轮 18 次已结束。9 份候选共 280 条观察、325 处有效类型的引用；77 处 article 引用非空，分布于 3 份回答。另有 3 处定位/文字问题：两处短语实际在所指段落中但句号填错，一处把原文的 in 写为句首 In。合计 5/9 份被结构拒绝。逐条清单见 `repaired/reference-census.json`。这是接口设计和检查的缺陷，不把它们全归罪于模型内容质量。

最终模型引用只填写 `{paragraph, text}`。代码计算全部匹配位置，输出 `matches` 中的 source_start、source_end 和精确原文；不让模型重新猜句号或字符位置。接受集合只有完整短语的字母大小写及空白等价；其余字符、标点、数字必须一致。写入的 text 始终从原文复制，保留全部位置，不凭同文判同一身份。原回答另存，可看到输入怎样被定位。article/unresolved 与 null、named/anonymous 与引用的搭配直接写成 schema 的两个分支。

此处不改变内容评价：不能补年、不能把事件日当发言日、不能混来源或把条件结果写成已知事实。月份虽不完整也必须保留。原文全文进入来源包，后续可以核对跨句条件。旧生产字段仍不做有损转换。

零成本先把 9 份旧候选转成新的接口形状（删除冗余句号，article 的来源由代码持有），逐条验证原文定位；这只证明接口可以保存这些内容，不是新的模型结果。最终再做 18 次新控制/候选，两次并行仅发独立对照请求；前三个 journal 的已用/保留额从原 $0.75 中扣除。没有提高总上限。结构拒绝记为样本失败，后续独立样本照常测量；网络或服务错误仍关闭新请求。
