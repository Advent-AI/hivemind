# 第二步取全已验证；第一步仍未通过

本轮确实改了代码、跑了真实数据和新模型回答。结果不是“两步都好了”：第二步的独立读取入口通过取全检查；第一步虽然修掉多项接口错误，仍会丢摘要的期间、拆散前提，并产生不合格的引文。不能把这个版本交给后续步骤当可靠事实。

例如，原文是“财年开头，网络业务收入同比增长至 148 亿美元”，一份新摘要只剩“2027 财年网络收入 148 亿”。原句还在，但独立读取摘要会丢掉关键期间。另一例是 2030 年市场规模的年份留在上一段，新拆出的 55% 和 8,250 亿市场机会记录三次都没有带上这个年份。

## 实际改动

| 位置 | 做了什么 | 实测结论 |
|---|---|---|
| `src/hivemind/source_reading.py` | 独立来源请求、严格输出检查、代码复制报道信息和原句、保留全文；引用位置由代码计算；不补日期、不按相同引文合并身份 | 接口能执行；模型内容未验收 |
| 同一来源模块 | 共享 schema 定义，构建前检查 1,000 枚举预算；把来源种类和空值搭配写进 schema；只允许大小写及空白等价定位，最终复制精确原文 | 旧接口的已定位失败能离线翻转；最终新回答仍有 2/9 引文改写失败 |
| `src/hivemind/research_context.py` | 2a 读取对象及配置主题的完整问题目录；选择 ID 后，2b 取该问题全部有效证据、来源、被替代前条、最近判断和依赖 | 全历史取全核对通过；不声称语义相关性选择通过 |
| 同一读取模块 | 固定 `before_seq` 和只读事务；不使用摘要关键词和前十排名；超出大小预算明确拒绝 | 不读未来，不静默截断，返回范围可审计 |
| `tests/test_source_context.py` | 真实临时账本验证历史状态、跨对象依赖、来源、最近判断、明确拒绝和来源到目录入口 | 6 个测试通过；4 个改坏副本被抓到 |

这些是独立研究入口，生产默认仍未替换。没有修改旧运行、旧标签、生产匹配或写入器，没有提交或推送。

## 第二步：取回了什么

`verify.py` 在 1,114 个历史输入处，和独立重建的历史账本逐项比较：28,918 次问题展开、1,047,953 次证据读取，问题集合、证据集合和来源一致。这里是重复历史读取次数，不是一百万条独立证据。全范围读取检查耗时 35.33 秒；一个输入下读取全部问题的最大实测时间 0.081 秒。最大目录 67,746 字节，最大单问题证据包 704,449 字节，均在本轮预算内。

Vera 在序号 1085 前的 v5 共 95 条有效证据，全部取回。原来的 AMD 反向主张 e647 保留；旧前十列表漏掉的五条也恢复：

- e111：厂商批准的测试应谨慎看待。
- e488、e649：测试尚非正式、需要正式结果才能可靠比较。
- e653：市场规模是公司预计，管理层能见度不是已确认收入。
- e654：独立 CPU 收入可能不达预期，或和整机收入重复计算。

读取本身没有模型调用。把结果交给模型会占输入 token。最大证据包仍较大；这里没有证明后续模型能有效消化全部材料，也没有声称已经做成论据压缩或去重。选择哪些问题属于下一步的语义任务。

这是这些已读案例的表现，不是总体准确率。完整输出共 257 条候选观察。7/9 份通过结构检查，2/9 份被整体拒绝：两个 Rest of World 回答都把 `spent months` 改写成 `for months` 作为引文。不能通过定位等价规则把不同词当原文。被拒绝的两份共有 78 条观察，没有部分交付；其余 179 条进入了真实来源 → 历史目录入口。

仍存在的内容问题：

1. `motley.1.candidate/p013o03` 丢掉财年开头的收入期间限定。
2. 三份 Motley 回答的 p009o01、p009o02 共 6 条市场机会记录没有携带上段的 2030 年。新控制均在相应记录的时间字段保留 2030 年。年份仍在全文和别条记录里，却不在这些独立记录里。
3. `motley.2.candidate/p013o01` 把前段 50% 市占率假设下的结果单独称作 forecast revenue，没有带上作者假设。不能当作独立无条件预测。

按既有 31 个内容标签读了 93 个机会，原始输出中都能找到有关内容；这不意味着内容可以准确独立读取，更不意味着 93 个都已交付。两份整体拒绝和上述限定损失已经使第一步不合格。标签未修改；人工判读由助手完成，非独立人工 gold。具体路径和摘要在 `final/semantic-review.json`。

最终控制/候选各 9 份：输入 token 合计 37,383 / 39,480，输出 token 27,537 / 30,022，估算费用 $0.0175068 / $0.0189590，中位响应时间 25.17 / 27.34 秒。新系统提示 1,943 字符，旧提示 1,998 字符；系统提示缩短没有让总 token 下降。

## 这次也有我的实现和实验错误

- 第一版把引用枚举重复展开，三篇 schema 分别 456、1,456、2,116 个枚举，后二者超过 API 上限。第 4 次请求 HTTP 400；旧 runner 没保存错误正文，因此“具体服务端理由”不能冒称已知。共享定义和本地预算检查修复该机制。
- 修复轮又发现 schema 允许、代码拒绝的空值搭配：9 份 / 280 条观察中有 77 处。另有两处句号错配和一处引文首字母大小写变化，共 5/9 份结构拒绝。代码定位加 schema 分支后，9 份的全部 280 条能离线表示；这不能代替最后的新模型测量。
- 我一度把单份结构不合格当作整个实验要停止的错误。随后保留原记录，完成剩余 16 个独立样本，没有重发已回答的请求；网络错误仍停止新请求。
- 历史比较脚本起初用了当前表定义读取旧运行的额外列，改成该旧运行的冻结定义后重建成功。全测试首个命令漏了 README 指定的 PYTHONPATH，集合导入失败；按 README 的 `src:poc` 路径运行后才得到有效测试结果。这些原始失败日志都保留。

本轮共 40 次请求尝试、39 个回答，1 次失败用量未知。已知用量估算 $0.0789317；包括未知请求保留额的保守占用 $0.284681，低于未提高的 $0.75 总上限。所有运行已经结束。
