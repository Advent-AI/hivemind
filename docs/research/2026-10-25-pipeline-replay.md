# 抽取到入库：先修读取顺序，再检验身份判断缺了什么

2026-10-25，D159。范围只有抽取、找已有观点、判断是否重复和写入。UI、Idea、分类、Pull、最终判定和上层投资论点不在本次范围。

**结果：顺序缺陷已修，214 项测试通过；身份试验在第一次调用前停止。** 审查发现原拟验收把“担保金额”和“当年实际出资”当成同一问题，会奖励错误合并。审查前草案保留在 `poc/reports/2026-10-25-pipeline-replay-01/design-before-review.md`，不能据它启动试验。下文是已核实的结论与下一步边界。

同一个 Ohio 项目，2500 亿美元担保、3500 亿美元芯片融资、包含芯片的项目总成本，可以属于同一组，但不是同一个问题。两家媒体转述同一笔 3500 亿美元芯片融资，则不该新开两个问题。

可复算记录：`poc/reports/2026-10-25-pipeline-replay-01/census.py` 及 `census.json`。读取八个 v15 库，不修改原库。这些运行共享文章，不能当成独立样本。

完整链路：`replay.run` 先给一天所有信息编号，再 `pre_extract` 用日初观点并行抽取；`round.run` 才逐条找、比、写。比对重新读到较新的观点，但它只收到抽取留下的东西，无法找回原答没写的问题、被丢掉的证据和分组。因此“比对能修重复，所以并行与逐条等价”的代码注释不成立。

另追 T4c 的四次比对，均读原答、交接、实际搜索编号和原文：

| 顺序号 | 实际结果 | 原文所支持的判断 |
|---|---|---|
| 116 | 担保归 v17、芯片融资归 v18，总成本新开 v20 | 正确的对照；三种金额不能全合并 |
| 126 | 芯片融资另开 v21 | v18 已在清单；同一 WSJ 消息的同一笔融资 |
| 147 | 财务支持另开 v22 | v17 已在清单；Wedbush 在评论同一 2500 亿美元担保 |
| 165 | 融资另开 v24 | v17、v22 已在清单，但候选的五格已经变成“2026 年实际提供的融资”，不能按相同原始报道强制合并 |

126、147 是同一交易被拆开的问题；165 则在抽取时已经改变了要核对的量。不能把三条混成同一种“没合并”。新候选只带证据摘要；旧候选只有问题、期限和答案区间，没有建立它的原句及来源。序号 126 还有更早的缺失：芯片融资候选连到的原句只说担保，3500 亿美元在全文下一句。因此补旧来源未必足够，不能先宣布是完整修复。

进一步读全八库中 `measure=financing_amount` 的 29 条观点及结果区间：165 的改变出现在一个原始抽取回答（call 460），复制进三个运行，分别是 T4/v29、T4b/v24、T4c/v24。不是三次独立模型错误。原句仍写“in talks”，但五格要求“2026 年实际提供”。原文和原答都保存在 `financing-meaning.json`。一个具体反例：2500 亿美元的担保可以成立，而当年真正出资为零；两个问题可以给出不同答案。让 matcher 合并会丢掉新问题的区间，无法叫修好。

既有 D158 对全部 326 个原答的追查仍适用：入口的数字优先和官方日期条件会压掉项目问题；后续比对不能修原答没写出的内容。其改写尚无在线结果，本次不把它一起混入试验。

还逐份查了这四条信息的抽取请求：四份都没读到 Ohio 的已有项目问题，尽管随后的身份搜索找到了。`views_for_prompt` 只从 NVDA 及它的依赖找，Ohio 问题存为 ai-capex，不能因为也涉及 NVIDIA 就被读到。顺序修复消除同日快照问题，但不会自动改变这个对象范围。`extraction-context.json` 列出每份请求实际可见编号。这是抽取前的上下文问题，与比对阶段搜索命中是两件事。

## 2. 实际修改与未采用的假设

**实际修复：一条完整写完，下一条才抽取。** 删除日初并行预抽取，由已有 `round.run` 执行抽取、比对、写入。分发的顺序号、失败恢复、每天重判一次均不改变。不新增模型调用。代价是失去最多八路抽取并行；真实用时尚未测量，不承诺加速。

旧并行交接不能冒充按新顺序读过。恢复若遇到尚未完成的旧并行交接，在新调用前拒绝并列出输入编号；保留原库。已完成的旧运行可从下一天继续，未回填历史。本次不用删除或静默重抽旧结果来解决。

**未运行的假设：给身份判断补上双方原句和来源。** 原来准备保持四个请求的搜索清单、问题、模型、schema、规则不变，额外展示新候选已有证据的原句及旧候选创建时的原句。审查指出，这对 165 的“成功”定义是错的。来源相同也不能让两种金额变成同一量；故不构建、不调用、不接产品。缺少来源仍是待验证因素，不能替代先检查抽取是否保留了原意。

## 3. 事前合同与表

### 状态 × 事件

| 状态 | 事件 | 后继与记录；读写日期 |
|---|---|---|
| 未抽取 | 正常到达、同日另一对象 | 按既有编号逐条跑；读已提交前序；日期用输入 publication_day |
| 正在抽取/比对 | 服务失败、检查拒绝两次 | 原失败记录保留；停止当天，后条不抽取 |
| 抽取已存 | 崩溃后恢复 | 原顺序号、原交接继续原步骤，不重复成功抽取；原 publication_day |
| 写入中 | 异常 | 原事务回滚；保存失败；后条不抽取 |
| 写入完成 | 重送、当天剩余工作 | 已完成输入跳过；后条读已提交库 |
| 当天完成 | 后一天继续 | 原 backdating 规则和日末重判照旧 |
| 旧并行交接尚未完成 | 恢复 | 新调用前明确拒绝，不改交接，不静默付费重抽 |
| 改配置/改输入后恢复 | 原流程支持范围 | 本次不改变原恢复合同；测试不声称支持输入修订重算 |
| 另一个进程写同一库 | 并发写入 | 此 POC 仍是一库一个 replay 写者；删除线程预抽取不提供跨进程调度 |
| 隔离试验未调用 | 每个案例每臂 3 次 | 各独立存档，顺序穿插；不使用缓存答案替代模型样本 |
| 隔离试验调用中 | 超时/预算/网络失败 | 记录本次，保留未知费用，不自动重发；其余未开始明记 |
| 隔离试验完成 | 答案错误/拒绝 | 原样评分，不补样，不接产品，不设计下一臂 |

## 4. 事前验证和停点

免费顺序证明用 T4c 顺序号 1 的电话会及 5 的 10-K，均 2026-02-25。前者建立 Rubin 出货问题；后者抽取请求必须看到它。真实临时库、真实记录，只假外部模型；恢复与失败也从 replay 入口跑。把日初预抽取放回去的反向修改必须被同一测试抓住。对八个库的 834 次预抽取路径，删除后这一路径为零；不等于追回 576 次旧语义结果。

原草案最多 24 请求、$1.50、30 分钟，实际 **0 次生成请求、$0 生成费用**，没有建新实验臂。D158 超时请求的未知费用仍原样保留。preflight 已执行：315 个旧抽取答案，152 个候选中保留 122、806 条证据中保留 694；155 条旧比对记录有 2 条原有缺失决策的拒绝。这些拒绝不是本次顺序改动新增，报告没有把它们隐藏成全通过。

下一步先与 Alex 定同一把尺：同一个问题才去重；同一个项目的不同问题放在一组；若抽取把谈判额度改成年度实际出资，记为抽取改变含义，不把强制合并算成功。此界限确认后再登记最小抽取对照，检查提问、证据链接、分组和去重四个环节，而不是只数少开了几个观点。不能用没有正确问题的“好分组”通过验收。

后续修复应落在这个顺序上：先让抽取看见相关的已存项目及其问题，读全文时保留金额和时间的真实含义、提出问题并归组，再分别判断“同一问题”与“同一项目”，最后沿用原子写入。不能拿来源相同代替身份判断，也不能让下游比对补造上游遗漏的论点。这里是在说明已有 D149 目标为什么尚未落地，不是新增一个事后全库聚类步骤。
