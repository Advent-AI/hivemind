# 抽取时归组：设计说明刷新

2026-10-25。Alex 要求把“读信息时就组织观点”写入相关 PRD。本次只改设计说明，不改运行代码、提示词文件或实验数据。

## 改前核对

问题在说明的层级：D142 起已明确要求在信息进入时归组，但当前主流程仍只写证据和候选观点，归组只在 D147 实验补充里。读者容易把它理解成可选的事后整理。

按字段和段落核对，而不是用某个词出现的次数当作缺陷数：

| 所在位置 | 核对范围 | 原来的缺口 |
|---|---|---|
| new-design.js | summary；extract 和 views 的 subtitle、status、purpose、inputs、outputs、checks；两者间的边，共 14 个字段 | 主图的交接不包含归属 |
| new-facts.js | TEMPLATE、PROMPT_EXAMPLE、PROMPT_NOTES、EXTRACT_STEPS、EXTRACT_TWO、EXTRACT_SORT_TREE、EXAMPLE_NOTE、EXTRACT_RELATIONS、VIEW_TREE、INTAKE_STEPS、MATCH_OUTCOMES、VIEW_FIELDS、TRACE_FIELDS、GROUP_RELATIONS，共 14 个常量；两处展开页标题与介绍 | 完整业务过程只在实验旁注中；“归入已有的只连证据”也会漏掉归属；原样交接与模型输入须区分 |
| 05、06 PRD | 全部 31 个生成块（9 + 22）及非生成的一句话、交接、验收、状态、相关决定 | 生成块随页面改；非生成段落需同步，不能手改生成块 |
| 00 PRD | 一句话、主流程、返回抽取的接口、信息流职责、术语、状态、模块表 | 把研究主线限定为实验概念 |
| 运行与实验说明 | pipeline-plan、hierarchy_study/README、CURRENT_STATE | 必须分开写目标要求与已经实现的能力 |

已知例子核对：05 的模板明确写“只给问题、看的是什么和到期日”，而归组输入在末尾实验补充才出现。运行代码也确实没有该能力：extraction.SCHEMA/Handover 不含主线，views/round.run 存下的交接只有证据、候选观点和剔除记录，writing.write 没有组成员写入。

根因不是把两类内容改成三类就能解决。证据和候选观点仍是读出的两类内容；候选观点需要同时带结构化归属。D142 的原答已给出关联，而后面的比对又改掉关联，说明职责边界必须在主流程写清。

## 同一条流程的边界推演

| 输入或结果 | 目标行为 |
|---|---|
| 空库先读 Rubin 出货 | 一个候选观点即可声明 Rubin 主线；写入时分开确定观点编号和主线编号 |
| 后读 SK 或 OpenAI 使用 Rubin | 候选观点引用已有 Rubin 主线，各自保留问题与到期日；不因成员同组就建立依赖 |
| 比对把候选观点归入已有观点 | 归属保存到最终那条观点，不因没有新建观点而丢掉 |
| 只有原观点的延迟证据 | 沿真实证据连线和已存成员关系更新，无需另提候选观点 |
| 出处被筛掉、最终不开、空闲主线声明 | 原检查继续生效；不产生没有最终成员的新主线 |
| 保存失败、重送、晚到 | 与原写入和顺序号规则一同处理；不把失败当完成，不重复成员，不回写过去 |
| PC 芯片、其他客户的专属主线 | 必须看业务过程的真实范围，同公司或同属 Rubin 本身不足以建立这些归属 |

修复的不一致：实验旁注与主流程的地位相反；输入没提可用主线；输出没提结构化归属；归入已有观点只写“连证据”；记录与最终编号映射没有提归属；总览模块表仍像已经全量实现。D148 的失败原样保留。
