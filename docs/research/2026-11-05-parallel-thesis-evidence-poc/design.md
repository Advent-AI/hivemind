# Parallel thesis-and-evidence POC

Alex: “我们分开一点吧，一个prompt 找新观点+文章内证据；另一个找已经存在观点的支撑证据 … 你想清楚怎么拆开来并行跑POC；写不同的两套prompt”. This authorizes a small isolated POC, not a production default, change to frozen rulers, new tradeoff in storage semantics, or new automatic criterion for importance. D369 keeps both relevant core and supporting evidence; D370 forbids starting 22 preset questions and importing reports as separate context; actual earnings-report source items remain eligible. D371 requires related present/future financial information. Signed extraction standard §3–5 controls materiality, admitted questions, source quality, and uncertainty. Frozen v74i and golden-v5 stay untouched; there is no new gold and no quality score that pretends to be independently signed.

## Why split and how it runs

A single unchanged article and a single read-only pre-article question snapshot feed both model calls **at the same time**. `new-thesis.txt` discovers important, genuinely new investment questions and returns each one's actual article evidence; `existing-evidence.txt` reads the same complete article against existing questions and returns support **and counter-evidence**, including uncertainty and source. Neither lane sees the other's output during its call. Do not invent a sequential pass or make B wait for A. A can still report what appears new even though matching may discover an existing equivalent; B can only link to question IDs actually in its snapshot. A returns only evidence supporting its own candidates; B returns only evidence connected to existing IDs. Both lanes see a neutral shared article metadata, category instructions, exact same existing questions and original full article; no hidden gold, no extra financial report, no list of fake seeds.

At the join, code checks the source quotations, field schema, candidate ladder/group/period, and links using existing v74i `sift_with_groups` and `file_reading`, separately per lane; lane A candidates and evidence remain together. Convert B's evidence-only response to the existing shape `{evidence, candidates: [], new_groups: []}`. IDs use lane namespaces before combining: original local IDs alone cannot identify the same record across two answers. Deduplicate exact duplicated wording within a single lane using existing code; at the POC join do **not** collapse similar evidence from different lanes solely because values match. Preserve raw records and each lane's destinations, note possible duplicates for later semantic matching; do not add a new production store. Distinct targets can both have same source. For candidate matches or rejection in the real pipeline, determine the candidate's final target before filing its source-backed evidence there; this POC stops at checked handover and does not claim matching/writing/judgement. If candidate rejected or neither lane provides an applicable home, existing product D209 discards that evidence; record limitations, not a silent parking lot. The user's earlier D251 day-start snapshot was frozen; the requested most-recent pre-article snapshot is exercised in the isolated POC, not shipped or declared already implemented.

A crucial limit: when one article introduces a new question, B cannot know it because both run in parallel. The A lane must carry **all article evidence it judges relevant to each new question**, not just the one opening quote. Otherwise a new question may open while its current supporting or contrary information is lost. A’s article evidence stays attached to candidates; the existing-evidence lane should not be asked to see a post-A question list. No requirement to open a question for every financial fact. Historical facts/effective guidance and optional vs excluded boundaries remain as in the signed standard; a valid relevant quarter/forward forecast can support an annual question. One model output per lane is stochastic, not a general efficacy estimate.

## Contracts / state

| State or event | Behavior and reader |
|---|---|
| No work | Start with source bytes, item id and immutable pre-item snapshot/hash; refusal if missing, incomplete or no archive/sequence; no shared mutable ledger. |
| Two lanes in flight | Two independent requests, same input, distinct schemas and output archives; neither receives other's output. One-call v74i fresh control on same article/snapshot. Limit concurrency; record send/receive. |
| One lane error/schema/refusal | Record exactly what failed and partial raw response; mark item incomplete, never treat failed lane as empty or successful, no silent manual retries. Already in-flight calls can complete; transport may itself retry and incur unknown cost. No write of a successful-looking joined outcome. |
| Both valid | Validate source-backed facts and candidates; filter invalid question ids; emit lane-labelled records with their destinations. No concatenation that overwrites IDs or drops one lane's evidence. |
| Candidate rejected or equivalent to existing | At actual matching, evidence must follow resolved target; rejected-only candidates can lose evidence. Test not claiming real matcher has run. Do not force similarity-based dedup in code. |
| Later input or crash | Preserve archives and record incomplete vs completed; a changed source or snapshot gets a new hash, no automatic resume or mixing. Immutable snapshots and read-only accesses; no edit during sends. |
| Readers | Prompt A → candidate and local source evidence → candidate checks → eventual matcher/writer/judge; prompt B → evidence attached to previously visible IDs → same evidence checks → eventual matcher/writer/judge. The POC's real checked handover stops before matcher/writer/judge. |

## Complete-request review and corrections

The read-only review found that the original evidence-only user block still told the model to propose questions, the control's system message still said day-start, and a generic groups block said none existed although group context was shown. The three experimental requests now consistently label the snapshot as immediately before the item; the evidence-only request removes candidate directions and the irrelevant research-reference block; the other group block says no separate group list is supplied. Both new prompts clarify that an unconfirmed/unnamed-source claim is a rumour, and lane A's schema explicitly includes contrary evidence. The original v74i control has the two snapshot/group wording corrections, so it is an experimental adapted control, not the production request.

The Microsoft article's archived upstream subject was only `ai-capex`, although the text concerns Microsoft earnings. For this diagnostic only, `MSFT` is added to that item's subject metadata for all three arms, making its fiscal-year context available. The underlying source and historical snapshot are unchanged. This is a deliberate correction shared by all arms, not a claim that production routing was fixed. The independent review identified a structural risk the POC must inspect: A can treat a question as already present while B does not link the relevant statement, losing evidence even though each call is locally plausible.

The first no-cost preflight attempted writes against the deliberately read-only snapshot, producing 12 operational refusals. Replaying against a writable SQLite backup instead yielded the same historical single matching refusal, single quote refusal, 31 skipped matches and two historical judgement schema refusals reported in `preflight.txt`; no frozen input was changed.
