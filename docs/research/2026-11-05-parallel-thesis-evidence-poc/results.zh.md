# 两条并行 prompt：真实文章 POC

## 结论

四篇文章、每组一次：拆分还不适合接生产。它在 NVIDIA 已有观点中保留了 70% / 44% / 无供应限制超过 100% 的比较，但漏了微软全年收入新问题，也有证据挂错或没有挂上。一次抽样不能说明哪种架构总体更好。

- 微软：文章写 FY2027 收入市场预期 3911 亿美元、下一季度指引 898.5–909.5 亿美元。并行 A 只开 Azure 问题，没有开总收入问题；B 没有相关旧问题，两个数字都没到交接结果。单 prompt 开了总收入问题并保留市场预期，但丢了季度指引。
- NVIDIA 增长预测：B 把 70%、市场预期 44%、无供应限制超过 100% 挂到已有问题 v70。单 prompt 的原文引用包含三者，但摘要漏掉 44%。两种方法也都把没有报道收购进展的猜测挂到具体收购问题，关联值得怀疑。
- NVIDIA 财报：B 提取了 1080 亿美元指引的“假设中国计算产品销售为零”，却没挂任何问题，检查后丢失；单 prompt 保留了它，也把它挂到了文中没有提及的具体 H200 许可问题。A 建了采购承诺问题，承诺金额是有用证据，但问题的方向和年报能否按该范围结算没有被文章证明。
- DLSS：两组都保留了正式发布时间和未完成版本提前流出的区别，并挂到已存在的发布问题；A 没重复开题。

独立逐条复核参见 [independent-review.md](independent-review.md)，含原文、具体记录 ID、链接和不确定性。四篇的完整原文、所有原始模型回答、丢弃理由和两套 prompt 在 [report.html](report.html)。

## 编号风险

财报文章的 A 输出把新问题编号为 `n1`，检查仍然接受。已有的 `file_reading` 仅用 `^c\d+$` 识别候选问题链接。基于这个真实输出，在本地构造“候选问题失去证据后被丢弃”的情况：`n1` 问题被丢掉，指向它的证据却仍保留；将相同候选编号改为 `c1`，证据则被正确丢弃。真实 POC 中的 `n1` 没有被丢弃，故这是可复现的条件风险，并非本次已发生的实际孤儿记录；未运行真实匹配与写入。

## 数据、调用与边界

- 四篇文章各运行单 prompt、A、B 一次，共 12 次真实模型调用，均成功；A、B 对同一篇并行。每一组收到相同的文章和文章前题库快照，每份各含 69 个问题。
- 微软原始上游标签只有 `ai-capex`；实验对三组统一补上 `MSFT` 以提供主体与财年信息，并未修改线上路由。快照从历史测试库重建，不代表当前线上实时题库；原始文章与日期未另行核实。
- 单 prompt 也使用本实验的最新快照及两处描述修订，是实验对照，并非不变的线上生产请求。
- 冻结的标准和金标没有改；没有新建金标或计算效果分数。本次停止在抽取及现有交接检查，没有真实跑候选匹配、入库、判断或下游验收。
- 模拟测试覆盖并发、有效与错误链接、原文伪造、候选失效、跨路同 ID/相同原文以及单路失败。历史预检重放 40 个抽取结果；已有 1 个原文拒绝、1 个匹配拒绝、31 个匹配被跳过及 2 个历史判断格式拒绝，不能说预检无问题。
- 根据 `model.PRICES` 中 gpt-6-luna 输入每百万 token $0.10、输出 $0.50、缓存输入按 10% 计算，12 个成功响应合计约 $0.0258：单 prompt $0.0101，并行两路 $0.0157；未计潜在传输重试费用。
