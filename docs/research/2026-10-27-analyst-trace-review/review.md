# 按分析师的工作重新检查：保留重要变化，而不只是给句子分配位置

**结论：D340 的提案只能部分解决问题。它能改善去向记录及阻止默认新建，但还不能完成去芜存菁；缺的是把整篇材料压缩成重要业务变化，并与已经知道的内容比较。** 给每条句子写关联理由、给每张新卡写独立理由，都可能产生很多看似合理的废话。

例子：旧系统读到船厂合作，原文明说主要价值是技术整合，最后却建了“500 万美元是否签约”的卡。下游一直认真回答签约问题，却没有把工业 AI 的采用价值保留下来作为研究重点。

本轮是用户要求的只读深查和提案修订，不是新的模型试验。以下数字描述保存的数据，案例判法是本次分析意见，尚未成为 Alex 确认的金标。没有股票推荐或当前市场判断。

## 1. 原提案遗漏了旧实验已经尝试过的东西

[trace.py](trace.py) 逐一读取 v29 账本全部 50 张卡的创建 handover；[traces.json](../../../poc/reports/2026-10-27-analyst-trace-review/traces.json) 保存计数和三个案例的完整请求、回答、检查、最终证据及首次评判。

- 50/50 都有 `opens_as` 和非空 `settled_by`。
- 13/50 已有非空 `folds_into` 和 `lost_if_folded`。
- 28 张以 `binding_obligation` 接纳，12 张为 `main_driver`，8 张为 `policy_stage`，2 张为 `industry_aggregate`。

因此，“让模型说明独立价值”不是本次新发现的充分解法。数量本身不证明这 28 张全无价值，也不证明只有 12 个主驱动合适；但证明必须读理由和结果，不能再把加字段当改进。

旧 v12 提示有一句决定性规则：`A different population, source, estimate, wording or direction is not a loss; a different quantity, period or decision is.` 它把“不同数量/决定”当成可独立的依据。与此同时，准入类型奖励公司的签约义务，要求完整结果台阶和可查日期。模型容易挑选最容易写成签约问题的细节，而不是文章最重要的业务内容。

这些原始请求来自 v29 研究工作树 `/Users/lchingen/hivemind-admission-v12-2026-10-26`，不是默认 v23。已核对其中的 `role-v12.txt`、`views/jev_matching.py` 和 `views/writing.py`，没有把两个版本混作一套实现。

## 2. 三条完整 trace 说明了什么

### A. 船厂合作：有关键内容，但研究问题选错重心

- 输入：`gnews:290c7cfa9a84a57518cacfe2`，extract call **2449**，seq **687**。
- 原文：NVIDIA 与 Kawasaki 建数字船厂；AI 用于焊接、喷涂、检查、搬运，数字孪生用于先模拟再施工。原文提到一则 500 万美元投资消息，紧接着说明主要价值在技术整合，不是大额持股。还说明劳动力短缺、交付效率和更广泛采用的可能性。
- 原答：留下合作、500 万美元、机器人三条；投资摘要删掉了原文关于主要价值的限定。创建 c1：“到 2027-07-30 是否签署该投资的约束性协议”；以 `binding_obligation` 接纳，`folds_into`、`lost_if_folded` 都为空。
- 写入：**v33**，三条证据 e852/e853/e854 全为这张签约卡服务。
- 后续：截至 seq 1087 的评判把合作和机器人内容称为签约的背景，再判断是否会签约。下游回答了被给定的问题，无法恢复被选错的研究重心。

**分析师应怎样处理：** 保留“工业 AI 出现具体采用场景”的简明更新，以及合作仍处早期、没有客户收入/规模化回报的限定。500 万美元可以作为来源细节，不据此单独开签约卡。是否值得建立工业采用的新问题，要看它是否形成独立、重要、可跟踪的不确定性；单篇试点新闻还不够。也不能为了保留这条材料，硬挂到汽车收入或总收入。

这不是“金额低于某个阈值就删”。如果小额投入打开重要平台入口，仍值得保留。判断对象是业务意义，而不是数字大小或是否存在合同。

### B. Vera 性能：问题重复扩张，信息却被过度合并

- 输入：`gnews:caf5e64df9edf2e567ad2813`，extract call **4385**，seq **1085**。已有 **v5**：“FY2027 独立 CPU 收入”。
- 原文：解释 agentic workload 对并发与单线程性能的要求，给出内部测试估计；Vera 对 AMD Venice 的四项负载比较最高为 1.5 倍，并有测试配置及估计限制。
- 原答：建 c1：“FY2027 Vera CPU 收入”，同时将性能证据连 v5 和 c1。`lost_if_folded` 是“不能单独看到 Vera 的贡献”。没有给出这次性能消息为何需要一个新的收入结果问题。
- 清洗：两条证据中 e2 被 `quote not in item` 拒绝，e1 保留。本轮记录此环节，不将旧引文问题混作 routing 漏读。
- matching record **660**：Jev call **4392** 对 v5 给 `part_of=0.81`；额外 collision call **4393** 认为两个收入范围不必相等，判 `distinct_question_same_matter`。最后 c1 仍为 `new`，写成 **v50**。已有额外模型复核，也没有回答独立重要性。
- 同轮 evidence call **4391** 又将新性能证据认作旧 **e652** 的 `same_statement=0.57`。e652 是五月 Kress 对 x86 的一般性能/功耗/密度比较，而新来源给出较具体的 AMD Venice、负载和内部测试条件。
- writer 的 repeat 分支给 e652 增加来源，并将旧 e652 连到新 v50；没有把新摘要及其测试条件写成在用证据。新材料仍可从来源档案追到，但评判输入中的内容退回旧说法。v50 首次评判引用 e652，承认没有销售、订单、产量或收入预测，却仍落入预先给出的收入区间。

**分析师应怎样处理：** 在已有 CPU 商业化问题下保留此次更具体的竞争力证据，并明确“厂商内部估计，不是客户采购或收入兑现”。先比较旧证据与新测试：共同的 1.5 倍说法可以收拢展示；不同的竞争对象、测试条件和来源时点不得因数字相同抹掉。两条都出自 NVIDIA，也不自动成为两份独立外部验证。

不应仅因能把 Vera 单独列出来就开收入卡。只有后来出现可独立验证的收入披露、独立业务情景或与其他 CPU 分化的重要问题，才重新判断是否值得拆开。这里不是声称 v5 和 v50 必然数学等同，而是说这次输入不足以证明拆卡有研究收益。

这个案例证明：**“更多卡片”与“更多有效信息”完全可能朝反方向走。** 把去重力度统一调高或调低都不解决。

## 3. 用 CoreWeave 演示真正的压缩

D339 的样本 **002** 有 15 条来源记录。我的上一轮重点看它们是否到达目标，没充分问它们合起来说明什么。逐条看似合理地解释去向，会让租价、寿命、旧机房、电力和订单散开，甚至将租赁价格写成“resale-value”来贴近融资卡。

分析师阅读后的主干可以是下面两项。**两项是这篇材料的结果，不是每篇固定配额。**

| 研究更新 | 保留的关键依据与限制 | 如何收拢 |
|---|---|---|
| 这些证据支持旧 GPU 在部分场景仍有商业用途，削弱“新架构一出旧卡很快无价值”的简单叙事 | A100 合同延至 2029（p006o01）；H100 续租为原价 95%（p008o01）；Kress 称旧 A100 满负载（p008o02）。同时保留 Burry 的折旧质疑和匿名专家的短寿命说法（p007），以及这次到期续租只占机队小部分的限定（p011o02） | 不把每个寿命数字开成问题；相同主张合并阅读，但各说话者、时点、证据类型分开。续租价格不是转售价格，未来合同也不是未来已实现利润，不能证明所有旧 GPU 均有相同寿命 |
| 电力/散热约束使旧卡继续被使用，也限制新设备和需求兑现的速度 | 老机房约 20kW/机架，新设备 120–140kW 且需液冷（p009）；Blackwell 无法直接替换（p009o03）；4.2GW 合同电力与 1.5GW 已上线的差距（p011o01）；1,040 亿美元积压订单另不含新增承诺（p006o02） | p009–p010 的参数及解释收拢为一个瓶颈机制，不重复写五条“支持需求”。保留合同/上线、订单/收入的区别；旧卡耐用也可能延后替换，不能全算新增 GPU 需求利好 |

季度收入增长是背景；设备瓦数是解释瓶颈的证据；文章作者“所以可延用”的推论与管理层原话不算独立佐证。保留关键并不是把其余每条都送入同一收入卡，也不是为了简短丢掉逆向证据和限制。

对 **v37“是否签约承担芯片贬值风险”**，这些寿命数据最多是潜在动机或风险背景，不能当已经签约的证据。如果当前只有收入卡和签约卡而没有适当的研究位置，先明确这个表示缺口；不能被现有卡片诱导，把文章意思改成签约判断。

## 4. 我作为分析师会按什么顺序处理

1. **先问这篇真正改变了什么。** 是需求强弱、兑现瓶颈、竞争位置、盈利能力、现金/信用风险中的哪一个具体判断？这只是阅读问题，不是固定字段分类或行业白名单。定性变化也能重要，不能只挑有数字、有截止日的句子。
2. **把支持、反对和限制一起读。** 找出最少但足够的关键证据；“删掉它是否会改变方向、力度、适用范围或可信度”是保留检验。不能为了故事顺畅删掉反例、小样本、计划状态或未知日期。
3. **与已经知道的内容比出增量。** 同源转述只增加出处；新数据更新同一判断；新条件修正适用范围；真正不同的因果关系才可能开新问题。没有读过相关旧证据，不能声称自己完成了增量判断。
4. **先尝试更新同一个研究问题。** 保留关键差异，不按新闻标题、公司名字、数字个数拆卡。若只在原问题下保留这条更新会失去一个重要、可独立跟踪的判断，才提出新问题。
5. **最后检查能否按当前产品表达。** 问题、范围、结果条件和期限应服务于前面的研究意义。不能为了满足“必须是年度数字或签约事件”倒着改写原文。重要内容暂时无法表达时，明确报告能力边界，不能变成无数待办或伪造问题。

还有一项资料边界：分析师最终会比较“业务情景”与“价格隐含预期”。本轮输入没有可靠、同一时点的定价/共识基线，因此这里能做业务研究更新，不能把新消息直接叫作超额收益机会。缺少这些数据也不应把长期重要风险直接删掉。

## 5. 对提案的具体修订

**工作单位从“每条来源找一个位置”改为“整篇形成少量有证据支持的研究更新，再与旧知识比较”。** 原始来源仍可细分，研究输出应凝练。不是再发一轮模型投票，也不预先固定为两三条。

- 第二阶段应一起看到同篇来源和必要上下文，输出一项业务更新所依据的多个来源 ID。共享解释按更新写一次，而不是给每条瓦数、租价重复写“影响收入”。每条来源仍可追踪到被使用、重复或作为背景的处理结果。
- 输入要有相关已有问题及其关键证据/限制，不能只有标题和期限。v50 的实际 matching 输入中，v5 的两条早期引文甚至有一条“74 篇 ICML 论文”，并未提供当前 CPU 收入判断的完整依据。增加更多相似标题不能替代增量比较。怎样有界地选取上下文，必须另用实际检索结果验证，不能声称已解决。
- 新建条件必须检验研究收益：“保持现有问题的判断不变，新问题的不同结果是否仍会显著改变一个业务情景？依据是什么？”仅仅范围可再细分、能查到一个签约结果不算答案。需要语义案例检验；换成更长的 reason 字段不构成实现。
- “合并”须区分三件事：同一陈述合并出处；不同陈述共同支持一项更新；重复问题合并目标。第二种可以收拢呈现但不能抹平说话者、条件、日期和相反意见。三者不能共用一个文本相似阈值。
- “去芜”要删除重复解释与无研究增量的维护负担；“存菁”要保留方向、强度、机制、范围和证据可信度。来源档案还在，不代表关键知识已经交给了研究读者。

这些改动首先是第二阶段任务和评价单位的修订。逻辑中的“研究更新”不是新获批准的持久化表、第三个模型调用或新的全局观点体系。当前 D38 数量/事件问题能覆盖部分需求，未必能承接全部商业论证；D162 又限制新增产品数据层。应先以这些真实案例确认所需输出，再决定在既有证据/评判中表达，还是需要新的产品表示。不能用研究提案越过这个决定。

## 6. 怎么确认做到了

此前的目标召回、卡片数量、字段完整度都不够。下一次实验需要 Alex 认可的语义标准，至少检查：

- **研究重心：** 船厂案例必须保留工业应用意义及未商业化限制；不能只成功建出签约卡。
- **压缩后的忠实性：** CoreWeave 要能读出旧卡寿命和设施瓶颈，以及反证/样本限制；不能全变成需求利好。
- **增量不丢失：** Vera 新测试的比较对象、条件和厂商属性仍在；不能用旧 1.5 倍话术替掉。
- **没有无意义扩张：** 重复新闻不增加问题，技术进展可更新原问题；同时用真正新现金/信用风险的问题作正控，不能一律合并。
- **最终读者看到了：** 追到真实写入及评判输入；不能停在模型 JSON 或原文档案里找到就算通过。

这次人工整理说明所需输出是什么，也揭示上一提案为什么不够；它不证明模型已经能稳定做到。没有新付费请求，没有改金标追求高分。下一轮不应继续测试一个仅增加新建理由字段的方案。
