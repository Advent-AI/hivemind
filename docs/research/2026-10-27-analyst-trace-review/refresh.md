# D341 刷新与验证

本轮按用户要求重新检查已有方案是否能去芜存菁，修改研究结论和普查工具，不修改产品规则或生产代码。例子是 Vera：同一输入可以新增一张收入卡，同时把新的测试信息合并进旧管理层陈述；卡片数和有效信息不是一回事。

## 依 PRD 顺序复核

按 `docs/prd/README.md` 的四问复核本次影响、页面/PRD一致性、示例及验收边界。

| 模块 | 本轮结论 |
|---|---|
| 研究范围 | 不改研究对象及类别，不以小额投资或特定公司名单做硬过滤 |
| 分类 | 不改分类、源元数据和报道日期；船厂及技术文章按原始分类读取 |
| Config | 不改模型或提示词配置；研究中的新阅读顺序没有成为新配置 |
| Dispatch | 修的是离线普查对并发调用的关联，不改调度、顺序或重试行为 |
| 抽取 | 再次确认重要问题与来源内容的区别；原提案增补整篇业务更新和反证/限制，保留个人备忘录例外。未改冻结 PRD 或生成块 |
| 论点库 | 将同一陈述、共同研究意义及问题身份分开；原始引用/日期不能为压缩而消失。现有问题不可重写，新的表示方式仍需决定；不直接改旧卡或合并数据 |
| 最终裁定 | 只读取历史评判以检查最终读者实际收到什么；不改评判规则 |
| Pull mode | 不增加定时去重、自动回查或归档任务 |
| 人工复核 | 研究案例不是新增人工队列或审批步骤 |
| 系统概览 | D341 记录研究方向，未批准新的持久化层；D38/D162 边界继续明确。页面描述仍为现行系统 |
