# 同一次响应的分包：接入代码修复

这不是多次采样。原研究接入代码在读取 DeepSeek 时额外要求 `len(tool_calls)==1`。目前四个已完成的 DeepSeek 分步响应都给出多个同名工具调用。逐一合并**同一条响应**的对象后，段落键无重复，完整对象通过原来冻结的 schema、原文位置和空原因检查。原始的拒绝来自接入代码的一包假设，不是这些响应缺段。生产代码不改。

先等原登记运行完成，普查全部响应。原记录和失败分数不覆盖。在 `repairs/<sample-id>/` 下记录修复读法及尚未执行的第二步。源模型请求绝不重发；第二步沿用原冻结 prompt/schema 生成器和参数，只执行原计划因解析失败而跳过的调用。共享原预算账本，已执行次数与补完次数合计不超过 54，总预算连同沙箱失败保留额仍不超过 $1.50。协议修复发生在看到格式错误之后，报告注明；不作为未经变动的预注册比较或独立验收。

## 关闭的接受集合

仅处理完整响应（`finish_reason=tool_calls`），且恰好一个 choice。其 tool_calls 为非空列表；每一个必须是原请求强制的函数名、arguments 是可解析 JSON 对象；对象键在同一响应中不得重复。拼成的对象必须通过原 schema 和原 source_observations，缺段、未知段、坏引用、逆序引用、空原因矛盾均拒绝。不得拼接多条响应，不得覆盖重复键，不得补字段、改写内容或择优取值。

## 状态 × 事件

| 状态 | 事件 | 结果 |
|---|---|---|
| 原运行在途 | 原样继续 | 不修改运行文件/请求/预算配置 |
| 原运行结束 | 普查原响应 | 记录全体格式、分包、联合 schema 结果 |
| 单响应已规范读取 | 第二步未执行 | 在新修复目录保存固定第二步请求，原预算准入一次 |
| 已有第二步或修复目录 | 再执行 | 拒绝，不覆盖、不补抽 |
| 第二步在途 | 有效响应 | 保存完整响应，按同一读法验证，旧 sift 后另存结果 |
| 第二步失败/网络异常 | 任何失败 | 保存失败、不重抽；未知费用继续占用 |

## 值 × 读者、新路径 × 旧检查

| 值/路径 | 写者与读者 | 保持的检查 |
|---|---|---|
| 联合对象 | 只从单条原响应读取；source_observations 消费 | 原 schema、所有段落键、原文范围、空原因；无重复键 |
| 来源陈述 | 原 source_observations 生成；原 route_request 消费 | 内容不改，第一步请求和响应不改 |
| 补完的关联 | 原模型和 route prompt；旧 sift 消费 | 原目标集合、必填项、source/link/candidate/group 检查 |
| 研究计分 | 分析优先读取修复目录，并保留未修复计分 | 原 31 个标签、核心 18 条、所有语义要求不改 |
| 原始失败 | 原存档 | 永久保留；报告它是接入失败，不能说模型没读到 |

零成本正例用存档 004；坏函数名、重复段落、漏段及坏句号 mutant 必须被拒绝。抽掉重复键检查的代码 mutant 必须使检查失败。此修复仅改变同一响应的封包读取方式，不允许补救语义错误。

## 费用与时间的完整性

修复结果合计原第一步响应的 usage 与新第二步响应的 usage，第一步的收费绝不能漏掉。原第一步因为解析提前退出而没有 metrics 文件时，从已保存的 response 取 token、缓存命中和型号，从 failure.json 取该第一步经过时间（含微小本地开销，标为近似）。第二步另存实际经过时间。两步时间之和是“模型步骤时间合计”，不包含先完成原实验再补第二步之间的等待，不声称是一次不中断产品调用的端到端延迟。费用使用两步的原始 token 和原计划费率估算，共享 budget journal 仍是保守上限的依据。
