# 总论点与底层 Thesis：小规模技术实验

状态：实验计划，不是生产设计或冻结决定。Alex 已要求开展 POC；不改封存库、不重跑抽取、不改线上 UI。

## 要回答的产品问题

目标是供 agent 阅读的总论点，不只是文件夹。总论点必须提出有边界的业务判断，逐项指出底层 Thesis 如何支持、挑战或限制它；下层保留独立身份、判断与证据。主题归组和总论点综合是两步，不用“平均分”把它们混成一步。

例如：Rubin 商业化是否足以支撑 NVIDIA 下一阶段增长？量产时间、Vera 收入、客户部署是不同下层问题；不能因为关键词都相似，就把它们认作同一个判断。

暂按“总论点有判断、支持与反证，不另造独立 ladder”做可逆实验。已向 Alex 询问这一点及比较标准；语义评审仅作为作者观察，不冒充已经接受的金标准。

## 数据与公平比较

- 读取同一份 `sealed-2026-10-24-run3-through-0815/views.sqlite` 和现有向量索引，记录文件指纹；源连接只读。
- 主集：全部 23 条 NVIDIA Thesis。跨公司探针：v1、v17、v28、v34、v54、v55、v81、v94，共 31 条。探针覆盖云资本开支、融资、AMD 平台及客户部署、CoreWeave 电力、TSMC 投入，不是预设正确分组。
- 最终比较使用相同 31 条、相同最新时点、相同摘要生成合同；每种模型方法做三个独立样本，每个样本有独立调用档案，避免缓存充当重采样。
- 流式 POC 按创建顺序分为四个历史快照（seq 6、166、373、584）。每个快照只读取当时已创建的 Thesis、当时的判断和关系。禁止将最终判断提前用于早期归组。
- 所有分组方法共用 `search.view_text` 的不可变输入：object、kind、looks_at、question 和全部 rung conditions。C/D 读取同一文本，不额外读取当前判断；A 使用这段完全相同文本的缓存向量，并检查文本指纹。B 额外使用已有依赖边，这是被比较的图方法特性；本研究比较完整方法，不声称控制住全部输入信息的算法排名。
- 综合步骤的输入对四方法完全相同：同一最终快照的真实判断、标签、条件、完整 reasons 和已引用证据文本。封存库中的问句/期限质量不在本实验修复。
- 快照读合同：views.created_seq <= cutoff；judgements.seq <= cutoff 后取 (seq, judgement_id) 最大者，没有则 null；rung 通过该 view 的 rungs 表解读。dependencies.seq <= cutoff，resolution 也只取 seq <= cutoff 的最新一条，目标必须已创建。证据及链接也须在 cutoff 内；不调用返回最终状态的 current_state/dependencies_of 代替快照查询。day-end 的 judgement 只有其 seq 已到达才可用。

## 四种方法

| 方法 | 分组机制 | 总论点生成 | 要观察什么 |
|---|---|---|---|
| A 向量密度聚类 | sklearn HDBSCAN；现有标准化向量，cosine 距离；最小组 3，噪声明确保留 | 同一个综合提示词 | 是否把收入指标混在一起、产品链是否被拆散 |
| B 图社区 | 仅用现有明确依赖边构造无向候选图，NetworkX Louvain；孤立点明确保留 | 同一个综合提示词 | 因果相连是否导致业务主题串成大团；图缺边的影响 |
| C LLM 全量归组 | 一次读取同一批 Thesis，提出有范围定义的组 | 同一个综合提示词 | 初始归组及跨公司综合质量、样本之间是否稳定 |
| D LLM 增量归组 | 四个快照；给新增 Thesis、既有组范围和代表成员；只归入、建组或保留独立，不重分全部历史 | 同一个综合提示词 | 早期决策锁定、碎组增长、历史稳定与新判断更新 |

A/B 的超参数固定后不根据输出美观调参。三个样本的 C 是重复控制；A/B 分组确定性部分不把重复计算冒充独立统计样本。D 是最小增量基线，不预先加入自动拆并规则。

## 统一输出合同

- 分组输出：范围名称、范围描述、成员 ID；未归组 ID 单列。每个输入 ID 必须且只能出现一次；输出不得新增事实或 Thesis。
- 综合输出：每组可有一个总论点，或明确 `insufficient`。每个判断句携带底层 Thesis ID；支持、挑战、背景三类关系；局限与下一步需验证的问题单列。不能只写主题名称冒充业务判断。主要依据必须含本组成员，也允许引用同一快照中的其他组成员，明确记录跨组支持边；主题主归属是分区，总论点支持图可以多对多。
- 对没有足够信息的组，允许不给总论点。单条事件不强行包装成宏大叙事。
- API 引用必须真实且在快照内；跨组引用明确列出。代码检查结构和引用，不能据此宣称语义正确。

## 检查与限制

- 三个重复样本比较成员对的一致性，避免组名/编号变化导致假差异。
- 报告组数、单成员/噪声数、最大组、覆盖与非法引用数、跨公司组、增量每步新增组数、输入/输出 token、耗时。没有被接受的人工 gold，不报告“准确率”。
- 同一组的支持/挑战并存不算错；相反，漏掉反证才需人工核查。
- 语义观察逐条引用输出，不用另一个 LLM 打分取代阅读。不注册固定“正确组数”。
- 运行上限 48 次 HTTP 模型发送尝试，使用现有 OpenAI / gpt-6-luna。实验 transport 只发送一次，不使用默认 transport 的三次重试。发送前持久化 started 状态和预算预留；完成后记录 usage 并释放未用预留；失败或 uncertain 保留预留。仓库价格估算上限 8 美元，预留使用请求 UTF-8 字节数作保守输入 token 数、max_output_tokens 作输出上界；达到就停，不提高上限。费用是仓库单价估算，不称供应商账单。模型、服务商不切换。
- 依赖只使用当前环境已安装的 numpy/scikit-learn/networkx；版本入清单。不引入 GraphRAG 全套或声称 Louvain 等于 Leiden。
- 结果写入全新带日期的实验目录与独立模型档案。下一轮抽取前，本实验至多提供设计建议。

## 补充对照 E：先总论点，后论证关系（独立探索组）

产品目标是总论点，不是主题标签；因此在 A–D 参数和标准冻结的同时，补充一个不同架构的探索组。E 使用相同最终 31 条快照、相同来源限制与三份独立档案，直接提出有实质内容的总论点并引用下层，允许多个总论点共享同一底层 Thesis，不强制每条输入都成为某个主题的成员。它不依赖 A–D 的输出，也不据 A–D 的输出修改提示词。

- 每个样本一次直接综合、一次相同 agent 阅读探针，共六次额外 HTTP 尝试；总计划由 39 次变为 45 次，仍在原 48 次/8 美元上限内。
- E 的每句仍必须引用真实下层 ID；可声明不足以形成判断；明确列出未使用的原子观点。没有独立总分或新事实。
- E 的输出不是互斥分区，因此不拿 ARI 和 A–D 硬比。比较独立覆盖、重用率、引用合法性、跨公司支撑、费用，以及逐条人工阅读总论点和 agent 的回答。
- 先保存 A–D 的完整结果，再运行 E；不在正在执行的 A–D 代码中更改机制，不把探索组当作预注册的胜者。

## 定向机制诊断：重看早期未归组观点

D 的前两个样本都把早期的 v7 留在组外，后续新组没有重新接纳它。待 D 三个样本完成后，使用每个样本的最终组和同一批输入，追加一次只重看未归组观点的调用；旧成员不得移动，主题边界不得改写。三个调用仍在总 48 次上限内。它只验证“重新查看孤立点能否改变这个机制”，没有额外生成总论点或重跑 agent，因此不能据此宣称 agent 质量提升。这是看到具体失败后的修复诊断，不列入 A–E 的公平排名。
