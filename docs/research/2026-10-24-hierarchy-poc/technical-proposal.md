# 总论点层：技术方案草案

状态：基于本目录 POC 的建议方案，等待 Alex 的产品选择；不是已批准的生产实现。实验结论和限制见 [findings.md](findings.md)。

后续核心验证：[历史重放](../2026-10-24-main-thesis-replay/findings.md)曾发现引用配对不稳定及反证遗漏；新的[依据与总结分开实验](../2026-10-24-main-thesis-basis/findings.md)在固定的两个问题上改善了这些行为，但更简单的直接综合对照也达到相同核心结果、成本更低。下列存储及接口仍只是草案，不是已批准的实施清单。

## 产品对象

本轮目标不是把卡片装进文件夹，而是为 agent 提供一组可继续追问的业务判断。一个总论点需要回答“我们目前相信什么、为什么、什么会推翻它”。

例子：`Vera Rubin commercialization` 是主题；“Rubin 的量产与客户部署支持增长机会，但具体收入确认仍不确定”才是有待验证的总论点。不能将组名直接冒充总论点，也不能把几条底层分数取平均。

保留三个不同对象：

| 对象 | 负责什么 | 不负责什么 |
|---|---|---|
| Atomic thesis | 已有问题、梯子、期限、独立判断与证据 | 不因归组而合并或改名 |
| Research cluster | 一个稳定、可解释的主题范围，供发现、检索和组织使用 | 不自动代表一个看多/看空判断 |
| Main thesis | 基于当前下层判断形成的、有引用的综合业务判断 | 不宣称自身是新的已发生事实；不从现有经营数据推断股价回报 |

同一个 atomic thesis 可以支撑多个 main thesis。主题主归属用于导航，论证边可以多对多；不能因为同组就补一条因果边。

多条下层 Thesis 引用同一条证据，不等于获得多份独立确认。综合输入按 evidence_id 去重，主版本保留它引用的下层判断版本和证据来源；不能把“下层三票支持”当作独立事实计票。

## 建议管线：先保证论点有用，主题只是材料组织层

1. 新建 atomic thesis 正式写入后，用语义检索、对象/产品线索和现有依赖找到受影响的研究邻域。主题归属是候选索引，不强制一组对应一个总论点。
2. 同时回看邻近的未归组观点，避免早期独立出现的关键问题永远被排除；仅处理新观点的 D 在三个样本都漏回 v7，回看诊断三次都补回，但组粒度仍不一致。
3. 在邻域内先形成有边界的综合判断，再确定支持、挑战和背景链接；匹配已有 main thesis 的问题身份，形成新版本或新论点，不按每次模型输出序号覆盖旧对象。
4. 更新导航用的主题成员与交叉引用。只有足够支持时才对 agent 发布 main thesis；不是每一个税率、软件版本或单独事件都需要一个顶层论点。

现有 `written` 日志已在同一事务记录新增 ID，适合作为增量输入。服务读取这份日志，按已有顺序号处理；第一版不另建消息基础设施。

新证据、下层状态变化通常只更新引用它的综合论点，不重复跑主题归组。归组出错和综合失败也不能让原始 Thesis 消失。main thesis 不必一对一绑定 cluster；它可以引用跨组材料，关联可由支撑叶子的分组索引得出。

## 数据合同候选

| 数据 | 关键字段 | 写入规则 |
|---|---|---|
| research_clusters | cluster_id、name、scope、created_seq | 稳定 ID；名字变化不改身份，范围实质变化通过新对象及关联表达 |
| cluster_membership_events | thesis_id、cluster_id、join/leave、source_seq、effective_seq、decision_id | 追加成员变化，不能覆盖过去 |
| main_theses | main_id、scope、created_seq | 代表一个持续跟踪的上层问题，不能按每次生成结果换身份 |
| main_thesis_revisions | main_id、revision、as_of_seq、claim、limitations、watch_questions、input_fingerprint、call_id | 每次综合形成新版本；保留引用的具体下层判断版本 |
| main_thesis_links | main_id、revision、child_id、child_revision、supports/challenges/context、reason | 归组与论证分开；同一 child 可被多个 main 引用 |
| organization_decisions | 输入版本、候选、输出、配置、调用记录 | 可回放、可解释；不在 prompt 或 FE 隐藏决定 |

可以先放在独立 SQLite sidecar 中，通过现有 view_id 连接，不修改封存库。当前试验产生的 JSON 不冒充已经存在这些生产表。

第一版只建立一层 main → atomic。将来需要 company/industry 层时，沿用 child 引用合同，但另行验证聚合规则；不在此 POC 自动递归生成无上限层级。递归层必须避免重复计入共同底层证据。

## Agent 与 FE 的读取面

- `list_main_theses(as_of, object_ids, query)`：返回总论点、边界、主要支持/挑战、更新时间和引用。
- `get_main_thesis(main_id, revision/as_of)`：返回综合判断与直接下层边。
- 下钻沿现有 Thesis API，继续取原始判断、证据与来源。
- 当前严格的 `thesis-ui/1` 保留；新增外层或独立的 main-thesis schema，不把未知字段塞进旧合同。
- 查询某个 Idea 时，选择相关 main thesis 和必要下层，不把整个主题的所有成员无条件推荐给 agent。
- 服务生成稳定引用 ID，展示名称与 ID 分离；agent 的选择应受可选 ID 的闭集合同约束，写入前仍核验外键。合法 JSON 不等于引用合法。

以上是接口形状提案，尚未对接生产 HTTP/MCP 或 UI。

## 增量状态与失败

| 事件 | 归组 | 总论点 |
|---|---|---|
| 新建 atomic thesis | 读候选主题，加入/新建/暂留独立 | 只更新受影响主题 |
| 旧 atomic 新判断 | 不换组 | 引用该判断的总论点需要重算 |
| 重复证据 | 不换组 | 下层判断未变化则不重算 |
| 某主题尚无足够下层材料 | 仍可作为发现入口 | 返回 insufficient，不编造结论 |
| 归组失败 | 保留待处理状态，成功才推进该消费者的进度 | 下层可正常读取 |
| 综合失败 | 成员记录仍有效 | 不发布半份新版本；旧版标明其时点 |
| 崩溃重启 | 按输入指纹与处理记录恢复，不重复建立主题 | 已发布版本不重写；不确定调用显式处理 |
| 主题需拆并 | 低频整理任务，记录旧→新关系 | 发布新结构版本，不回写历史 |

用 `source_seq` 记录哪些数据触发了任务，用 `effective_seq/as_of_seq` 记录这个组织或判断何时可被读取；后台晚完成的归组不能伪装成历史早就存在。对旧库的首次组织应发布为新的当前快照；若要还原历史组织，单独做有标识的历史重建。

## 验证分界

- 代码能证明：真实 ID、快照内引用、每个版本完整、禁止重复写入、无循环引用、没有越过预算或偷偷重采样。
- 代码不能据此证明：上层判断正确、反证完整、哪些跨行业联系有经济意义。
- 需要人读原始输出和依据，必要时用用户认可的边界样本评测。不用组数少、文本顺滑、引用通过代替语义质量。

## 预期实施切片

1. 选定归组机制和 main-thesis 合同；本轮四方法 POC 是这一切片的依据。
2. 独立存储及只读 agent 接口，先回填现有数据为一个新快照。
3. 接入 `written` 的增量归组；覆盖重试、晚完成、多个同批新观点。
4. 接入下层判断变化的总论点更新；只发布完成版本。
5. 最后才切换 FE 到 main → atomic 阅读路径。

每步都应保持现有 Thesis 读取可用。此草案不授权启动新的全量抽取或自动改变已有论证结构。
