## Implementation decisions (what the plan left to the implementer)

| Decision | Choice | Why |
|---|---|---|
| Where legacy answers become canonical | At the three model boundaries that read an answer: `extraction.sift`, `matching.check`, `judging._record`; and at the consumers that compare stored values (`service` tier counts, the UI adapter's kind and tier maps). Storage readers return rows as written. | Stored requests of the Chinese configurations stay byte-identical (their builders print the stored values), so a cached replay of an old configuration still costs nothing; new writers store canonical values. |
| Which prompt version is English | Extraction version ≥ 6 (`role-v6`, `categories-v6`), `matching-v2`, `judging-v3`, `idea-v11`. The schema, the dynamic request text and the retry note follow the version. | The version is the one switch Config already owns; no environment flag. |
| Schema enums | English enums only in the new schemas; `direction` becomes an enum of the four canonical values in `matching-v2` (it was free text). | Code over prose: the schema refuses an unknown value before any check reads it. |
| Year text | `universe.canonical_year(object_id, text)` full-matches the accepted single-year forms (FY2027, FY 2027, fiscal 2027, fiscal year 2027, 2027财年, CY2026, calendar 2026, calendar year 2026, 2026自然年, bare 2026) and writes `FY2027` for a company whose fiscal year differs from the calendar, else `2026`; multi-year and unknown text stay as written and never resolve a waiting dependency. Applied when a view and a dependency are written. | The waiting-dependency join compares year text; two spellings of one year must join, two years must not. |
| Half-year filter | `QUARTERLY` gains the English revenue forms (H1/H2/1H/2H revenue or sales, first-half/second-half revenue, half-year revenue); an event scheduled in a half-year is not matched in either language. | Review finding 4: translation must not bypass the admission check. |
| Successor orientation | Numeric bounds first (`lo`/`hi` on both ladders), the prose parser (now with billion/million/trillion) only when a ladder has none. | Every rung of the English library carries bounds. |
| Score orientation in bundles | `bundle.view_bundle` carries `lo`/`hi`; the UI adapter orients a theme ladder from the bounds and falls back to the prose magnitudes only without them. | Review finding 2: 12 of 18 themes reversed without `condition_zh`. |
| Universe | New version `poc-2026-10-25-en1`: theme names in English, the Chinese names kept as aliases; `resolve` also matches aliases. | The extraction request prints the theme catalogue; the English request must not show Chinese names. |
| Preflight | The request parsers accept both header languages; part D checks each prompt file against the enum set of its version. | The $0 replay must cover English requests before the first paid English call. |

## Conclusions at the end of 2026-10-25 (Alex: "做到了什么 / 做不好的是什么 / 抽取质量好吗 / grouping 有成功吗", judged as a product manager and a hedge-fund analyst)

**Done.** The pipeline reads the original English sources and writes an English library with no translation step: 20 seed documents and the week 2026-07-24..31 were built three times (ungrouped poc-v17/18, grouped poc-v20, grouped poc-v21) with comparable numbers; every stop was traced to its cause and fixed where the rule lives (four code rules, two prompt-fidelity corrections), each proven on stored data before a rerun. Research groups are in the default pipeline: a group is a named matter, code decides its identity by names and keeps a company's own lines out of it. The grouped week: 45 theses, 365 evidence, 0 duplicate keys, 5 groups, 13 memberships, 0 wrong memberships, the first successions (2027 capex, Amazon FY2027) and the Rubin rollout holding its customer deployments. Published-rate cost of the whole day's model work: $1.76.

**Not done well.** (1) The unit of thought. 26 of 45 theses are a company's own reported lines; the week's biggest NVIDIA story (the OpenAI financing) opens no thesis in any English run, trivia still opens (RTX Spark, NemoClaw), and the AI-spend aggregates stay as near-duplicates under different scopes. An analyst would open two or three theses about the financing cycle and one about hyperscaler capex, not seven lines of guidance. (2) Groups are structurally right and semantically coarse: one group holds the capex cycle and the Rubin rollout, four groups have one member, 13 of 45 theses are grouped, and nothing can split or merge a group after creation. (3) The graph the idea card needs is nearly empty: 1 dependency in the grouped week (6 ungrouped, 21 Chinese), a translation loss not yet repaired (`matching-v4` staged). (4) Stability is unmeasured: each run's thesis set differs by a few theses (sovereign-AI revenue, the notes offering, H200 appear or not), and every configuration was run once. (5) Evidence fans out onto the two NVIDIA revenue theses (138 of 365 pieces link to several theses) and the judge flags "changed" without a rung move 42% of the time.

**Extraction quality, as an analyst.** What is captured is captured faithfully: quotes exact, tiers right, fiscal periods and due days right after the bare-year fix, ladders numeric and valid in every kept candidate, and the model restates the question the way a desk would ("Can sustained demand drive FY2027 data-center revenue into which range?"). What is chosen is weak: the library mirrors the documents' reporting lines rather than the debates that move the stock (circular financing, demand sustainability, custom-silicon share, China access is the one debate it does track). Capture 8/10, selection 5/10, identity 7/10 (keys end spelling duplicates, not meaning duplicates), grouping 6/10.

**Did grouping succeed.** The mechanism did: on the real stream the decisive relation held (Rubin shipments with the SK Telecom and NAVER factories), company lines stayed out, no wrong membership in a week, cost no higher than without groups. The quality did only in part: the breadth of a group is fixed by its first declaration and the model fused two matters on day one; every membership in the final run was the model's own citation (the alias rule reproduces 9 of 13 and added none); one product figure (Vera CPU) is reached by no name. One run is not stability. Verdict: keep it on, measure it on the next window, and give the design the one operation it lacks (split or merge a group with its history) before judging group quality further.
