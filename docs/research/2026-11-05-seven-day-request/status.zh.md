## 用户要求

从测试开始日前的已有研究题库出发，连续处理七天，让之前新开的题影响后续输入；按用户的尺子，值得追踪的主题，库里已有则不重复开、库里没有则要开。证据只按有帮助/没帮助看；作者观点只要相关且逻辑清晰可以保留，并标明作者，不需要是公司事实。未经证实的说法不改成事实。金标 v5 原文件和历史成绩不动。

## 先核对评分

`topic_score_table.py` 只实现四种已确认的开题判断：有题不新开、没题新开为正确；有题又新开、没题也没开为错误；金标可选或“同主题是否已有”无法判断时不计分。七个输入控制通过，旧的“无论已有题与否都要求新开”反例被拦住。这个程序**不能决定两句话是不是同一主题**；需要独立读者对原文、金标题和模型当次看到的题库做语义核对，然后再和模型输出对比。金标没评价的新主题不能自动当作错题。证据按 D372 将冻结金标 core/supporting 合并为 helpful、not-kept 为 unhelpful、optional 为中性。第三方观点不因是观点而排除。

## 为什么实际新版本还不能连跑七天

最新的简化 A prompt 只输出问题、理由和原文，没有生产写库所需的对象、到期日、档位等字段。它的实验实际只发送请求，不会匹配、写入或产生下一天题库。老版产品 replay 能写库但使用的是合并的旧抽取 prompt；原始拆分 POC 也使用另一份旧 A prompt，且停在交接。原型 join 只对合成匹配决定调用写入，不能证明实际新问题可写库。独立只读复核：`independent-implementation-review.md`。

因此，用旧版跑七天不能当作新版分数；用人工构造或模型仅提议的问题冒充系统真正开题，也不能正确衡量后续日期的实际输入。目前**没有发起七天模型运行、没有七天分数**。为完成用户请求，需要先将实际简化 A 和选定的 B 接到真实匹配、写入与次日读取，并用已保存的真实回答验证完整交接，然后运行同一个冻结配置。相关 prompt/产品行为若需要改变，必须清楚披露；不能静默改成旧 prompt 或更改冻结金标。

## 独立评分复核

独立只读复核确认四格计数符合用户的话，但它只对已知值得追踪的金标题作决定，不能计算所有新开题的准确率，也不能发现两个新题同时重复、或多个与金标无关的错误新题。语义映射、实际写入结果及不计分原因都必须另列；不能将这张表的正确比例称为整体开题 precision。完整复核：`independent-score-review.md`。

## 2026-11-05 用户新决策：选填信息不挡开题

用户明确要求：日期等信息未来可由研究 agent 补充，不能用当前手写代码把它们设为入库硬门槛。新的 PRD 允许观点和文章证据先入库，日期、核对材料、期间及判断区间未知时留空；预计日期不是确定日期。无区间时暂不进行区间判断，观点和证据仍可继续积累。这个产品决策不更改冻结金标或旧成绩。七天 POC 仍需使用 08-28 的真实历史题库作为起点并把实际写入带入后一天；接线状态与运行状态以本文件后续结果为准。
