# Seven-day split POC: incomplete research records

Alex's 2026-11-05 decision supersedes the previous mandatory date/ladder admission. The 68-question Aug 28 ledger is copied, not seeded from the future. A and B use the actual open questions at day start. A identifies new questions and associated evidence; B identifies evidence for already shown questions. The POC must use the real matching and writing machinery. No candidate receives a fabricated deadline or ladder. A blank deadline does not close; a missing ladder has no ladder judgement and continues collecting evidence. Separate agents could enrich it later; this POC does not invent an enrichment workflow. It keeps the existing gold unchanged; gold topic matching is against each article's actual shown state. Existing score measures remain historical and are not claimed as production acceptance.

| State/event | Behavior |
|---|---|
| Before item | read the exact start-of-day questions from isolated copied ledger; record item, request and snapshot |
| A and B returned | retain source-backed A questions and B evidence; preparation derives only subject and attribution needed by the existing writer; unknown optional fields remain empty |
| Unknown date/ladder | store question and evidence; do not auto-close or send a ladder judgement; next-day reader still shows it |
| Known date/ladder | preserve evidence-supported model output when present; a known deadline is not evidence of an outcome |
| Failure of either call, matching or write | record failure and stop the run; never treat as a pass; retry only with same preserved state |
| Crash/resume | use existing ledger's sequence/handovers; raw requests and responses remain in archive; no concurrent writers |
| At day end | judge existing eligible questions; preserve unjudged questions; next day uses the new actual ledger |
| Source changed or another writer | immutable source snapshot and one isolated writer; refuse mismatch |

| Value | Source | Readers |
|---|---|---|
| A question and its evidence | A answer and original article | actual matcher, writer, next-day A/B, scorer |
| Subject and source attribution | model preparation from question and original article | actual matcher and evidence writer; raw answer kept |
| Optional date/ladder | only when known | close and judge, respectively; unknown stays blank |
| B links | B and actual day-start IDs | actual matching and writer |
| Final identity | actual matching/writing | next-day input and post-run scorer |

## Review follow-up

The prior independent review `optional-fields-design-review.md` found the first design incomplete. Alex's exact words are now recorded in `docs/DECISIONS-log.md` and at the head of PRDs 05 and 06. For this POC the four combinations are: (1) no date/no ladder: retain, no ladder judgement, no date closure; (2) date/no ladder: retain, no ladder judgement or auto-closure while it is unjudged; (3) no date/ladder: retain, permit ladder judgement, no date closure; (4) date/ladder: existing legacy behavior is unchanged for pre-existing records. The user's design is stronger than (4): estimated dates cannot close unresolved new questions. Therefore the POC must not turn any optional/estimated date into an exact `due_day`; new simplified-A records leave that legacy field blank and preserve the original check wording as provenance. A future implementation with typed exact/estimated dates must implement confirmed-result closure explicitly; this POC does not claim it does.

A candidate always retains its exact A question and original supporting quotes and summaries. Identity uses a model-supplied subject when available, the existing universe resolution and actual model matcher; no code-typed financial importance list or inferred category is used. Missing dates, periods and rungs are empty, never made up. Evidence gets code-assigned unique IDs; each A/B source passage and summary is saved independently, with correct destinations and original source attribution. The same quote with different meaning is not merged; exact A/B repeats remain two attributable records and are not independent sources. Matcher outcomes determine whether candidate-linked evidence goes to the new or merged question; a skipped candidate is reported. All raw A/B answers, provenance, snapshots, and handover are persisted before matching.

The independent review identified crash boundaries and incomplete historical provenance; the POC must show these limits and cannot claim the starting library is exhaustive. The dated manifest must preserve complete body/version hashes, the input chronology and unknown provenance and never use future-dated material. The actual source list and frozen snapshot are held before a send. A new candidate's future reading and linkage are verified on the real writer, with fake external decisions labelled as such, before sending real model calls. The review does not authorize POC execution until these conditions pass.

### Experimental handover field mapping

For each article, persist the exact A and B requests, snapshot and provider responses. A metadata-only model request reads the article and A answer and returns one position-bound candidate entry and evidence entry per A item. The exact A `question`, `why_it_matters`, `why_not_already_covered`, `how_and_when_to_check`, source `quote`, `what_it_shows` and `original_speaker` are retained verbatim in the archive/sidecar. Candidate `object` and `kind` come from that metadata model; `looks_at` and `question` both preserve A's question; `year`, `due_day` and `rungs` remain blank when unknown; `evidence_ids` are positional local IDs and `group_refs` empty. Source `speaker`, `original_who`, optional `original_day`, `tier`, and `event_time` come from the metadata model; it sees the original article and A `original_speaker`. B supplies its existing evidence fields unchanged; code assigns unique local IDs and verifies its links refer to the day-start snapshot. Matching validates subject resolution; an unresolved subject is a recorded failure, not a fabricated result or a measured pass. The metadata model cannot add or remove an A question or evidence; position/count mismatch is an explicit incomplete item. Preserve actual original article text and check source quotes against it. Existing generic matching/check/writer remain the destination owners.

Every meaning remains a separate evidence record even when quotes match. All records retain the same actual source ID; this does not claim to have decided whether different summaries refer to the same fact. The current writer does not mark same-input cross-lane same-claim relationships. This is a disclosed POC limitation: the later judge might double-count; actual generated articles containing such repeats must be traced. Candidate-only evidence dropped on a skipped candidate remains in the preserved raw A answer, not in the research ledger; the skip is counted as a matching outcome.

No claim of full crash recovery: any interrupted run preserves outputs and its isolated ledger, marks itself incomplete, and is not resumed silently. Per-step resumes require a separately tested design. Days complete serially; no shared writer or mutable source. Seven-day source-version exclusions and unverified start-library provenance are reported in the manifest. This plan enables a first bounded diagnostic, not acceptance.

Mapping review correction: an A candidate's every evidence item has `links: [candidate_id]`; B uses only shown existing IDs. On all candidate merge/succession outcomes, verify that the candidate's resolved subject is the stored target's subject; an identity mismatch makes the item incomplete rather than silently routing it to another company. This identity check does not decide importance or make optional dates mandatory. For the one-article pilot, the model-supplied source attribution, dates and tiers must each be independently read against the source before writing; a quote's presence alone does not prove attribution. Unknown original dates stay blank. The next offline proof must include every A evidence and a source-backed B fixture on the same article, and exercise actual matching/writing; a further real B/metadata call follows only once that proof passes. A/B duplicates from a single source are explicitly disclosed and judged by source identity, not counted automatically as independent.
