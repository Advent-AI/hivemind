# Narrow storage slice: missing date and ladder

This incremental slice implements and tests only the effects of a missing date and/or ladder in the existing real library. It does not implement an A/B adapter, duplicate handling, subject inference, paid calls or recovery. Those remain open in `optional-fields-poc-design.md` and must be designed before the POC. Alex's decision is quoted in `docs/DECISIONS-log.md` and PRD 06.

State × event: a real writer stores a question with each of four combinations: date blank or known, ladder blank or present. At day-end, no date never closes; no ladder never closes or gets ladder judgement; both present keep the historical behavior. At next-day read the three incomplete combinations remain open. A later evidence arrival preserves all links and can be read; a ladder-less question cannot enter rung judgement. A successor with an absent ladder on either side is stored as given; no orientation can be inferred. A crash or retry remains under existing round transactions; this slice introduces no new split stages. These cases run on temporary actual SQLite storage, actual writer, pull, judgement and extraction reader, and fake only model transports.

Value × reader: `views.due_day` is empty string when unknown, otherwise unchanged; pull treats blank as absent. `rungs` is an empty list when unknown; judging excludes it, pull does not close it, and succession orientation cannot index it. `shown_views` returns the same persisted question with no invented date or rung. The old model request and gold never change. On a stored real A answer, construct a candidate directly in a test fixture only (the proposed production adapter is out of scope); actual writer with a fake external checked decision writes the verbatim question and original evidence, then pull and the real next-day reader expose it. The fixture's subject is verified against the article. B is not claimed to run. A valid dated and laddered control proves existing handling stays intact. A mutation removing blank-date and blank-ladder handling must fail.

New path × old checks: real matching and writer do not enforce extraction's old ladder check; this is an intentional isolated test of the new PRD, not proof the live extractor admits incomplete candidates. A future POC must solve the adapter/duplicate/recovery issues raised by the independent review before a real seven-day run. Source records and the gold are untouched.

Independent review corrections: test an undated but laddered question through the real judgement round using a fake external model and verify a judgement was actually written. Use `round.run` with fake external matching responses, not a fabricated checked plan, for initial and later evidence; add a succession whose prior or next ladder is empty. The extraction day-start reader verifies the question only; `research_context.Reader.expand` separately verifies both stored evidence links. This is an offline slice only and does not solve the separate split-adapter issues.
