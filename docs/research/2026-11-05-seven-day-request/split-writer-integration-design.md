# Experimental integration: split extraction to real matcher and writer

Alex explicitly asked to connect the tested new-question lane and existing-question evidence lane to the real system, then simulate seven days. The goal is an isolated experiment, not a default switch. Keep the last-tested simple A system text and schema, and the completed single-call B2 evidence lane; B's newer two-stage v3 stopped before linking, so is not silently represented as complete. A and B read the same source and actual day-start library. Their outputs are not considered written until the real matcher and writer run.

The simple A output lacks the 19 candidate fields, five rungs, date and keys the existing writer requires. It also does not provide the existing evidence-tier fields. There is no lossless deterministic way to derive those fields from its free-text output. Therefore an **additional record-preparation call** takes A's actual outputs and source, and emits only the production candidate/evidence shape; it does not select new topics or add evidence. Rungs and dates are analyst decisions and can change downstream behaviour; this is a third model call, not mere mechanical formatting, and its raw answer, omissions, added assumptions and refusals are separately evaluated. The record preparation prompt/schema is derived from the existing v74i schema and candidate-writing rules and keeps A's topic text and source quotes as given. This preserves the actual simple A inference, rather than replacing it with an older A prompt. B2 emits its existing evidence shape. Code assigns identity and joins; no list of important topics, keyword matching, or fake semantic decision is introduced. If the preparation cannot make a valid representation, preserve the result as a failed handover, never count it as a pass or write a made-up record.

## State x event

| State | Event | Effect and date |
|---|---|---|
| Before item | Both requests prepared | Same stored article, day and day-start question snapshot; record request hashes. |
| A/B in flight | Either fails, invalid schema, or source changes | Keep all responses; item is incomplete; do not write either lane; retry only according to explicitly configured transport policy, never silently classify as empty. |
| Both returned | A has no questions | No candidate-format call. Existing-lane evidence proceeds through checks and actual matcher. |
| Both returned | A has questions | Prepare records for exactly those questions and their evidence. Preserve A question string and exact quoted text; missing or added question/evidence is refused, not rewritten into success. |
| Formatter returned | Shape, identity, source or existing product checks reject | Preserve raw; report refusal with reason and affected source; do not make a synthetic candidate or silently retry it as a network failure. |
| Valid handover | Actual matcher and writer complete | Use `views.round.run` actual lists, Jev matching/checks, second-pass and `writing.write`; next day reads whatever actually committed. Same-day reads use the product day-start snapshot. |
| Matcher fails, conflict, writer fails | Earlier lane calls have completed | No successful item claim. Real code records failure; remain resumable only from the preserved immutable input and outputs. Do not assume failed item was written. |
| Run crashes | Some calls or writes persisted | Retain archive and per-item status; reconstruct the exact prior request to use recorded responses. Completed writes are not repeated. Source/config/prompt hashes are pinned. |
| Day completes | Later date | Next day uses the ledger after committed writes, not the initial or final seven-day snapshot. No future publication input. |
| Another writer or changed config | Source or ledger altered | Only one writer in isolated dated directory; refuse changed inputs rather than combine runs. |

## Independent review: required resolution before a full integration

Read-only review: `independent-integration-review.md`. It found six substantive gaps, so this design is **not approved for a seven-day run**. The next permitted slice is a standalone candidate-preparation feasibility probe on a stored A answer, not a claim the A/B handoff is solved.

### Field-by-field preparation contract

| Stored field | Input and allowed derivation | What must be checked |
|---|---|---|
| question | verbatim A `question`; code owns the ID | Exact text retained. No second idea or topic decision. |
| object/kind, looks_at, measure/scope | model interprets the actual A question using source and universe | Cannot broaden/narrow a supplier, company, quantity or condition; uncertainty is not made into certainty. If unresolved, do not write. |
| year, period_start/end, due_day | A question's period, its stated resolution/check source and company's actual fiscal calendar | Source date versus analyst check date distinguished. A month or an expected report date does not establish an exact day. If no supported or explicitly labelled check date compatible with the real writer can be made, mark incomplete; do not manufacture a date. |
| rungs / bounds / unit / basis | analyst-defined mutually exclusive outcomes for the **same** A question and its source, per frozen standard; 2 yes/no or 5 numeric | New ranges are analyst-generated decisions, not facts from the article. Numeric ranges cover all possibilities without overlap; currency/unit and GAAP basis not invented. If no meaningful neutral reference, incomplete rather than fabricate. |
| opens_as, settled_by | frozen standard's reasons and A's stated check source | The formatter is not authorized to reject significance or choose a new question. Incompatible fields reveal the integration cannot encode this A result. |
| group_refs and new_groups | source-backed ongoing matter under existing group contract | A company alone is not a group; no unsupported new associations. |
| A evidence quote, one_line, original_speaker | copied from A, not rewritten by model | Code preserves exact original quote and meaning; source check may refuse, not quietly repair this A handoff. A's speaker string is retained as provenance even if the writer needs a more structured form. |
| speaker, original_who, original_day, tier, event_time | source and A evidence context | Author views remain admissible, tier labelled as view; no guessed date or attribution. Full structured fields checked independently against article. |
| B evidence and target links | raw B2 response against same library | preserve actual quoted statement, meaning and source; code allocates unique IDs before mapping references. |

### The exact-quote collision is a real open defect

Read 106 stored split-experiment answers (535 evidence records). Two answer instances contain the exact same quote with two different summaries; both are the same source article's total-revenue and data-center-revenue statements. The current `sift` merges by quote and retains only total-revenue summary, adding the data-center target to it. E.g. `poc/data/parallel-b-link-2026-11-05-v2/gnews_3df0bbc8aff2c1d008bc0a32-control-3/result.json`: `e1` ($81.6bn total, v2) and `e2` ($75.2bn data center, v10) become e1 with links v2+v10 and the wrong standalone summary for v10. This is a source-backed reproduction, not proof every matching quote means two matters. The user asked to capture helpful evidence; same quote cannot by itself establish same research matter. The actual matcher/writer and same-source provenance must be respected when resolving exact quotes across lanes or within B; a heuristic equating distinct paraphrases with distinct facts is not a proven general fix. No seven-day run starts until an integration preserves the separate meanings and doesn't turn the same source into independent confirmation on real cases. Diagnose the actual consumer consequences and compare any proposed rule on stored answers and same-matter controls before coding it.

### Durable stages and scorer

The actual `round.run` only resumes a stored complete handover; it does not persist A/B/format as independent durable steps. The existing `ParallelDay` prepares the single-prompt extraction, so it must not be claimed to run the new path. A future experimental runner must persist each exact input and exact wire-ordered request and original provider response before the next stage, bind them to article/day/snapshot, and use the actual ordered writer with a separately specified crash/restart state table. Archive hashes over sorted JSON are not a substitute for exact bytes sent. Each failure must remain visibly incomplete.

The current question truth table consumes independently labelled values; it does not supply actual topic-to-gold semantics, count all duplicate candidate openings, or estimate precision for new unlabelled topics. User-facing scores require actual writer outcomes and independently assessed semantic mapping to the actual shown snapshot, with unknowns and disputed gold recorded. This is distinct from the evidence helpful/not helpful count under D372.

### Narrow offline slice: position-bound record bridge

The independent review `formatter-slice-independent-review.md` permits an offline bridge test, not a claim of semantic or seven-day readiness. The bridge takes a saved A output, the exact source article, and an externally supplied *mock* record-preparation answer. It does not choose fields or call a model. Code owns only local IDs and A's explicit question/evidence positions: candidate question is copied from A, each quote and `what_it_shows` is copied to the output, and each evidence reference points to its original A candidate. The mock supplies the fields missing from A. A's `original_speaker` is kept as sidecar provenance, not replaced by the mock's classification.

The sidecar retains full A and mock, position mapping, each date's source-versus-analyst-check label and reason, and analyst rung basis. A labelled analyst check date is not represented as a confirmed publication date. A full production record has no dedicated due-date provenance field: this remains a design risk for automatic closure, and the mock test cannot authorize such a write. The bridge refuses malformed fields, missing and extra positions, invalid exact quote, source-side empty A evidence, date after source rules violated, or post-check changes to source quote, evidence summary, period or topic semantics. The real `sift_with_groups` is run for its checks and any changes and drops are surfaced. A same-quote collision that merges different A matters is a refusal, not a successful write. It does not address B or actual matching or writing.

The fixture uses an already saved real A/source, with **test-only generated field values**; no answer-rung numbers or date are adopted as real guidance. Negative controls mutate a quote, question count, reference, due date, summary or field structure; a different saved same-quote/two-meaning B example is used to reproduce the production loss. Exact fields, same-source references, and the real frozen gold remain unchanged. A passing bridge proves only that code can preserve known strings in an admissible synthetic shape; semantic accuracy, real provider output and the actual writer remain separate work.
