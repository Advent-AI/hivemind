# 判断的尺子，第 1 版（D3 立场金标）

写于 2026-11-02。Alex 的话："你已经改了好几次尺子了，到底什么是对的，以及你怎么 freeze。"

## 0. 一句话

一道题判得对不对，拿它和**一位资深对冲基金分析师读完同样 14 天材料后的看法**比：他认为市场原来预期什么、材料推出来的结果是多少、
相对预期是高是低；系统最后一次判断落的那一档，有没有把这个结果包进去。分析师不是我，不是写代码的人，不看系统的输出；他的看法写成文件、算出
sha256、记进决定，之后一个字不改。

## 1. 什么是"对"

- **单位**：一道金标题 × 一个时点（14 天窗口末，2026-07-14 收盘后）。23 道题：22 道种子（`poc/seeds/nvda-2026-07-01-v2.json` v1–v22，每次运行里
  编号固定）加金标 must_open 里种子没覆盖的 1 道（俄亥俄租约担保是/否，2026-07-01 的 must_open）。其余 27 条 must_open 都是这 23 道的同一赌注
  （信用支持金额 ×10、Kyber 出货 ×11、云厂商资本开支 ×5、内存价格 ×1、中国放行 H200 ×2），映射写在 `questions-v1.json` 里，Alex 签。
- **材料**：签过的抽取标准对这 14 天的读法，即金标 golden-v5（dev，118 篇）的 309 条事项（核心 86、辅助 151、可选 72），带日期、标题、
  来源层、说话人、原文和意思。不用系统的账本（账本随每臂变，尺子不能随臂变），不用原始全文（那是重做抽取）。这和抽取的尺子是同一把：标准第 5 节
  说的"分析员会记的"就是这些。
- **分析师写什么**（每道题一条，`reader-brief.md` 是他拿到的全部说明，里面只有标准和 PRD 06 的原话，没有系统的提示词）：
  1. `reference`：到 2026-07-14 为止市场预期这道题的答案是什么（一致预期、公司指引、既定计划或截止日），出自哪几条事项；材料里没有就写
     "没有，参照 = 现状"。
  2. `implied_outcome`：材料推出来的结果——数字题给一个数或一个区间，事件题给是/否和日期——怎么推的，出自哪几条。
  3. `direction`：结果相对参照：above / in_line / below；事件题 yes / no。
  4. `confidence`：high / medium / low（材料把这件事定到什么程度）。
  5. `decisive_items`：撑起这个看法的 2–6 条事项编号；`against`：最强的反面一条。
  6. `no_view`：材料里没有任何关于这道题的东西时为 true；这道题不进分数，记"没练到"。
  7. `reasoning`：三到六句。只用材料，不用材料外的知识，每个说法都要有编号。
- **分析师是谁**：两位互相独立、都没写过这套代码也没看过系统输出的模型读者（A：Codex；B：一个干净上下文的 Claude 读者），各自从同一个包
  写一遍。都标明"模型写的"。**Alex 定（2026-11-02，D262）：金标 = 读者 B 的 23 条答案，原样；读者 A 的答案留作对照记录**，两者的差别
  （区间或是/否不同 3/23：q09、q12、q23；方向标签不同 12/20）就是这把尺子自身噪声的记录（`reconcile-v1.md`）。
- **判"对"的方法**（`score_judgement.py`，全部是代码）：取一次运行里每道题在 2026-07-14 及之前最后一次判断。数字题：金标的区间
  [low, high] 和系统所选那一档的 [lo, hi) 有没有交集，有 = 一致；事件题：是/否相同 = 一致。没判过的题单独数（那是证据没到，D2 的事，不算
  判断错）。另外打印两条零假设：**查表基线**（把金标写的参照数落进哪一档，就选那一档）和**永远中性基线**；判断要在这两条线之上才算有判断力。
  读者之间的分歧率一起打印，那是尺子自身的噪声。
- **第二层，读不是数**：分数之外，对一个样本的判断，由没写代码的读者看系统写的理由（从 judging-v6 起还有 reference 和 implied_outcome）
  是不是从所示证据得出。这是 AGENTS §7.2 的"分数是线索、trace 是测量"。

## 2. 怎么 freeze

原则先于机制（D261，Alex 2026-11-02："我们做完的 review 过的尺子金标不能再动了"）：这一页、读者说明、题单和金标在 Alex 审过签字之后一个字不改；之前只在建的过程中改，签字前不拿它打任何分。下面是把这句话变成代码和文件的做法。

1. 读者只看 `packet-v1.json` 和 `reader-brief.md`，看不到任何运行、账本、提示词；读者的原始答案 `reader-A.json`、`reader-B.json` 原样保存，不改。
2. 我不写金标。我做的只有：拼包（代码）、按 direction 机械对齐两位读者、把分歧按材料写成对照记录（引编号）；分歧由材料定，定不了的列给 Alex。
3. 金标文件 `gold-v1.json` 带 `ruler_version: 1`、两位读者的 sha256、每道题的来源（A/B 一致，或裁定及理由）；文件的 sha256 写进
   `gold-v1.sha256` 和决定 D261。Alex 签的是：23 道题的清单和映射、裁定过的题。签之前每个分数都标"金标第 1 版，未签"。
4. `score_judgement.py` 开头读金标的 sha256 和 `ruler_version`，和自己写死的对不上就拒绝打分，打印两边的 sha；每份分数都印金标版本。
5. 冻住后不改文件。发现错了，写进 `corrections-v1.json` 一条带日期的记录：哪道题、改前、改后、为什么；打分器不悄悄应用它，只在分数旁印
   "有 N 条更正未并入"。更正积累到要并入时，出第 2 版：新文件、新 sha、决定里记，旧分数作废并说明。
6. 这一页的定义本身改了（单位、材料、字段、判对的方法），就是第 2 版尺子：金标必须重写，打分器拒绝版本不符的金标。改定义只能由记录在 Alex
   原话上的决定触发（AGENTS §7.1）。
7. 一把尺子：判断这一步不再有别的评分标准。我昨天定的判断规则 D260 是系统这边的规则，不是尺子；读者的说明里没有它。

**冻结记录**：2026-11-02，`gold-v1.json` sha256 `636c056d1e4252fa759660803067e6ccd67a81067b012905e918aa9dec4005f2`，写在 `gold-v1.sha256` 和 `score_judgement.py` 里；`corrections-v1.json` 为空。当天下午提过的两条改法（读者分叉时打三档分；五五开的题不计分）Alex 没采纳：一题一个区间，每题都算。

这把尺子作为整体（抽取标准 + 题目 + 判断）写在 AGENTS §7.1 "The frozen ruler"，每个文件的 sha256 由 `tests/test_frozen_rulers.py` 守着：任何一个动了，整套测试变红。

## 2′. 这把尺子沿用了什么，新的只有哪一层

沿用、不重做：抽取标准页（第 3 版签字 D243 + D250 的四条界线）和 golden-v5 是这把尺子的**材料**，按 sha 引用（`packet-v1.json` 记了金标的 sha）；golden-v5 的题目部分（28 条 must_open，题目标准第 3 版）映射进 23 道题；种子 v2（D253）给题的身份和档的边界；PRD 06 的判断规则和 AGENTS §8 的分析师原话是读者说明里的全部规则；桌面尺子 README 的 D1、D2 不动。2026-10-27 的步骤 3/4 金标（`research/2026-10-27-stage34-gold/`，24 例，量的是重复 / 替换 / 并入的决定，不是档位）里写的分析师标准 A（谁先说的，复述只加一个出处不加事实）、B（期间和定义要对上，季度不是全年）和这份说明一致，两者量的是不同步骤；那份金标是在旧账本上写的，助手自己写的，当时就标了不是独立金标。新的只有一层：判断这一步的档位从来没有金标，这是第一份，还有打分器。

## 3. 这把尺子不量什么

该开的题开了没有（D1）、证据挂得对不对（D2）、14 天里每天的路径、依赖和主题推力。它只量：窗口末，系统的档位有没有包住分析师认为的结果。

## 4. 已知的弱点，写明

- 读者是模型，不是人。金标是一位读者（B）的看法，Alex 选的；另一位（A）留作对照，两者在 3/23 道题上区间不交，这是尺子的噪声下限；Alex 的裁定是人的那一票。
- 材料外的知识：事后结果（FY2027 年报、2026 年底 Rubin 出不出货）都在模型知识截止之后，无法作弊；但模型可能用它记得的"常识"补材料，说明里
  禁止并要求每句引编号，对照时查。
- 参照：材料里不一定有每道题的一致预期（内存价格、CoWoS 产能），那时参照是现状，direction 的意义弱一点，分数仍按区间交集算。
- 种子的档不是围着一致预期写的（总收入题一致预期 $392B 落在中性档 350–400 的上沿）：所以分数不比"看涨/看跌"的标签，只比区间有没有包住。
