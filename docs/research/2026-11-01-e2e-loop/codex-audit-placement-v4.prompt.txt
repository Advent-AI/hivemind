Read-only review of one prompt rewrite. Scope: the placement step only (src/hivemind/placement.py and its prompt files). Out of scope, write nothing about them: the extraction prompts, the judge, the UI, the service, cost.

What changed: src/hivemind/prompts/placement-narrow-v4.txt replaces placement-narrow-v2.txt (both in the repo; read both). The change's reason, written before this review: one full placement request, read as the model reads it, holds two rulebooks that contradict each other. The v2 system prompt says a company-wide figure question "takes only the company's own reported figures, guidance, estimates of that figure and management's statements about it", while the code-written takes line of the same question (placement.py, function takes) says "figures, guidance, estimates and revisions for <scope> over <period>, and the direct drivers of that figure stated with a size". v2 also says filing under none is "a valid answer, not a failure", and the model's own account read the takes line's period as a precondition (an estimate with no period stated was filed under none although the matching question was open). v4 keeps one rule: the takes line is the rule for what belongs in a file; the system prompt only says how to apply it. Three v2 sentences were cut, one (product generations) moved to the takes line's ownership, and one sentence was added about the period.

Governing texts, in this order of authority: docs/DECISIONS.md entries D207 (placement, one home, narrowest question, no sink), D209 (evidence is what bears on an open question; dropped with reason), D240 (a missing amount, date or scale is never on its own a reason to drop a statement; weight is judged apart), D248 (one bet = one question); the extraction standard page docs/prd/05-extraction-standard.html section 5 (placement) where it exists; AGENTS.md section 6 (writing prompts: the prompt carries the standard, not new rules; a prompt serves every company; never grow a prompt to fix quality; an example is an instruction).

A sample of what the model reads: the system prompt is messages[0]; the user message lists open questions, each as "- vN (object, due day): question" followed by its takes line, then the statements as "- eN [tier] who: X | one-line summary | quote: ...". The takes lines are written by placement.py takes(); read that function, it is part of the request.
