## 2. 验收单位与业务标准

一个案例是「原文 + 本次读到的已有研究 + 应保留的重要内容」，不是一篇文章必开一个问题，也不是必须得到某个组名。每项先写原句依据和业务含义，再写允许的结果。

| 应做什么 | 合格结果 |
|---|---|
| 已有观点管不到的重要问题 | 开新观点；合适时加入已有主线，否则新建；重要内容有真实出处 |
| 已有观点能回答的新材料 | 更新那条观点的证据；沿已有成员关系可查，不强迫新建观点 |
| 同源转述或重复材料 | 保留新增出处，不增加独立证据份数 |
| 背景、广告、没有新增含义 | 可以不抽；不能用这种案例证明归组能力 |

关系分三类：必须保留、允许但不强求、明确禁止。名字、编号和可选的小组不同不扣分。仅同公司、同产品关键词不能证明该归组；同一业务过程的支持和反对材料均保留。同组不等于同一问题，也不自动产生依赖。

六层分别报告，不合成总分：

| 层 | 分子和分母 / 判断方式 |
|---|---|
| 内容覆盖 | 实际正确保留的重要内容 / 事先标出的重要内容；候选、证据分别列；漏抽与检查拒绝分别归因。多造的问题逐项列，不拿它增加分母 |
| 归属含义 | 必须关系保留数 / 必须关系数；禁止关系出现数；未审查的实际关系数。漏抽仍使对应的必须关系未满足；另列「已抽出部分」的结果，不取代端到端结果 |
| 观点身份 | 相同问题是否复用；不同量、范围、时期、事件是否被误合并；不要求所有数字都成为观点 |
| 证据忠实 | 原句、计划与事实、支持与反对、同源转述、数字口径逐项核对。原句存在只是代码核对，不等于含义正确 |
| 连续读写 | 当前选择 → 最终观点 → 成员 → 来源；同日下一条读到先前提交，重送、中断恢复、历史时点不混淆；离线快照核对不冒充已测恢复 |
| 稳定性与成本 | 同一输入重复运行的重要内容与必须关系逐项比较；记录每次错误、请求数、tokens、时长。先测新鲜对照自身变化；小样本不证明全市场规模或错误率 |

三次是初步筛查，不是「2/3 就可靠」。已覆盖的代码确定性规则须全部满足；核心关系的严重错归、错误合并、证据丢失不能被平均分抵消。即使三次全对，也只说明这些案例通过。更大范围的通过率与速度预算在对应范围登记时定，不能事后挑线。

## 4. 离线检查器合同（编码前）

入口仍为 `python3 poc/hierarchy_study/review_subject_names.py --out <原实验目录> --case dev|google|amd`，增加 `--case all` 检查全部登记样本，增加 `--json` 输出结构化报告。只读已存文件；不 import 运行器、不调用模型、不写原实验目录。返回 0 仅表示离线结构核对完成，输出必须写明非语义验收通过；记录缺失、运行失败或核对错误返回非零。零引用为 unexercised。

| 状态 × 事件 | 本轮处理 |
|---|---|
| 没有任何样本产物 / 产物不全 / 运行失败 / 记录完整 | 分别报 not_started / incomplete / failed / complete；失败不丢出分母。failed.json 优先于其他记录，即使已有结果也算 failed。complete 要求抽取、比对、结果和 checks.json 都齐全，调用状态 complete，checks.history_unchanged 严格为 true 且 resend 为 skipped；缺 checks 是 incomplete，检查值不符为 failed |
| 已完成、无候选、有或无证据 | 归组 unexercised；列原答证据和拒绝原因；覆盖语义 pending，不推断漏抽 |
| 已完成、有候选 | 名字选择与投影引用逐条比较；旧形状直接读引用；据拒绝和身份决定核对最终归属 |
| 投影少一条 / 同数量换目标 / 名字相同而范围不同 | 结构错误；不是「同样多就通过」；模糊或缺失映射报不可核对 |
| 成员属于旧输入 / 本次输入 / 未来顺序号 | 旧关系单列；本次按输入和序号双重核对；未来记录错误 |
| 缺文件、坏 JSON、原文或输入身份对不上 | 检查前提失败；输出具体文件与原因，退出非零，不伪装语义失败 |
| 另一进程在写 / 配置已变 / 后一天审查 | 只用完成的已存快照；同次读取前后摘要不同拒绝；以存下的请求为准，不拿当前配置重新解释，不读当前日期 |

| 值 × 输入 / 写者 | 读者与约束 |
|---|---|
| 原答、投影 | 模型归档、名字转换器 → 检查器；预期独立从原答和请求生成，不能复用被测转换器 |
| 当前输入和已有研究 | 已存请求与 items.json → 检查器；全文、编号一致，不凭文件夹名称认定业务含义 |
| 最终目标和成员 | 已存身份决定、new_views、bindings、threads、memberships → 检查器；本次映射与快照逐项比较；新组只在本次唯一声明与唯一写入可核对时认定，不凭同名认定历史身份 |
| 检查报告 | 检查器 → 人、测试；删除旧 core_kept/关键词 scope_errors 的伪语义数字，不再输出旧 wiring_errors 总数 |
| 旧运行器的 dev-review.json | 是人另写的文件，旧检查器也不生成；本轮不生成这个批准文件，不用结构核对结果启动留出调用 |

| 新路径 × 原检查 | 验证 |
|---|---|
| 原四份空候选 | 仍读原请求、结果、拒绝；4 次归组均未测到；6 份未执行保留状态 |
| 实际非空回答及受控副本 | 直接用 D147 sample-2-retained 的非空旧格式作正例，并将同一原答改写成名字格式作独立正例；两种格式都经检查入口，交换有效引用、删除引用、错误最终成员均须被发现。改写副本不当模型样本；旧格式的语义错归不能冒充代码接线错误 |
| 入口默认参数 | 从任意 cwd 用绝对路径运行；返回码、JSON、缺文件的负例均测；无网络和凭证 |

先前决定：D149「归属按业务过程判断」「不能混成一个一致性数字」；D150 的失败保留；D155 的当前产品修复不重做。本轮修正 D152 研究计划中以数量与名字当语义结论、以 2/3 当推广通过线的测量；旧报告留作历史。
