# 证据能支持什么：六例对照

用户授权：深读 trace，确定分层标准并开始实验。本次只检验第四步的判断方法；不是生产写入、页面匹配、第一步抽取或全周效果验收。不改旧金标和旧记录。

## 诊断与规则

完整读了旧第四步请求的系统指令、schema、正文和记录，以及 NVIDIA 四份、NN 三份、Corning 三份原答。对旧 fact-inference-v4 目录的 answer.action 全量清点：32 份回答；NVIDIA propose_new 10、background_only 2；NN background_only 12；Corning background_only 8。行为分类不是错误率。旧两种提示各模型三次：Haiku 对 NVIDIA 12 份跨模型答案中的四份明确断言 NVIDIA 提供信用支持；旧报告和模型续问指出原文没有确立提供方。不能将所有背景判断等同于丢弃。

请求 Action 段把新信息是否有用与是否足以提出改变仓位的判断相绑；普通供应商信息被示例写成背景。NVIDIA 原文支持收入分成模式，却没确定信用支持提供方；NN 有 47 台、全部预售、2026 年 8000万–9000万美元目标，回答仍称缺规模；Corning 没说明翻倍指标和终点，但有具名管理层、光纤与 NVIDIA 合作联系。模型关于 NVIDIA 的保存续问承认支持方是推断；这是线索，不是因果证明。源文本、输入片段、prompt、输出都分别保留。

单位是“一个主张用于一个判断”，不是一篇文章或一个来源一个等级。先看用途，再看来源和缺口。同一 NVIDIA 公告可用于证明公司宣布分成模式，但仅能成为追查信用风险承担方的线索。

- usable：给定来源足以支持明确且有限的结论；不是认证为世界真相。
- conditional：可支持方向或情景，但必须保留重要条件或未独立验证的性质。
- lead：值得研究，但关键桥梁未建立，不能拿去定量或断言关系；写明缺口及具体查证事项。
- reject：不在研究范围、无新增信息或没有可识别可追查主张。这里依用户排除指定新加坡案；不以此排除所有监管风险。

来源依据、信息缺口、可用程度分开，不求和。可信性按“谁对哪个主张有何接近事实的条件、证据及独立支持”说明；不能机械给官宣高分或匿名低分。报道日、原发言日、事件/预测期间分开；部分时间原样保留，未知不补。原文没有的称来源缺口；原文有而回答遗漏/歪曲的称系统错误。结论不得因先验投资方向而加减分。

## 唯一改动与六例

控制为存档的第四步系统指令。实验仅替换其 Action 段：先在已有 new_information 中表达原文能支持的有限结论、关键缺口和可追查项，再决定已有 action。保留 system 其余段、相同 schema、同一正文、同模型与设置。不新增等级字段或存储机制；由审读者按上述四级判断回答表达的用途，不用 action 标签代替语义。不是人为构造的弱二元控制。

开发四例：NVIDIA 商业模式、NN 液冷扩产、Corning 展望、用户排除的新加坡案件。检验两例：AMD 模拟比较、Google Cloud 财务；来源以前读过，不冒称从未见过的文章，但未用这两例调实验段，分别检验反证与已有完整财务信息。每臂每例三次，共 36 次 Haiku；无 Luna，无全流程。前三例为完整保存请求；后三例从冻结来源构成相同字段的研究输入，标明非原生产请求。six references 在发出前冻结。

登记目标：NVIDIA 两种用途分开，不断言支持方；NN 保留数字和供应联系不写成 NVIDIA 收入；Corning 不把 size 改成 revenue 或指定年份；AMD 不当独立实测；Google Cloud 不等于 NVIDIA 订单；新加坡不扩成可用证据。各例逐次报 useful_content、bounded_claim、source_and_time、followup 的人工判断及理由。可追查项仅对有重大缺口的用途要求；不为完整事实凭空制造任务。

采用判断：处理臂必须减少至少一个开发案例的实质误断或无理由贬低，不增加任何案例的错误确定性或误收；两个检验案例不得退化。控制三次互相比，公开摇摆，不以表面等级变化算改进。若没有改善或只换标签，则结论为不支持此改法，不叠第二轮补丁。缺失或截断明确计失败，不删除。
