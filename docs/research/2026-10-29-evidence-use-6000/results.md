# 分层判断实验：局部改善，整版未通过

标准确定为：按“主张能支持什么用途”判断可用、带条件可用、待查线索或不收；来源依据、缺口和系统错误分别记录。同一公告可证明公司宣布新模式，却只能给风险承担方提供调查线索。规则与边界在 [scoring.md](scoring.md)，原文和单项要求在各 reference.json。旧 v5 的事实忠实性要求不变。

本轮方法比较出现清楚的局部改善，但不满足登记的“不新增错误”条件，不用于产品。没有继续叠加提示或开展下一轮。

## 真实结果

完整对照为 6 例 × 两种方法 × 3 次，共 36 答、42 个主张用途观察。全部结构检查通过；逐答阅读后由独立只读审阅核对。数据为模型审读的有限开发证据，不是独立人类金标或全周保留率。

| 检查 | 原方法 | 新方法 |
|---|---:|---:|
| 把 NVIDIA 已有信用敞口当事实 | 3/3 | 0/3 |
| 保留 NN 的47台、全预售和2026年金额目标 | 3/3 | 3/3 |
| 保留 Corning 未来几年可能规模翻倍 | 3/3 | 3/3 |
| 保留 AMD 模拟比较及限定 | 3/3 | 3/3 |
| 保留 Google Cloud 三项财务数据 | 3/3 | 3/3 |
| 遵守指定新加坡案件排除 | 3/3 | 3/3 |
| 无依据断言收入表内部矛盾 | 0/3 | 1/3 |
| 以“不属于本记录”为由忽略已给的合作上下文 | 0/3 | 1/3 |

NVIDIA 的新方法三次均将经济风险作为假设或待查事项；只有第二次明确把“谁承担信用风险”列为未知。不能说所有风险归因问题已经彻底修好。控制三次都明确断言已有信用敞口，而非三次都断言循环融资已经成立。

新方法对 NN 三次都说出供应监测用途；Corning 两次展开供应研究、一次仍忽略同篇合作信息；AMD 三次至少承认竞争讨论用途，最后一次虽然仍标背景，但不是丢失。Google Cloud 新方法第二、三次承认客户背景，第一次仍把取得 NVIDIA 采购联系当作研究门槛。不能把背景标签当删除，也不能把多开页当收益。

## 必须保留的问题

1. `cloud-treatment-2` 宣称 NVIDIA 收入表内部不一致且不能使用。所附表里 NVIDIA 的季度收入从30.0到81.6，逐季增长，末值与正文一致；81.6/30约2.72也符合“接近三倍”。回答没有提供支持其否定判断的矛盾。原始数据的现实真实性未核验，不等于文本内部已经矛盾。
2. `corning-treatment-2` 说合作建厂信息来自其他条目、不属于当前记录。当前请求的全文和附带记录已经提供合作信息；这是读取范围问题。
3. 控制组也有问题：`cloud-control-1` 自行把81.6B季度写成Q2 FY27，来源给的是截至4月的季度；`nn-control-1` 漏了 late June 2026 的公告时间。两组保留目标数字不等于所有期间信息都正确。
4. 原输入已经给三个人物发言填了未获正文确认的7月1日。继承这些日期单列为输入冲突，不计处理新造错误，也不宣布日期已经验证。

## 改了什么，没测到什么

只替换 Action 一段。系统提示3830→3805字符，每个输入少19 tokens；模型、正文、schema一致。这里实测的是“先限定用途再决定行动”整段规则，不是分离证明其中某一句话的效果。

提出新问题从3/18到8/18；这不是收益，空目录试验无法判断会不会多开重复页。每次调用中位耗时6.36→9.32秒，输出tokens合计17780→26878，增长约51%；本轮没有速度收益。

第一轮因我将原请求6000输出上限缩到1800，14次已发中2次被截断。已完整保留，22次未发；随后仅恢复原6000上限，重新发完整两臂36次，没有按答案修改标准、提示或来源。两轮共50次调用，输入221439、输出63272 tokens。两轮全额保守预留合计$0.3565332，未超过既有$0.60上限；预留不是账单。见 [run-correction.md](run-correction.md)。

本次未改产品、默认模型或存储，也没有测已有问题的更新、匹配或全流程。下一项应检查完整上下文读取与研究用途判断之间的接口：当前模型仍会把“不是 NVIDIA 自身指标、没有直接采购金额”误当成缺乏研究用途。此处先保留标准与失败结果，不展开另一个未验证改法。

## 复算与审读

`assessments.json` 列42次用途判断、原答散列、理由和问题；`measure.py` 校验36答/42观察齐全并汇总，缺一条会拒绝。`summary.json` 是可复算结果。脚本不判断投资价值。`results-review.txt` 是独立只读审阅，`results-review-resolution.md` 是逐项核对。`run.py verify` 校验发送前固定的输入、提示及代码未变。
