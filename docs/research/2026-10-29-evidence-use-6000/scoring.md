# 发送前固定的判定方式

判定人读完整回答，不以 action、关键词、条数代替。每次回答保留用途等级及具体理由；不把四个维度相乘成全对分。等级描述具体主张的用途，不是概率。

1. useful_content：保留来源中的目标内容，未因资料不完备宣称毫无研究价值。背景标签本身不扣分；遗漏与无理由贬低分开写。
2. bounded_claim：区分原文确立的有限事实与经济推断。明确错误断言记错误；只提问不视为断言。未写任何结论不能据此奖励有用保留。
3. source_and_time：保留原说法的主体、预测/实测/报道性质、原有期间；不发明精确日期或假装读过未提供的原始披露。
4. followup：对实质未知给能解开缺口的查证事项，不要求所有事实都配待办。缺少下一步不与事实错误同等计分。

研究用途不要求开页；留在背景但准确说明它能支持什么可合格。试验只比较这些内容、失真及误收；新页数单列，不算收益。控制三次也按同一办法审读和展示。所有判定均为模型人工审读，不是独立人类金标。

## 判定单位与不确定答案

一共七个固定用途单位：N1 公司宣布收入分成模式、N2 谁承担信用支持风险、NN 供应商扩产与预售目标、C 供应商管理层展望、S 指定排除案件、A AMD 模拟比较、G 报道的 Google Cloud 财务。N1 只要求能支持“宣布了该模式”，N2 只可作为查证线索。其余各单位的合格内容、界线与查证项为上表；同义表达、分合句、保守地明确注明来源均接受，不要求复述标签。等级以用途而非措辞判定。每答相关单位都要判，不能挑最好的一句话而忽略另一处相反断言。

对是否断言仍有歧义的，标 uncertain 并引用原句；不自动算对或错，也不作为支持采用的证据。内容遗漏、明确错误断言、无理由宣称线索不可用分开计；不给单一综合正确率。

三次合并规则：同一开发单位、同一类问题，控制至少 2/3 次出现、处理 0/3 次出现，才称本次“稳定改善信号”；2→1、1→0 等仅为摇摆/不确定。任何单位新增明确错误断言或误收、或两个检验单位出现退化，均不能采用。即使达到，也只称有限开发信号，不是统计显著或全体能力提升。控制自己三次的不同结果也逐单位展示。所有 36 答和 42 用途观察都必须列出；不完整答列未完成，不能跳过。

保留三个历史请求的完整输入，以免把输入修正混进处理。NVIDIA 的 James Manning、Corning 的 Wendell Weeks 与 Emily Capek 的 original_day 均填 2026-07-01，正文只支持报道日、不确认发言当日。两臂收到相同冲突。回答照抄这些值单列 inherited_input_conflict，不计为处理新制造的日期错误，也不能算日期已验证；回答主动纠正可单列，但不计入本次主收益。其他自行补出的主体、日期或原文不存在的确定性仍属于输出问题。此限制随所有结果呈现。
