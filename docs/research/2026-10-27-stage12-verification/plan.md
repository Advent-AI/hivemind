# 第 1、2 步验证范围

Alex 要求认真验证抽取与查库。先在已有真实资料上检验具体要求；不改变 prompt、生产代码、金标或预算。模型质量不能由数据库查询成功替代。

## 固定检查

1. 来源：D339 全部 18 个独立来源响应、3 篇完整原文、553 条记录。原响应重建、逐段覆盖、引用位置完整性全量检查；沿用已冻结 31 条内容标注（18 核心）及 D340 明确错误案例，重新对照原文。单列条件、反证、原主体、来源拆分、日期角色。旧标注只衡量其覆盖的内容，不报全量语义准确率。
2. 新来源合同：重放原先结构正反例，确认哪些能拒绝，哪些语义错误仍会放行。新 prompt 没有新模型输出，不能称作已验证。
3. 查库：原 v29/v30 运行库的全部 677 条 matching 记录。按处理前序号重建历史状态，重算实际调用的候选/证据查询；比对保存列表并记录不一致。用原始 snapshot 在三个时间点核对历史重建，不用最终库假装历史。
4. 查库语义：历史选择不是金标。单列“能找回已保存的选择”与人工核对的 Vera 关键旧证据。另对所有抽取后证据，用现成全文搜索函数尝试“直接从来源记录查问题”，报告结果如何随归属前缀变化；这是拟议新入口的诊断，不冒称现行路径。

## 状态、读者与边界

| 情况 | 动作 |
|---|---|
| 原输入/响应缺失或结构前提失败 | 停止该检查并报告；空集合不通过 |
| 历史状态重建不一致 | 不用它作检索结论，先追溯到首个差异 |
| 全量重放完毕 | 保存每条记录的输入、结果、耗时和必要引用 |
| 反例 | 原数据不变；只在内存副本制造破坏，确认断言拒绝 |
| 质量已失败/合同仍未定 | 不靠付费重跑回避问题；提交失败证据及剩余范围 |

本轮所有新增写入只在此研究目录。来源读者为原适配器与候选验证器；查询读者为原 matching 列表构造及研究审计。保存的参考列表只作重现，不用作语义真值。原始来源、账本、回答、标签和已有研究全部只读。
