# 抽取金标的尺（2026-10-28）

这份文件先于金标、先于任何发送。它说一条陈述凭什么进金标、金标长什么样、怎么和模型输出对账。金标是模型（Claude）写的，Alex 过一遍改错后冻结；冻结后发了请求就不改，改了是新版本并写原因。

## 1. 一条陈述凭什么进金标（分析员的尺）

进：它改变一个在追的问题的答案的可能性，并且有一个数、一个日期、一个有名字的动作或一个具名的估计。四类（和提示词 role-v18 一致）：
1. 公司自己的数字、指引或决定；
2. 客户、供应商、竞争者、伙伴的有规模/日期/名字的动作；
3. 具名一方的主张或估计；
4. 政策或监管的决定或步骤。

不进：背景（"A100 2020 年上市"）、复述已知事实（两个月后再说一遍 Q1 收入）、规格和跑分（瓦数、TB、"x 倍快"）、估值算术、股价涨跌、投资人仓位、记者的框架、没有数字的政治/战略看法、公司套话。

一件事一条：同一篇里五句话说同一个部署，金标一条，列出它的所有句子；三家媒体转同一个报道，各自那篇里是一条，但说话人写原始来源。

分量：每条标 `core`（分析员当天会写进笔记的）或 `colour`（会留着但不改变看法的）。丢一条 core 比丢一条 colour 重；多留的垃圾按条数数。

## 2. 金标的形状（系统设计师的尺）

每篇文章一个块，每条陈述：

```
- id: a07-2
  span: "<原文逐字子串，8 个字符以上，定位这条陈述的那句或那半句>"
  also: ["<同一件事的另一句子串>", …]        # 可空：模型只应写一条，覆盖其中任一句算同一条
  kind: 1|2|3|4
  tier: fact | party_statement | third_party_view | rumour
  who: "<原始说话人>"
  weight: core | colour
  bears_on_now: [v2, v10]        # 按那天请求实际展示的论点（公司论点）该挂哪
  bears_on_with_themes: [v3]     # 按 A 的请求（加全部开放主题论点）该挂哪；没有主题相关就和上一行相同
  note: "<一句话：为什么它改变答案>"
```

文章块头写：input_id、发布日、类别、那天展示的论点 id 清单、那天开放的主题论点 id 清单（都从快照的请求和账本读出来，不是我记的）。金标为空的文章也写块，`statements: []`，作阴性对照。

四类都不沾但分析员会记的：写进块尾的 `contract_gap`，不进 statements。

## 3. 怎么对账（代码做，不是我打分时判断）

一条模型输出（交接前的原始答案，经过 sift 的留/丢都看）和一条金标匹配，当它的 quote（normalise 后）覆盖 span 或 also 里任一子串。然后每条金标落在恰好一格：

| 格 | 条件 |
|---|---|
| kept_right | 匹配的一条被留下，links 包含 bears_on 的任一 id |
| kept_wrong_link | 被留下，links 不含 bears_on 的任何 id |
| written_dropped | 原始答案里有匹配，交接丢了（带丢弃原因：links 为空 / 挂到未展示 id / 引文不在原文 / 其他）|
| not_written | 原始答案里没有匹配 |

另外两格按模型输出数：

| 格 | 条件 |
|---|---|
| split | 同一条金标被两条以上输出覆盖（多出的条数）|
| extra_kept | 留下的输出不覆盖任何金标（多留，按条数）|

对照组用 `bears_on_now` 打，实验组（A）用 `bears_on_with_themes` 打；两列相同的条目两组一样打。两列都空的条目（分析员会记、库里没有问题接它）只分「写了 / 没写」，落在 `no_destination` 格，永远不算 kept_right：它量的是设计（D42：没有问题就没有证据）丢掉的部分，不是模型。每格的数字后面必须跟案例 id 清单；"写了被丢"和"没写"的每一条我读原始答案并写一行原因。

## 4. 抽样和冻结

- 池：长跑快照 `snapshots/2026-10-28T1450/` 里喂过的文章，发布日 2026-07-01 到 08-18，正文 800–8,000 字符，排除我今天已经对着答案读过的 10 篇（`pick_items.py` 的那 10 个 id）。
- 分层：T7 10 篇、T8 5 篇、T6 5 篇；每类内按周分散（七周，先每周一篇再补）；随机种子 2026。
- 留出：每类按种子顺序最后 2 篇（共 6 篇）为留出集，任何提示词决定不看它们。
- 写金标时只看原文、那天的展示清单和主题清单；不看模型答案。
- 冻结：`gold-extraction.md` 写完记 sha256 到 `gold-extraction.sha256` 和本文件末尾；之后的改动是新文件名加版本号。

## 4a. 这 20 篇长什么样（写完才知道的）

按规则抽出来的 20 篇，经资深分析员那一遍复看后冻结（Alex：作者自己定）：15 条陈述（core 8、colour 7），11 页金标为空，没有去处的一条不留（复述的旧数字、跑分倍数、定性辩解、库里没问题接的小事都删了，删的理由记在每篇的 rejected_note 里），只有 3 条（2 篇文章：Kessler 的 H200 证词、管理层的超大规模资本开支数）和主题论点有关。这是真实的底：大多数页面没有 core 陈述，所以这套集合量得准的是「多留」和「留对」，量不准 A 的收益。A 的决定性证据要另加一套「按事件选」的文章（H200 那几篇、资本开支那几篇），按同一把尺写，标明是按事件选的、只做开发集。

`gold-extraction.json` 是源，`gold-extraction.md` 是渲染给人读的；`check_gold.py` 核每个片段逐字在原文里、每个 id 当天展示或开放，并打印 sha256。冻结的 sha256 在 `gold-extraction.sha256`（e0db1121…，2026-10-28 16:10，发送前）。

## 5. 噪音底

对照组每篇发 3 次。一条金标在三次里出现的次数是它的稳定度；对照组自己三次间翻来翻去的格子，不拿来判实验胜负。实验组也发 3 次，三次都成立才算翻转。
