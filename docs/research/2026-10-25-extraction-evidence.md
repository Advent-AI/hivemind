# 把重要论据保留下来，再决定要不要新开问题

2026-10-25，D161。Alex 在 D160 失败后要求继续改进抽取，为后续运行和封存做准备。本轮只修抽取的阅读任务；不加新的证据存储层，不改观点身份、归组含义、UI、Idea、分类、Pull 或最终判定。

例子：一项融资安排有拟议担保额度、项目总成本和分析师对风险的批评。这些内容可以共同检验一个项目问题，不需要每读到一个数字就新开问题；也不能因为不用新开问题，就把总成本和批评丢掉。

## 一处修改、完整请求审查

用 D160 角色作新鲜对照，不再拿更差的 role-v5 作主要对照。实验角色先要求保留直接影响判断的事实、条款及支持和反对的理由，再决定复用问题或新开问题。合并重复的“一个问题”和“同一个问题”要求；保留年度、研究检查日、来源原意、逐字引用、对象、梯子及键的合同。没有 Ohio、Goldberg 或某个金额的专用提示。

逐层审查：system 是阅读任务；类别段仍按 T7 读来源和事件、按 T8 读论据；对象及参考清单仍只供参考；既有问题和组已可见；全文不截取；schema 已可表达同一问题的多条支持/反对证据；匹配只判断身份及证据新旧。schema、模型、reasoning、输出上限、全文、归组段、匹配和写入均不变。角色字符数和完整首请求字符数在运行前记录，实际输入 token 在运行后记录。不新增模型调用。

## 本轮验证及停止条件

使用 D160 同三篇输入、同六个独立序列，每臂三个新鲜样本，交错运行。每篇抽完并写完再读下一篇。沿用 D160 的 O1–O6 及金额原意判断，不因这次输出改答案；另列“第一篇是否已保留总成本”定位这次修改。原标准是否通过与新诊断项分别报告，不把补回算首篇通过。

每条检查问题、答案条件、证据原句、链接、出处、最终成员及重复归并；读所有错误的原答。三次实验必须全部满足旧核心标准，且首篇总成本三次均保留，才说明这个开发案例修好。对照自身的差异也逐次报出。任何拒绝、未完成、错误链接均不是通过；不能靠多开问题掩盖证据缺失，也不要求逐字输出相同。

这是开发案例验证，不是全抽取模块验收；即使通过，也不能直接封存全部类别或启用默认归组。通过后才固定其他类别的回归案例与默认接入方案；本轮不预授权一个未定输入和答案的付费测试。失败停止这轮，报告最大剩余原因，不暗改标准、补采或换模型。默认产品仍用 v16，只有通过完整后续验收才提升版本。
