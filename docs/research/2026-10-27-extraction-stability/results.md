# 单次抽取稳定性：实测结果

2026-10-27。**这一版 prompt 没有通过整体稳定性要求，不能推广。** 60 次独立调用已完成；没有投票、拼接答案、失败后补抽样或改标签。部分内容覆盖改善，但另一篇上的空关联和拒收明显恶化。

具体例子：CoreWeave 的 1,040 亿美元积压收入是客户需求信息，不是 NVIDIA 已确认收入。新 prompt 在原网页上有 3/5 次把所有证据的关联留空；在清理正文上则 5/5 次漏掉这条积压收入。两种失败不能用同一个“模型随机”解释。

## 1. 测了什么

[预先固定的方案](plan.md)、[原 prompt](control-v12.txt)、[新 prompt](analyst-v1.txt)、[助手标注的事实](claims.json)、[执行脚本](study.py)、[汇总脚本](analyze.py)。数据位于 [本轮记录](../../../poc/reports/2026-10-27-extraction-stability/analysis.json)。

- 三篇旧基准文章，原 prompt / 新 prompt × 原网页 / 清理正文，每组五次，共 60 次。原网页和清理正文保留相同的论点、研究组、模型和 schema。
- 每组五次 HTTP 请求体逐字节相同。恢复生产代码的 schema 字段顺序；此前存档排序造成的字段顺序变化不再混入本轮对照。
- 模型均返回 `gpt-6-luna`、`service_tier=default`；60/60 `finish_reason=stop`，无传输失败、无截断。响应没有 `system_fingerprint`，不能据此排除服务端未披露的变化。
- 388,120 input tokens，104,916 completion tokens；按仓库费率估算 **$0.06248872**，不是账单。保守预算记账 $0.300049，60 次均已完成，没有未决调用。
- 系统 prompt 从 7,458 字符减到 7,453。完整请求 input tokens 在三篇、两种正文下均减少 17，未通过加长 prompt 获得改善。

## 2. 每个样本，不只看平均数

这里计的是预先标出的核心事实，在**通过旧代码检查的引文**中出现几个。CoreWeave 共 5 个，Motley 共 6 个，Rest of World 共 7 个。不是原始 evidence 条数，也不是完整语义准确率；拆句、合句不重复计分。原始条数、保留条数、31 个事实的全部五次出现情况、关联集合和原回答保存在逐样本 JSON。

| coreweave | analyst_raw | 0, 0, 2, 0, 1 / 5 | 0 |

原 prompt 自己对自己也不稳定，不能拿一次原回答作为“正确答案”。新 prompt 的改善不具有一致性：Motley 原网页的六个核心事实全部达到 5/5，但新 prompt + 清理正文只有两个核心事实达到 5/5。清理正文不是稳定性的充分条件，也不能据此推断噪音有益。

## 3. 全请求审计发现的拉扯

| 决策点 | 原请求里的拉扯或空缺 | 本轮怎么处理 / 结果 |
|---|---|---|
| 什么能作为证据 | “每个陈述默认是证据”“客户部署可作为供应商证据”，同时要求只保留直接相关内容、禁止推导收入 | 新 prompt 区分业务驱动与已实现结果；Motley 竞争机制从原 prompt 两种正文均 0/5 到新 prompt 原网页 5/5，但清理正文仅 1/5 |
| 时间范围 | 新论点的本年/次年限制，与历史数值、长期计划可否作为当前证据混在一段任务里 | 明确候选期限不排除历史和前瞻证据；仍有遗漏，不能宣称此项单独因果已证实 |
| 什么可关联 | 研究组展示成员论点编号，而完整可关联论点列表不包含其中一部分；schema 允许任意字符串 | 全存档 1,218/1,553 个请求展示此类编号；154 条证据只关联了这类组成员，涉及 67 次调用 |
| 能否空关联 | schema 允许 `links: []`，下游却拒收 | 全存档 452/4,088 条原始证据为空关联，涉及 143 次调用。本轮仍出现，且新 prompt 更严重 |
| 是否逐字引用 | 模型复制一长段原文，同时负责摘要、归类、关联；正文保留 HTML 留下的标点前空格 | 全存档 130 条引用失败中，45 条只需消除标点前空格即可匹配；本轮 21 条中 16 条属于这种情况 |
| 每条证据的单位 | 一个 evidence 只能有一套来源、日期、层级，但一个原段落可能混合公司数值、管理层陈述和记者解释 | 新 prompt 要求一个独立陈述一条；模型仍合并不同陈述，单个 tier 无法准确表达整条 |
| 做多少件事 | 选事实、判断关联、写摘要、查来源日期、判层级、新建论点、写五档区间、选组在同一次生成中完成 | 本轮保持调用结构以测 wording；出现开新论点时只返回该论点证据的样本。是待进一步隔离的机制线索，非已经证明的唯一根因 |

新 prompt 是组合修改。本轮可以判断这个组合没有稳定改善，不能把变化精确归因到其中某一句。清理版也是人工保留完整报道的实验输入，不是已验证的生产网页解析器。

## 4. 从模型回答一路追到拒收

529 条原始 evidence，437 条通过现有检查；92 条没有进入保留集合：70 条空关联，21 条引用失败，1 条只指向被拒绝的候选论点。另有一个 2030 年候选被期限规则拒绝。这些类别按实际检查顺序统计。

- **读到了，关联为空**：样本 002、013、039（新 prompt + CoreWeave 原网页）和 047（新 prompt + Rest of World 清理正文）最终零保留，但原回答分别有 10、4、3、17 条 evidence。`score.json` 同时记录原数、拒绝原因和保留数。不要把这些说成模型返回空数组。
- **读到了，格式拒收**：021 的 40 万颗芯片、512 亿美元收入、训练与推理三条内容被复制出来；原文 `chips .`、`billion ,`、`World .` 在输出中变成正常标点，整条引文被拒。16/21 为同类；其余包括 019 改写首词、028 拼接不相邻句子、050 使用省略号、035/048 改变引号边界。
- **确实没写**：CoreWeave 清理正文的新 prompt 五次全部没写 1,040 亿美元积压收入；原 prompt 也五次没写。正文第一段明确存在。它不属于拒收，更不能由放宽引用检查补回。
- **关联改变**：040 原 prompt 将旧 GPU 合同、价格和替换限制全部关联 `v37`（NVIDIA 是否签署芯片贬值风险担保）；其他样本关联 `v6`（数据中心收入）。它们对需求或资产价值有解释力，却不是 NVIDIA 签署担保的证据。表中的引文覆盖数因此是语义合格数的上界。
- **分支互相挤占的线索**：018 新建网络收入候选，只返回三条网络证据，省略同文计算业务收入与竞争事实。该候选还出现区间文字与数值矛盾。030 原 prompt 新建不允许的 2030 行业候选，随后被代码拒绝。不能仅靠 evidence 数量评判这两次。

[历史边界普查](../../../poc/reports/2026-10-27-extraction-stability/boundary-census.json) 由 [census.py](census.py) 生成。它逐字段读原始输出，类别可重叠，不能与 preflight 的按顺序拒收数直接相加。已用原调用 3278（8 条有效证据，无空关联/引文失败）作已知对照。调用 117 展示 `g3` 的成员 `v3/v4`，模型把 2026/2027 行业支出挂到这两个编号，随后因不在可关联集合而被拒收。

## 5. 语义复核，不把出现率当准确率

已阅读 001–060 全部原始 evidence 的摘要、关联、来源与层级，共 529 条；另逐条回看 21 个被拒引用和所有三个原始候选。以下是必须独立保留的语义失败：

- 010、059 的 AMD 交易摘要保留 500 MW，却漏掉原文的 $10bn。引文命中不代表摘要保留了全部重要数值。
- 034/045 等把营收实际值和 Blackwell 售罄陈述合在一条，统一标为 `fact`；042/053 把假设情景的比较与历史网络收入混在同一条 `fact`。包含公司实际值不等于整段都是已实现事实。
- 010、023、034 等把自动驾驶出租车与数据中心计划放在一条并挂数据中心收入；058 把纯出租车事实挂 `v6`，而 `v9` 汽车收入问题已展示。最具体关联的指令没有可靠执行。
- 002/026 把没有写年份的 Burry “November” 补为 2025-11；大量样本把报道发布日期写成受访者原始发言日。059 甚至把“said on July 14”加入摘要。来源日期仍不可靠。
- 001/003/015 对同一个 A100 合同分别使用第三方观点、事实、当事方陈述；层级稳定性未通过。多个人同段发言还被合成一个 `original_who`。
- 043/054 原 prompt 清理正文把估值情景/股价目标挂到总收入问题。报告保留这种多抽且错挂，不把多抽算进改善。

31 条标签是助手预先标注的开发案例，不是人类批准的全覆盖金标。固定锚点可能漏计不同引文表达的同一意思；完整匹配也可能因摘要删掉限定语而高估正确性。这里不修改标签来抬高任何一组分数，也不宣布任何一组已通过语义验收。缺失核心信息的失败已足以否定整体稳定性的结论。

## 6. 判断与下一步

这轮的结论是：**当前开放式选句任务的遗漏仍在；请求、schema 和拒收规则的不一致又放大了结果差异。只改角色描述和相关性措辞不够。** 已经证实的是这些具体输出路径；未证实的是各条指令、上下文长度和服务端采样各自贡献多少。

下一项应先收敛一个合同：**模型看见的可关联目标、允许输出的目标、代码接受的目标必须是同一集合；每个候选来源片段都要有可检查的处置结果。** 先处理可机械证明的请求矛盾，再用未调过的文章检验遗漏、摘要和关联，不采用多次投票。片段编号、逐片段保留/不保留的输出形状，或引用空格的规范化，均尚未实现或通过模型验证；不把其中任一项冒充已经证明的稳定性修复。

[新 prompt](analyst-v1.txt) 和全部失败保留作研究记录。生产 prompt、模型配置、现有检查及数据库未修改；本轮没有恢复长任务，也没有切换默认。

## 7. 验证与边界

- 预付费检查使用冻结 runtime 和 item/views 数据库副本：1,553 次抽取、662 条匹配记录、209 个枚举检查、50 个 open key。三篇原始样本 3278/667/716 分别 8/13/8 条通过，零拒收。
- 现有 preflight 的历史 judge 回放仍使用旧中文 schema，出现与本轮无关的已知拒收；历史抽取拒收逐类保留，没有用一次退出码为 0 掩盖这些结果。
- 60 个有序请求检查通过；真实积压收入正例通过；删掉证据、篡改引文数字、使用不存在的目标三个变异均被抓住。两个付费前只读审查无严重阻塞项。
- 完整 Python 套件和文档机械检查结果见本目录 `refresh.md`；这些检查不证明模型稳定。
