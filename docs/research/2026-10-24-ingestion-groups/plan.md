# 在入库时自然组织观点：短序列实验

状态：固定实验与免费诊断重放已完成，见 [findings.md](findings.md)。只在新的实验库运行，不改封存库、生产模块、MCP 或 UI。

## 要证明什么

一条文章进入抽取和比对时，能否顺便建立观点之间的研究分组，并让后来文章沿已有关系更新，而不另外扫描全库聚类。

例子：第一条信息创建 Rubin 出货观点和其他经营观点；第二条信息带来客户工厂部署，两条独立观点应能属于同一个商业化问题；后来风险证据仍连回原观点，并标明影响已有分组。分组成员不是因果依赖，也不是合并底层观点。

## 输入与实验臂

使用 `poc/data/items-window-tags2-2026-10-24.sqlite` 的三条原始全文，按存储的知识日期顺序：

1. 2026-02-25 NVIDIA 电话会：空库开始，有产品执行和经营数字，不手工预先建立分组。
2. 2026-07-24 SK–NVIDIA 合作发布：出现客户部署等相关新问题。
3. 2026-08-12 Network World 汇总报道：包括 Rubin 延期风险及其他消息。正文里较早日期仍原样保留，不把收到日期当作事件发生日期。
4. 重送第3条的同一 input_id：只测原有分发去重，不调用模型。

三份独立样本，每份两个独立空库：普通入库控制、入库同时组织分组。两臂都用全文、相同原生英文抽取及普通比对规则。新臂只多组的短范围、抽取关系提示、匹配时组归属决定。模型仍为既有 gpt-6-luna；抽取 low、比对 medium，输出上限沿用现有配置的 16k/12k。基本 36 次调用，必要的候选归入后证据二次比对也照原有路径执行；全实验硬上限 48 次/$8（仓库价格估算），到限停止，不提高上限。

## 复用与隔离

复用真实的 `dispatch.route`、`store.views_for_prompt/search_views`、`matching.build_lists/check`、`extraction.sift`、`writing.write`。实验在这条入库链上调用，不使用预先选好的 Thesis 快照。新的英文提示词和输出合同放在实验模块，不修改正式提示词。原有枚举检查需要的内部标记通过控制值适配，不翻译正文或封存数据；模型和新实验库的文字均原生英文。

抽取的新臂交出关系提示，但不决定持久 ID。比对的新臂在同一回答中交出：原有候选/证据去向；新的研究组问题与范围；本次新候选或已展示观点的成员关系及理由。代码在 `writing.write` 得到真实新观点 ID 后、同一事务中保存组和关系。新字段不能绕过原有检查。

## 数据与决策合同

| 数据 / 写者 | 读者与检查 |
|---|---|
| 抽取证据与候选 / 抽取模型 | 原出处、日期、梯子、同一句合并检查；正文只读这一条全文，已有观点只给问题/范围/期限，不给状态 |
| 关系提示 / 抽取模型 | 比对模型参考；只能引用本次候选和已展示观点，允许没有提示 |
| 研究组 / 比对模型提议，代码定 ID | question、scope、title；不得只是公司目录；新组必须有实际成员。组成员关系单独保存，不写成依赖 |
| 成员关系 / 比对模型 | 只能指本次保留的候选、已展示的真实观点及已展示/本次新建组；候选归入后由代码解析为最终观点 ID；不因列表顺序建立父子关系 |
| evidence→view、dependency / 原写入器 | 沿用既有检查和写入；不把同组自动当依赖，不合并不同问题 |
| 受影响组 / 代码 | 从本轮 changed_views 和新成员求并集，写到本次处理记录；不重扫/改写其他组，不在此实验重判或生成总论点摘要 |

初版只增加组及成员，不自动拆组、并组、删成员或强制覆盖所有观点。相关观点可加入多个组；没有充分依据可保持独立。允许给已展示旧观点补入新组，因此不会只处理新候选而永久遗漏早期观点。

### 展示范围与引用解析

抽取的旧观点只由 `store.views_for_prompt` 根据这条信息的已标对象及原有依赖取得，不手工加入 Rubin 或其他答案。比对候选集使用 `matching.build_lists` 的原有全文搜索与 `search_top_n=10`。抽取的组描述只取其展示观点已加入的组；比对再加上候选搜索实际找到的观点所属组。只读 title/question/scope/member IDs，不带总结或历史证据。每次存下真实展示集合；检索缺失与模型漏关联分开报告。没有声称这个候选取得机制能找全未来跨行业关系。

新建候选解析为本轮 `written.new_views[candidate_id]`；归入候选解析为检查后的 target_view_id；discard 或未通过原检查的候选不能成为成员，有引用就拒绝本次写入。旧观点只能取实际展示集合。新组引用使用本轮临时标识，由代码生成持久 gN；旧组只能引用展示集合。组必须有至少一个成功解析的成员，同一 view/group 只保存一次。原 `writing.write` 与这些写入使用同一个 SQLite 事务，不在中间 commit，任何新关系检查失败则整个写入 rollback。

### 英文协议与原函数适配

模型/实验库的枚举分别为：kind=`company|theme`；tier=`fact|party_statement|third_party_view|rumor`；五级标签=`strongly_bullish|bullish|neutral|bearish|strongly_bearish`；候选去向=`existing|successor|new|discard`；证据去向=`duplicate|replace|new`。二级标签为 yes/no。题目、理由、范围、条件均原生英文，原句照抄。

为调用原检查，仅在内存里将上述枚举按原常量的对应顺序转成 `extraction.SCHEMA`、`extraction.TIERS`、`extraction.OBJECT_LABELS`、`matching.OUTCOMES`、`matching.EVIDENCE_OUTCOMES` 要的控制值。检查完成后候选的枚举恢复英文，交给原写入器；Checked 内部去向继续是原控制值。原文、题目、条件和理由不经过翻译。把 theme 候选排在 company 前，再交给原写入器，保留原来的建对象顺序。新关系字段独立检查，不能通过原函数忽略未知字段而跳过验证。

## 状态 × 事件

| 状态 / 事件 | 转移与写入 |
|---|---|
| 空库 / 首条信息 | 抽取、比对、生成真实观点 ID；新臂可在同一事务建组与成员 |
| 已有库 / 后续信息 | 只读当时已写入的观点及组；抽取和匹配沿当前候选范围处理 |
| 只增加证据 | 不要求新建组；由已归属观点求受影响组 |
| 新候选归入旧观点 | 原二次证据比对照常做；组引用解析到旧 ID，不能创造重复成员 |
| 新观点与旧观点相关 | 仍保留不同身份；可以加入共同研究组，依赖另判 |
| 重送同 input_id | 分发识别已处理，0 次新调用、0 个新成员 |
| 模型拒绝/非法答复 | 保留原答，本条不写观点或组，停止该流；其他独立流继续，不修答案或补样 |
| 二次比对或事务失败 | 整条最终写入回滚，不留半个组；重启不重发 started 请求 |
| 重启/配置变更/另一写者 | 独占实验目录；已有成功处理跳过；输入、代码、配置指纹不同拒绝复用；调用沿用单次发送和预算预留 |
| 终态 | 保存每条之后的图、原始请求/回答、检查及成本；封存原库不变 |

运行按文章轮次推进：每轮依次跑六个独立流（样本1控制/新臂，样本2新臂/控制，样本3控制/新臂），然后才进入下一篇。预算不足则全局停止，已经在途的单次请求按原预留记账，不给后续请求补名额。每流报告计划文章3、实际完成数、各阶段发送数、失败/未执行原因；不足三份完整控制时只报部分验证，不能宣称完整比较。任一流的结构失败不修复、不重试，但其他流继续。第四个重送事件只对完成第三篇的流执行。

## 测量及限制

先免费跑原 preflight、真实存档的原出处检查和新合同正反例，再付费；新臂和控制均三次，不用缓存代替新样本。普通入库本身的失败不能伪装成分组失败。逐条看：是否自然产生 Rubin 商业化范围；部署是否进同组且仍是不同观点；收入/成本等是否被无理由塞进去；第3条风险有没有连回并触及该组；组 ID 是否稳定；重送是否没有新调用。主题名不同不算失败，不预设组数，不作自动语义准确率。

每次模型请求包含什么、比普通臂多多少字符/token、实际新增调用数与费用都报告。没有摘要生成调用，没有额外全库聚类调用。

这是修改冻结机制前的隔离 POC。D139–D141 的摘要实验不是这次输入；D133 的英文输出要求保留。D39/D44 的身份比对、D51 的依赖及 D63 的逐日判断规则不改；本次只验证入库组织，判断/摘要刷新仅记录受影响组，不声称已经完成。

## 运行前检查

两轮只读审查后，展示范围、控制值适配、原子写入及不完整样本的统计口径已明确。六项新测试通过：真实原句经原 sift 检查；普通写入与组写入一起回滚；未知/丢弃/重复成员拒绝；组只随真实展示观点出现；归入候选解析为旧 ID；完整 process 经原函数入库并对同 input_id 零调用跳过。提前 commit、允许未知成员、向模型展示全库组三个突变均被测试抓到。

仓库 preflight 已重放，既有拒绝分布未变。抽取基础提示词 1,420 字符/260 token，组增量 411/74；比对基础 1,210/221，组增量 761/142（o200k_base）。这些是两个英语实验臂之间的实际新增内容，没有把组织工作伪装成免费的后处理。全文和实际 schema/context 的完整 token 费用会按请求统计。

DNS 可达，运行前没有其他研究模型进程，机器负载约 6（16 核）。本轮使用新日期目录和六个独立空库，不复制封存观点或手工建立主论点。

## 完成后的定向免费诊断

三个 SK 公告样本均在抽取输出中给出与已有 Rubin 出货观点的关联，但比对输出都未把它们放到共同组。追加只读原答的关系投影：用原有匹配结果解析临时候选 ID，保留抽取已有的 related_view_ids、共同问题和理由；不追加模型调用，不改原组，不把这个投影称作已完成组维护。

同时发现重复成员导致 affected_groups 过大的实现缺陷：9 个事件中 4 个受影响。修正实验写入器，只在真正插入成员或底层观点改变时标组；在新 verified 目录免费重放全部 37 个原请求，原付费输出不覆盖。所有模型请求字节相同，证明这是代码修复，不是新的模型样本。
