# 官方建议与本次请求的差距

Alex 在 D348 运行期间要求检查最佳提示实践，并问几个示例是否有帮助。已读取 OpenAI 官方页面：[Reasoning best practices](https://developers.openai.com/api/docs/guides/reasoning-best-practices#how-to-prompt-reasoning-models-effectively)、[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。

官方建议先用直接清晰的指令，复杂输出可增加少量输入/输出示例；示例须与指令一致。需要清楚区分输入各部分。格式约束不保证内容正确，仍需例子或任务拆分与实际评价。

| 已核查的实际请求 | 判断与行动 |
|---|---|
| D347 系统 351 tokens，D348 强化文字 623 tokens | 长度本身不是瓶颈；扩充明确了分句归属、条件比较、时间短语，但也出现机械补全与冗余说明 |
| 只有一句“记者背景；工程师估计”的文字例子 | 不是完整 few-shot。它没有演示 JSON、两种时间字段、跳过重复与保留反证如何同时成立 |
| 文章有段句编号，schema 独立 | 来源坐标与数据边界清楚；词编号方案增加了认知负担，其得失由 D348 三臂实测决定 |
| 类型由 schema 限定，交叉关系由代码查 | 空理由/空观察同时出现仍能通过生成 schema 再被 writer 拒收。需要把已有互斥规则前移到 schema，不能靠额外文字补规则 |
| 不要求模型输出思维链 | 保留。应给可观察的合格输出，不用“深度思考”替代合同 |
| 同一旧金标准与新控制 | 保留。范例使用虚构公司、不同数值与年份；不把开发文章的标准答案作为示例 |

下一次只比较“同一强化提示，无完整范例”与“加四个正确输入/JSON范例”。示例覆盖多说话人/未知年份、跨段有条件比较、软件迁移机制与重复/反证、实际但不完整期间。二者同时采用已有空行互斥规则的 schema 表达；原 writer 与接受集合不变。这是单独的新轮次，不篡改在途 D348。
