# NVDA no-look-ahead POC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the frozen Hivemind design end to end on one company (NVDA) over a replayed window with no look-ahead, and measure the three things the experience PRD says the product stands on: a belief maps to the right question, a state moves only on sourced evidence and triggers a pre-set exit condition with the source sentence, and the days the state said "unchanged" when hindsight says it should have moved.

**Architecture:** A test database of classified items (the "team's own database" of D7) is streamed in publication order through dispatch → extraction → views database (search, matching, writing, one re-judging round), exactly as `docs/prd/04`–`06` describe; a minimal pull mode runs at the end of each replayed day with that day passed in as "now" and freezes views due that day. A thin stack-side harness (not Hivemind) maps one sentence to a view, stores an exit condition and emits an event with the evidence when a judgement crosses it. Every model call is archived and replayable; records are append-only.

**Tech Stack:** Python 3 standard library only (sqlite3 with FTS5, json, urllib, unittest); one model provider behind one function (provider is decision 3 below); the TrueNorth MCP read-only JSON-RPC client ported from `../tn-hivemind/src/tn_hivemind/models/truenorth.py`; credentials through a port of `../tn-hivemind/scripts/with_credentials.py`.

**Spec:** `docs/experience-prd.md` (what to prove, §十一 items 1–2 and §十三), `docs/prd/00-system.md`, `01-universe.md`, `02-classification.md`, `03-config.md`, `04-dispatch.md`, `05-extraction.md`, `06-views.md`, `08-pull-mode.md` (the frozen design), `docs/DECISIONS.md` D7, D12–D14, D31, D38, D39, D44, D51, D54, D57, `docs/granularity-research.md` §4 (the five tests a candidate view must pass, a proposal). The plan argues from these; executors read them.

## Global Constraints

- Alex's messages win, then `docs/DECISIONS.md`, then the PRDs. The frozen modules are built as written; a finding that argues for something else is reported with evidence and recorded as a decision before any departure (AGENTS.md, Authority and scope).
- No product code until Alex starts the build (AGENTS.md §11). This plan starts nothing: Task 0 is Alex's decision, recorded in `docs/DECISIONS.md` as D62, and every later task runs only after it.
- Standard library unless a measured need justifies a dependency (AGENTS.md §3).
- Never order by the wall clock: order comes from dispatch's sequence number; only pull mode acts on time, with its "now" passed in (D12, D13, D31, D54).
- No look-ahead, enforced in code: an item is read only in a round whose replay day is not before its publication day; a guard trips, never warns (AGENTS.md §3 "One owner").
- Records are append-only: views, evidence, links, judgements, match records, switch records are inserted, never updated or deleted (06-views.md 先后顺序; D39).
- Every model call records the Config version and checksum, the exact request, the raw answer, prompt characters and tokens (03-config.md 验收标准; AGENTS.md §6).
- Citations are checked by code: a judgement that cites an evidence id not under the view, or one marked replaced, is refused and retried once, then fails to the review pool (06-views.md 状态).
- A number ladder has five rungs (two for a yes-or-no question), each a checkable range; rungs neither overlap nor leave a gap (06-views.md 梯子 rule 2); checked by code for number ladders.
- Number views are annual; the due date is the day the number is published; quarterly reports are evidence, not views (06-views.md 梯子 rules 5–6). The POC does not open quarterly views.
- Credentials never appear in Git, documents, logs, prompts, stored data, URLs or command arguments; tests never load them (AGENTS.md §9).
- Spending: a cap is set before the first paid run (decision 8); the run stops at the cap; never raised silently.
- The views database never holds future state: a replay refuses to process a day earlier than the last day it completed on that database (the old ledger's "clock never moves back"). With that, every read of "current" state, lists and dependencies is historically correct without an as-of parameter, and resuming continues from the first unfinished item, never from an earlier day.
- The views database holds no item text, only the quoted sentence of each source (05-extraction 出处记什么). Item text lives in the test database (the team's own database, D7); the model-call archive, which must hold the request bytes for a $0 rerun, is a POC artefact kept beside the test database, never inside the views database.
- Known look-ahead channels no code can close are written into the report, not hidden: a preview captured today may differ from what it said on its publication day (provider edits, re-clustering); a model with a June 2026 cut-off judging a February item knows March to June. Every item carries `retrieved_at`; the report prints the capture day and the model's cut-off next to the results.
- Explain results to Alex as to a sixteen-year-old: answer first, one concrete picture, his questions in his order (AGENTS.md, Authority and scope).

## Review Focus

Input classes the spec implies that a person using the POC will meet, most likely first; each line names the task whose test pins it.

1. **A news preview that only mentions NVDA in passing** (a listicle, "Forget Nvidia…"): extraction must return no evidence and no candidate view, and the round must not call matching or re-judging. Pinned in Task 7 (`test_extraction_returns_nothing_for_background_text`) and Task 10 (`test_round_with_no_evidence_calls_no_matching`).
2. **The same story from four publishers within one day** (Distilla showed 16,420 rows for 5,918 distinct titles in the window): classification merges copies (`copy_of`), dispatch merges them into the original; one evidence with four sources, no re-judge on the repeats. Pinned in Task 3 (`test_same_title_same_day_is_a_copy`) and Task 10 (`test_repeat_adds_source_without_rejudge`).
3. **The model answers with the right rung but cites an evidence id that was replaced an hour earlier in the same round**: refused, retried once with the refusal reason, then the item fails to the review pool and the next item proceeds. Pinned in Task 10 (`test_judgement_citing_replaced_evidence_is_refused`, `test_second_refusal_sends_item_to_review_pool`).
4. **An item published on day D arrives (in the feed) after items of day D+1** (late source): the replay guard must refuse the feed order, not silently process it; the feeder sorts by publication day first. Pinned in Task 2 (`test_feeder_orders_by_publication_day_then_arrival`) and Task 12 (`test_replay_guard_trips_on_item_after_replay_day`).
5. **A user sentence that matches no open view** ("I think Jensen is a genius"): the belief mapper must return "none" with the three nearest questions, never force a match. Pinned in Task 13 (`test_belief_mapper_returns_none_when_nothing_fits`).
